# WEO01：控件类型载荷与顺序

状态：类型联合体、seqNo及排序缓存已实现，build.bat Debug编译及链接通过；未运行客户端。

## 数据与生命周期

- 保留WindowElementType作为唯一类型标记，将WindowElement::data改为类型指针联合体，成员为graphic、animation、text、mouse、input、inputCaret、number。EventArea不持有载荷。
- 访问、创建、释放均使用与type对应的成员，不保留void*通用成员，不读取非活动联合体成员。沿用当前对象所有权与分配族，文本对象正常析构wstring。
- 滚动接口既有Graphic/Mouse双类型消费者按type访问对应字段，保留原字段值与滚动行为；焦点引用仍按现有身份规则匹配。

## 排序

- WindowElement增加int32_t seqNo；值越小越先入队及处理鼠标，在当前同层逆序绘制规则下位于上层。只影响同一窗口的控件，不改变窗口层级及渲染器各层规则。
- 原型末尾提供seqNo，默认-1表示实例创建时使用原索引；实例seqNo是实际排序值。同值按原数组索引排序。
- WindowInstance增加WindowElement** elementsSorted，缓存借用原控件的指针，不复制控件；按用户最后确认的双指针方案实施。窗口释放时只释放缓存数组，原载荷仍由原控件负责。
- 开窗时初始化缓存，之后仅在update维护。原数组地址或数量变化时重建；每次update检查当前排序是否仍然有效，seqNo改变使顺序失效时立即重排，最迟每1000毫秒刷新一次。坐标、可见性和载荷修改通过原控件指针实时生效，无需复制或重排。
- 不移动elements数组，不改变回调参数中的原索引、控件指针与滚动条相邻关系。鼠标和绘制共用缓存；遍历中的seqNo变更在下一次update重排时生效。分配失败清空有效缓存，下一次update重试，避免使用旧数组指针。
- 动态分页显式初始化seqNo以保留既有绘制层次；银行最前两个原控件仍先于页按钮，页按钮先于其余原控件。原先分页鼠标特殊优先遍历统一收敛为seqNo顺序。
- 默认绘制、大地图自定义控件绘制及原生/自动战斗扩展控件鼠标分发均使用缓存；自定义地图底纹等非WindowElement绘制保持既有顺序。
