## 范围与工程合同

原型54E3C0：window id 9，初始坐标(15,97)、尺寸315×261，
37元素起于560F50；更新4774C0、绘制46FBC0、释放4744A0。
本步补齐完整更新（含47752C公共尾）、刷新478010及释放，
不登记部分元素或占位按钮，不称37元素及编辑/提交交互完成。

按既有委托采用以下局部方案，不触发总SPEC对齐或日志压缩：

- 玩家name/level/titleIndex/ownTitle继续借SceneState既有owner，
  原称号表FF0508及排序表DE03F8继续共用既有TitleRecord。
  不重新排序、不复制列表快照、不以编号有效性过滤六行。
- 草稿D45FC0用256B原字节数组，CF4E54用独立S32页起点；
  InputContext D2DC10由Input唯一持有，UI原型57CCB8以原生非拥有T*借用。
- 输入原型沿既有WindowInputPrototype表示；编辑分支取原型当时的
  context->text，不改成直接读固定D2DC10，也不误读原型内嵌初始化文本。
- 只比较原字节是否相等，使用strcmp零/非零结果；不做大小写折叠、
  locale或Unicode转换。两次比较分别执行，不缓存第一次结果。
- 所有复制包含NUL且不增加截断；保留各次current window/elements/data
  的快照与重取。页索引、文本异常按RPLAN.24，不增加范围保护。
- 释放采用既有void签名；主更新保留S32参数，-1初始化，公共尾返回1。
  刷新原返回无人消费，采用void，不固定伪造有效原返回值。

## 完整更新、刷新与释放

当前原cg2d IDA已核266条指令，按IDA分段共32基本块：

| 入口/区间 | 指令/基本块 | 合同 |
|---|---|---|
| 4744A0 / [4744A0,4744E5) | 17 / 3 | 固定窗口9实例，逐窗写7/8/58坐标 |
| 4774C0 / [4774C0,47752C) | 38 / 3 | 参数-1才清页码及两次复制ownTitle |
| 47752C / [47752C,477537) | 3 / 1 | 478010后返回1，为更新公共尾 |
| 478010 / [478010,478293) | 208 / 25 | 名称/等级/当前称号、草稿与六行列表刷新 |

4774C5的条件跳转及47752B的顺序流都到47752C；
不能把IDA自动划出的4774C0终点当成更新返回点。
47752C的自动std::locale名称不构成业务合同。

### 同源状态与输入原型

| 原地址 | 原跨度 | 新承载与边界 |
|---|---|---|
| CF4E54 | 4B | gTitlePageCF4E54，只存S32列表起点 |
| D45FC0 | 100h | gTitleDraftD45FC0，至已有D460C0前，不合并相邻物品槽 |
| D2DC10 | 15Ch | input::gInputContextD2DC10，至独立D2DD6C前 |

前三项在原.data虚拟尾区，IDA is_loaded=false；
get_bytes显示FF属于未加载字节，不作为FF映像初值或字节摘要。
新端按既有虚拟零区合同零初始化，真实主更新仍执行原初始化。
后续草稿提交、滚动、焦点发布入口仍待，不以这些初值代替实际写者。

输入原型原首六W32为`D2DC10,105,31,3,12,6`；
原+18..+21C前516字节均0；尾四S32为`1,16,0,0`。
分别映射context、x/y、renderMode、fontType、color、内嵌text、
maxLine、maxCharPerLine、value224、encrypt。556B原型摘要为
`a71d6ab42423b8940a03b6508710a73fd0831d02b155c49a15820dfdac1fc13c`。
只有指针拓宽，不扩大各数值字段。

57CCB8首槽原xref47817D用于编辑正文读取；4775BA/4781C5传给476570。
4775C4/4775C9才是后续编辑按钮选择D2DC10的真实入口；
本步不凭刷新分支擅自调用SetContext或注册部分按钮。

### 初始化4774C0

参数等于-1时按序：

1. 4774D3把CF4E54写0；求ownTitle原字节长度并含NUL复制到D45FC0。
2. 4774FA重新取current window/elements，重新求ownTitle长度，
   然后才取元素8.data并复制到其text，不复用第一次长度或草稿代替源。
3. 到47752C公共尾调用478010并返回1；参数不是-1也走同一公共尾。

不清草稿尾部、不重置输入上下文。

### 刷新478010

| 阶段 | 原证据与实现次序 |
|---|---|
| 名称→元素6 | 478021先固定data，再求FDA808名称长度，最后取data.text复制 |
| 等级→元素7 | 47804F读取FDA704，使用553FCC的`%3d`，478072固定data后复制 |
| 当前称号→元素9 | 478094先取FDA800索引，再取当前窗口/data，源FF0510+1Ch×index |
| 非编辑分支 | 4780D6当前输入不等于D2DC10时，先元素8.visible=1；再重取data复制草稿；比较草稿与玩家ownTitle，然后重新取data只写首颜色字节，相等0、不同6 |
| 编辑分支 | 47817D先取原型当前context并从其text复制到草稿；再元素8.visible=0；重新取current window，按Y→X读取坐标，调用476570(proto,x,y,1)，忽略返回，不改文字颜色 |
| 公共确认显隐 | 4781D2再次比较草稿/玩家ownTitle，相等写元素21.visible=0，否则1；不复用上一比较结果 |
| 六行列表 | 478234只读一次CF4E54并固定排序表起点，从DE0400+1Ch×start连续取六条text，分别复制至元素10..15；每行重取当前窗口/data，不重读页码，不过滤id、不限长 |

元素8.visible/data原偏移138h/13Ch，元素21.visible原30Ch；
列表首行data原184h，对应10×24h+1Ch，不是元素9。
非编辑分支只更新文本元数据的低颜色字节，其他三字节保留。
编辑分支的476570可能改变共享状态，公共尾必须重新比较草稿与ownTitle。
内联逐字节比较只消费相等/不等，strcmp不引入其他业务排序。

### 释放4744A0

入口只取一次窗口9实例；非空时按7.x、7.y、8.x、8.y、58.x、58.y
依次读取固定实例坐标并写状态。没有重新取窗口9共享槽，也不改为先全Y。
原EAX=1由既有void释放边界丢弃，不改原型函数指针类型。

本步只做原指令/字节、同源状态、源码与差异静态核对；
37元素及编辑、提交、称号选择和滚动仍待，不宣称完整窗口或客户端验收。
不构建、不新增或执行测试、不运行客户端、不检查产物。

实施结果：完整4774C0（含公共尾）、478010及4744A0已有唯一本体；
输入上下文、原型、草稿及页码分别只有一个owner。556B输入原型
回映摘要一致，初始两复制/公共尾、两次比较、六行固定起点与释放写序
已静态核对。剔除新增段后旧UI、Input及两个头文件逐字一致，
原型主表、玩家/称号生产者和Yobi未改。
主回调缺口48降至46，元素仍33组、暂缓回复仍1；不将窗口9加入
元素/主回调均齐的清单，不以源码接线代替实际编辑、提交或运行验收。
