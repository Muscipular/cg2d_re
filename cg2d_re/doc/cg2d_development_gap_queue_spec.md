# 开发差集队列 SPEC（GQ01）

2026-10-05，为现有R1/R7收尾增加可直接选项推进的差集视图，不新增调用图谱。
上位：[追踪验收体系](cg2d_traceability_acceptance_spec.md)、[收尾清单](../plan/cg2d_spec_closure_checklist.md)。
固定快照：`cg2d-re-development-gap-queue-source-20261005`。

<a id="development-gap-queue-baseline"></a>
## 当前问题

[现有汇总器](../plan/measure_cg2d.ps1)已经读取原库存、历史定位、语义记录、具名分类和验收登记，
但看板只列“无合同关联”等总数；源码定位与语义身份都未登记的入口没有逐项推进清单。
历史定位快照不是当前源码扫描，不能据缺定位直接断言功能未实现。

<a id="development-gap-queue-decision"></a>
## 实施裁决

在同一静态汇总器内派生两个互不混计的队列类别：

1. `mapping_location_unrecorded`：原库存身份的历史定位、语义索引、pending索引及source关联均为空。
   列原ID/入口/原库存名称、既有具名范围/处置/合同依据和下一步。这是登记证据缺口，不是源码缺失证明。
2. `semantic_identity_unrecorded`：语义记录没有inventory_id。
   保留原语义JSON引用/入口/状态，并列当前库存中同入口的候选ID；匹配到ID也不自动赋值或升级验收。
   无匹配时先核代码段、原函数/chunk与未归属区间，不能由新端符号强行造原函数身份。

范围只取已有具名全入口排除、混合、显式功能成员的暂停及现有host处置。
无具名依据的项保留在范围内未归属状态，先核具体范围/当前源码与原身份；
不按名称关键词或地址前缀猜音频、库函数、不可达或排除，也不启动暂停事项。
库存名称只供定位，不能作为指令、实际函数职责或完整实现证据。

新快照字段`development_gap_queue`为标准JSON逐项数组；metrics新增两类别、总数及需核/暂停/排除数量。
看板新增§5，先列类别和范围数量，只逐项展开非暂停/非排除的范围、定位与身份核定项。
暂停/排除全明细保留快照，暂停计数只限本队列的明确成员，不是音频源码或全功能分母。
需核项数也不等于待实现或获准运行项数；未归属项仍须先核具体范围与当前源码。
继续只输出原看板与快照，`-Check`同时比较这些派生内容；禁止手改新队列。
不改变旧计数定义、函数/导入/区间分母、政策、处置或门禁，队列总数不参与完成率。

<a id="development-gap-queue-acceptance"></a>
## 限定静态验收

检查汇总器精确补丁、两类别按原输入定义生成、原身份/语义引用/候选ID与范围来源一致，
排除/混合/暂停/host不被当成普通待实现；无依据项不自动扩张排除或恢复音频。
新增Markdown/JSON字段、UTF-8无BOM/LF、原计数/政策/完整门禁保持及生成/独立Check核对。
不访问源码内容作全工程复检，不访问IDA或网络，不构建/测试/运行客户端/算法样例或计算摘要。
R01/R03/R04与R1/R7/完整SPEC保持open；该工具把证据缺口显式化，不证明这些缺口已解决。

<a id="development-gap-queue-source-state"></a>
## 本组交付状态

同一汇总器生成可追踪差集行，入口从看板可见，快照保留原身份、引用和范围依据。
差集随台账更新自动减少或变化；源码已有而登记缺失的项先补事实，确有代码缺口才实现或迁移。
既有语义/原新函数分类、软件实现及完整验收结果不因工具变更提升。
