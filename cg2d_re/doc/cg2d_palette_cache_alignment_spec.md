## 具体差异与实施合同

<a id="palette-cache-decision"></a>
### 动态池 44E150

1. 入口保存 `gGraphicDataCacheList`；负图号扫描、正脏计数扫描均沿此同一
   基址，计数为 S32，容量保持 104。不给空池加保护或补造备用对象。
2. 空槽先沿保存基址写 imageNo；随后独立重读共享池写 dirtyCount=0，
   最后再独立重读共享池返回该槽。
3. 正脏项复用：先取 DX 基址，再沿入口池读旧 imageNo，清其 DX palette；
   随后依次重新取池写 imageNo=-1、写新 imageNo、写 dirtyCount=0，
   最后重新取池返回同一槽。保留全部写入，不合并两次 imageNo 写。
4. 无正脏项时强制首槽：沿入口池先取旧 imageNo，随后取 DX 基址清引用；
   重新取池后取新图号实参，写 -1；再分别重读池写新图号、清脏计数、返回。
   此分支的 DX/旧图号取序与上一分支不同，不统一成 helper。
5. 当前源码逐次读取共享池来扫描，旧图号与 DX 基址读取也未显式按原次序；
   本步恢复保存/重取阶段。池分配、owner、释放和帧末老化保持。

### 颜色生成 44E290 的 32 位路径

1. 无 triples/quads 才将 mode 改为 0。入口只借用一次色调指针；
   空指针或 applyTone=0 切换为局部中性色调。静态槽选择先比较 blue，
   再 green、red；槽号仍为 mode0 的 0/2、mode1 的 1/3。
2. 槽0的 activePalIndex=0 命中即返回，不读帧作额外门禁。
   其他静态槽先保存活动调色板号，再读槽中旧号；相等时才读旧帧并比较
   当前帧。未命中先写保存的活动号，随后独立读当前帧并写入。
3. 固定调色板头16/中224/尾16以及动态256项分段保持。
   PALETTEENTRY 为 RGB+flags，动态源为 BGR/BGRX；第四字节不成为 alpha。
   triples 优先于 quads，不按 paletteSize 裁短 256 项。
4. 私有颜色 helper 改为同步借用原色记录，按原顺序取样：
   不映射时 red→blue→green；映射时先取 red 表/原 red，
   再取 blue 表，查 red，取 green 表并读/查 green，最后读/查 blue。
   不先把源三字节作为实参全部读齐，也不把三表预取成长期快照。
5. 每项先写完整 `0x00RRGGBB` W32；为纯黑时再写 W32 1。
   最后仍单独把 payload[0] 的完整 W32 写零，命中返回跳过生成。
   旧 helper 将颜色与纯黑修正合成一次写，本步拆回原两阶段。
6. 动态池返回空的原失败门禁保留；取得项后先清 activePalIndex/frameIndex，
   applyTone 非零才写真实活动号/帧。不改变 imageNo、dirtyCount 或调用者失效规则。
7. 只改既有 [GraphicPaletteCache.cpp](../src/render/GraphicPaletteCache.cpp)
   的两个根及私有颜色 helper；公开声明、0x410 项布局、104/4 容量、
   图形上传、池 owner/初始化/释放/老化、变换缓存和四顶点设备保持。

依据为原指令，不引入新业务或外部依赖。C++ 私有 helper 的接口收敛只承接
同步取样，不宣称机器 ABI、原编译器指令发射或调用轨迹相同。
越界、数学溢出、空映射表等异常按 RPLAN.24，不新增保护、回绕模拟或故障测试；
本步不记安全或故障等价通过。
