# UWF01：内部文字仅使用UTF-16

用户2026-10-15明确要求“UTF-8格式应该彻底删除，只保留wchar/wstring”。本方案覆盖此前UTL02保留UTF-8兼容视图、窄格式化及显示重载的过渡约定，按既有工程委托实施。

## 范围与边界

- 内部界面常量、格式模板、动态正文、提示、分行、测宽及绘制统一wchar_t／std::wstring／std::wstring_view；删除Utf8View与不必要的宽窄往返。
- 已明确GBK的网络／文件字段完成原字节解析、解转义后直接转宽；发送／保存时由宽正文编码GBK。原协议、资源、存档字节布局及容量不变，不把原二进制数组整体宽化。
- UTF-8只允许出现在必须接收该编码的外部API边界，不能继续作为业务文字或格式化中间表示。系统错误、库诊断及文件签名不是界面正文；不按char类型无差别修改。
- 保留原地址注释、字段宽度、读取发布及回调时序；字符预算按已批准UTF-16／像素合同，仍有实际GBK字节预算的边界保持字节口径。

## 实施顺序

1. 修正同类GBK错误消费，追踪局部别名及混合来源的名称owner，避免机械替换ToUtf16。
2. 窄格式化模板、格式化辅助及结果临时成组改为宽格式化；动态结果不回到固定char数组。
3. 静态兼容视图与显示／输入／窗口辅助的窄重载成组退休，网络发送接口接收宽正文，GBK转换收敛到真实边界。
4. 检索残余并逐项核来源、签名、临时寿命和固定记录消费者；同步函数行号与追踪台账，精确提交。

## 验证与限制

仅静态源码、差异、声明／定义／调用及文本台账核对；不构建、测试、运行、附加、部署或计算摘要。已有外部键盘两历史引用缺失不通过恢复文件或放宽检查掩盖。每步记录实际完成范围，不以局部修正宣布全工程迁移或运行验收通过。
