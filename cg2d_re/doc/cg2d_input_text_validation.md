# cg2d 旧编码输入文本拒绝校验还原

## 函数边界

- `sub_404060@[0x404060,0x40411E)`，84 条指令、20 个基本块，原型为
  `bool __cdecl(char*)`；返回 `true` 表示拒绝，返回 `false` 表示接受。
- 新端公开为 `input::IsRejectedInputText_404060(const char*)`。原函数不修改
  文本；`const` 只收紧新端接口，不改变读取行为。

## 严格判定顺序

1. 先以无界 `strlen` 读取文本长度。
2. 再以大小写敏感、无 DBCS 对齐意识的原始字节 `strstr` 查找
   `A1 40`；命中立即拒绝。
3. 长度为零时拒绝。
4. 从左到右扫描。每个字节先按 `uint8` 解释：
   - bit 7 置位时，无条件读取下一字节，以
     `(first << 8) | second` 组成无符号 16 位值；命中含端点区间
     `A140..A1FE`、`A240..A2FE` 或 `A340..A3E0` 时拒绝，否则额外推进
     一字节，把下一字节一并吞掉。末尾孤立高位字节会读取终止 NUL，随后
     退出扫描。
   - bit 7 未置位时，严格依次拒绝 `|`、`\`、`/`、`isspace`、
     `iscntrl`。传给 ctype 的值先转为 `unsigned char`，避免 C++ 未定义
     行为。
5. 扫描全部通过后，才以同样大小写敏感的原始字节 `strstr` 查找 `[GP]`，
   按是否命中返回拒绝结果。

函数不检查空指针，也不为缺少 NUL 终止符的输入建立扫描上限；这些调用前置
条件与原函数一致。

## 编码边界

高位字节成对读取以及三个 `A1xx..A3xx` 区间，是输入采用 Big5/CP950 旧编码
边界的强证据，但本函数不是 Big5 合法性校验器：

- 三个区间按连续无符号整数比较，包含 Big5 尾字节空洞。
- 区间外的任意高位首字节均无条件吞掉任意下一字节。
- 不检查尾字节是否合法，不进行 UTF-8、GBK 或 Big5 转换，也不改变大小写。
- `A1 40` 与 `[GP]` 的子串搜索均不感知双字节字符边界。

## 输入校验改接原共享分类表 SPEC（2026-10-02）

发现当前本体两处std::isspace/std::iscntrl读取宿主CRT分类状态，与已经实现的
原58FC30共享分类指针分离。按用户工程委托，本步改接原表，不新增分类副本、
locale设置器或NLS通用接口；上文宿主ctype的承接说明由本节修正。

### 原端证据与限定调用域

- 4040E1/4040E5对当前字节符号扩展后调用53BDEF；高位字节已由前面的
  bit7分支处理，因此此处实际值为0..127。只有返回零才在4040F1/4040F6
  再读取当前字节并调用53BE17。拒绝次序仍是空白在前、控制字符在后。
- 53BDEF和53BE17各13条指令；SrcSizeInBytes<=1时读58FC30所指表项低字节，
  分别与8和20h；>1则把相同mask传541955。
- 541955共46条，54195C..541971对-1..255直接读同一U16表再与mask。
  因此输入校验可达的0..127域，在两个模式下都是同一表项及相同mask，
  无需新增SrcSizeInBytes影子状态，也不能把初值1当常量。
- 541955其余输入域会按高字节lead标记选一/两字节并调用CRT NLS包装。
  本步不公开一般S32 isctype，不声称该域或其他运行库调用已实现。

### 实施边界

在既有LegacyStringCompare平台边界增加ClassifyLegacyByte(uint8_t,uint16_t)，
只返回当前gCtypePointer58FC30[value]与mask，不缓存指针或分类结果。
Input.cpp两次真实调用分别传0x0008和0x0020，保留分支先后；接口仅U8输入，
不为EOF、负数或宽字符建立推测规则。原比较器及其NLS路径不改。

移除Input.cpp已不使用的cctype头；除此不改输入扫描、旧字节区间、分隔符、
子串搜索或调用方。不把高位字节改成Unicode，也不增加严格输入限制。
原表初始ASCII结果与宿主C locale可能相同，但状态来源必须回到真实共享对象。

三个语义入口只按输入校验及已有比较器的已证字节域映射，其他CRT caller、
负值/NLS及全局locale生命周期继续未验。集中静态检查两个调用/mask顺序、
唯一共享表、限定差异与UTF-8/LF；不编译、测试、运行或进行哈希校验。
