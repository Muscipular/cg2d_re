| 1 | 清零本地 128 字节，再依次解析 `newest:`、`savedata:`、`datafolder:`、`binfolder:`、`mapfolder:`；均为 `%s` | `0x465F0A–0x466059` |
| 2 | 固定用 `data\0\%s` 与 `save.dat` 写入 `0xFF4E30`；不使用本地 savedata 或 `gDataPath` | `0x46605C/0x466061/0x466066/0x46606B` |
| 3 | 每槽依次处理 Graphic、Graphic 二次覆盖、GraphicInfo、Anime、AnimeInfo，然后进入下一槽 | `0x4664EE–0x4666A6` |
| 4 | 每槽先 Coordinate 数据、后 Coordinate Info；名称任意位置含星号即跳过数字键 | `0x4666B0–0x466789` |
| 5 | 另一轮逐槽先数据、后 Info，按 `*%d` 从同表复制名称 | `0x466791–0x466841` |
| 6 | 命中 `windowmode` 则置 1；取 DC，查询索引 12 的设备信息，保存后释放 DC | `0x46684C–0x46688E` |
| 7 | `nodelay` 清零原值；`winpos:` 用 `%d,%d` 解析，两值均非负才一起写回 | `0x466899–0x46690F` |
| 8 | 先清零标志、将模式首字节置 1，再解析 `3Ddevice:` 的四字节整数 | `0x466915–0x46695C` |
| 9 | `soundoff`、`musicoff` 分别清零；非零 Setup.ini 模式再覆盖模式首字节 | `0x46695F–0x4669A3` |
| 10 | `onlyactive` 将标志低字节或上 `0x10`；`0xFF0D40` 写入 1，最后调用 `0x507C80` 并返回其结果 | `0x4669A8–0x4669EA` |

所有键均使用大小写敏感的 `strstr`，只取首次子串命中，不检查词边界，不按命令行出现顺序调度，也不新增引号、转义或重复参数规则。
原 `savedata:` 只有解析写入，之后没有读取该本地缓冲区；不得将它接入固定路径拼接。
无条件写回之外，未命中的参数保留调用前全局值，不补充每次调用时的统一重置。

别名只有一遍，后槽会观察此前已写入的前槽；引用未处理的后槽时可能复制仍含星号的名称。默认 `*3` 复制本轮数字参数已经改写的槽 3。

### 模式写入的四字节别名

`0x466927` 使用 `mov ... ,bl`，`0x4669A3` 使用 `mov ... ,al`，均只写首字节；但 `0x466945` 将同地址交给 `%d`，`0x466957` 的扫描成功时写四字节。
因此不能直接把单字节地址传给现代 CRT 的 `%d`，也不能将扫描后结果截断并丢弃后三字节。实现将 `%d` 指向整型承载，再由字节引用执行默认值及 Setup.ini 覆盖。
`0x62A641–0x62A643` 未见直接引用；`0x62A644` 起的下一全局另有消费者，本次四字节写入不涉及它。
原消费者在 `0x44BCA6/0x44BE4C/0x44BE83/0x44BEBA` 使用有符号字节比较；公开的字节引用只表达原始位，后续消费者不可未经核对改成无符号范围判断。
`onlyactive` 在 `0x4669C0` 读取整个标志 DWORD，`0x4669C5` 对 AL 或入 `0x10`，
`0x4669C7` 仍写回整个 DWORD；不是对全局内存只写一字节。源码的 32 位 `|= 0x10` 保留该行为。

2026-09-14 主线程再次核对 `0x466945/0x46694F/0x466957` 及相邻对齐区，确认四字节存储加字节引用方案。
`cg::platform::gRendererModeStorage` 与 `gRendererMode` 仅由本项定义，`MainLoop.hpp` 已采用 `extern std::uint8_t& gRendererMode`。
本次读取 `MainLoop@0x457020–0x4574D9` 确认其在 `0x457053` 读取实际模式，在 `0x457058` 读取 `gSupportedRenderMode@0x628FEA`；后者由主线程 `MainLoopState.cpp` 定义。
`gRequestedRenderMode@0x628FE0` 继续由 `StartupState.cpp` 定义，`gPaletteCapability@0x9A7F64` 继续使用既有 Palette 存储，本项均不重复定义。

## 5. 色深边界

用户目标仍为 x64 加 32 位渲染，8 位资源解析必须保留。本函数没有按 8/16/24/32 位选择渲染的分支，也没有将 `3Ddevice:` 解释成色深的证据。
`0x466878` 压入查询索引 `0x0C`，`0x46687B` 调用 `GetDeviceCaps`，`0x466889` 原样保存结果；实现不强制改为 32，不添加兼容模式。
`3Ddevice:` 保留任意 `%d` 的四字节解析及 Setup.ini 后覆盖次序，不自行限定为 1–4，也不据此建立 SDL 驱动映射。
原 `Renderer::Init@0x44B630` 所属函数内在 `0x44B6C5` 有色深比较，另在 `0x44BCA6/0x44BE4C/0x44BE83/0x44BEBA` 比较模式 1/4/3/2；这些消费者不是本项实现范围，模式到新后端的策略仍待后续证据与裁决。
本项未实现或恢复任何 8/16/24 位渲染分支，也未删除索引资源名称解析。

| 原依赖 | 现场确认 | 本项处理 |
|---|---|---|
| `strstr@0x53BE40` | 两个 C 字符串参数；原函数各键按此查找 | 使用 `std::strstr` |
| `sscanf@0x53CADC` | `%s`、`%d`、`%d,%d`、`*%d` 实际格式与写址均已读取 | 使用 `std::sscanf`，不新增校验、固定成功或容量截断 |

| `strchr@0x53C2F0` | 第二参数 `0x2A` | 使用 `std::strchr` |
| `GetDC`、`GetDeviceCaps`、`ReleaseDC` | IAT `0x54D308/0x54D05C/0x54D30C`；调用 `0x466870/0x46687B/0x46688E` | 使用既有 Win32 实现边界，窗口承载复用 `gLegacyWindow` |

`0x507C8A–0x507C98` 清零从 `0xD69798` 起的 `0x96C8` 个四字节单元并清零 `0xD69794`；随后从命令文本扫描 `IP:`，写入目标表并修改 `0xD9F2D4` 起的计数。
`0x507CA4` 的 `strstr` 为空时，`0x507CB0` 跳到公共返回，EAX 为 0；`0x507CC4` 扫描 `%d:` 后，`0x507CD0/0x507CD6` 将索引作为无符号值与 `0x320` 比较，越界则保留扫描返回值退出。
公共尾部 `0x507D83–0x507D87` 不改 EAX，因此返回的是整数结果而不是可解引用字符串。本项只确认调用契约，不实现其表布局、解析内部或计数逻辑。

## 7. STONAGE 架构思路参考（不计证据）

## 8. 输入限制与交接

本项保留原函数的不检查行为，没有增加“修复”业务规则：

1. `gCommandLine` 必须是有效 NUL 结尾文本；`%s` 无宽度限定，调用方必须保证目标容量。`gTextFF4E30` 的已确认容量为 `0x88`，并与待提交图形存储前缀共用唯一存储。
2. 首次资源数字扫描失败会读取未初始化的共享 `int`；后续失败可能沿用上一次值。`winpos:` 也不检查是否读满两个整数。此类输入不承诺可移植、确定的行为，不伪造默认值。
3. Coordinate 槽 6–8 若不含星号，原函数会将空键指针传给 `strstr`；别名展开后的第二次调用可能触及此路径。未增加空指针跳过或重复调用支持。
4. 别名索引无范围检查；错误索引、跨对象越界和过长名称不保证可移植复现原端内存破坏，不能据此增补修正规则。
5. 模式的高三字节不是独立业务值；完整枚举、`0xFF0D40` 值 1 的意义及渲染后端映射仍未裁决。

本项最初只新增 `include/cg/platform/CommandOptions.hpp`、`src/platform/CommandOptions.cpp`、本文；
后续队列布局项将 `gTextFF4E30` 收敛为 `render::gLegacyPendingStorage.prefix` 的同址数组引用。
不宣称完整客户端可链接。2026-09-20 独立静态复核已在上述限定范围通过；`ParseIpOptions_507C80`
本体及未定义输入行为仍按本文遗留处理。
