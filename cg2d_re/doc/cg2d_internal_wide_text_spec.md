# 内部文本统一宽字符串（IWT01）

状态：用户已确认，实施中。2026-10-19，用户要求除网络和文件边界外，其余内部文本统一使用wchar/wstring。

## 目标

本线cg2d_re自有C++代码中的文本存储统一std::wstring，借用参数统一std::wstring_view，必要的宽字符API使用wchar_t*。内部格式化、比较、查找、测宽、裁剪及UI绘制直接处理宽文本；编码转换收敛到明确边界。覆盖当前旧SPEC中要求业务对象继续持有GBK文字的条款，但不改变网络协议、文件格式和非文本字段。

这不是将所有char逐字替换成wchar_t：像素、压缩数据、封包原字节、位标记、整数以及未知用途的字节域均不是文本。第三方源码和系统SDK声明不修改，不增加外部依赖。

## 边界

| 场景 | 处理 |
| --- | --- |
| 网络输入/输出 | 收到的原始封包保留字节表示；解析业务文本字段后解码，发送时编码并执行既有字节容量约束。协议控制符、转义、分隔和命令编号语义保持。 |
| 文件输入/输出 | 边界只指文件内容的编码与序列化布局，加载后转换内部文本，保存时转换回约定编码。path、文件名、目录属于内部文本，使用wstring或filesystem::path；Windows使用宽字符文件API，只有确实仅收窄字符的外部API在调用点临时转换。 |
| Lua、SDL、YAML等仅接受char的外部API | 只在调用适配点临时转换或保留API要求的标识字面量，不把这些窄字符串继续存入业务对象。Lua对外字符串编码沿原GBK合同，SDL等按各API自身编码合同。系统异常what()等窄字符串在接收边界处理。 |
| 二进制记录/缓冲区 | 逐字段核对用途：内部语义文本迁移为wstring/wchar_t；真实文件/协议记录仅在读写边界保留原字节布局，必要时拆出边界记录；像素、压缩数据、数值和未解析封包仍为字节。不能因旧类型为二进制记录或来源于网络而保留整个长期业务对象的窄文本。 |
| 诊断日志 | 自有业务信息使用宽格式化和宽输出入口；文件落盘编码由日志写入边界控制。 |

第三方API的最小适配是其签名要求，不是保留内部窄文本的例外；用户已确认此边界定义，并补充二进制记录/缓冲区也需视实际用途宽化。

## 固定布局与生命周期

1. 先核对每个字段的生产、消费、保存和复制路径，再迁移整条链；不同时保留长期GBK和宽文本两份业务状态。
2. 含wstring的内部对象使用正常C++构造、赋值、移动和析构，禁止继续对整个对象calloc、memset、memcpy、realloc或直接fread/fwrite。
3. 现有sizeof/offsetof断言逐项分类：真实文件/协议记录布局继续固定；仅还原旧运行期文本内存偏移的断言按新内部对象修订或移除，并记录依据。原数值字段、指针语义和协议容量不顺带调整。
4. 文本长度/索引按用途区分UTF-16码元、完整字符、像素宽度和边界编码字节数。既有服务器字段容量仍以编码后字节数判断，不能直接替换为wstring::size()。
5. 已有用户未提交改动继续保留，按自身差异暂存和提交。
