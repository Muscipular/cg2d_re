# 角色选择场景控制器证据

## 范围与依据

本文只记录当前 `ida-32980/cg2d.exe` 的
`sub_460FF0@[0x460FF0,0x461A77)`；STONAGE 未参与地址、行为、命名或验收
结论。

- 函数大小 `0xA87`，共 721 条指令、180 个基本块。
- `call` 指令 78 处，去重后的直接目标 41 个。
- IDA 原型为无参数、返回 32 位整数；唯一调用者是
  `World::Update@0x51C430` 的场景类型 3 分支（`0x51C4E6`）。
- 当前重建公开唯一入口为 `cg::character_select::ProcessScene_460FF0()`；
  `WorldUpdate` 不再保留旧 `Sub_460FF0` 声明。
- 已有唯一实现直接复用公开接口：`sub_450B70` 对应
  `render::SelectPalette`，`sub_45CE00/sub_45CE10` 对应
  `login::ResetLoginMessage/login::UpdateLoginMessage`；内部依赖头不重复声明。
- 未完成的真实目标只保留声明，没有空实现或固定成功返回。

## 四组跳转表陷阱

四组分发都不能直接按反编译器生成的普通有符号 `switch` 理解。

1. 主状态：`0x461005` 以无符号 `ja` 检查 `state > 21`，
   `0x461013` 经 `jpt_461013@0x461A78` 分发 22 项。负状态按位解释后也走
   默认，不会命中正数状态。状态 3 与范围外值只跳到主分发尾部。
2. 第二分类：`0x4614AF` 先以无符号门槛 20 检查，再以
   `byte_461AD8@0x461AD8` 映射到 `jpt_4614BC@0x461AD0`。状态
   0..9、19、20 走第一条返回路径；10..18 以及无符号范围外值进入两槽
   角色循环。特别是状态 21 并不走早退。
3. 动作：`0x461500` 以无符号门槛 6 检查，
   `jpt_461509@0x461AF0` 的 3/4、5/6 分别共用目标。返回 -1 的位模式大于
   6，必须走默认动作，不能误作数组下标。
4. Puk 版本：`0x461A20` 先把 `0x9A6E1C` 截为 `uint8`，再以无符号门槛
   7 检查 `jpt_461A2A@0x461B0C`。0/2、5/6 各共享发送分支，7 使用独立
   载荷，1/3/4 及范围外值不发送；不论是否发送，只要更新标志非零，尾部
   都把场景状态清为 0。

第二分类形成两条不同返回路径：

- 状态 0..9、19、20 直接返回
  `sub_45F090(0,0,3,245060,0,-1)` 的结果；
- 其余状态完成两槽循环、按钮和背景绘制后，返回更新标志 0、版本发送结果，
  或没有发送分支时的 Puk 数值。尾部背景绘制结果在这条路径上会被覆盖。

`0x4610C0..0x4610E5` 的 capability/Puk 拒绝条件严格为：

```text
capability < 2 && Puk >= 5
capability < 1 && Puk >= 3
capability < 3 && Puk >= 7
capability < 4 && Puk >= 8
```

Puk 1 在这些条件之前直接进入状态 10。未拒绝时，更新标志只在以下组合写 1：
capability 1 且 Puk 0/2；capability 至少 2 且 Puk 0/2；capability 至少 3
且 Puk 5/6；capability 4 且 Puk 7。capability 与图号比较均保持 signed32，
Puk 始终保持 `uint8`。

所有切场景调用之后都继续执行原函数规定的本帧剩余逻辑；没有把
`SetCurrentSceneType` 误改成即时函数返回。

## 两槽角色记录与动作

角色记录复用 `login::gCharacterRecords` 的 `2 * 0x94` 原始字节，并复用
`login::gSelectedCharacterIndex` 的 `int16`。循环从原 `0xFF03F8` 开始、每次
推进 `0x94`，以 `0xFF0520` 为末端，严格执行两次。

| 记录偏移 | 访问与证据 |
|---:|---|
| `+0x00` | 名字。原函数用 20 字节栈缓冲和 `strcpy`；重建保留“输入已在临时区内 NUL 终止”的原有效输入前提。 |
| `+0x18` | signed32 图号；`0x4615EA` 读取，动作 3/4 在 `0x461702..0x4618C2` 读写。 |
| `+0x20` | signed32 删除条件；`0x461664` 判零。 |
| `+0x24` | signed32 图号分类；原 `v9[3]`。 |
| `+0x50` | signed32 预览切换值；原 `v9[14]`。 |

四个定宽字段全部通过 `memcpy` 读写，不把原始记录强转为结构指针，也不做
x86 绝对地址指针算术。

动作映射如下：

- 0：写选择索引，依次调用五个准备目标，切场景 4，播放 `(53,320,240)`，
  清理 Yobi 和两枚预览指针。
- 1：写选择索引，把名字复制到 `0xDA391C`，把 `+0x18` 写入
  `0xF7C9FC`，切场景 5，播放 `(59,320,240)`，清 `0x9A6E10`，调用
  `sub_52B990`，再清理 Yobi 和两枚预览指针。
- 2：写选择索引；`+0x20` 非零时复制名字到 `0xDA3A9C` 并写状态 12，
  否则写状态 21；随后播放 `(55,320,240)`。
- 3/4：执行下述图号转换，最后无条件播放 `(51,320,240)`。
- 5/6：`+0x50` 仅在 0/1 间翻转，其他值保持；把结果写到 `0x9A6E14`，
  调用 `sub_460D00(slot)`，再播放 `(51,320,240)`。

动作 3/4 的区间与顺序严格如下。

Puk 7 以上先排除图号 33100、33101，然后按顺序更新分类：

```text
[30000, 98000)       -> 0
[202800, 204200)     -> 1
[200000, 202700)     -> 1
[240000, 242800]     -> 2
[205000, 205600]     -> 2
[270000, 270200]     -> 2
其他                 -> 保留原分类
```

令 `selector = class + 2 * action - 7`，按原顺序转换：

- class 0：selector 1 只调用 `sub_51BB80`；其他值先调用 `sub_51BB80`
  并立即写回，再以该结果调用 `sub_51BFF0` 并二次写回。
- class 1：selector 2 调用 `sub_51BFF0`；selector 0 在图号
  `[200000,202700)` 时调用 `sub_51BFF0`，区间外调用 `sub_51BAC0`；
  其他 selector 不转换。
- class 2：selector 3 且图号 `[240000,241400)` 时，先调用
  `sub_51BF00` 并立即写回，再调用 `sub_51BAC0` 二次写回；其他组合只调用
  `sub_51BF00`。
- 其他 class 不转换。

Puk 5/6 同样先排除 33100、33101；`[30000,98000)` 写分类 0，
`[202800,204200)` 写分类 1，其他保留。随后分类 0 调用 `sub_51BB80`，分类
1 调用 `sub_51BAC0`，其他不转换。Puk 小于 5 不转换。每个分支的上下界、
闭开关系和中间写回顺序均来自 `0x4616F3..0x4618C2`。

即使第一个槽的动作已经切换场景，原循环仍处理第二个槽，然后继续按钮与尾部；
重建保持这一点。

## 全局宽度与所有权

| 原地址 | 重建承载 |
|---|---|
| `0xFF0D64` | 复用 `world::gCurrentSceneState`，signed32。 |
| `[0xFF03E0,0xFF0508)` | 复用 `login::gCharacterRecords`，两项原始字节记录。 |

| `0x9A7F64` | 复用 `render::gPaletteCapability`，signed32。 |

| `0x9A6E44/48` | 两枚真实 `YobiAction*`；新端为两个 64 位指针，不把指针塞进 `int32`。 |
| `0x9A6EAC` | 本控制器私有 signed32 更新标志。 |
| `0x9A6EB0` | 本控制器私有真实 `YobiAction*` 确认窗口。 |
| `0xF7CA06` | 共享 `int16`。 |
| `0xF7C9FC` | 共享 `int32`。 |
| `0x9A6E10` | 共享 `uint16`。 |
| `0x9A6E14` | 共享 `int32`。 |

| `0xDA3A9C` | 共享 `char[132]`。 |

公开头文件仍只有场景处理函数。

## UI 与尾部

`0x55C318`、`0x55C338` 都严格为 7 个 `int32`、大小 `0x1C`：

```text
55C318 {534,438,64,16,245045,245047,245046}
55C338 {296,433,49,17,244542,244544,244543}
```

`sub_45F100` 与 `sub_45EFD0` 使用强类型 UI 指针；x64 不经过 `int32`
截断。`0x55C338` 更新按钮只在更新标志非零时绘制；状态 11、交互标志为 0
且点击时切场景 13，并把本帧后续 UI 样式改为 1。`0x55C318` 返回按钮在样式
仍为 0、状态仍为 11 时响应：清理 Yobi/预览、调用 `sub_5081A0`、切场景 2，
播放 `(54,320,240)`。两按钮处理后仍绘制图号 245060 的背景。

更新标志非零时，尾部按 Puk 发送：

```text
Puk 0/2 -> sub_512D30(socket, 2, "20031229_20")
Puk 5/6 -> sub_512D30(socket, 4, "20031229_30")
Puk 7   -> sub_512D30(socket, 5, 0x9A5C10)
其他    -> 不发送，返回 Puk 数值
```

## 仍未决

- `sub_461B30` 的完整角色槽 UI、`sub_460D00` 的预览对象构造，以及其余
  直接目标仍待各自函数还原；本项只完整承接当前控制器对它们的调用。
- `gKeyState.states` 只按索引 17 的 W8 bit 1 声明为窄外部依赖，尚未重建
  整体键盘状态结构。
- `0x9A5C10` 的真实容量和生产者未决，因此禁止将其声明成固定长度数组。
- 本项不运行客户端，不用运行现象替代静态证据。
