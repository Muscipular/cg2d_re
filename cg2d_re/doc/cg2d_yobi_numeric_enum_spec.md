# Yobi 数字枚举补充（YEN01）

日期：2026-10-25。延续战斗角色phase命名，本轮整理攻击模式、数值类型及关联特效握手状态。沿用用户已确认的命名原则：业务名称无法证实时，只描述已证行为。

## 范围与实施边界

在既有battle_base.hpp的cg::yobi::detail内新增三个以std::int32_t承载的普通枚举，替换相应字段、同源局部变量及已证参数位置的整数引用。字段、函数参数和返回类型仍保留原整数，不改变布局、数值、比较、分支、调用、取样、计数自增或RNG顺序；不新增输入过滤。

本项是已有整数域的命名补充，不涉及业务设计或重构。只读使用当前cg2d.exe会话及本机服务端；游戏data中的技能／图号不作为这三个内部域的枚举定义，不以相同数字推断业务。原phase、技能号、动画号、图号、工厂type、link参数及位掩码各自保持。

## 数值类型 BattleNumberType

| 数值 | 成员后缀 | 已证行为 |
| --- | --- | --- |
| -1 | SkipAfterEffect | 状态技能生产；动作204按非负门禁跳过数字显示及资源操作，不是数字图表索引 |
| 0 | Style0 | 动作159／160显示22459浮动图标；动作204可以显示第0行数字；计时数字同样使用第0行 |
| 3 | DecreaseFp | 159／160／204减FP；其他调用只使用同号数字样式，并不由数字工厂扣FP |
| 4 | IncreaseFp | 159／160／204加FP并保留原上限处理 |
| 5 | IncreaseHp | 159／160／204加HP并保留原上限处理 |
| 6 | DecreaseHp | 159／160／204减HP并保留原下限处理 |
| 8 | SetFp | 159／160直接赋FP，保留原上下限处理；204没有该资源赋值分支 |
| 9 | SetHp | 159／160直接赋HP，保留原上下限处理；204没有该资源赋值分支 |

原0x4107C0／0x410B00的+1034消费直接调用HP／FP加减或赋值函数；0x4124E0只消费3～6。0x410811及0x412622是读取+1034后比较6的指令，反编译switch对应比较分支链，这两处没有跳转表。原0x41F1A0按style访问0x54D4E8的四列数字图表；MCP直接读取确认第0、3、4、5、6、8、9行与源码一致，不用图像颜色猜类型。

-1只对已证的204路径表示跳过；159／160原门禁是类型非0，不能改成非负。0不能统一命名None、免疫或未命中。样式1／2／7虽有图表行，当前本组未见业务生产／消费，不补业务成员；未知整数和原有调用约束保持。

## 特效状态 BattleEffectPlaybackState

| 数值 | 成员后缀 | 已证行为 |
| --- | --- | --- |
| 0 | Idle | 初始／清理状态，多个创建入口以此作为门禁，不表示世界中没有其他特效 |
| 1 | Playing | NewBattleEffect_41CD00在link=1时保存父对象并向施放者+1024写1 |
| 2 | Completed | 关联效果结束时通知父对象；动作162等消费后清0，204按结果结算后仍使用原自增进入3 |
| 3 | HoldAfterResult | 204累计60次回调；原状态和计数更新顺序保持 |

原0x41A17F读取父+1024，0x41A189写2；反向发射控制器0x41A7A3／0x41A7AB同样只在原值非0时通知。0x410E30消费2并清0。0x4125A9判断完成、0x412747自增、0x41275E判断3、0x412774写4、0x41278E判断4及透明度，收尾在0x412791清0。本组属于施放者载荷的握手状态，不是角色或特效对象自身phase，也不是41CD00的link参数。
