<a id="network-buffer-lifecycle-decision"></a>
## 开发裁决与完整局部合同

1. 九缓冲仍同一NetworkRuntimeState、同一SDK malloc/free域。
   先写传入U32长度，再按原序清九指针；重复调用不释放旧值。
   首malloc用入参；后续按各自原点取共享U32长度，四普通字节块、原生char*指针表、
   四三倍字节块依次发布。指针表只将地址槽尺度拓宽，数值字段/3倍字节积仍U32。
2. 按16DF9/16E0A在第二/第三malloc返回后先取下一长度，再发布本次结果；
   按16E7E/16E84在末malloc返回后先取首清零长度/指针，再发布末结果。
   每个后续清零阶段独立取当时长度、对应指针；三倍数量重新在U32计算。
   count=0仅跳过原REP本就不执行的内存写，不跳掉共享读取。
3. 移除九个新增的非空检查/terminate故障模拟，不新增保护、拒绝、回滚或异常捕获。
   九清零后才按原顺序检查九指针，首指针用16F7E的同次快照；
   失败按首、第四、第三、第二、指针表、四三倍块顺序释放，返回-1，不清槽。
   本步不模拟/宣称非法地址写、溢出或原x86内存异常等价，RPLAN.24保持。
4. 516B60保默认/传入回调发布、弃九缓冲返回、原生18槽表零初态、
   每元素分配后重取表发布/检查。失败仅free当前首项并返回-1，
   不释放外表/其他已分配项，不改原泄漏或悬空槽。
5. 508140保WSAStartup(1.1)失败返0；成功弃516B60返回后写active=1、
   连接状态0并返1，不将其返回解释为工作区分配均成功，不新增启动回滚。
6. 507DF0保首标志/计时→活动与连接门禁→8帧取模→两个fd集合/零timeout；
   recv>0写reset0再追加，recv0不增加断线处理；-1先日志/过滤，再error>0才关闭并写状态1/错误。
   明文帧提取→实际分派→清0x8000派发区/四普通块/指针表/四三倍块/再次指针表；
   全部共享长度仍各次重读，不去重后一个表清零。
   send>0重采tick；send=-1错误路径不消费发送队列，其他返回（含0）交原消费叶。
   尾部先tick、再当时deadline/active；U32加30000比较及nr请求/低U8返回保持。
7. 5081A0在inactive时零副作用返回；否则值0→active0→polling0→连接0，
   再close当时socket→WSACleanup→协议状态重置→九块释放→18元素→外表释放。
   元素每轮重取外表，释放后不清指针、不重置长度、socket或计时字段；
   不新增整owner析构、退出登记或“可重复清理”承诺。
8. 两错误叶保WSA错误S32快照→未清256B局部真实格式→日志→仅10035返0，
   其他透传；“SNED”原字节保持，不提前过滤或读取close结果代旧错误。
   真实Malloc/Free/SDK结构差异沿已有x64与宿主合同，仍单列adapted，外部ABI/运行不豁免。
