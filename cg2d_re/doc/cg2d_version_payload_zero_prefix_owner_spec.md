## 原端已证读取合同

1. 9A5C10 位于 .data 的未装载区，is_loaded=false、文件偏移=-1。IDA一字节unknown item只证明标注，不证明原数组分配容量；get_bytes在未装载区呈FF也不是原加载初值。原PE静态未装载存储由加载器零初始化。
2. 定向遍历389569个代码指令的立即数／内存／位移操作数，在9A5B00..9A5D6C共30个命中：版本起点仅461A56与462384两次PUSH，分别属于460FF0创建和462330升级，两次均随后传版本整数5、原socket，调用512D30。相邻9A5B08消息起点的五个引用另属45EBB0既有264B owner，不并入版本正文。
3. 在所有非代码段扫描未对齐W32地址位型，并逐候选四字节核is_loaded，没有指向9A5B08..9A5D6C的静态地址别名。版本指针只由上述两个已证调用外传；不是仅凭起点无写xref宣称恒零。
4. 512D30完整33条107B依次构造Xoee、格式化版本整数、将第三参数传517160、追加结果并发送。517160完整14条38B将该指针传5171F0，之后只给其返回的独立网络工作区追加ASCII空格；不写输入或向其他模块外传输入。
5. 5171F0完整66条222B：先清网络输出首字节，5171FE只读输入首BYTE，零时517201直达5172BE，再给独立输出首字节写零并返回其指针。此路径不递增输入、不读+1、不写原输入。因此原加载零值的正常可观察正文只有一个NUL；没有需要补造的运行版本正文生产者。
6. 原保留区总容量不能从9A5D6C下一个命名对象反推为348，也不能借9A4EAC的128B。原未使用尾部容量不作虚假事实；本裁决只承接原正常可观察的1B读取合同。全函数原字节、两caller和检索元信息见[证据](cg2d_version_payload_zero_prefix_owner_evidence.json)。

## 委托裁决与实现

- 新端在现有 CharacterVersionUpgrade.cpp 的 character_select::detail 定义唯一 const char gVersionPayload9A5C10[1]，零初始化、静态存活期。头文件同类型定长声明和sizeof断言，两个既有consumer借同一对象；不增新文件或provider函数。
- 1B是原已证正常读取足迹对应的新端容量，是工程存储裁决，不冒称原预留容量。原路径没有写入合同，采用const固定该事实；加载零值是有原证据的数据生产，不是链接占位、默认版本、容错补空或删除业务。

- U03源码数据合同据此收口为唯一对象／正常内容／足迹容量／全程寿命／两consumer。旧“容量未决，禁止固定数组”的条款保留其历史时点，由本局部裁决替代当前实现约束；不把未知尾部伪装已取证，不新增原地址Hook或二进制布局替换要求。
- 该裁决不外推其他BSS、负分类20字节、外部模块或未证读写；不讨论异常写坏／越界等RPLAN.24故障模型，亦不新增拒绝、保护或补零分支。
