2. 文档任务使用 `RPLAN.N`；执行阶段使用 `R0` 至 `R8`，细项使用 `R阶段.任务.小步`。
3. 新编号与旧 `M` 系列及 `M6R` 子系列隔离，不沿用其完成状态或验收分母。
4. [旧计划](../../plans/cg_engine_dev_plan.md) 与 [历史进度](../../plans/progess.md) 仅供参考，不构成本线已完成证据。
5. 历史成果不能自动计入本线完成度；cg3a 地图、graphic、anime 按 2026-09-27 裁决作为可信参考，封包不确定时按 2026-09-29 授权参考 cg3a 网络处理并标明来源和差异，其余材料核对适用基线。已确认内容无重大冲突不重复复检，有具体差异时仅核受影响项。
6. 目标是在用户确认范围内逐项还原原二进制可证实的函数、数据和内部执行逻辑；新工程采用用户确认的 x64，渲染采用 SDL3 `SDL_Renderer`，必要架构适配与渲染替换差异分别记录，不扩展为业务逻辑修改。仅复刻 32 位色渲染；8/16/24 位色渲染路径、屏幕键盘、登录 `newest` HTTP/raw-socket 五函数检查链及用户指定的网络加密链为范围排除。原 8 位索引资源读取、调色板读取及转 32 位色解码仍须保留；`newest:` 命令参数解析、原端阶段证据与 `LoginScene` 的 -3/-4 分支同样保留。非加密组包和网络分发不随加密链排除。
7. 已取得的数据库身份、输入哈希及工具统计见[基线记录](../doc/cg2d_reconstruction_baseline.md)；未经取证的版本说明、结构布局、模块存在情况和资源绑定仍保持未确认，不以工具统计代替完成度。
8. 阶段名称只是待盘点范围，不表示原端采用同名模块、类、目录或现代架构。
9. 未知项保持未知；磁盘与 IDA 的差异按第 3 节已定优先级记录，其余未决事实冲突或实施方案不确定时停止受影响任务，请用户裁决。
10. 新项目位于 `cg2d_re/`：`src/`、`include/` 按真实边界承载实现与头文件，`doc/` 保存实际证据，`plan/` 保存本计划及唯一执行进度；不预建未经盘点的模块。

## 2. 内部还原标准

### 2.1 函数身份与调用契约

- 以原二进制可证实的函数边界和代码片段归属建立稳定映射，记录入口、出口及共享尾部。
- 逐项核对签名、调用约定、参数来源与宽度、返回值、寄存器及栈使用、副作用和调用链。
- 原端为 x86 不等于所有函数采用同一调用约定；必须结合调用者、被调用者和指令确认。
- 新工程已确定 x64；原调用约定仍作为证据，新端参数、返回值和指针承载按目标 ABI 建立对应，不声称直接兼容原 x86 外部 Hook ABI。
- 原源码名称、被内联前的源函数划分通常不能仅凭二进制证明，不能用反编译猜测补全。
- 分析别名与原名称严格区分；边界或签名未确认的条目不得标为完整还原。
- 不以功能相近的新函数拆分、现代状态机或统一调度器替代原有函数划分与调用关系。
- 渲染替换仍须保留原渲染上层函数身份、接口语义、副作用及逻辑时序的可追溯对应。

### 2.2 结构、数组与全局数据

- 逐字段记录偏移、宽度、符号性、对齐、联合覆盖、嵌套关系和实际读写用途。
- 原指针按 32 位核对；不能由 x86 自动推定结构对齐、打包方式或目标工程布局。
- 新端 x64 指针与原 32 位指针字段的映射逐项核对；不因指针变宽而扩大原资源、协议或非指针数值字段，也不擅自改变原业务关系。
- 数组须记录容量、步长、有效元素判定、边界访问和关联计数，不能仅保留有效业务字段。
- 全局数据须记录原始字节、零初始化范围、运行初值、初始化顺序及重置、释放时点。
- 跟踪所有权、别名、共享读写和生命周期，不以现代容器或自动管理对象替换后直接宣称一致。
- 字段名称可用中性别名；未经证实的业务含义、缺失字段和未知填充必须单列。

### 2.3 执行逻辑与可观察行为

- 逐项还原分支条件、循环边界、退出路径、状态取值与转换前后读写，不只覆盖正常路径。
- 核对正常整数宽度、截断、符号扩展、取模、掩码、位运算、移位、比较及运算顺序，保留正常算法与输出；越界、数学溢出等异常按 RPLAN.24 不专项处理，不要求专项回绕或故障等价适配。
- 记录调用次序、字段更新时点、回调注册与触发、重入、时钟读取和随机数消费次序。
- 网络输入、资源读取及失败返回造成的副作用必须追踪；不能由现有测试预期反推旧端行为。
- 对 2026-09-22 已批准替换的 DX7 `Blt`、`BltFast` 等底层操作，不要求复刻逐项 `HRESULT`、显存 caps、`DDBLTFAST_WAIT`、surface lost/busy/restore、原失败码，也不要求复刻被替换 DX7 原生 API 边界的 COM 接口 ABI、对象/vtable 布局及其调用约定；这只豁免该 DX7 原生 API 边界的底层机制与 ABI，不豁免上层函数或其他外部 ABI，不能改变上层触发时点、`RAND` 消费、状态读写、`W32`/`S16` 规则、坐标与裁剪、像素内容、共享 Back/Temp 生命周期及提交顺序。
- 功能可用、截图相似或流程可操作不能替代内部一致性；获批替换差异必须明示。
- x64 目标不等同于原 x86 EXE 字节一致或二进制直接替换；固定装载地址、外部 Hook ABI、部署及编译器相关兼容要求仍须单独确认。
- 不擅自扩大或缩小上述要求；若与渲染替换发生冲突，列明冲突并请求确认适用范围。

3. 确认有无磁盘补丁、加载器、注入组件、Hook 或运行期修改；存在差异时分别登记。
4. 原文件和原数据库保持不变；未经用户授权，不修补二进制，不改 IDA 名称、类型或注释。
5. 按 `ida-analysis` 以当前选定 IDA 数据库中的字节和反汇编作为内部语义证据；反编译只用于辅助阅读，自动名称、类型或注释不能单独作为事实。
6. 关键结论交叉核对调用者、被调用者、数据读写引用，以及函数表、跳转表的实际表项。
7. 跳转表必须确认输入来源、表项宽度、实际目标和目标指令，不能只信反编译分支标签。
8. 运行观测用于验证路径和时序，不能替代函数边界、字段偏移或未触发分支的静态证明。
9. cg3a 地图、graphic、anime 的现有代码和资料为可信参考；封包不能确认时，cg3a 网络处理可补充协议语义、字段及流程分析，须记录具体源码、适用范围和冲突。`server`、`xlsx`、其他未获上述授权的旧计划和源码仍只提供线索。参考不覆盖已证原客户端事实，不把旧工程完成度转记为本线验收。
10. 磁盘与 IDA 的差异保留各自来源、地址及上下文，按用户裁决以当前选定 IDA 为准，不猜测差异原因；其余尚未裁决的证据矛盾仍须停止受影响项并提交用户裁决。
11. 禁止先改二进制或 IDA 标注使其符合预期，也不能静默套用历史例外消除冲突。
12. IDA 分析基线发生变化时建立新标识，标出受影响条目并重新验证，不将不同版本证据拼成结论。
13. 当前源码的符号定位、文本检索与关系核对全面停用代码图谱：仅使用 `rg --encoding utf-8`、显式编码文件读取及必要的 Git 只读命令；不得建立、更新、查询或引用任何图谱及其既有结果。该工具裁决不改变本节的 IDA 取证要求。

### 4.2 实施前待落实

以下项区分原端事实与工程方案：事实不明继续取证，方案按 §4.1 最新委托记录裁决并推进；历史“须确认”不再要求逐项等待用户回复，也不表示全部方案已自动实施。

1. 新工程 x64 已确认；需逐项落实原 32 位指针与新端地址或资源引用的映射，以及原、新结构布局校验，不再把目标位数列为待裁决。RPLAN.24 的异常不专项处理不改变正常指针、布局及共享 owner 的对应要求。
2. 各函数调用约定、结构对齐及打包、外部接口布局须先取证，再裁决工程配置与边界方案；唯一相关例外是已由 SDL/CPU 等价替换的 DX7 原生 API 边界，其 COM 接口 ABI、对象/vtable 布局及调用约定按 2026-09-22 裁决无需复刻。该例外不适用于上层函数或其他外部 ABI。
3. SDL3 `SDL_Renderer` 接口与 Windows 驱动策略已确认：传 `nullptr` 自动选择，不强制 `direct3d11`，调用方不自行重试或回退；SDL 自身选择的实际驱动须在运行验证时记录。仍须逐项核对现行 `AGENTS.md` 的类型隔离与后端边界适配。
4. 音频原生后端已获单独 SDL3 替换授权；各原入口的失败映射、资源生命周期及音量/声像/变频数值仍须取证落实。其他 DX7 范围之外的底层 API 如何对应仍待逐项核对；未获授权不得顺带更换输入。

## 5. 原 DX7 渲染替换边界

- 原 DX7 渲染相关函数和资源先按证据盘点，不预设具体 API、图形效果或资源类别一定存在。
- 为范围内每个原上层函数建立到新实现的映射，保留输入输出、副作用、资源关系和逻辑执行时点。
- 按已定驱动策略实施时，原生资源类型、API 调用及生命周期确需改变的，逐项记录必要性、替换位置和验证办法。
- 不声称原 DX7 与替换实现的原生对象布局相同，或底层 API 调用能够逐指令一致。
- 除用户明确排除的低色深渲染路径外，API 替换不能扩展为更改游戏逻辑、原渲染排序、坐标、提交次序、调色、透明或画面语义。
- 上述语义的具体形式仍须取证；不能因为计划列出检查维度，就认定原端具有某项效果。
- 逻辑提交次序与新 API 实际调用序列分别记录，必要差异须说明如何保持原可观察语义。
- 共享 Back/Temp 等上层可观察资源的创建、更新、使用、共享及销毁时点仍须覆盖；对已批准等价替换的 blit 操作，不要求仿真显存 caps、逐 `HRESULT`、`DDBLTFAST_WAIT`、surface lost/busy/restore、原失败码状态机，也不要求复刻被替换 DX7 原生 API 边界的 COM 接口 ABI、对象/vtable 布局或调用约定；该豁免不延伸至上层函数或其他外部 ABI，也不得据新后端结果新增原上层不存在的状态分支。
- `Blt`、`BltFast` 等上述底层差异已获批准，不再作为待裁决项；其他无法直接对应的行为仍进入差异台账请用户裁决，同意此项替换不代表任意渲染差异都已获批。
- 替换接口已确认为 SDL3 `SDL_Renderer`，由 SDL 自动选择驱动；不擅自改用原生 DX11 直连或 `SDL_GPU`。
- 上述 blit 可采用等价 SDL 或 CPU 像素操作，但必须保留原上层触发时点、`RAND` 消费、状态读写、`W32`/`S16` 规则、坐标与裁剪、像素内容、共享 Back/Temp 生命周期及逻辑提交顺序；验证这些约束，不以底层 API 调用序列一致为目标。
- `sub_521870` 波纹链使用 CPU 像素缓冲并保留快照与逐条回拷语义；2026-09-25 至 09-27 的后续委托已选择共享 CPU Back/Temp、CPU 节点面及 SDL 最终呈现，见[呈现器](../doc/cg2d_sdl_presenter.md)和[DX x64 SPEC §10–12](../doc/cg2d_graphic_dx_cache_x64_spec.md)。不再把 CPU owner 仅限波纹作为当前限制；其他未裁决绘制模式仍逐项处理。
- 8/16/24 位色渲染路径的原函数、分支仍须盘点并标记“用户范围排除”，不编码、不列为未完债务。资源格式位深不等于渲染输出色深：须保留 8 位索引图的索引、调色板读取及转 32 位色所需调色、解码，不将排除扩大到其他资源处理、字节码或 8/16/24 位整数、协议及结构字段。
- 同一函数包含多种色深分支时，只排除已确认的低色深渲染分支，保留 32 位色及资源解码所需共享逻辑，不能将整个函数标为排除。
