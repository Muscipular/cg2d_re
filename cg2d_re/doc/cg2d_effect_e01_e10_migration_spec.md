# E01–E10 技能特效业务迁移

## EFM01：范围与裁决（2026-10-17）

用户要求迁移 E01–E10，完成后用 `build.bat` 修复并编译。本轮按子项目第8条既有工程委托，直接承接 `twcg_hook/src/hooks/EffectHooks` 的业务合同；不迁入固定地址、Detours、内联汇编或原 x86 布局。使用本线现有 YAML、静态 LuaJIT 和 Yobi 对象，不新增依赖、协议、技能配置或玩法。

配置入口仍为运行目录的 `effectHook.yml`，脚本入口仍为 `lua/battleSkillEffect.lua`。原参考 YAML 的零 ID 示例及只有注释的 Lua 示例不作为真实技能配置，不覆盖运行目录的用户资源。配置／脚本加载失败通过 `m_log` 记录；未配置的原生特效、未注册的 SKL 继续原流程。

## E10 接管与寿命

技能演绎使用第三个独立 Lua 状态，开放 base、bit、table、string、math，注册 `Skill.register` 和 PacketReader，不与 UI／自动战斗状态混用。Lua C入口沿本线异常边界转换，脚本字节保持既有合同。

迁移参考中的199项有效队列、200项物理数组、20个普通角色槽、247个排序对象及每批80操作等约束，不外推到原生技能。SKL读取沿原十六进制字段，保留注册长度、重复注册拒绝、读取器代次和报文恢复策略；不修改网络收发。

原动作推进、逐帧更新、标死和释放改为源码直连；原生正文仍可供状态机回调调用，避免递归进入同一接管函数。SKL返回“处理中”走公共状态回存，返回“已完成”跳过回存，对应参考437A29／437ABA两个出口。普通未注册技能保持原分派。

子节点和视觉对象由原Yobi链拥有，运行表仅观察；逻辑完成、标死、物理释放分别处理，父节点按waitMode等待子节点或整棵子树。场景释放时终止当前演绎，回收待提交对象及Lua引用；客户端关闭时先清演绎状态，再关闭该Lua状态。HP及状态操作仅更新客户端展示，不实现服务端结算。
