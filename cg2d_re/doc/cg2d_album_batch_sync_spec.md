# 图鉴按回复分批同步 SPEC

日期：2026-10-20。编号：ABS01。状态：用户已确认每批最多20条、收齐本批回复后再请求下一批；源码已实施，随SendResult统一改动完成Debug编译与链接，联网验证待进行。

## 1. 目标与现有入口

用户要求限制图鉴请求数量，并明确选择“收到本批回复后，再请求下一批20条”。自动图鉴同步同一时刻只等待一批，不把全部分包连续入队。

- `Ilz` 经 `HandleAlbumEntryMaskReply_50E5B0` 提供版本与位掩码。
- `SynchronizeAlbumEntryMask_518A40` 根据掩码和本地记录生成图鉴编号列表。
- `CgConnection::RequestAlbumEntries` 组装 `kza 数量 编号...`，整数沿用Base62。
- `dM` 经 `HandleAlbumEntryReply_50E5D0` 返回单条图鉴记录，第一个数值为图鉴编号；现有协议没有批次号。

## 2. 分批合同

1. 图鉴业务保存完整请求列表、下一条位置以及本批待收编号；每批最多20条，最后一批可以不足20条。
2. 先发首批。每条 `dM` 完成现有记录更新后，仅对本批中尚未收到的编号确认一次；重复编号及本批之外的编号不推进批次。
3. 本批待收编号清空后，才调用同一连接的 `RequestAlbumEntries` 发送下一批；不改变通用组包函数或传输层，不增加协议字段。
4. 最后一批收齐后发布并保存同步版本。中断或发送失败不得提前标记新版本已同步；已有记录仍沿原入口逐条更新。
5. 没有待更新条目时保留一次 `kza 0`，入队成功后完成本轮版本更新。
6. 示例354条请求按17批20条和最后1批14条发送；第21条只会在首批20个不同编号的回复全部到达后请求。

## 3. 会话、重复掩码与失败

- 临时状态位于现有图鉴业务文件，绑定连接对象、连接ID和角色槽；不写入图鉴存档结构。
- 图鉴初始化、角色进入时加载图鉴、清空角色图鉴时清理等待状态。每次处理掩码、确认回复或继续发送前核对会话与角色；身份不符时废弃旧任务，不续发旧请求。
- 同一任务等待期间收到新的 `Ilz`，持有最新版本和掩码的字节副本；收齐当前批后按最新掩码重新计算列表，替代旧任务尚未发送的部分，避免两批并行。
- 发送返回失败时结束本轮，不发布新版本；后续服务端掩码可重新触发同步。不新增自动重试。
- 未收齐本批时持续等待，不增加超时、跳过缺失编号或定时重发。现有 `dM` 没有批次号，因此只能按当前会话、角色和图鉴编号关联，无法独立判定同编号迟到回复的服务端版本。
- 保留既有非本批 `dM` 的记录更新行为，仅不把它计入当前批次完成数。
