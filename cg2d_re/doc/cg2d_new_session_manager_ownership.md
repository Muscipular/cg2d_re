# NSM01 会话状态所有权清单

2026-11-03 当前源码静态盘点。此清单只记录已定位的共享存储和直接消费者，不代替完整全局/静态局部闭包或运行验收；新增项须沿真实生产、借用、回调和释放链继续补全。实施合同见 [NSM01](cg2d_new_session_manager_spec.md)。

| 边界 | 当前入口/存储 | 目标 owner 与迁移门槛 |
| --- | --- | --- |
| 网络 | `CgConnection::Impl` 已持协议缓冲、`CgTransport`、连接身份、回调注册、保活、登录请求/消息、主循环断线阶段和 BtWt/SpDt 三项服务端参数；`GetGameConnection()` 仍返回 `ClientHost::FirstSession().Connection()`，登录/世界/脚本/窗口大量调用它 | 每个 `ClientSession` 持独立连接；所有业务发送与回复回调显式沿所属会话传递，不能只让 `GetGameConnection()` 改为返回一个隐藏的“当前连接”。世界战斗对象与聊天计时等其他回调目标尚未隔离 |
| 登录与选角 | `LoginRequestState` 已持请求码、时钟、错误、凭据、选服索引、两条角色记录、所选槽位、连接提示阶段、分类/分页/高亮及登录错误正文；`LoginMessageState` 已持消息与动作借用，`LoginSceneState` 已持服务器控件、输入上下文/两类焦点、能力3/4动画及模态状态。登录/选角模态动作全部由对应连接所属会话创建，其他场景状态仍散落在登录模块 | 图鉴回复按回调连接取槽位；其余世界/存档/UI及登录入口仍从单例连接取状态，不能用于多会话调度。`input::gCurrentInputData`、IME、其他焦点/动作寿命仍属进程级，切换前必须沿全部借用链隔离；服务器表仅由启动 `ParseIpOptions_507C80` 生产，宿主只在创建首会话前解析一次即可共享，运行中重解析不在此证明范围。可执行文件摘要仍待核所有写者 |
| 角色选择 | `CharacterSelectSceneState` 随连接持有角色列表/删除进度、认证失败弹窗、版本升级动作借用、Puk版本W8及登录成功正文；版本与正文的网络生产者使用回调所属连接 | 创建资料/预览和保存状态仍共享，Yobi动作池仍进程级；场景函数和多个窗口仍从唯一 `GetGameConnection()` 读取，不能据局部实例字段并行调度 |
| 场景/世界 | `world::gCurrentSceneType` 借 `platform::gCurrentSceneTypeStorage_FF0D40`；`World::Update` 读取待切换状态、更新场景，内部又执行输入、UI及绘制。聊天 Enter 键至发送的连接/四槽节流门禁、64 条输入历史和浏览游标已按会话贯通，历史仍共用原 `chathis.dat` 磁盘路径；入场等待回复的两位标记及地图调色板待消费值由场景与网络回复沿同一会话读写。四象限转场的阶段与四组 X/Y 坐标随场景会话保存。显示聊天记录、`PlayerState`、地图缓冲/对象、战斗、邮件、相册和断线状态仍有跨模块消费者；战斗背景图号的网络生产、Yobi 淡变回调写入及渲染器重建读取横跨三处 owner | 按完整别名组归入会话；场景分发必须对该会话的网络回复、角色记录和资源借用生效。通用转场重置门禁、其他转场数据、调色板实际设备及地图名仍共享，现阶段不能让后台会话直接执行画面副作用。背景图号要在 Yobi 动作能定位会话且重建能定位当前呈现会话后整组迁移，不得仅迁网络写入或保存四个场景整数便循环调用旧 `World::Update()` |
| 地图路径/交互 | `SceneState.cpp` 的 100 项方向/X/Y 队列、两项待发方向、计数、重建标志和转场门禁共同驱动普通移动；`Copilot.cpp` 以静态引用别名持有路径计数、重建标志和三个门禁。地图矩形请求标记、转场回复等待/矩形等待、转场中地图名收到标记、两类转场共用序号及各自待回复序号、观察准备标记已沿所属会话传递；地图缓存与其余请求/回复标志仍和 CRC、地图块、名称、场景阶段交错 | 队列与 Copilot 别名、网络回复及场景消费者须一起迁移，不能只移动原定义后保留静态引用；当前已迁移的地图发送连接、文本缓冲和部分节流值不表示路径/地图状态闭合 |
| 地图观察链 | 独立观察组链表头、五槽对象号/图号快照及主图号、方向、持续时间归入 `ClientSession::Yobi()`；网络观察回复由现有目标/来源动作入链，场景保存、转场、背景、清理和回调沿相同会话读写 | 观察组仍通过共享的玩家/世界对象表查询成员；背景效果及音频设备共享，不能独立运行后台观察场景 |
| 地图绘制去重 | 原 100 项图号/X/Y 去重表与计数归入 `ClientSession::WorldScene()`；地图角色回调按动作 owner 查询/写入，普通场景只清其计数 | 绘制队列及其他地图缓存仍共享；此项不代表后台绘制副作用可安全运行 |
| 地图方向特效 | 普通/战斗场景的地图特效更新传递其会话身份，方向特效的 Yobi 动作按该会话入链 | 地图特效池、方向状态、随机数与图形队列仍共享，背景会话不可独立推进此链 |
| 战斗显示 | 悬浮图标继承父战斗动作的会话；战斗动作100的连续序列游标由回调动作所属的 `YobiSessionState` 保存。数字、倒计时、顺序提示和战斗文本从回调/场景/角色源动作入链，战斗文本面板也沿源会话创建 | 登录/选角模态面板已显式归属，但其他 UI 窗口开启动作、战斗对象表和绘制队列仍共享 |
| 随机数 | 客户端初始化和部分网络回复已使用所属连接的随机引擎；战斗种子、宠物退场、战斗动作/攻击/命中/角色回调及战斗效果模块的范围取样沿动作身份，地图漂浮及粒子正常帧/转场补跑、捕获变体与随机画块转场取样沿场景会话。窗口键盘快捷键的随机表情与恢复位置取样沿窗口帧会话。`SceneState.cpp` 的无参 `Rand16()` 和范围取样已清空，`RandomRange_46FAF0` 有显式连接入口 | `LegacyCryptInt` 默认构造、临时赋值与第 21 次读取换掩码仍通过无参 `Rand16()` 取首会话引擎；世界/玩家/Yobi 对象的构造 RNG 顺序尚未解决，窗口动画创建及其他 UI 范围取样仍有无参调用；转场数组与 CPU 临时画面也仍共享。不能启动第二会话 |
| 地图/玩家可变资源 | `gPlayerX/Y` 等 `LegacyCryptInt`、地图 tile/obj/hit/walkability 平面及世界对象由世界、Yobi、Lua 和窗口借用；动作指针又回指窗口/地图角色，地图缓存路径包含角色与地图字段 | 连同初始化、回调、渲染、脚本查询和保存路径核对真实 owner、借用寿命及别名；进程可共享的只读资源须与角色可变缓存分开证明，不能靠切换时复制全局 |
| UI/输入 | `WindowRuntime.cpp` 的 `gWindows`、`gWindowStates`、焦点/拖拽指针和各窗口文件的静态状态共享；窗口帧入口已显式接收会话，场景通知上次值及编码失败去重槽按会话保存，转生计时请求使用该连接。`WindowRuntimeState.hpp` 定义多份仍共享的输入上下文，`WindowComponentHost.hpp` 又借鼠标、当前窗口和输入指针 | 窗口实例、文本草稿、焦点、拖拽及绑定的 `YobiAction*` 按会话保持地址和寿命；原型/回调表是否可共享须逐项核对其可变字段。主窗口的键鼠/IME只路由当前会话，切换不模拟业务释放事件 |
| Lua/自动行为 | 两套 UI/战斗 `lua_State*`、关闭门禁、封包收发订阅和 UI/战斗桥接表已由 `ClientSession` 持有；脚本发包/编码及自动战斗 Lua 发包按 VM 所属连接执行，窗口帧场景/按键通知按会话筛选。通用窗口事件及按键订阅仍共用容器，但关闭时只移除所属 VM 的引用；其他窗口事件、自动战斗/Copilot 控制状态及扩展窗口仍共享，关闭一个 Lua 会话仍调用共享窗口/特效/音频清理 | 每会话独立 VM、回调表和自动行为状态；C++ 对象、Lua 句柄及异步回调不能跨会话引用。后台继续执行，不能只更新当前 VM |
| 绘制/声音 | `MainLoop` 清共享图形队列并在一次 `World::Update()` 后提交；世界/窗口/Yobi 的更新与绘制交织。帧背景模式及强制呈现门禁已按会话归属，清屏震动的随机数也使用所属连接。战斗背景图号由入战连接、Yobi 淡变动作所属会话、战斗快照及当前呈现会话的渲染器重建贯通。Yobi 链表哨兵和生命周期、四阶段门禁与轮转相位由会话持有；地图动画注册表 399×399 标志/非拥有动作指针从绘制、回复、地图资源初始化到清链沿同一会话；震动升降、X/Y、当前/最大幅度由动作回调与本帧主循环按会话读写。环境特效查重/创建、计时与生成计数从地图回复、主循环到动作回调沿所属会话；战斗排序计数与原 257 槽非拥有临时数组也归所属会话。战斗追加效果链由场景动作生产、战斗动作查询、会话退出清理；战斗场景根、事件与角色根动作、骑乘/命中/装备附件、全部 `battle_effect.cpp` 特效分配及地图角色骑乘/观察子动作沿源会话入链；地图转场根及四个一次性动画从网络回复到回调子动作也沿所属会话。地图角色根动作从普通场景、玩家/对象网络回复、转场恢复及角色附件沿对应会话创建，装备、跟随宠物与世界角色骑乘附件继承父角色动作身份。世界帧更新、角色绘制、战斗排序、登录/选角清链及克隆按所属会话访问。其他 Yobi 模块的旧无参创建入口仍固定首会话，世界对象/玩家表、战斗对象表、地图 tile/obj 平面、环境地图偏移及波纹相位仍共享。SDL 呈现设备、CPU 面及当前音频播放仍为单套 | 将游戏副作用与实际呈现分开；后台保留必要生产/消费次序，但不能污染当前画面或提交像素。音量/音效设置进程共享，播放仅当前会话，最小化时当前音频继续 |
| 存档/退出 | `LoginSavedState.cpp` 的 `gSavedState`、窗口设置及角色存档选择仍基于单套当前角色；`ClientShutdown.cpp` 停一个连接、关闭单套 UI/Lua/资源 | 保存路径、记录映射及窗口布局按角色/会话核对；关闭一个会话保存后直接断线并释放该会话 owner，不触碰其他连接。最后一个会话或确认全部关闭才释放进程级设备 |
| 宿主窗口 | `ClientHost` 已持稳定有序的会话集合与当前项，首会话由构造自动创建；新增对象不自动选中，移除当前项按相邻规则更新标识。宿主枚举菜单快照按角色名、账号名、稳定 ID 的“登录中”回退；网络 Pump 终止后保留断线标记，重新连接成功才清除，返回登录场景时清旧角色名。业务初始化/清理、并行调度和菜单尚未接线，`wWinMain` 仍只传首会话给主循环。`WindowLifecycle.cpp` 仍使用系统标题栏；`WindowProcedure.cpp` 持进程级键鼠与 IME | 新标题栏占额外高度，游戏画布尺寸/坐标不变；保留系统关闭确认、最小化与拖动。菜单命中先于游戏输入，仅当前会话绘制与发声；新建/切换/关闭在安全的帧边界处理 |

## 下一阶段入口

1. 继续闭合登录/选角剩余动作、创建资料、保存及网络回调的显式会话 owner；网络回复中的 `world`、`ui`、`yobi` 写入不能仍指向共享存储。当前连接实例字段完成不表示登录场景可多开。
2. 随世界分发迁移玩家/地图/战斗、UI 实例/原型可变数据及脚本桥接，逐模块检查静态局部、非拥有指针、借用返回值、文件保存和间接回调。
3. owner 闭合后接宿主调度、后台无实际呈现/音频、窗口自绘与菜单。每阶段保留原单会话分支及失败语义；按用户最新要求仅在整体实现后统一编译，当前新增改动未通过编译/链接，客户端多账号运行、画面与音频验收仍未验证。运行工作目录及可执行文件不部署的约束见 NSM01。
