# 进程内多会话管理 SPEC（NSM01）

2026-11-03 用户确认。此功能是新端扩展，不冒称原 cg2d 行为；原业务协议、角色逻辑、失败分支与适用验收标准不因多会话而改变。实施与进度仅落在本子项目的 `src`、`include`、`doc`、`plan`。

## 目标与边界

1. 单进程、单游戏窗口内并存多个独立账号会话；客户端不校验账号重复，服务端决定登录结果。同一会话返回登录界面后允许更换账号。
2. 所有会话持续运行登录、网络、世界、战斗、脚本和 UI/窗口逻辑；后台会话不接收键鼠、不提交画面、不播放音频。切换不额外取消、提交、重置拖拽或模拟游戏输入；输入草稿、焦点、弹窗及其他游戏状态随会话保留。
3. 各会话以现有目标逻辑频率更新；不设人为会话数上限。资源不足时允许帧率下降，但不能静默丢失会话或串写状态。窗口最小化后全部会话继续更新，当前会话的音频继续播放。
4. 窗口布局按角色保存；音量、音效设置为进程共享。各会话关闭时先保存其角色布局与本地偏好，再直接断线移除，不等待服务端登出。不改变现有存档格式和原协议字段；实际保存路径、别名与失败处理需在迁移时逐项核对。

## 所有权

- `ClientHost` 拥有进程级 HWND、输入路由、SDL 呈现设备、共享音频设置、会话集合和当前会话标识；启动时自动创建首个会话进入现有登录界面。
- `ClientSession` 拥有自己的 `CgConnection`、登录/选角、场景/世界/战斗、UI 实例和焦点、脚本 VM 与任务、角色设置、保活时钟、动画及其他运行期可变状态。连接回调必须定位其所属会话，不能写入另一会话的世界或 UI。
- 只读资源与进程级设备可在证明身份、别名和生命周期后共享；可变缓存、渲染队列、调色板、动作对象、临时缓冲和静态局部状态须按真实消费者确定 owner。不得通过逐帧复制原全局、隐藏的活动会话指针、线程局部状态或私有影子状态掩盖遗漏的跨会话依赖。
- 单会话运行路径保留原调用/状态/返回及 RNG 消费合同。新增宿主调度只改变实例归属和呈现选择，不修改协议格式或给业务增加成功假体。

## 帧调度与呈现

当前 `MainLoop` 只泵一个 `GetGameConnection()`，`World::Update` 同时进行状态推进与绘制。先沿网络回调、登录、世界、战斗、UI、Lua、Yobi、输入和保存的生产/消费链迁移所有权，再建立每会话的主线程逻辑帧调度。每个会话的保活、收包、断线和脚本副作用在其自身上下文内完成；只有当前会话接收真实键鼠与 IME。

后台不得因为“不渲染”跳过会影响游戏行为的绘制相关逻辑；必要的绘制命令和状态副作用仍按原顺序生产，但不得污染当前会话的队列或提交到窗口。仅当前会话的画面和音频被呈现/播放；切换和最小化不暂停任何会话的逻辑。调度按同一目标周期逐会话推进，超载允许降帧，不宣称任意数量仍能保持 60 FPS。

## 自绘窗口与菜单

1. 保留固定尺寸，不增加最大化或拖动缩放；在原游戏画布之外增加标题栏高度，画布尺寸和坐标不变。自绘标题、图标、会话下拉、最小化和关闭，保持原窗口拖动、激活、系统命令与 DPI/命中行为。菜单为 UI，不绑定键盘 Tab。
2. 下拉菜单位于最小化按钮左侧，包含“新增”和每会话的切换项及“关闭”。会话项优先显示角色名；未选角色显示账号名；两者未知时显示“登录中 1、登录中 2……”；断线会话保留并显示断线状态。
3. “新增”创建独立会话并立即切入其登录界面。登录、战斗和模态弹窗中均可切换，原会话输入草稿与弹窗保留。关闭非最后一个当前会话后优先切到菜单下一项，没有下一项则切上一项；最后一个会话关闭直接退出。
4. 标题栏关闭按钮关闭整个进程，先沿现有退出确认；确认后逐个执行会话保存、断线和移除。菜单中的“关闭”只处理对应会话。关闭或新建失败不能误操作其他会话。

## 实施顺序与验收

1. 建立按模块的可变全局、静态局部、别名、回调和资源 owner 清单，记录不能安全共享的跨会话消费者；先完成连接及登录会话化，再迁移世界/战斗、UI/脚本/动作、时钟/音频和存档。每阶段保持单会话路径可用，不用仅有连接复数的阶段冒充多角色完成。
2. 拆开逻辑副作用与实际呈现，建立宿主帧调度、输入路由、音频选择和会话关闭顺序；最后接入自绘标题栏与下拉菜单。每个可验证小步更新 `plan/cg2d_full_reconstruction_progress.md` 并精确提交，不改旧工程或根 CMake。
3. 静态验收核对所有 `GetGameConnection()`、全局/局部状态及回调归属、切换边界、保存路径、关闭顺序、后台绘制副作用与队列隔离。运行验收需覆盖不同账号同时在线、后台战斗/脚本/UI与断线、任意场景切换、最小化、音频选择、拖拽/IME、角色布局、关闭及资源失败；原单会话行为也须回归。
4. 用户已授权使用 `build.bat` 编译，并提供启动参数供后续多账号验收参考；编译/链接通过不等于运行或业务验收通过。运行时以 `H:\Games\cgmsv_21.2a\CrossGate7.1.0` 为工作目录，可执行文件保持在本项目构建目录，不复制到游戏目录。账号和密码不写入 SPEC、进度或命令输出；当前所有权尚未闭合，不以五个账号启动多个单实例冒充进程内多会话。
