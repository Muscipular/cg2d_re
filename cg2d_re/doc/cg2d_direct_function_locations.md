# R1：直接函数定义定位

## 范围与实施方案

本清单补充[原函数元数据](cg2d_ida_inventory.json)和[显式语义映射](cg2d_semantic_function_mappings.md)，用于直接定位当前C++源码本体。不是函数验收表，不把地址命名、源码本体存在或脚本成功当作语义一致、编译、链接或运行通过。

2026-10-02按既有工程委托采用以下方案：

1. 只读取本线src/include下的.cpp/.hpp和既有函数元数据，显式UTF-8；不读取原EXE、数据库、构建产物，不调用编译器或运行客户端，不计算文件哈希。
2. 词法剔除预处理指令行（包括续行）、注释、字符串与字符常量后，定位以六位十六进制地址结尾的函数名；参数括号闭合后须能直接找到函数体花括号，宏指令、声明、调用与地址注释不算定义。支持const/noexcept/override/final后缀，记录所在命名空间及当前定义行。
3. 本工具不是完整C++解析器，不进行预处理、模板实例化、链接或重载决议；宏生成入口、复杂声明、汇编、无地址名函数仍按已有人工证据处理。源码条件分支中的定义也不证明当前构建会采用它。
4. 一个名称含多个地址时单列共享适配候选，不自行把一个尾地址当唯一归属。同一原入口命中多个定义时逐项保留，不自动当链接重定义或合并为已完成；后续依实际包装、命名空间、重载和调用合同分类。
5. 源码地址不是现有元数据入口时单列，不生成新稳定ID、不修改原函数分母。未命中的原函数只表示本规则没有找到直接定义，不表示缺失、排除或不可达。
6. 产物只记录原函数ID到源文件定义位置及上述候选，不生成调用图、依赖图或索引服务。由本线程使用Python标准库生成，不引入外部依赖、不委派工作。

脚本为[scripts/locate_direct_function_definitions.py](../scripts/locate_direct_function_definitions.py)，生成[定义定位清单](cg2d_direct_function_locations.json)。定义行是生成时的定位辅助；后续源码变动应以文件与完整符号重新定位，不能依旧行号推断实现状态。本轮只运行于实际源码作静态定位，不新增或执行测试。

## 核对与剩余边界

先核脚本在实际源码上输出的多定义/多地址/非元数据入口候选，再静态核对稳定ID、来源文件、定义位置和元数据集合关系。语义、参数返回、状态生产、调用及RNG次序、失败分支和资源生命周期仍沿各原函数合同验收；本产物不降低总PLAN标准，也不更新总SPEC或压缩进度。
