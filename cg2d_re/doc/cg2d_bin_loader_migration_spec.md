# binLoader 迁移 SPEC（BLM01）

日期：2026-10-16。用户范围：迁移 `twcg_hook` 的 binLoader，并将 `fseek` 改为 64 位定位。

用户进一步明确“只需要业务逻辑搬过来”：全部行为直接落入新端现有资源／初始化函数，不引入hook、地址扫描、注入或二进制补丁机制。

## 来源与裁决

依据参考项目 `src/hooks/binLoader.cpp` 的配置、图形、动画、坐标、地图色表和注册代码，迁移功能盘点 A01–A04。按本线 AGENTS 第8条已有工程委托，先记录取舍，再实施；这是明确的功能迁移，覆盖下述入口此前固定九组／容量／EOF处理的还原合同。磁盘记录布局、图形解码、动画帧／动作格式、渲染和网络不变。

原端补丁 `0x0051795F: jle → jmp` 已在当前 cg2d.exe IDA 会话核实：原函数 `0x00517880` 将动画编号与动画数量容量绑定。新端移除相同判断，保留静态图分流及真实动画索引查询。

## 配置与依赖

- 工作目录的 `cgmsv.yml` 是必需配置；`BinLoader` 为1–32项序列。没有配置、结构不符或超过32组时提示并结束启动，不回退旧九组。
- 六个字段为 `GraphicInfo`、`Graphic`、`AnimeInfo`、`Anime`、`CoordinateInfo`、`Coordinate`，缺省空串；路径相对工作目录，保留参考代码的窄字节文件边界，不附加 `gBinPath`。`Name` 仅为配置说明。
- 顶层 `MAX_GRAPHIC` 默认2,500,000、`MAX_ANIME` 默认30,500；必须为正整数。分配、临时动画表及主表使用同一容量，资源文件槽／图形基址槽统一32项。
- 路径改用字符串拥有存储，六组路径指针在解析完成后绑定；旧命令行资源名称及 `gBinPath` 与光标存储的别名保留，但资源六类路径由 YAML 决定。
- 复用工作区已经存在的 `3rd/yaml-cpp`，不下载／复制／修改第三方源码。CMake仅接解析库，关闭其工具、测试、格式化和安装，禁用RTTI；用户既有第三方暂存文件不夹带本轮提交。

第三方CMake的旧策略版本在父工程局部作用域中适配；既有策略设置优先，第三方文件不改。

示例结构（文件名须按实际资源填写，可继续增加组）：

```yaml
MAX_GRAPHIC: 2500000
MAX_ANIME: 30500
BinLoader:
  - Name: 基础资源
    GraphicInfo: Bin/GraphicInfo.bin
    Graphic: Bin/Graphic.bin
    AnimeInfo: Bin/AnimeInfo.bin
    Anime: Bin/Anime.bin
    CoordinateInfo: Bin/CoordinateInfo.bin
    Coordinate: Bin/Coordinate.bin
```

## 加载合同

| 链路 | 迁移行为 |
|---|---|
| 图形 | 空数据／Info对跳过；打不开的资源对提示后跳过。完整40字节记录才入表，全局图号为组基址加SeqNo；下一组基址加本组记录数加1。MapNo索引后组覆盖前组；非0／1／6／8组且MapNo≥800000时，运行时MapNo置零。 |
| 动画 | 空数据／Info对跳过；打不开提示后跳过。完整12字节记录按AnimeNo减100000去重，后组覆盖偏移、动作数、标志和来源槽；标志大于1归零。索引暂存262144项，配对暂存按MAX_ANIME分配；最后发布并排序。 |
| 坐标 | 空路径组继承前组文件；每个成功加载的坐标数据文件成为全部配置组的共享文件，后组覆盖前组。这是参考hook的实际行为。Info版本1，完整10字节记录按动画编号写偏移／坐标数；动画与坐标的图形基址仍取动画来源组。 |
| 地图颜色 | 唯一共享颜色表扩为800000字节，取消按图形来源槽排除取色；1000–19999及220000–265535按hook取色。后一范围保留新端已证的同表别名：下标减200000，不新建影子表。 |
| 帧推进 | 删除动画编号大于MAX_ANIME加100000的拒绝；不改变100000–199999的动画分流、GetIndex和动作加载。 |

图形分配容量与查询上界分开：分配／MapNo索引使用MAX_GRAPHIC，查询上界使用预扫记录数加 `max(10, 配置组数)`，覆盖最多32个组间空槽。此处具名扩展参考固定“加10”的预留，不改变组基址算法。正常资源仍须满足SeqNo与全局表容量合同；不专项处理畸形索引、数学溢出或短数据载荷。

参考算法没有按最大SeqNo估计查询上界；稀疏序号资源的覆盖／查询适用性仍待实际资源证据，本次不改变图号排列规则。多个坐标文件也不会形成独立组来源：所有动画最终使用最后成功的坐标文件，较早Info留下的偏移与该文件是否兼容仍须由资源本身证明。

旧 `auto.dat` 仅校验0／1／6槽时间且只容纳500000字节，无法代表任意资源组及覆盖顺序。本迁移启动时直接重建颜色，不读写旧缓存；旧缓存辅助入口保留为历史提供者，不改缓存文件格式，也不创建新缓存格式。

## fseek64 与寿命

- MSVC实际接口为 `::_fseeki64`；新端当前所有业务 `std::fseek` 调用直接替换，覆盖参考hook对CRT全局入口的作用范围，不新建同名包装。
- `SEEK_SET` 的原32位偏移先按无符号32位解释，再扩为64位；资源记录的 `0x80000000`–`0xFFFFFFFF` 不再成为负偏移。`SEEK_CUR`／`SEEK_END` 保留原有符号值。
- 图形Info预扫改 `_fseeki64`／`_ftelli64`，长度计算用64位；磁盘图形／动画／坐标偏移字段保持32位。此迁移支持原32位无符号偏移可表达的范围，不宣称磁盘格式能表达4GiB以上的记录偏移。
- 临时Info文件逐个关闭，数据文件留给消费者。坐标共享文件在被后组替换和退出时只关闭一次，全部别名清空；图形／动画退出遍历32槽。
- 容量不足／分配失败通过既有初始化错误出口结束启动；补齐图形初始化非零返回的接线，避免旧switch漏掉3／-1。不迁移参考代码的进程内地址补丁、VM／扫描器或CRT文件域。
