# 图形与动画自动定容 SPEC（RAC01）

日期：2026-11-01。状态：按用户“完成SPEC后执行”及已有工程委托定案，源码已实施，build.bat Debug配置／编译／链接通过；真实资源及画面未运行验证。用户已撤销0.6秒规则，不设耗时门槛。

## 范围

- 不再读取或依赖YAML的 `MAX_GRAPHIC`、`MAX_ANIME`，不保留250万／30500默认容量；保留 `BinLoader` 路径、组顺序及32组上限。
- 加载时先完成同号覆盖，再剔除没有有效引用的Graphic记录及被覆盖的旧Anime记录／专属引用；不因启动时无人播放删除独立AnimeNo。
- 原始资源只读，不重写文件、不改资源格式、不热加载、不更改外部SeqNo／MapNo／AnimeNo及磁盘偏移。
- 本SPEC覆盖BLM01的固定配置容量、图形连续大表、无消费者首见记录集合及相关初始化次序；解码、网络、渲染语义不扩展。

## 引用与覆盖

1. 同MapNo仅最终查表目标作为MapNo根；覆盖撤销的是旧映射，不直接删除旧Graphic。
2. 同AnimeNo仅最终记录进入主表；只由最终动画的动作／帧生产图形依赖。旧动画专属引用不再进入保留集合。
3. 保留全部最终MapNo目标，以及最终动画的帧、Coordinate目标。动画与坐标图号仍加动画来源组的原基址；基址按原完整记录数加1计算，不随剔除改变。
4. 独立调色板固定／DBF队列及完整AnimeNo同号图档回退均经MapNo，故由最终MapNo根覆盖；查找、回退及像素加载顺序保持，不解析／删除调色板载荷。
5. 保留场景漂移变体4直接SeqNo 227334／227335／227336及已有槽0；这些根不依赖MapNo是否存在。其他通过MapNo或动画帧得到的运行时图号沿对应根保留。
6. Coordinate沿现有“后成功数据文件成为全部组共享来源、Info逐次覆盖”合同读取，不擅改成每组独立文件。
7. 不以MapNo为0、动作数为0、未加载缓存或未播放作为删除条件；不将缺失目标补成新资源，不把畸形数据清理混作无引用剔除。

## 存储与查询

- GraphicInfo使用紧凑记录数组及按原SeqNo索引的S32位置表。位置表中-1表示不存在／已剔除；记录物理排列变化不改变SeqNo，查询为O(1)，不引入外部句柄或改变DX页式缓存。
- 图形逻辑上界覆盖实际SeqNo及原记录数／组间预留；MapNo位置表独立按实际最大正MapNo加1分配，至少保留槽0。缺失／超出实际MapNo范围的查表结果为原未命中值0，不访问表外内存。
- 初始按完整Info记录建立紧凑候选及SeqNo映射，保留最后一次写入同SeqNo的结果；引用标记合并共享依赖。最后只为保留记录分配精确数组，重建位置表并释放旧候选及标记，不以清零／不加载像素代替回收。
- 图形表通过具名表类型提供原SeqNo只读索引及真实保留记录遍历；不再暴露可被当作连续SeqNo数组的裸指针。不存在项的元数据读为原空槽零值，实际资源读取直接失败。
- 原去重MapNo集合／首见记录指针树没有实际消费者，连同其独立启动项退休，避免线性查重与悬空指针；不把旧首见版本当额外引用根。
- Anime临时配对按实际唯一数量增长，最终主表只分配唯一数加1，额外项保留既有包含上界查找的空槽合同；缓存按同一容量分配，不改变256个实际活动槽。
- 删除Yobi“动画编号大于容量加100000”拦截，交由真实AnimeNo索引判断；保留两个入口各自的静态图分流。

## 加载与失败

启动顺序调整为：GraphicInfo及数据文件 → AnimeInfo及动画文件 → CoordinateInfo及共享坐标文件 → 引用扫描／紧凑发布 → DX目录及动画缓存 → 原调色板／加载画面／地图颜色等后续初始化。

Info按组批量读取完整记录，不逐条fread、不为定容重复打开扫描；动作头沿12／20字节格式，帧沿10字节、坐标沿8字节扫描，仅记录引用，不构建播放动作／帧缓存，不消耗RNG或发布图形动作／坐标状态。帧采用可复用批量缓冲，避免逐帧文件调用。

引用扫描出现I/O失败时终止初始化，不能把无法完成扫描等同零引用；分配失败沿现有初始化失败出口。扫描沿当前业务已有动作／帧／坐标数量门禁，不新增资源大小／格式限制；数学溢出及畸形资源不扩大专项兼容。文件与新增存储在失败／退出时按唯一owner释放，不恢复固定容量回退。

地图颜色重建只遍历保留记录，并仅对最终MapNo目标取色；被覆盖但因动画保留的旧Graphic不得反向覆盖最终MapNo颜色。
