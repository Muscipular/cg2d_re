## 2. 实际差异与生命周期界限

六provider分别在GraphicDxCache、GraphicInfo、GraphicRead的独立模块中自动调用，无法保证相对于世界/玩家/UI的原序。原553018/55301C在世界表后、窄宽流配置前；553058/55305C在场景值后、动画值前；553104/553108在主/宠物后。各owner已有被动字节存储、真实显式构造/即时宿主登记，不需要重复建对象。

当前546CAE模块调用在LegacyMouse末尾，原C5的553178先于全部C++90；将已有调用移为同一TU前置，保其已证setmbcp(-3)/门禁与失败后置1，不新增执行旧CRT、编码选择或系统输入。SDK iostream自身初始化与TextureSurfaceOwner自动清理不改；这些及旧FILE/OS/环境状态与全程序退出继续各自合同，不从本组推完整启动。

<a id="active-initializer-order-decision"></a>
## 3. 实施裁决

1. 在既有LegacyMouse.cpp按上述三个原位置承接SurfaceTransformCacheStartup、GraphicInfoContainersStartup、IndependentPaletteContainersStartup；六调用仍逐项弃结果，完成后由各真实provider即时登记原退出。增加既有三个公开头，不新增cpp/CMake、框架、全局业务类型或依赖。
2. 同一小步从三个原文件移除其模块类型/对象与对应无用type_traits头，保所有存储/函数/构析/业务正文。保GraphicRead仍使用的type_traits。三个新位置只有平凡适配析构，不复制owner、登记、lambda清理或空回调；各旧模块不残留第二调用。
3. 将既有LegacyMultibyteStaticInitializer从末尾移到第一应用适配前；只移动一个真实调用/对象声明，不新增once、提前声明新的locale状态、改变原门禁或C5其他状态，旧cinit/CRT根仍不活动。
4. 既有保护/世界/场景/13坐标移动、UI/菜单、鼠标/玩家、两SDK流与四原空退出配对适配顺序和body保持。当前68槽按同一TU声明序及现有wrapper内部原序投影，不把音频/键盘/17流或locale缺口替换为null或跳过后称完整90表完成。
5. 六迁移入口、C5多字节/原父及所有当前68槽的语义绑定同步。29缺条目补为“仅原表/现有源码位置和调用顺序绑定”，保原库存ID，不进入已审/已验分子；既有本体未经本组全审。原回调数组继续真实extern，不造新数组消未接符号。
6. 原六owner/std::atexit与TextureSurface*借用、DBF载荷/共享计数/分配域不变。TextureSurfaceOwner独立自动析构和完整scene/重建/进程退出另验；不以本组构造顺序证明所有面已清理或快速退出正确。

## 5. 当前源码收口

四源码按限定迁移/include/注释重放后全文一致，六provider无双模块；当前66应用+2宿主流配置槽的声明顺序与现有坐标/移动/选择器wrapper展开按原表核对通过。原90槽保留1 null、2音频暂停、2键盘排除、17Legacy流或经典locale待接；68不是完整原90，更不是全功能分母。
