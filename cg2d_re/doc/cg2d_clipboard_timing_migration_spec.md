# 剪贴板、诊断与64位时间迁移 SPEC（CTM01）

日期：2026-10-16。用户要求迁移盘点A07、A11，升级time32为time64、GetTickCount为GetTickCount64；继续仅迁移业务，不引入hook／扫描／地址补丁。按既有工程委托记录取舍后实施。

## A07：剪贴板

参考 `twcg_hook/src/hooks/core.cpp` 的Ctrl+V、Shift+Insert、WM_PASTE三条入口，直接接新端WindowProcedure。新端已有UTF-16输入上下文及AppendText，优先读CF_UNICODETEXT，CF_TEXT仅作为CP_ACP兼容边界；先复制文字并释放剪贴板／全局锁，再交给既有AppendText逐个完整字符插入。

保持当前输入的光标插入、GBK写回／容量、行数和控制字符规则；无当前输入上下文时仍由AppendText处理。快捷键消费该次按键，WM_CHAR产生的Ctrl控制码仍由原输入过滤；不另造输入控件或修改协议文字编码。

## A11：诊断

- 复用ClientEntry已存在的异常／Debug断言minidump，不重复注册异常过滤器或引入转储库。现有输出位置、线程串行及文件生命周期保持。
- Debug构建或`--debug`启用控制台和FPS／帧间隔／场景状态显示。控制台仅释放本次创建的实例，不改变已有控制台所有权。
- 每秒更新窗口标题，使用现有窗口基础标题和玩家名；参考的三秒帧数滚动平均用于FPS显示，不引入Lua UI或渲染后端替换。
- 从WinMain启动时取得GetTickCount64基线；所有业务统一使用ReadTickCount64返回的启动后64位毫秒，主循环和网络不再绕过该边界。源hook最后截W32的做法由用户明确64位升级覆盖。

## 时间宽度

| 数据 | 实施边界 |
|---|---|
| 本地日历时间 | 使用__time64_t、_time64、_localtime64，覆盖日志、邮件、网络日期文字、窗口日历及游戏时间采样。 |
| 运行时毫秒 | 本地基线、截止、经过时间及相应函数参数／返回按实际消费者拓宽64位；登录、网络保活、鼠标长按、技能预览、聊天／行动节流、转场／地图文字和截图均接同一时间域。 |
| 差值／哨兵 | 时间差用64位有符号解释，截止的“无期限”哨兵同步64位；状态计数、位标记、帧数及阈值数值不因时间升级扩大。 |
| 浮点帧截止 | 现有double截止及1000/60增量保留，输入改64位相对毫秒；不改帧调度算法。 |
| 原资源／协议／存档 | 外部时间字段及格式保持原宽度。留言板的W32时间在日历边界按原位型零扩展；发给服务器的毫秒字段、随机种子和非计时业务返回在边界显式取W32，不把截断值用作本地计时存储。 |
| 游戏时间 | 本地秒采样与累计计算升64位，服务端调整／时间字段按原W32合同接入，最终GameTime六个日历／时段字段仍W32。 |

私有鼠标状态、转场／地图对象载荷及玩家计时字段随时间拓宽原生承载；相应旧尺寸／偏移断言同步或退休，原地址注释仅保历史身份。先核sizeof分配、成员访问、正常别名及全部生产／消费，不让时间拓宽改变原协议／磁盘布局或其他业务数值类型。

用户要求覆盖此前“time32／tick32及回绕保持”的局部合同，适用范围仅本地计时链。已有32位协议时间可表达范围仍受原格式约束，不能宣称服务端／存档也支持任意64位时间。
