## 完整控制流

### 1. 入口与提前返回：0x507146–0x507195

1. 先读取 `S16` 图形计数，决定本次使用的末尾排序槽位置。
2. 将 `0xD6978C` 的旧值按 `U32` 比较：小于 59 时加 1，否则置 0。
3. 用更新后的索引查询 `0x58ACC8[60]`，将结果写入 `0xD69768`。
4. 写入 `0xD6976C = -1`。
5. `0xCA0AB4 != 0` 时清槽并提前返回；该路径保留旧文本索引、鼠标事件字节和描述缓冲，不得补写这些状态。

入口确定的排序槽位置与后续重新读取的图形计数属于不同读取阶段，不能合并为一次快照。

### 2. 文本正序命中：0x5071A4–0x507256

文本从下标 0 开始正序遍历；每次失败后重新读取 `S32` 文本计数，仅处理 `value7 != 0` 的记录。

调用 `TextMeasure` 后，按下列顺序短路判断，边界均包含等号：

1. `X <= x + w + 2`。
2. `x - 2 <= X`。
3. `Y <= y + fontHeight + 2`。
4. `y - 2 <= Y`。

四项分别执行相应的 `CryptInt` 读取；不能将同轴两次读取合并或先读出鼠标坐标再复用。首个命中结束文本搜索。

### 3. 文本命中收尾：0x50733F–0x507407

先写入文本下标，再按 `value7` 处理：

- `value7 == 2`：绘框参数为 `(x - 3, y - 4, x + w + 2, y + h + 4, 218, D69768, 0)`。
- `value7 == 3`：绘框参数为 `(x - 3, y - 4, x + w + 2, y + h + 4, 214, marker, 1)`，其中 `marker` 为 `0xD69768`。
- 仅上述两类在绘框后调用排序；其他命中文本不补调用排序。

随后写图形索引 `-1`，将鼠标事件低 8 位写为 `0xD4`。仅当 `0xD460C8 == 0 && 0x58589C != 0` 时清 `0xD68AC8`，然后返回。

### 4. 文本未命中后的图形逆序搜索：0x50725C–0x507585

仅在文本未命中时重新读取 `S16` 图形计数，并写文本索引 `-1`。

从入口确定的末尾位置逆序遍历每项 4 字节的排序槽，以槽内 `S16 cacheIndex` 定位每项 40 字节的图形记录：

1. 先要求图形记录 `+0x10` 的 `value4 != 0`；该字段不是 `layer`。
2. 再调用 `0x522570(imageNo)`，要求 `EAX != 0`。
3. 任一条件失败即继续搜索，不能提前做后续对象或矩形处理。

### 5. 图形命中矩形：0x5072B8、0x507408、0x50748D–0x50756F

| 条件 | 命中范围及限制 |

### 完整控制流与调用合同

1. `0x507090..0x50709A`：保存 `EDI`，令 `i = 0`，以 `S16 count <= 0` 判断提前返回。只有计数为正才保存其余三个寄存器并初始化两条遍历指针。
2. `0x5070AD..0x5070B6`：读取当前记录的完整 `W32 value4`，再读取完整参数并比较。不匹配直接到 `0x507124`，不读层、DX、hover 或矩形字段。
3. `0x5070B8..0x5070FD`：匹配后按 `U8 layer < 0xD4` 选择两档框层。`0x5070BE jb` 成立时传 `0xCE`（206），否则传 `0xDA`（218）。包括 `layer >= 226` 在内都落入 `0xDA`，不存在父函数的第三档。
4. 匹配路径的业务数据读取顺序固定为：层字节 `0x5070B8` → DX 索引 `0x5070BA` → DX 基址 `0x5070C0/0x5070E2` → hover `0x5070C6/0x5070E8` → y `0x5070D5/0x5070F7` → x `0x5070D8/0x5070FA` → h `0x507102` → w `0x507106`。不得提前读取尺寸、合并为整项快照或交换宽高读取顺序。
5. `0x50710A..0x50711C`：按下表计算并传递绘框参数；负宽高和反向矩形照算，不交换边界、不取绝对值、不跳过。
6. `0x507124..0x507134`：匹配绘框后与不匹配路径汇合，重新读取当前 `S16 count`，然后 `++i`，再令记录指针加 `0x28`、层指针加 4，以 `S32 i < count` 决定是否继续。
7. `0x50713A..0x50713E`：恢复寄存器并返回，不计算返回值。

这是同模块内部承接，不新增业务或公共 API 设计，不形成 owner 冲突；具体共享符号与入口名字由主线程选定并对应原地址，不描述为用户另行单独批准的名字。原布局位宽与偏移不能因现代内部命名改变。

### 入口过滤与分段复制

1. `0x44B052..0x44B066`：先按有符号数检查 `color >= 13` 或 `fontType >= 14`，成立则早退；没有下界检查，不新增负值过滤。
2. `0x44B06C..0x44B0AE`：读取入口 `index` 选定记录，扫描源串直至并包含 NUL；先前向复制完整 DWORD 块。
3. `0x44B0A6`：在 DWORD 块已复制、余字节尚未复制的时点采样 `stream` 作为日志 gate；随后复制余下 0 至 3 字节。
4. 不清目标尾部，不截断，不新增容量保护；空串仍复制终止 NUL 并进入记录更新流程。

gate 为空时跳过日志分支，后续保留入口取得的 index。gate 非空时进入以下日志路径，后续记录选择按指定时点重读 index。C 的复制承接须保留 DWORD 块、gate 采样、余字节三者的顺序及正常别名行为；不能用一次整体复制改变采样时点，或自行改成具有不同重叠语义的复制。

### 时间参数槽与未完成的时间实现

日志路径中，原 `color` 早已保存于 `EBP`；原入口 `ESP + 0x8` 的 color 参数槽随后复用为同一个 `S32 T`：

| 地址 | 调用与栈槽事实 |
| --- | --- |
| `0x44B0B6`、`0x44B0BA` | `lea` 取得 `&T` 后压栈 |
| `0x44B0BB` | 调用 `0x53BA26`，实参为非 NULL 的 `&T` |
| `0x44B0C0`、`0x44B0C4` | 在前一次参数尚未清栈的栈偏移下再次 `lea`、压栈，修正后仍指向同一 `T` |
| `0x44B0C5` | 调用 `0x53B8C6`，实参仍为 `&T`，不是 time 返回的 `EAX` |
| `0x44B0D0` | 一次 `add esp, 8` 清除上述两个参数 |

现代内部承接复用现有 `platform::ReadLegacyTime32_53BA26(&T)`，不得改为 `time(NULL)`，也不得改传 time 的返回值。`LegacyTime.hpp` 第 9 行已有真实 `S32*` 输出参数；`cg2d_game_time.md` 第 85 行确认其 `ConvertLocalTime_541160` 转换及后续依赖仍未实现，因此复用入口不等于时间链可链接运行。

`0x53B8C6` 当前没有实现，本次 C 仅新增模块私有的真实不透明类型前置声明与指针返回入口声明：

```cpp
struct LegacyTm53B8C6;
LegacyTm53B8C6* LocalTime_53B8C6(std::int32_t* value);
```

不定义该不透明结构或入口，不使用现代 `std::tm`、现代 CRT 回退、固定返回值，不新增时间 cache 或 TZ owner。`0x44B0E3`、`0x44B0E6`、`0x44B0E9` 仅分别证明返回对象 `+0x0`、`+0x4`、`+0x8` 是本 caller 读取的 `S32` 秒、分、时；不得据此推出完整结构、TLS 或生命周期。

旧时区 `0x58FB78/0x58FB7C/0x58FB80` 与 `R6.1.3.163` 共享；`cg2d_game_time.md` 第 143 行附近的既有证据已将其与 wrapper cache 区分。当前没有现代 CRT 全域替代的批准，本次既不重建另一份时区状态，也不把本 caller 的字段读取视为完整 localtime 实现。

### 日志路径、原始格式与重读顺序

gate 非空后的顺序如下；gate 仅决定是否进入此分支，不是后续所有文件调用共用的 stream 快照：

1. 完成上述 time、localtime 调用后，`0x44B0CA` 重读 index，重新选取该记录的 `text` 作为日志正文，不能改为原入口 `text` 实参。
2. 读取返回时间对象的秒、分、时字段；格式调用实参为 `(stream, fmt, hour, min, sec, text)`，栈压入顺序为 `text, sec, min, hour, fmt, stream`。
3. `0x44B0ED` 重读 stream，供 `fprintf` 对应调用使用；`0x44B100` 再次重读 stream，供 `fclose` 使用；两次调用均忽略返回值。
4. 随后执行 `fopen(path, "a")`；`0x44B11B` 再读 index，至 `0x44B124` 才保存重开的 `FILE*`，后续字段写入使用此次重读的记录位置。

`0x554954` 的格式字节完整保留如下，不转码、不猜编码：

```text
20 25 30 32 64 3A 25 30 32 64 3A 25 30 32 64 81 40 25 73 0A 00
```

其顺序为前导空格、三组由 `:` 分隔的 `%02d`、原字节 `81 40`、`%s`、LF、NUL；三个整数实参依次为时、分、秒。`%02d` 为最小宽度，不新增截断或值域钳制。`0x554904` 的模式字节为：

```text
61 00
```

既有 `0x53BC0F` 变参转交、格式化及缓冲收尾证据支持承接为对应的 `fprintf` 标准文件行为；关闭再以 `"a"` 重开的顺序保持，不以 flush 代替关闭、重开，也不缓存后续重读。该标准文件行为的等价替代依据不授权把旧 time/localtime 换成现代实现。

### 记录收尾、索引与计数

| 次序与地址 | 正常路径必须保持的行为 |
| --- | --- |
| `0x44B136`、`0x44B13C`、`0x44B148` | 对最终选定记录依次写 `color`、`fontType`、`state = 0`，保留 `+0x12C` 未知字段 |
| 索引推进 | 先保存本地 `index + 1` 计算值、写入共享索引，再按有符号数比较该本地值；`>= 512` 时才另写 0，不新增共享槽读取 |
| `0x44B15C` | 调用 `0x4A76E0`；此 helper 范围为 `[0x4A76E0, 0x4A76FD)`，七条指令 |
| `0x4A76E0` 计数合同 | 先计算 `S32 count + 1` 并写回，再按有符号数判断 `> 512`，成立才另写 512；`EAX` 返回封顶前的加一值，本 caller 丢弃 |
| `0x44B162` | 最后向 `0x626C10` 写入 `W32` 十进制 20 |

索引与计数的比较分别为 `>= 512` 与 `> 512`，不能混同；计数的返回值不是最终存储值。空串也执行这些收尾动作，只有入口颜色或字体上界早退才跳过本体后续处理。
