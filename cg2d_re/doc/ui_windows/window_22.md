## 工程边界

复用现有D2F0B8前缀、CC4CA0候选计数/五索引/五对槽、
Input唯一D66CA8和D45F94焦点载荷，不复制宠物、输入或联系人。

通过char视图复制文本，不扩展或猜测其余字段。4A6D00只比较两个值副本的
value00/value04，短路不比较方式/宠物/物品/正文。调用前先复制旧草稿，再复制当前前缀。
4A5650只保存已证五个S32和正文，不复制value26C或整块清零。

原22CH只有首指针扩宽及既有标签适配，原几何/颜色/容量仍S32。
输入失败仅22初始化按原分支恢复context指针，不重试初始化，也不附加清正文。
原型文本57E758与Input正文为不同位置，按原分别复制/清首字节。

群组状态由本UI唯一承载：CC1A30计数、CC1A34模式、CC1A38的200个索引、
CC1D58的200个选择标志和CC2078初始化标志。4B5630清两数组，
4B5660先置索引-1/选择0再生产，循环末地址CC2078证明两数组各200项；
均属未加载零区，不用IDA的FF当初值。窗口49完整生产者尚待接入，
不把零初值当作已具备群组选人流程。

52E1D0复用世界宠物技能查询52E180，不凭数值猜测技能名：
实际技能号严格22C4/22C5/22C6/22C7，任一非零返回1，逐次重查、短路。
510FA0在既有网络文件内新增CV封包，不另建工具文件；其整数/文本/整数
按三个阶段独立取容量、格式化后重读输出缓冲，复用现有组包发送。
工程边界不增加发送成功门禁、输入长度保护、失败补零或索引钳制。
