## UpdateNRTime

原范围 `[0x458DE0,0x458EBB)`，对应 `world::UpdateGameTime`。
入口是一个原生输出指针，指向六个连续 32 位字段，完整大小 24 字节。
字段偏移依次为 year=0、month=4、day=8、hours=12、sTick=16、minutes=20；
不是 CRT `tm` 或 Windows `SYSTEMTIME`。

`0x458DE4` 先调用原 `_time(NULL)`，然后按原次序读取：
`0x559508`、`0x73ED68`、`0x73ED4C`、`0x73ED40`。
所有加减在 32 位内回绕，得到：

```text
time32 + (value73ED4C - value559508 - value73ED68) + value73ED40
```

其中 `value559508` 的 IDA 静态字节为 `0x3AE805E7`；
其余三个值和 `gCgTime@0x73ED50` 位于已核实 PE 零填充区。
运行值会被 `sub_50C870` 改写，分别在 `0x50C880`、`0x50C890`、`0x50C8C2`，
不能把映像初值当作完整初始化后的状态。

原除法及乘高位常量对应以下无符号整数分解：

| 写入点 | 输出 |
| --- | --- |
| `0x458E1D` | 总值 / 2592000 |
| `0x458E3E` | 年内余数 / 216000 |
| `0x458E56` | 月内余数 / 7200 |
| `0x458E70` | 日内余数 / 300 |
| `0x458E89` | 小时内余数 / 5，先写偏移 20 |
| `0x458EB6` | `(192 * (总值 % 7200) / 7200 + 168) % 192`，后写偏移 16 |

`0x458EB4` 的最后一次有符号 `idiv 192` 保留商在 EAX、余数在 EDX。
被除数范围为 168..359，因此源码用无符号计算有相同商、余数；
**函数返回这个商，不把它解释为更新成功或输出秒数。**
有效输入要求输出指向可写的 `GameTime`；不覆盖原失效指针或异常内存破坏。

## 原 32 位 time 入口

原范围 `[0x53BA26,0x53BB02)`，对应 `platform::ReadLegacyTime32_53BA26`。
使用独立标准整数接口，不把新 x64 的默认 `time_t` 引入原字段。

1. `0x53BA33` 调用 `GetLocalTime`，随后 `0x53BA3D` 单独调用 `GetSystemTime`。
2. 按分钟、小时、日、月、年顺序与 `SYSTEMTIME@0x1085FD0` 缓存比较；
   相同则读取 `0x1085FC8` 的缓存值，不重新查询时区。
3. 不同则 `GetTimeZoneInformation`。返回 `0xFFFFFFFF` 时选 -1；
   其余情况仅返回值为 2、DaylightDate.wMonth 非零、DaylightBias 非零时选 1，
   否则选 0。
4. 先复制完整 16 字节 UTC 缓存，再写入 32 位缓存结果，保持原次序。
5. `0x53BAEF` 把本地时间的年、月、日、小时、分钟、秒及缓存值传给
   `__loctotime_t@0x541160`，均为 32 位参数。
6. 可选输出指针非空时写入返回值，随后原样返回该 32 位值。

SDK 类型和 API 仅在 `src/platform/LegacyTime.cpp` 使用，游戏时间实现没有
Win32 类型。两个缓存的映像零初始化不代表任意调用时的运行状态；缓存之间的
未访问间隔不冒充已还原字段。

`ConvertLocalTime_541160` 目前仅有真实七参数声明，**未实现**其时区转换及后续依赖。
没有回退为 `_time32`、`time64`、`mktime` 或固定返回值。虽然本地 UCRT 提供 `_time32`，
它不能证明原两次采样、缓存与内部时区计算逐项一致，故没有直接替换。

### 已确认的本体事实

- 范围 `[0x541160,0x541222)`，194 字节、65 条指令；`cdecl`，
  `S32(year, month, day, hour, minute, second, daylight)` 七个 S32 参数依次位于
  `EBP+08/+0C/+10/+14/+18/+1C/+20`，EAX 返回，保留 EBX/ESI/EDI/EBP；
  `0x54121F: 5B C9 C3` 为退出尾部。已知 wrapper 调用点为 `0x53BAEF`；
  `_fstat@0x53CCD0` 内 `0x53CE53/0x53CEB3/0x53CF10` 仅确认 caller 身份，未展开。
- `0x54116A` 减 1900 得 `Y`，`0x541170/0x541179` 与 70/138 作 signed 比较；
  年份不在 1970..2038 时由 `0x54121C: 83 C8 FF` 返回 -1，不初始化时区。
- `0x54118A: 8B 34 BD 20 22 59 00` 直接读取 `table[month]@0x592220`，无月份边界检查。
  已读 13 个 S32 依序为 `365, -1, 30, 58, 89, 119, 150, 180, 211, 242, 272, 303, 333`；
  月份 1..12 对应后 12 项，不把 index 0 的邻接值 365 解释为合法月份。
- `0x541194: F6 C3 03` 与 `0x541199` 对应 `(Y & 3) == 0` 且 `month > 2` 时日序加 1，
  无世纪规则。令 `D = table[month] + day + 闰日`，夏令时修正前原 W32 运算次序为：

```text
R = (((365 * Y + SAR(Y - 1, 2) + D) * 24 + hour) * 60 + minute) * 60
    + timezone + second + 0x7C558180
```

`0x5411AF: C1 F9 02` 为算术右移；`0x5411E6: 8D 8C 11 80 81 55 7C` 加入该常量。
`0x5411DD..0x541218` 中，参数 `daylight == 1` 无条件加 `dstbias`；
参数为 -1 且共享 `daylight` 非零才调用判定，判定非零再加；其他参数值不调用判定、不加修正。
依[计划 RPLAN.20](../plan/cg2d_full_reconstruction_plan.md)，数值 overflow/专项回绕不另设门禁；
正常宽度、掩码、取模及算法顺序仍须保持，不承诺溢出域的确定输出。

### 已确认的依赖与共享状态

- 两个直接 callee：`0x54119F: E8 64 F9 FF FF` 调用 `___tzset@[0x540B08,0x540B1D)`；
  `0x541205: E8 71 FB FF FF` 调用 `__isindst@[0x540D7B,0x540F27)`。
  惰性入口 `0x540B08` 检查 `0x1086120`，为 0 才由
  `0x540B11: E8 07 00 00 00` 调用刷新 `__tzset@[0x540B1D,0x540D7B)`，
  再由 `0x540B16: FF 05 20 61 08 01` 递增标记；刷新早退也递增，本惰性路径不自动重试。
- 以下是映像初值，**不是运行常量**；写者为刷新入口 `0x540B1D`，
  消费者还包括 `_localtime@0x53B8C6`，修正值也供 `_cvtdate@0x540F27` 使用。
  它们不是 wrapper 的 `0x1085FD0/0x1085FC8` 缓存，也不是转换函数私有状态。

| 地址 | 共享含义 | 映像字节（小端） | S32 初值 |
| --- | --- | --- | --- |
| `0x58FB78` | 时区秒偏移 `timezone` | `80 70 00 00` | 28800 |
| `0x58FB7C` | 夏令时启用 `daylight` | `01 00 00 00` | 1 |
| `0x58FB80` | 夏令时秒修正 `dstbias` | `F0 F1 FF FF` | -3600 |

- `0x1086068` 为系统时区资料有效标记，`0x1086070` 为时区结构，
  `0x108611C` 为缓存 TZ 串指针，`0x1086120` 为惰性标记；
  这些地址 `is_loaded=False`，不能把读取到的 FF 当作初值。
- DST 缓存 `0x58FC10/14/18`、`0x58FC20/24/28` 为两组年/日序/毫秒阈值，
  各组映像值为 `(-1, 0, 0)`；刷新将年置 -1，
  `_cvtdate@[0x540F27,0x541067)` 写回缓存，其算法未展开。
- 刷新先用 `_getenv@0x54518B` 查询 `TZ`，仅缺失时调用 `GetTimeZoneInformation`；

- 其他仅确认身份的依赖：名称缓冲 `0x58FB84/0x58FBC4`、指针 `0x58FC04/0x58FC08`、

### GetCate：小时分类的读取与分支

原范围 `[0x458EC0,0x458EF6)`，54 字节、21 条指令；`cdecl`，参数为 `GameTime*`。

后续比较均对该 EAX 值作 S32 比较，不重读小时，无共享状态访问或 callee。

| 小时值域（S32） | 返回值 |
| --- | --- |
| `0..3` 或 `19..23` | `2` |

### LocalTime：两端分支的有序调整

`0x53B940` 将原 `T` 传给 GMT，不是传入口值的副本；`0x53B948` 无条件调用 IsDST，
不先检查共享 `daylight`。在 IsDST 返回后才读取对象秒槽作为 S32 `u`；
仅 IsDst 判定非零时才读取并减 `dstbias`；随后无论判定为 0 或非 0，都读取并减 `timezone`。
以下除法、余数按有符号语义，除法向零截断，不能替换为地板除法或通用日历归一化：

1. 写秒 `sec = u % 60`；余数为负时 `sec += 60`，同时 `u -= 60`。
2. 令 `u = 原 minute + u / 60`，按同样的 60 余数及负余数修正规则写分钟。
3. 令 `u = 原 hour + u / 60`，按同样规则以 24 写小时；负余数时小时加 24、
   `u -= 24`。令 `d = u / 24`。
4. `d > 0` 时依次写 `weekday = (旧 weekday + d) % 7`、`day += d`、
   `yday += d`，然后返回；`d == 0` 直接返回。
5. `d < 0` 时先写 `weekday = (旧 weekday + d + 7) % 7`，再写 `day += d`。
   调整后 `day > 0` 仅执行 `yday += d`；否则在 `0x53BA10..0x53BA1D`
   依序执行 `year--`、`day += 31`、`yday = 364`、`month = 11`，然后返回。

不补通用跨月或闰年归一化；两端保留 GMT 写入的 DST=0，即使判定非零也不另改为 1。
GMT 对负输入的空返回必须保留，LocalTime 原本没有统一判空保护；本次不新增兜底、

### GMT：四年分解、月份表与写序

GMT 先读 `*T` 为 S32；为负则返回空指针，不写共享对象。非负值 `t` 按下列顺序分解：

1. `q = t / 126230400`，`r = t - q * 126230400`，`year = 70 + 4 * q`。
2. 依次尝试扣第一年、第二年的 `31536000`；不足即落在相应平年，
   每次扣除成功均将 `year` 加 1，才继续下一年。
3. 到第三年时，`r < 31622400` 选择闰年表；否则扣 `31622400`、`year` 加 1，
   选择平年表。无世纪规则，不替换为现代日历计算。
4. `yday = r / 86400`；从 `i = 1` 起找首个 `table[i] >= yday`，
   写 `month = i - 1`、`day = yday - table[i - 1]`。
   日内余量再按 3600、60 分解时、分、秒。

| 表 | 13 个 S32 项（索引 0..12） | 本次证据归属 |
| --- | --- | --- |
| 闰年 `0x5921F0` | `[-1, 30, 59, 90, 120, 151, 181, 212, 243, 273, 304, 334, 365]` | 本次逐项读取全部 13 项 |
| 平年 `0x592224` | `[-1, 30, 58, 89, 119, 150, 180, 211, 242, 272, 303, 333, 364]` | 前 12 项继承 `.163`；第 13 项 `0x592254 = 364` 本次补证 |

GMT 的平年表起点为 `0x592224`，不与 `.163` 的 Convert 表基址 `0x592220` 混同。

### 惰性入口与刷新共同前序

`TzSet_540B08` 无参数，先读共享计数 `0x1086120`，非零立即返回；
为零则由 `0x540B11` 调用 `Refresh_540B1D`，返回后 `0x540B16` 对共享计数执行 `inc`。
这是**调用返回后对当前共享值的读改写**，不是固定写 1，也不是入口值加 1 后覆盖。
刷新即使早退，计数仍递增；此惰性入口没有自动重试。

`Refresh_540B1D` 开头的顺序必须保持：

1. `0x540B2E` 写系统有效标记 `0x1086068 = 0`。
2. `0x540B34` 写 DST 结束组缓存年 `0x58FC20 = -1`。
3. `0x540B3A` 写 DST 开始组缓存年 `0x58FC10 = -1`。
4. 其余缓存字段不清零；`0x540B40` 调用 `GetEnv_54518B("TZ"@0x54FAD0)`。

只有 GetEnv 返回空指针才进入系统分支；TZ 存在但为空串不是缺失。
后述空串、相同缓存、系统查询失败或分配失败均发生在上述失效写入之后，不回滚它们。

   任何其他 API 返回值都继续，不只接受标准时或夏令时两个值。
2. `0x540B63..0x540B8F` 先读取 `Bias`、`StandardBias` 并判断标准切换月，
   先发布 `timezone = Bias * 60`，再写系统有效标记为 1；
   标准月非零才再加 `StandardBias * 60` 并发布 timezone。

3. `0x540B94..0x540BBE` 检查夏令切换月及 `DaylightBias`；
   两者均非零时依次写 `daylight = 1`、
   `dstbias = (DaylightBias - StandardBias) * 60`，
   否则依次写 `daylight = 0`、`dstbias = 0`。随后依序转换两个名称。

### 系统名称：两次转换与调用后重读

标准名称先、夏令名称后，各次调用形态均为：

```text
WideCharToMultiByte(运行代码页槽, 0x220, 对应宽名称, -1,
                    运行名称指针, 63, nullptr, &usedDefault)
```

两次共用一个 BOOL `usedDefault` 槽。调用返回 0 或使用了默认字符时，仅清目标 `[0]`；
否则写目标 `[63] = 0`。第一次失败仍执行第二次，已发布的偏移不回滚。
代码页每次调用分别读取，名称指针在调用前读取用于转换，调用后再读用于终止写入；
不能沿用调用前缓存的目标指针。

| 名称与动作 | 已交接指令位置 |
| --- | --- |
| 标准：读取运行名称指针、读取代码页、调用 | `0x540BD7`、`0x540BE4`、`0x540BEA` |
| 标准成功：重读指针、写 `[63]` | `0x540BF6`、`0x540BFB` |
| 标准失败或默认字符：重读指针、清 `[0]` | `0x540C01`、`0x540C06` |
| 夏令：读取运行名称指针、再次读取代码页、调用 | `0x540C11`、`0x540C1E`、`0x540C24` |
| 夏令成功：重读指针、写 `[63]` | `0x540C38`、`0x540C3D` |
| 夏令失败或默认字符：重读指针、清 `[0]` | `0x540D6D`、`0x540D72` |

### TZ 存在：早退、缓存生命周期与标准名称

1. `0x540C49` 遇空串即返回。自有缓存非空且 `StrCmp_5450F0` 比较相等时，
   `0x540C63` 返回。两条路径都已经使系统标记和两组年份失效，
   不重新发布偏移、名称或缓存，也不转入系统查询。
2. 需要更新时，`0x540C69..0x540C93` 先释放旧缓存，再对原 TZ 借用串求长度，
   分配 `length + 1` 字节，并把分配返回指针发布到缓存槽。
   分配失败时已发布空指针并返回；成功才复制完整字符串。
   不改成先分配后释放，也不在原发布点之前提前清旧缓存槽。
3. `0x540C98..0x540CB1` 以 `StrNCpy_53BEC0` 复制标准名称的 3 字节；
   `0x540CA1` 调用后，`0x540CA6` 重读标准名称指针，
   `0x540CB1` 对重读目标写 `[3] = 0`。
4. 后续解析使用最初 GetEnv 返回的**原借用串**，不是已复制的自有缓存；
   游标先前进 3 字节。不增加短串检查、输入有效性前提或缓存副本替代。

### TZ 数值解析与逐次发布

数值转换与游标扫描是两条独立逻辑；保留真实 Atol 调用，不用 `strtol` 的结束指针替换。

1. 仅游标当前位置立即为 `'-'` 时记录整体负号并推进一字节。
   小时按 `Atol(cursor) * 3600` 计算，先发布 timezone 并保存局部 `offset`；
   交接列示的位置为 `0x540CC7/0x540CC9/0x540CCF`，不补作逐指令对应。
   不能等待全部解析完才统一写入。
2. 小时后的游标跳过任意连续的 `'+'` 或 ASCII 数字；遇 `':'` 才进入分钟解析。
   `0x540CED` 调用 Atol，`0x540CF2` 乘 60，`0x540CF6` 重读共享 timezone，
   `0x540CFC` 相加，`0x540CFE` 立即发布并保存局部 offset；随后只跳 ASCII 数字。
   加法必须使用该次调用返回后的共享读值，不能只沿用上一步局部 offset。
3. 遇第二个 `':'` 才解析秒；`0x540D18` 调用 Atol，
   `0x540D1E` 重读共享 timezone，`0x540D24` 相加，
   `0x540D26` 立即发布并保存局部 offset；随后仍只跳 ASCII 数字。
4. 若整体负号成立，`0x540D3D` 对局部 ECX 中的 offset 取负，
   `0x540D3F` 发布；这里不重新读取共享 timezone。

游标手工扫描 ASCII 数字的事实，不等于 Atol 的空白/数字判定也是固定 ASCII；
两者不能合并推定。

### TZ 尾部与夏令名称

`0x540D45..0x540D72` 把当前尾字节按 S8 符号扩展为完整 S32 `daylight`，
不是“存在则 1”的布尔值。非零时 `StrNCpy_53BEC0` 复制夏令名称的 3 字节：
`0x540D54` 读取运行名称指针，`0x540D5A` 调用，
`0x540D5F` 重读指针，`0x540D67` 对重读目标写 `[3] = 0`。
尾字节为零时，仅由 `0x540D6D` 重读夏令名称指针、`0x540D72` 清 `[0]`。
**整个 TZ 字符串分支不写 `dstbias`**，不能依据名称、偏移或启用值额外重置它。
