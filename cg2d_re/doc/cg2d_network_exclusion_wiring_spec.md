# 网络加密排除后的接线 SPEC

> 2026-10-02；待明确服务端封包格式。本节整理实施边界，尚未批准或实现替代传输协议。

## 已确认范围

用户排除 `403C50/403E50` 所涉包加解密链，同时要求保留非加密组包和网络分发。当前两个真实接线点仍是：

- `NetworkRuntime.cpp` 的 `InitializeNetworkRuntime_508140` 将 `Sub_403E50` 作为发送回调传给工作区分配入口。
- 同文件 `NetworkLoop_507DF0` 调用 `Sub_403C50` 取包；仅返回零时进入现有 `NetworkDispatch_512E40`。

私有依赖头保留两声明，当前未提供本体。这属于未收口的排除接线，不能记为链接或收发完成。原默认回调返回零；把初始化实参改为空指针会进入该默认路径，不能作为本项解决方案。

## 既有证据及参考的适用范围

[原网络合同](cg2d_network_runtime.md)的取包段已经证明：原入口先读取 W16 包长，等待 `包长+2` 个字节，再调用解密。成功后还执行输出复制、首次 CR/LF 状态处理、补 NUL、消耗接收队列及协议状态更新。发送入口也承担发送区和发送长度的生产。排除加密并不自动证明这些非加密副作用均可删除。

允许参考的 cg3a 源码：

- `src/packet/PacketBuilder.hpp` 的 `BuildPacket` 最终返回 `BuildPlainTokenString(tokens)`。
- `src/packet/Utils.hpp` 的 `BuildPlainTokenString` 按字段追加文本和空格，不生成长度前缀或行结束符。
- 同文件 `SplitPlainTokens` 在 NUL、CR 或 LF 处停止文本解析；这是文本解析合同，不能据此断言 TCP 以换行分包。

以上参考支持应用层文本组装和拆分，不足以确认取消加密后的网络帧格式。本节没有核定完整 cg3a 传输层，也没有把该参考替换为 cg2d 的已证实现。

## 待确认的协议选择

需要明确服务端取消加密后的实际契约：

1. 是否继续发送两字节长度前缀；若保留，其字节序、计数范围及明文正文边界是什么。
2. 是否改用 CR/LF 等分隔符；若采用，具体终止字节以及拆包规则是什么。
3. 与密文内容耦合的协议状态、异常标记及首次 CR/LF 转换如何处理。

两种格式都只能作为候选，现有授权和上述参考无法替服务端作决定。推荐先取得实际协议说明或服务端对应实现，再落位一对明确命名的非加密发送/取包入口；不自动探测格式，不增加静默回退。

## 确认后的整板块实施边界

- 保留现有命令变换、字段组包、分发以及唯一队列 owner，沿确认后的协议完成发送生产与接收消耗。
- 替换上述两个接线点，并清除不再使用的加密私有声明；不为旧地址符号提供空体或固定成功。
- 按已确认格式处理半包、连续多包、正文长度、返回值与原循环退出关系；发送和接收必须作为同一板块完成。
- 对不再适用的原协议状态逐项说明原因；仍被上层消费的状态保持同源生产。不能只删除调用而放弃这些消费者。
- 整板块完成后集中核新增调用、队列读写顺序、返回及差异，再记录进度和提交。当前不构建、不运行、不新增或执行测试、不做哈希校验；实际互通验收保持未完成。

在协议未明确前，保持两处缺口可见，继续其他有充分证据的板块；不将整个网络功能排除，也不以暂缓接线宣称总 PLAN 完成。
