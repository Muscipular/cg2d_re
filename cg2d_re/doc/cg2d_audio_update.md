### 2.1 本体事实伪码

以下仅表达原指令行为，不是可用源码或替代实现。`R32/W32` 严格为 32 位读写；原缓冲指针亦为 32 位，COM 返回按 `EAX` 的 32 位位型保留。

```text
gate = R32(0x10507D4)
if gate != 0:
    return gate

for i = 0..499:
    p = 0x103E7C4 + i * 0x60
    v = R32(p)
    if v != 0:
        W32(p, v - 1)

call 0x52CB50()
call 0x52C910()

a = R32(0x1050808)
if a == 0:
    W32(0x105080C, 0)
    return 0

a = R32(0x105080C)
if a == 0:
    return 0

q = R32(0x103CFB0)
if q != 0:
    buffer = R32(0x103DD78)
    if buffer != 0:
        q = q - 1
        W32(0x103CFB0, q)
        return buffer.SetVolume(R32(0x10505D0 + q * 4))

a = call 0x52B940()
W32(0x58D4F8, 0xFFFFFFFF)
return a
```

`SetVolume` 的实参按 `LONG32` 解释上述 32 位表项，返回 `HRESULT32`。非终止等待或坏内存访问不得在映射中化为成功返回。

## 4. 已证：被调函数闭包

### 4.1 Sub52CB50：空间音效槽更新

- 范围 `[0x52CB50, 0x52CC3D)`，零参数，遍历 50 槽。
- 无 request 时，仅 `channel` 在 `[0,63]` 内才执行 `Stop(self)`；随后重读 channel、清通道 `+0x30`、置槽 `channel=-1`，须保留该分支条件及先后顺序。
- 有请求时初始化新 channel/cache，依据 stereo 计算 `screenX/5` 并限于 `[0,127]`；旧声像每次最多改变 2；调用 `0x52C680(slot,isNew)` 后清 request。
- `EAX` 在末槽可保留 channel、重读 channel 后的 `channel*3`，或 `0x52C680` 的 0/-1；不能统一当作成功，本体 caller 不消费该值。

### 4.2 Sub52C910：BGM 请求状态机

范围 `[0x52C910, 0x52C9A1)`，零参数，`EAX32`。跳表 `0x52C9A4` 的四个真实目标为 `0x52C925/0x52C967/0x52C973/0x52C987`。

| 阶段 | 目标 | 已证行为 |
| --- | --- | --- |
| 0 | `0x52C925` | 处理请求；编号不同时先写阶段 1，再调用 `0x520750(signextend16[0xFF0C08])`、`0x520200()`，最后清请求 |
| 1 | `0x52C967` | 调用既有 `0x52B990` 后递增阶段 |
| 2 | `0x52C973` | flag 为 0 时写阶段 3 |
| 3 | `0x52C987` | 调用 `0x52BE60(target)` 后清阶段 |
| default | 不经上述四项 | 返回旧阶段 |

各分支可留下请求、索引、持久化返回、`0x52B990` 返回、flag 或 BGM 返回；不是统一成功值，`0x52CCA0` 后续会覆盖 `EAX`。

### 4.3 Sub52B940：清理分流

- 范围 `[0x52B940, 0x52B98E)`，零参数。IDA 的 `void stdcall` 标注不等于无返回；零参数也不足以判断 cdecl/stdcall。
- 模式非 0 时调用 `0x52B8E0`；否则对非空缓冲 `Release` 后清指针。
- 两路都依序清 `0x105080C -> 0x1050808 -> 0x1050814`，`EAX` 保留清理返回。

### 4.4 Sub52B8E0：通知等待与资源释放

- 范围 `[0x52B8E0, 0x52B93F)`，零参数，`EAX` 为 0 或 `Release` 的 `ULONG32`，不是有效对象指针。
- 模式非 0 且 buffer 存在时先 `Stop`；`0x52B8FD` 至 `0x52B905` 重读 W8 通知直到 1，然后清模式、清通知、`free(0x10507E0 所指分配)`、清分配指针，最后重读 buffer 并释放。
- 通知生产者为线程 `0x52BD40` 中的 `0x52BDBB/0x52BDC4`。线程合同不能以常量“完成”、超时退出或未经批准的同步重设计代替。

### 4.5 COM ABI

| 方法 | x86 vtable 偏移 | 参数与返回 |
| --- | --- | --- |
| `SetVolume` | `+0x3C` | 栈传 `self, LONG32`；返回 `HRESULT32` |
| `Stop` | `+0x48` | `self` 显式压栈，不用 `ECX` 传 this |
| `Release` | `+0x08` | `self` 显式压栈；返回 `ULONG32` |

以上为原 x86 合同，不直接授权 x64 指针表示、COM 生命周期或线程映射。

### 4.6 Sub52C680 / Sub520750 / Sub52BE60

- `0x52C680`：`[0x52C680, 0x52C90D)`，cdecl，两个 W32 栈参数，caller 清栈 8，返回 0/-1；包含真实 `DuplicateSoundBuffer/Release`、音量、声像、频率、播放及通道保留副作用。`0x52C8ED` 至 `0x52C902` 的正常 `&0x3F` 不能删。
- `0x520750`：`[0x520750, 0x520764)`，cdecl，参数为 S32 index；`W16[0xFF4C2E+index*2]=low16[0x1050818]`，返回 `EAX=index`。目标是既有当前存档 `+0x316`，禁止另建数组替代。
- `0x52BE60`：一个 W32 参数的 BGM 函数；源码现仅有 `login::detail::LoadAndPlayBGM` 声明，不能把声明当实现。
