## 2. 直接可编码的控制流分组

以下 `R8/R16/R32/R64`、`W16/W32/W64` 表示原内存访问宽度；`s32/u32` 表示同一 32 位位模式按有符号/无符号解释。`D` 仅是本文对 `gLastRenderDt@0x73ECC8` 的缩写，不是新增字段。

浮点比较的 `超过(a,b)` 指 x87 有序的 `a > b`。其反面包括 `a <= b` 和 unordered，详见第 4 节。

### 2.1 一次性前导：`0x457020..0x457052`

1. `0x457023 -> sub_4576B0()`；以完整 EAX32 判零。
2. 返回 0：`0x45702C` 释放本函数栈空间，`0x45702F` 直接返回。**不调用 `0x457A40`，也不调用 `0x4042B0`。**
3. 返回非零：依次 `sub_4041E0("kernel32.dll"@0x55918C)`、`sub_4048D0()`。
4. `0x457046` 只在这里读取 `GetTickCount` 的 IAT 槽 `0x54D1F8`，保存到 EBX；后续本函数九个 tick call 点调用这个已保存的函数指针。
5. ESI=0、EBP=1，进入 `0x457053`。本函数不另行初始化所有循环全局，也不在此重新设置截止时间。

`sub_4576B0` 成功路径内有加载/淡入淡出循环，不可把其资源初始化替换为固定成功返回。其失败路径可能已自行清理，例如 `sub_4585F0` 的消息退出点 `0x4587B7 -> sub_457A40`；调用者不能对所有初始化失败再追加一次同样清理。

### 2.2 循环头的模式重建与丢失恢复：`0x457053..0x4570D4`

1. 分别 R8 `0x62A640`、`0x628FEA`。不相等时，先 `sub_458A40()`，再 `Renderer::Rebuild@0x466B80()`。
2. 重建返回后重新 R32 `gCRenderer@0x627360`，从原对象 `+0x90` R32 palette 指针。
3. 仅当 palette 非空且 R32 `gWindowMode@0x9A7F48 != 0`，执行 `palette->SetEntries(palette, 0, 0, 256, &gDxPalette)`。
4. 随后另行 R32 `gCRenderer::isLost@0x62B064`。非零时调用 `Renderer::TestCooperativeLevel@0x44C6B0()`；其 EAX32 非零才再次调用 `Renderer::Rebuild()`，随后重复同样的有条件 palette reload。
5. 进入消息泵。

两项是顺序执行的独立 `if`，不是互斥分支。第一次重建会修改状态，第二项必须读取修改后的值；不能在循环头统一快照所有状态。

`Rebuild` 自身在 `0x466D0D` 也可能 SetEntries，然后 `0x466D26` 重新采样 tick、`0x466D37` W64 截止时间。调用返回后主循环自己的 SetEntries 仍要保留，不可去重。

### 2.3 所有非退出迭代共有的工作：`0x4570D5..0x457155`

按以下顺序执行，不能以 inactive 或 skipped-frame 为由移出：

1. `sub_466D50()` 消息泵。EAX32==0 则跳至唯一循环清理节点 `0x4574C6`；否则继续。
2. `KeepAlive@0x457AB0()`。
3. `World::UpdateNRTime@0x458DE0(&gCgTime@0x73ED50)`。
4. `0x4570F1` W16 `pendingGraphicCount@0x1020EB8=0`。
5. `0x4570F8` W32 `peddingGraphicCount2@0x73ECB8=0`。
6. `Renderer::CacheReset@0x456D30()`。
7. `NetworkLoop@0x507DF0()`。
8. `0x457108` R32 `0x58D3C0`，`0x45710E` 压栈，`0x45710F -> sub_52CD30`。真实调用点携带一个 32 位值，见第 3 节。
9. `World::Update@0x51C430()`。
10. 重新读取 `gWindowActiveState`；非零时，依次 `World::CursorUpdate@0x506E00()`、`Renderer::SortTexture@0x520790()`、`sub_507140()`。
11. 无条件 `sub_450BB0()`。
12. **再次读取** `gWindowActiveState`；非零时 `sub_449160()`。
13. 无条件 `sub_459760()`。
14. `0x45714A` R32 `0x73ECE4`。非零直接去实际绘制路径 `0x457246`，跳过下面全部 inactive/active 时间分流。

`sub_450BB0` 是有资源读取及调色板计算副作用的真实调用，现已接入
`render::UpdatePalette_450BB0` 的共享逻辑和 32 位路径；`sub_459760` 对 256 个按键状态逐字节 `&=0xEA`。
二者均不是可以省略的占位调用。调色板函数返回的 EAX 在本调用点仍被忽略。

`World::Update`、消息泵、重建及其内部调用可改变截止时间、状态与队列。共用工作执行完才作时间/渲染分流，不能把“是否要画”提到其前面。

### 2.4 inactive：`0x457156..0x4571E7`

进入条件：`0x73ECE4==0` 且第三次读取的 `gWindowActiveState==0`。

1. `0x457163` 采样 tick，无符号 32 位零扩展后与当前 `D` 比较。
2. 若 `超过(tick,D)`，直接去第 5 项。
3. 否则 `Sleep(1)`；其后若 R32 `0x62A65C==1`，立即做 **无 palette 判空、无 windowMode 判断** 的 SetEntries，然后 W32 `0x62A65C=0`。
4. `0x4571B0` 再调用 tick。只要没有 `超过(tick,D)`，回到第 3 项。等待内部不泵消息。
5. x87 先算 `R64(0x5590F0)+D`；`0x4571D7` W32 `0x5590F8=1`；`0x4571DD` 再把结果 W64 到 D。
6. `0x4571E3 -> 0x457053`，立即下一迭代。

本路径不执行 `0x457246` 之后的防护查询、DrawAllQueued、Flip、state 递增、float 备份和帧后上报。原共用工作和原 callee 内部的防护/上报仍照常执行。

特别是：若首次 tick 已超过截止值，**不会处理 `0x62A65C`**。不得把 reload 提到 inactive 等待循环之外。

### 2.5 active 与 skipped-frame：`0x4571E8..0x457245`

进入条件：`0x73ECE4==0` 且 `gWindowActiveState!=0`。

1. 仅当状态恰好为 1，`0x4571EC` W32 为 2。其他非零值不归一化。
2. `0x4571F6..0x457202` 先计算 `R64(frame_dt@0x5590E8)+D`，并把结果存为栈上的 **double**。
3. `0x457206` 才采样 tick，转换后与已经存下来的 double 比较。
4. 未超过该阈值，直接去 `0x457246`。
5. 已超过时再 R32 `0x5590F8`。按 **有符号** 比较，`>=20` 仍去 `0x457246`。
6. 否则是 skipped-frame：先算 `R64(0x5590F0)+D`，W32 `0x5590F8=旧值+1`，再 W64 D；`0x457241 -> 0x457053`。

跳帧不是跳过逻辑更新，只跳过本次实际绘制及帧后部分；本路径没有 Sleep，不处理 pending palette reload，也不递增 `state`。

计数器静态初值/正常重置值是 1，因此从重置值出发最多连续走 19 次此跳帧分支，随后计数为 20 时强制进入实际绘制。不得改为“积压即重置截止到 now”。

### 2.6 实际绘制前的防护与绘制：`0x457246..0x4572C2`

此路径可由强制标记直接进入，故不能额外要求 active；`0x73ECE4!=0` 时 inactive 也会绘制，而且不会执行 `1 -> 2` 的状态提升。

1. `sub_4043B0("GetTickCount"@0x55917C)`；只消费 AL8。
2. AL 非零才调用 `sub_510140()`；返回恰好 1 才 `sub_512CA0(R32(s),4)`。
3. 无条件 `sub_4048E0()`，把 EAX32 保存在 EDI。
4. EDI 按有符号解释 `>0` 才再次调用 `sub_510140()`；返回恰好 1 才 `sub_512CA0(R32(s),EDI)`。
5. `0x457294` 先 R32 `0x73ECC0`，`0x457299` 再 W32 `0x73ECE4=0`。
6. 已读取的 `0x73ECC0==0`：`Renderer::ClearSurface@0x4512C0()`；`==3`：`sub_423640()`；其余值：这两个都不调用。
7. 汇合后依次 `Renderer::DrawAllQueued@0x520DD0()`、`sub_468FF0()`、`Renderer::Flip@0x44C560()`。

防护函数本身也有检查、上报、全局写入和随机数副作用，不得仅保留外侧 `if` 而把 callee 置空。也不能将 `0x73ECE4=0` 移到防护调用前。

### 2.7 实际绘制后的等待与状态存储：`0x4572C3..0x457355`

1. `0x4572C3` tick；未超过 D 则 `0x4572DF -> Sleep(1)`，然后 `0x4572E5` 重新 tick，循环直到超过。
2. **等待退出之后**检查 `0x62A65C==1`，进行无判空、无 windowMode 门槛的 SetEntries，然后清零该字段。即使没有 Sleep 也检查一次。
3. `0x45732C..0x457332` x87 先计算 `R64(0x5590F0)+D`，暂留浮点栈。
4. `0x457338` R32 `state@0x58B7E4`。
5. `0x45733E` W32 `0x5590F8=1`。
6. `0x457344..0x457345` 32 位递增并写回 state。
7. `0x45734B` 最后 W64 D。
8. `0x457351 -> sub_5208F0()`，备份两个 32 位浮点位模式，见第 4.3 节。

原顺序是 **Flip -> 等待 -> palette reload -> 计数/截止存储 -> float 备份**，不是等待后才 Flip，也不是所有帧开始时统一提交上一帧状态。

### 2.8 F10/窗口枚举相关报告：`0x457356..0x4573F8`

1. `GetAsyncKeyState(0x79)` 返回 SHORT；按 **AX16 有符号 `<0`** 检查，成立则 W32 `0x73ECEC=1`。不取低位，也不以 EAX32 判负。
2. 无条件 `sub_4587D0()`；EAX32 必须恰好为 1，再检查 `s32(0x73ECF8)>=3`。
3. 同时成立时依次 W32 `0x73ECEC=0`、`0x73ECF8=0`。
4. `0x457387` 第一次 tick，`0x457389` 立即 W32 `0x73ED08=tick1`。
5. `0x45738E` 第二次 tick，执行无符号 `div 10`，计算 `60000 * (tick2 % 10 + 10)`。
6. `0x4573AA` **重新读取已存下的** `0x73ED08`，32 位加上该偏移，再 `0x4573B4` W32 回原处。两次 tick 不得合并。
7. 随后按原短路顺序检查：`s32(0x73ECF4)>0`；`sub_510140()==1`；采样 `0x4573CA` tick；`u32(tick)>u32(0x73ED08)`；`s32(0x73ED08)>0`。
8. 全部成立才调用 `sub_512CA0(R32(s),R32(0x73ECF4))`；返回后 `0x4573EF` W32 `0x73ED08=0xFFFFFFFF`。

第 7 项必须保留 unsigned `JA` 与 signed `JG` 的混用。`0xFFFFFFFF` 是该路径写入的哨兵，不是 64 位时间，也不能转为带回绕修复的新截止判断。

### 2.9 系统时间与周期报告：`0x4573F9..0x4574C5`

1. 无条件第一次 `sub_510140()`。仅若返回 1 且 `lastSystemTime` 两个 32 位半部 OR 后为 0，执行初始化分支。
2. 初始化分支：`GetTickCount@0x457411 -> sub_53B4BF(tick)`；再 `sub_4589D0()` 返回 EDX:EAX64；**先 W32 低半部 `0x73ED10`，再 W32 高半部 `0x73ED14`**；随后 `rand()`，有符号 `%200+1100`，W32 `0x73ED18`，并把该结果保留为待传参数。
3. 未进入初始化分支则在 `0x457447` **第二次调用** `sub_510140()`。仅返回 0 且 lastSystemTime 非零时，依次 W32 低半部=0、高半部=0、`0x73ED18=0`，传参值为 0。
4. 第二次返回非零，或 lastSystemTime 已为零，则 R32 `0x73ED18` 作为参数。原第二次判断是“零/非零”，不能复用第一次“是否等于 1”。
5. 所有分支汇合到 `sub_458A10(参数)`；即使参数为 0，仍调用，不可在主循环外侧跳过。
6. 返回 EAX32 **不等于 1**：`0x457487 -> 0x457053`。
7. 返回 1 才重新 R32 `0x73ED18`；有符号 `>=1650`：`0x457497 -> 0x457053`。
8. 否则无额外连接状态查询，直接 `sub_512CA0(R32(s),101)`，之后再 `rand()`；`0x4574BB` 把有符号余数 `%200` 加到**当时内存中的** `0x73ED18`，以 32 位写回。
9. `0x4574C1 -> 0x457053`。

不能把最后的 `rand` 提前到上报前，也不能给报告 101 补上其他报告所用的连接判断。状态门槛、报告编号、重复查询和随机数消耗顺序都是原行为。

### 2.10 所有循环 continue 与 exit 节点

| 分支指令 | 条件/来源 | 目标 |
|---|---|---|
| `0x4571C9` | inactive 等待仍未超过 D | `0x45717E`，只继续等待，不回主循环头 |
| `0x4572FE` | 绘制后等待仍未超过 D | `0x4572DE`，只继续等待 |
| `0x4571E3` | inactive 本迭代结束 | `0x457053` |
| `0x457241` | skipped-frame | `0x457053` |
| `0x457487` | 周期时间检查返回不等于 1 | `0x457053` |
| `0x457497` | 报告阈值有符号 `>=1650` | `0x457053` |
| `0x4574C1` | 报告 101 及 rand 累加完成 | `0x457053` |
| `0x45702A` 的未跳转分支 | 初始化返回 0 | `0x45702F` 直接返回 |
| `0x4570DC` | 消息泵返回 0 | `0x4574C6` 清理后 `0x4574D9` 返回 |

进入循环后的清理顺序严格为 `0x4574C6 -> sub_457A40()`，然后 `0x4574CB -> sub_4042B0()`。两者返回值均忽略。不得提前释放防护模块，也不得正常退出时只销毁窗口而漏掉两次原调用。

对“异常退出”的边界：本函数没有异常捕获保证；不能宣称任意访问异常都会自动到达 `0x4574C6`，也不能从本文推导新增 catch/finally。原错误处理若最终使消息泵返回 0，就走上述顺序；初始化失败按 2.1 原样返回，不强行统一。

## 3. 按指令顺序的完整 call 合同

表中参数按**逻辑参数顺序**列出，而非压栈逆序。`无` 表示调用点未新传显式参数且不存在已证实的 ECX-this 合同；函数名不是 `thiscall` 证据。

`忽略` 表示主循环不消费返回值。`void` 为当前 IDB 合同；只从 EAX 遗留的数值不能为未知 callee 发明业务返回类型。所有这里列出的普通内部参数均由调用者清栈；Win32 API/COM 为原 x86 stdcall。

| call 点 | 实际 callee | 实参 | 返回宽度与本调用点用途 |
|---|---|---|---|
| `457023` | `4576B0` | 无 | EAX32；零/非零，初始化入口 |
| `457039` | `4041E0` | 字符指针 `55918C`，`"kernel32.dll"` | void，防护前导，非纯查询 |

### 3.1 伪码遗漏参数：`0x45710F`

原指令顺序：

```text

4570EC  call 458DE0
...     上面的参数仍留在调用者栈上
457108  mov edx, [58D3C0]
45710E  push edx

457114  add esp, 8
```

`[58D3C0]` 的静态值为 `0xFFFFFFFF`，但调用点确实读取内存，并非直接压常数。

## 4. 时间、整数与浮点存储合同

### 4.1 double 截止与两个可写帧间隔

`get_int(u64le)` 和实际字节确认：

| 地址 | 字节，小端 | 原始位模式 | binary64 值/用途 |
|---|---|---|---|
| `5590E8` | `AB AA AA AA AA AA 30 40` | `0x4030AAAAAAAAAAAB` | `16.666666666666668`；active 是否追赶的阈值增量 |
| `5590F0` | 同上 | 同上 | `16.666666666666668`；三条路径的截止递增量 |
| `73ECC8` | IDB 未定义，不能读成 FF 数值 | 映像零初值，进入循环后动态 | W/R64 double 截止，不是 float、int tick 或“上一帧耗时” |

两个帧间隔是**不同地址的可写全局**，即使初始位模式相同也不能合并为一个常量或一个字段。`4043B0` 会检查并分别修复它们；具体写入顺序见第 7 节。

主循环每个 tick->浮点转换都先 W32 低半部为 EAX，再 W32 高半部为 0，再 `fild qword`。因此 tick `>=0x80000000` 时仍是正的 unsigned32 值，不可先转 signed32。

| tick 点 | 临时栈对象 | 转换/比较 |
|---|---|---|
| `457163` | `var_30`，低/高各 W32 | `45716D fild qword`，`457171 fcomp qword D` |
| `4571B0` | `var_28`，低/高各 W32 | `4571BA`，`4571BE` |
| `457206` | `var_20`，低/高各 W32 | `457210`，与 `457202` 已 W64 的 `var_8` 比较 |
| `4572C3` | `var_18`，低/高各 W32 | `4572CD`，`4572D1` |
| `4572E5` | `var_10`，低/高各 W32 | `4572EF`，`4572F3` |

主函数中的所有 `fld/fadd/fcomp/fstp` 内存浮点操作数均为 8 字节，**没有把帧截止写成 float32 的指令**。

每次比较接 `fnstsw ax; test ah,41h`。跳转 `jz` 表示有序“大于”；`jnz` 表示小于、等于或 unordered。若使用高级语言比较表达式，不能无条件以 `<=` 替代 `!(a>b)` 的 NaN 分支。原 FPU 控制字/异常掩码未由 MainLoop 设置，本文不假定额外的 NaN 修复或异常抑制。

栈阈值和全局截止各有明确 binary64 存储点。原加法先在 x87 中计算，再按这些点写回；不改成 float32、FMA、整数毫秒、时间差归一化或 64 位单调时钟，也不把加法越过中间的全局写入。

### 4.2 首次进入主循环时不是重新从零计时

`sub_4576B0` 内：

```text
457956  GetTickCount
457958  W32 临时低半部
45795C  W32 临时高半部=0
457964  fild qword
45796D  W32 NextSceneType=-1
457977  fst qword [73ECC8]
45797D  fadd qword [54DDA8]     ; 3000.0
457983  fstp qword [73ED00]
457991  call 4585F0
```

随后 `4585F0` 在 `458609` 再 tick、`45861D` 再设置 D，其淡出循环继续推进 D、state、跳帧计数。`4579B5` 还有真实初始化调用 `4705D0`。所以 `457053` 的第一次迭代必须继承完整初始化后的状态，不能声称 D 恒等于 `457956` 那次 tick，也不能将 state 重置为其映像初值 3。

`Rebuild@466B80`、WndProc 经消息泵、World::Update 的部分场景路径也会重设 D；例如 `51C6A6` tick 后 `51C6B8` W64 D。不得用 MainLoop 的长期局部缓存替代这些共享全局。

### 4.3 32 位 tick、64 位整秒和 float32 备份不能混用

1. 延迟报告 `73ED08`：两个独立 tick 调用，中间有一次真正 W32，最后的计算按 32 位回绕。`tick2%10` 是无符号 `div`。偏移的指令乘法为 `3*5*5*5*5*32=60000`。
2. `lastSystemTime@73ED10`：无符号 64 位整秒，仅在主循环以低 DWORD、高 DWORD 的顺序分别读写。不可把两次存储调换，也不能与 double D 别名。
3. `458A10` 实际只比较**低 32 位秒差**，不是伪码看起来的完整 64 位时间差。原指令 `458A15..458A24` 为取 EAX、减 `[73ED10]`、signed `jl`。
4. `5208F0` 的精确顺序：

```text
5208F0  R32 [9DAD4C] -> EAX
5208F5  R32 [9DAD50] -> ECX
5208FB  W32 [1020EF4] = EAX
520900  W32 [1020EF8] = ECX
```

`9DAD4C/9DAD50` 的 float32 宽度另由 `4683BA/468404` 的 `fstp dword` 证实。这里是**先读两个值，再写两个值**，保留 float 位模式，不能写成把 float 数值强转为 int；其具体业务名称未冻结，不能仅因处在帧尾便命名为 tick/delta-time。

## 6. palette reload 的 nativeDX7 边界

### 6.1 已证实的对象与虚表槽

原 `Renderer::Init@44B630` 在 `44B6FA` 请求 `0xC4` 字节、`44B6FF` flags=`0x40`，调用 GlobalAlloc/GlobalLock，`44B70E` 发布到 `gCRenderer`。本循环只需要其 `+0x90` 字段；未知其他字段不能猜成业务类。

`Renderer::InitPalette@450470` 的 `450855..45086B`：

```text
dd7 = R32[gCRenderer+4]
out = gCRenderer+0x90
dd7.vtable[0x14/4](dd7, 4, &gDxPalette, out, 0)
```

IDA 的实际类型库确认 IDirectDraw7 vtable `+0x14` 为 CreatePalette，输出位置与本循环 R32 的 `+0x90` 一致。IDirectDrawPalette vtable 的实际类型成员如下：

| 原 x86 字节偏移 | 0 起槽号 | 成员 |
|---|---:|---|
| `00` | 0 | QueryInterface |
| `04` | 1 | AddRef |
| `08` | 2 | Release |
| `0C` | 3 | GetCaps |
| `10` | 4 | GetEntries |
| `14` | 5 | Initialize |
| `18` | 6 | **SetEntries** |

四个主调用点均实际压入 5 个 DWORD：`entries`、`count=256`、`base=0`、`flags=0`、`this=p`，然后间接 call `[vtable+0x18]`，无调用者 `add esp,20`，符合原 stdcall HRESULT32 合同。

这四处真实目标均为运行时 COM 槽，不是可从 EXE 静态字节取出的固定函数指针表。已核验“字段来源、槽偏移、参数、调用规约和类型库”；**未获得运行时 vtable 内容，也不伪造实际 DLL 目标地址**。

### 6.2 四处条件不能统一

| call 点 | 原先决条件 | 调用后处理 |
|---|---|---|
| `457093` | 模式不同；重建后 palette 非空；windowMode 非零 | 忽略 HRESULT；不清 `62A65C` |
| `4570D2` | lost 非零；cooperative 成功；重建后 palette 非空；windowMode 非零 | 忽略 HRESULT；不清 `62A65C` |
| `4571A7` | inactive 等待体内，已经 Sleep(1)，`62A65C==1` | 不判 palette/windowMode；调用返回后清 `62A65C` |
| `457323` | 实际绘制后等待已结束，`62A65C==1` | 不判 palette/windowMode；调用返回后清 `62A65C` |

后两处即使 HRESULT 失败也清请求，因为原调用者未检查 HRESULT；不得改成成功后才清。原指针有效性是 nativeDX7 初始化链的先决条件，不是可用空指针加 `if` 静默跳过的依赖。

该表明确的是原 nativeDX7 合同。x64 端不可把原 `+0x90` 原样套在任意新 C++ 对象上，原 32 位 COM/SOCKET/HMODULE 指针承载须与本机 ABI 区别；其余 8/16/32/64 位游戏数据不能随指针一起无差别扩宽。

已有 SDL 最终帧提交适配器不提供这些 COM 生命周期、丢失恢复与 SetEntries 契约。本文不决定未授权的驱动替换策略，不把 reload 实现成空函数，不用 renderer 非空/空值伪装原分支，也不把四个不同调用点改为统一 callback 表。

## 7. 防护、上报和退出的不可删减合同

### 7.1 保留所有原防护调用，而非只保留报告外观

- `4041E0("kernel32.dll")` 在初始化成功后执行，含真实模块加载、检查数据初始化、版本及进程相关状态记录。
- `4043B0("GetTickCount")` 每个实际绘制迭代都调用，内部自行计数；计数达到 1380 才执行后续检查。不能由主循环另做低频包装或直接返回 0。
- 它可自行调用报告 3、2，并检查函数入口、mutex、进程与已有检查数据；这些副作用归原 callee，不因外侧报告 4 的条件为假而绕过。

### 13.1 本体状态及顺序

| 原地址 | 原指令行为 | 新端边界 |
|---|---|---|

### 13.2 回调原始标题、宽度与终止条件

回调使用原生 `BOOL CALLBACK(HWND, LPARAM)`；`0x458846..0x458873` 先读取共享 `byte_593850` 写入标题缓冲首字节，再将后续 127 字节清零，`0x458874` 调 `GetWindowTextA(hWnd, title, 128)`，`0x458880` 调 `GetWindowRect`，两者返回值均不检查。新端通过网络运行期的 W8 只读接口逐次读取同一 owner，不借此推定 `593850` 后续文本容量。原 ANSI 标题只作以下原长度的 `strncmp`，不与现有 UTF-8 窗口标题或登录场景字符串合并：

| 比较点 | 原地址与前缀原始字节 | 命中时原写入 |
|---|---|---|
| `0x4588B4` | `559384`: `C5 5D A4 4F C4 5F A8 A9`（8 字节） | `0x4588C0`: `flags@73ECF0` 低字节 OR `1` |
| `0x4588E1` | `55937C`: `50 43 BA EB C6 46`（6 字节） | `0x4588ED`: 低字节 OR `2` |
| `0x45890E` | `559370`: `20 AB 48 AE A7 B8 EA AE C6 20`（10 字节） | `0x458920..0x458922`: 低字节 OR `4`、写回低 16 位 |

`0x458886..0x4588A2` 由 RECT 外框计算 `right-left`、`bottom-top`，仅同时严格等于 `249`、`136` 时，`0x458938..0x45893A` 给 flags 低字节 OR `8`、写回低 16 位。原指令对矩形值作 W32 减法；新端以无符号 W32 运算保留回绕位模式。上述标记可跨不同窗口累计，不按窗口清零。

`0x458942..0x458965` 仅在 flags 低 16 位恰为 `15/13/11/7/9/5` 中之一时进入 `0x458975`：先读原 DWORD、只清 flags 低 16 位，取旧低 16 位零扩展写 `reportValue@73ECF4`，返回 `FALSE` 使枚举停止；其它值返回 `TRUE` 继续。高 16 位不清，回调不检查 `GetWindowTextA` 或 `GetWindowRect` 是否成功，也不追加 `IsWindow` 等门槛。

风险及后续义务：原 `GetWindowRect` 失败后仍读取未初始化 RECT 域；新端保留无默认矩形的原调用形态，不能宣称这条失败路径具有确定可移植结果。`InitializeClient@0x457956..0x457983` 原先取 tick、写 `gLastRenderDt`，并执行 `73ED00 = 当时 D + 3000.0`；该初始化函数尚未实现，后续实现它时必须写入本独立 deadline，不能以本项的零初值或空 stub 代替。现有网络 `reportValue` 清理链及 UTF-8 标题路径不在本项修改范围。
