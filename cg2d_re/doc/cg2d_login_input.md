# cg2d 登录输入上下文初始化证据

## 范围与函数边界

本文只记录当前 `ida-17524/cg2d.exe` 中以下三个函数及其直接使用的数据：

- `sub_45C7C0@[0x45C7C0,0x45C96E)`：110 条指令、4 个基本块，原型为
  `void()`；两个 caller 为 `sub_45C2D0@0x45C2D0` 与
  `sub_45C5A0@0x45C5A0`。
- `sub_5203E0@[0x5203E0,0x520409)`：21 条指令、6 个基本块，读取
  `[0xFF494F,0xFF4982)`。
- `sub_520440@[0x520440,0x520469)`：21 条指令、6 个基本块，读取
  `[0xFF4982,0xFF49B5)`。

本项实现唯一公共读取入口与上下文初始化器，但不接线上述两个初始化 caller。
`sub_45CA20`、两个槽的写入函数、登录提交和网络链均不在本项范围。

登录控件命中与鼠标位打包的独立证据见
[`cg2d_login_control_hit.md`](cg2d_login_control_hit.md)；该单项只提供
`sub_5036F0` 的公共入口。登录控件绘制 `sub_503780` 的独立证据见
[`cg2d_login_control_draw.md`](cg2d_login_control_draw.md)；两项均不接线
`sub_45CA20`。两个函数共享的 `LoginSceneControl32` 字段为：

| 偏移 | 字段 | 语义 |
|---|---|---|
| `+0x00` | `drawX` | 基础图绘制 X |
| `+0x04` | `drawY` | 基础图绘制 Y |
| `+0x08` | `left` | 命中矩形左边界 |
| `+0x0C` | `top` | 命中矩形上边界 |
| `+0x10` | `width` | 宽度 |
| `+0x14` | `height` | 高度 |
| `+0x18` | `normalImageNo` | 常态基础图号 |
| `+0x1C` | `activeImageNo` | 激活基础图号 |

## 唯一存储与读取边界

原 `0xFF494F`、`0xFF4982` 各为 51 字节零填充槽。新端在
`LoginInput.cpp` 中各保留一个私有 `char[51]`，不从登录场景复制或另建同义
存储。两个公开读取函数分别映射原 `sub_5203E0`、`sub_520440`：

1. 目标为空时立即返回空指针，不读取源槽，也不写目标。
2. 目标非空时逐字节复制，最多复制 51 字节。
3. 复制到首个 NUL 后返回原目标指针。
4. 51 字节均非 NUL 时不追加终止字节，仍返回原目标指针。

IDA 对两个槽各显示两个直接数据引用：本项实现读取引用；原
`sub_5203B0@0x5203B0`、`sub_520410@0x520410` 的写入语义留待后续单项，不在
这里预建 setter。

## 共享状态

| 原地址 | 新端唯一存储 | 宽度与映像初值 |
|---|---|---|
| `0x9A5960` | `gInputContext9A5960` | `InputContext`，静态零初始化 |
| `0x9A5678` | `gInputContext9A5678` | `InputContext`，静态零初始化 |
| `0x9A4B8C` / `0x9A4B8A` | `gInputContext9A5960X/Y` | signed W16，映像零 |
| `0x9A4B9E` / `0x9A4B9C` | `gInputContext9A5678X/Y` | signed W16，映像零 |
| `0x9A6E20` | `gValue9A6E20` | W32，映像零 |

两个上下文会被多个原场景函数引用，因此只按地址中性区分，不命名为账号或
密码。原焦点表 `0x559FFC` 的三个 W32 表项依次指向
`{0x9A5960,0x9A5678,0x9A5960}`；新端使用内容相同的三项原生指针数组，不把
x64 指针截断为 32 位。

## 初始化顺序

入口先调用 `resource::ProbePaletteCapability_45C970`。`0x45C7CC` 的
`cmp eax,1` 位于 `0x45C7CF` 写 `gPaletteCapability` 之前；新端先计算
`capability >= 1`，再把返回值写入唯一的 `render::gPaletteCapability`，不为
探测表或图形查询增加空指针保护。

能力值大于等于 1 时严格执行：

1. 写第一组 `(x,y)=(114,341)`，预清 `0x9A5960` 的文本首字节、总长
   `(+0x12C)` 和光标 `(+0x128)`，
   读取 `0xFF494F`。
2. 调用 `InitializeContext_449CF0(ctx,114,341,0,0,3,text,1,20,0,1)`，
   随后再次写 `encrypt=1`。
3. 写第二组 `(x,y)=(114,309)`，预清 `0x9A5678` 的文本首字节、总长
   `(+0x12C)` 和光标 `(+0x128)`，
   读取 `0xFF4982`。
4. 调用 `InitializeContext_449CF0(ctx,114,309,0,0,3,text,1,20,0,0)`。

能力值小于 1 时严格执行：

1. 写第一组 `(x,y)=(335,300)`，预清并读取 `0xFF494F`。
2. 调用 `InitializeContext_449CF0(ctx,335,300,0,0,3,text,1,20,0,0)`，
   调用返回后才写 `encrypt=1`。
3. 写第二组 `(x,y)=(335,260)`，预清并读取 `0xFF4982`。
4. 调用 `InitializeContext_449CF0(ctx,335,260,0,0,3,text,1,23,0,0)`。

共同尾部先读取焦点表第 1 项，再把 `gValue9A6E20` 写为 1，最后调用
`input::SetContext_44B330` 传入此前读取的指针。

## 安全边界

原函数复用一个未初始化的 256 字节栈缓冲；若 51 字节槽被损坏为全非 NUL，
后续初始化器的 `strlen` 会继续扫描未初始化栈。新端为两次读取分别使用
零初始化的 256 字节本地缓冲，因此 `[51]` 必为 NUL。正常含终止符的槽行为
不变；仅损坏或非终止槽不再复现原端越界扫描未初始化栈的未定义行为。
