# 动画同号图档调色板回退 SPEC

日期：2026-10-17。状态：用户确认包含索引0的回退范围，已实施；实际颜色效果待复测。

## 目标与已核实路径

用户要求：动画调色板找不到，但存在mapNo等于animeNo的图档时，使用该图档调色板。

- AnimationRuntime.cpp的AnimeInit_45BB20将磁盘动画号减100000后存入AnimateRecord::animeNo；匹配图档时必须加回100000，使用完整资源编号。
- AnimeLoadAction_45B760读取动作的S16 paletteIndex；旧格式动作没有该字段，赋0。Yobi/animation.cpp的ApplyYobiAnimeFrame将其交给绘制描述符。0当前使用默认调色板。
- GraphicRead.cpp的独立调色板通过静态表及CGLoadSpr.dbf将索引映射到mapNo，再读取图档像素尾部的BGR调色板；现路径没有动画号信息。
- 图档mapNo索引默认0表示未命中；实际图档序号为0时，还需核对该记录的mapNo。后加载资源覆盖同号映射。PNG和不带独立色表的RD图档返回paletteLength=0，不能仅凭图档存在就认定有调色板。
- RendererRebuild.cpp会释放并重新初始化独立调色板池；新增匹配必须覆盖这条生命周期。

## 已确认规则

1. 优先使用动作原指定的有效调色板；原索引越界、来源图档缺失或无法取得内嵌色表时，才查同号图档。
2. 用户明确选择包含paletteIndex=0：未指定或指定的调色板缺失时都尝试同号图档；原调色板可用时不替换。
3. 候选图档使用既有mapNo覆盖顺序，以完整animeNo查找；仅在成功读到内嵌BGR色表后发布回退结果。不扫描相邻图号，不使用动画第一帧代替，不从PNG推导色表。
4. 同号图档也没有可用色表时，保留原行为。不同动画即便原paletteIndex相同，也不能相互覆盖回退结果。
5. 新映射沿用既有原色／色调、透明索引0及绘制缓存流程；保留原资源索引含义与S16字段，不将完整animeNo截断后塞入paletteIndex。

## 实施边界

在已有GraphicRead模块内提供动画调色板解析入口，由仍持有animeIndex及动作原paletteIndex的ApplyYobiAnimeFrame调用；动作资源记录保留原值，避免原指定索引被回退索引永久覆盖。资源侧缓存匹配结果和色表，避免每帧读盘；原调色板索引与新增索引分开判定，避免原本越界的资源索引意外指向新增记录。

新增色表记录具有稳定地址，运行时索引从S16最大值32767向下分配，始终位于原静态／DBF有效索引区间之外；容量不足不截断、不覆盖既有记录，经m_log报告并保留原路径。原非法索引在回退也失败时归0，与既有523140绘制规则一致，避免误认成另一动画的运行时索引。

实现中核对到活动动画不一定在渲染器重建后立即换帧，单纯清理映射可能让旧索引失效或串色。因此细化生命周期：渲染器重建保留新增索引与CPU源色表，只使色调版本失效并清除原索引可用性缓存；图档关闭／重新加载时再清空整个动画调色板缓存。资源版本不变时编号和色表地址稳定，后续Refresh按当前色调更新。运行中修改DBF或图档内容须完整重载资源，不在渲染器重建路径提供资源热更新。

读取候选复用既有解码区，但不发布临时图档为当前渲染图：读盘前将gGraphicDataBuffer设为-1，随后正常绘制按需重新读入，避免旧当前图号误指向新解码数据。候选只接受非空、长度不超过768且按BGR三字节对齐的内嵌色表，缺少的尾部颜色沿既有短色表规则补齐；不修改资源字节或原解码器。

不新增第三方依赖，不改资源文件、原地址注释、动作帧索引和非动画绘制规则。缓存使用函数内static宿主、unique_ptr拥有色表，命中与未命中都按动画编号缓存，不增加逐帧读盘。
