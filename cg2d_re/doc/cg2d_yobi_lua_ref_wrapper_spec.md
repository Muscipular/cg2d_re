# Yobi Lua 薄引用封装 SPEC（YLR01）

日期：2026-10-27。状态：目标及死亡失效规则已确认；以下封装方案待确认，尚未修改源码。

## 1. 用户已确认的边界

- 移除 Yobi Lua 完整 runtime，仅保留薄的对象引用封装，参考 UIWindow 的职责划分。
- 旧 Yobi Lua 接口与脚本不必保留，不建设兼容旧接口的第二套执行路径。
- C++ Yobi 对象 markDeath 后，Lua 引用立即不可再操作；不等待物理释放。
- 本轮单线程，只作静态检查，不构建、测试、运行或计算文件摘要。

## 2. 当前源码依据

- `src/Yobi/battle_lua_skill.cpp` 的 `LuaSkillRuntime`、`RuntimeNode`、`RuntimeCastBinding` 与 `PendingBatch` 承担技能接管、节点树、阶段观察、子树等待、批量提交和完成调度；这超出了对象引用封装。
- 同文件另外创建 `gSkillEffectL`，注册 `Skill.register`、PacketReader 并加载 `lua/battleSkillEffect.lua`。现有公共脚本模块另有 UI 与战斗 Lua 状态。
- 接管入口分布在 `battle_message.cpp` 的 SKL 分派、`battle_actor.cpp` 的角色更新、`battle_base.cpp` 的动作推进、`base.cpp` 的标死与释放，以及 `battle_skill_effect.cpp` 的元数据绑定和初始化／退出。
- `src/script/LuaUIRefs.hpp`、`LuaUIProxy.cpp` 按引用临时解析原生对象，属性和生命周期属于原生 UI。LUR01 允许同 ID 重新打开后旧引用重新命中，该条不适用于本次 Yobi 对象引用。
- `base.cpp` 除 `MarkDeath` 外还有 `MarkDeathUnchecked`、整链标死及复制死亡字段；不能只在一个命名函数里拦截。实施时必须核对其余死亡字段写入和所有实际释放入口。

## 3. 建议封装方案

### 3.1 原生对象负责执行与寿命

保留原生 Yobi 链、动作队列、更新、绘制、标死和释放。移除 Lua 私有节点树、批处理事务、等待调度、阶段镜像和 SKL 接管。不将这些结构搬到另一份文件或改名后保留。

Lua 只进行引用解析、参数转换和调用已有原生操作；不复制对象属性，不拥有 YobiAction，不因 userdata GC 标死或销毁原生对象。

E02～E09 原生特效配置不属于旧 Lua runtime；其仍使用的 techId／skillId 元数据保留。仅清理 E10 专用绑定字段及已无消费者的声明，不能整块删除 BattleSkillMeta。

### 3.2 引用与失效

建议使用由原生对象持有的最小引用绑定；绑定只保存非拥有对象指针及失效状态，Lua userdata 持有该绑定的弱引用。可采用已有标准库的 shared_ptr／weak_ptr 管理绑定本身，不能用其拥有 YobiAction。

- 同一对象的所有 Lua 引用共享失效结果；不另建全局对象表、技能节点表或调度器。
- 创建或查找已死亡对象时不产生可操作引用。
- 每次属性读取、写入或方法调用均先解析绑定，并核对原生死亡标志。
- markDeath 时永久失效现有绑定；直接死亡字段写入路径也必须覆盖。死亡标志被后续复制或初始化覆盖，不能使旧绑定重新有效。
- 物理释放前断开绑定，随后释放对象；禁止先释放再解引用检查 deathFlag。
- 原生复制／赋值不得复制引用绑定到新对象；原对象释放、同战斗槽换人或内存地址复用，旧引用均不能命中新对象。
- 建议失效引用的属性读取、写入和方法调用统一抛出 Lua 错误；不静默返回成功，不对死对象执行回调。
- 引用本身可提供只读 `valid` 查询；该查询不读写已失效对象。

### 3.3 Lua 状态与入口

建议撤除 E10 独立 Lua 状态及旧脚本加载，在现有战斗 Lua 状态注册薄引用接口，不额外创建 VM，不改变现有 Lua 标准库开放范围。

本次不重建 Skill.register、PacketReader、动作计划或自定义技能编排。新接口只按所需原生对象操作暴露，禁止把任意地址、裸载荷、链指针或可写死亡标志直接交给 Lua。

首批公开属性／方法及对象获取入口仍需确定；当前只确认“薄引用”目标，不能据此自行扩展完整战斗脚本 API、创建工厂或回调体系。

## 4. 实施顺序与静态验收

1. 明确首批 Lua 接口，确认以上寿命与 VM 方案后修改源码。
2. 拆除旧 E10 接管，恢复已有原生更新、推进、SKL 分派和释放调用链，保留原生特效配置及必要技能元数据。
3. 接入最小引用绑定、对象获取与已确认操作；在标死、释放、复制和 Lua 关闭边界闭合失效规则。
4. 集中核对旧 runtime 声明／引用、死亡字段写入、回调后引用有效性、复制边界和关闭顺序；逐项记录静态证据。
5. 更新本 SPEC 与唯一进度，精确暂存提交。静态检查不替代编译、链接和运行验收。

旧 EFM01 的 E10 合同在新方案实施后由本 SPEC 覆盖；其历史迁移与编译记录仍保留，不据此声称新方案已经验收。
