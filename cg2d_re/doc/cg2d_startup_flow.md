## WinMain

原范围 `[0x465790,0x4659ED)`，新函数位于 `src/platform/ClientEntry.cpp`。
原 x86 入口为 `_WinMain@16`，新入口使用 SDK 的 `WINAPI WinMain` 与原生句柄。
没有另设演示 `main`、SDL 事件循环或现代启动调度器。

入口先保存显示参数、实例和命令行，再按以下原分支执行：

1. 区分大小写查找 `CGstart`。命中后清零 4096 字节命令行缓冲区和 64 字节文件名缓冲区，
   以文本模式读取 `.\data\argument.ini`。每轮清零行缓冲区的前 1025 字节，
   `fgets` 上限为 1024；累计长度达到 4096 时在追加前退出。打开失败仍采用空的文件命令行。
2. 创建名为 `XZYDRaEvyPQC`、初始拥有者为 TRUE 的互斥量。原入口既不检查重复实例错误，
   也不释放这个句柄，不另加“单实例成功”分支。
3. 命令行不含 `updated` 时，按原字节及 `0x10` 标志显示消息，随后返回 0。
4. 仅在 `previousInstance == NULL` 时填写窗口类，加载图标 `0x67` 和 11 个光标，
   清零两个原全局，使用黑色背景画刷并注册窗口类。注册失败返回 0。
5. 初始化尾部严格采用下表顺序；入口忽略各返回值，主循环返回后入口返回 0。

## 光标与路径的重叠存储

原循环从 `0x55CE88` 开始，步长 12，读取资源 ID 的低 16 位，终点为 `0x55CF0C`。
因此读取 **11 条**，不能以 IDA 标注的 120 字节数组误判为 10 条。

- 前十条记录占 120 字节，每条为三个 32 位值；后两值保持中性名称，不推断业务角色。
- 第十一条资源 ID 位于 `0x55CF00`，值为 `0x6E`。
- 第十一条的后八字节与 `gBinPath@0x55CF04` 的前八字节重叠，初始字节为 `Bin` 及零尾。
- `CursorPathStorage` 承载 `[0x55CE88,0x55CF84)` 共 252 字节；
  编译期断言记录步长、尾 ID 偏移 `0x78`、路径偏移 `0x7C` 和总尺寸 `0xFC`。
- `gBinPath` 改为此对象内 `char[128]` 的数组引用，保留路径写入与完整存储的别名关系。
  引用的目标 ABI 不等于原数据符号 ABI；不承诺原地址 Hook 或二进制直接替换。

光标加载通过完整对象的字节视图加 `memcpy` 取 16 位 ID，不在十元素子数组上越界取第十一项。
目标固定 Windows/MSVC/x64，小端字节解释与原 x86 对应，路径消费者继续使用同一个 128 字节槽。

## 共享状态与小函数

`Startup.hpp` 的注释记录各原地址，`StartupState.cpp` 保存已核实的静态初值。
实例、窗口、互斥量、光标和命令行指针采用原生宽度；模式、计数、版本和坐标不随指针扩大。
`gRequestedRenderMode@0x628FE0` 按实际字节写入保留为 `uint8_t`。
窗口类名保留原八字节及 NUL，不推测其编码或转为另一套字符串。

| 原范围 | 行为 |
| --- | --- |
| `[0x4659F0,0x465A12)` | 用 `Ver %d.%d.%d` 解析 `Ver 1.02.02`，保存三个版本值并返回 `sscanf` 结果 |
| `[0x465A20,0x465A2E)` | 读取 `COLOR_BACKGROUND`，写入原桌面颜色全局并返回该值 |
| `[0x532E70,0x532EC3)` | `_chdir("data")`，依次格式化并创建 `0` 至 `9`，再 `_chdir("..")`，最终返回 1；不检查 API 结果 |

`ParseCommandOptions` 的返回值声明为 `int`：`0x4669D8` 调用 `0x507C80` 后保留 EAX 退栈。
后者的退出路径为 `strstr` 未命中所得 0，或解析索引不小于 800 时保留的 `sscanf` 结果。
Hex-Rays 的 `char*` 推断不能作为新端指针返回契约。

## 适配与未完成

- `WNDCLASSA`、`HWND`、`HINSTANCE`、`WPARAM` 等使用 Windows x64 SDK ABI。
  SDK 类型仅在平台实现及私有头出现，不人为把新窗口类打包为原 x86 的 40 字节。
- 原 CRT 对 `FILE` 内部 EOF 位的读取以本机 `feof` 表达，字符串内联操作用对应 CRT 调用。
  原读错误未设置 EOF 时继续循环的行为未擅自修复。
- 入口核对范围要求输入及源、目标缓冲区有效，字符串在原容量内终止且 CRT 写入不重叠。
  溢出、失效指针、旧栈布局及 x86 地址回绕不在本项已覆盖范围内，也没有获批排除。
- `CreateSaveDirectories` 会改变 CWD、创建目录；窗口化 helper 会改变系统桌面颜色。
  本次只编译和静态核对，不执行这些副作用，完整恢复和退出依赖仍待接通。
- `gValueD67AE4@0xD67AE4` 是映像零值 W32；`World::CursorUpdate` 以零选择
  表驱动光标分支、非零选择原生光标分支。其余生产者仍按各自函数逐项还原。
- `gValueD68DC4@0xD68DC4` 是逐帧光标状态请求；`World::CursorUpdate` 尾部
  重新读取后清零，并把旧值写入 `gValue9A6F44@0x9A6F44`。两者仍由
  `StartupState.cpp` 唯一持有，入口写零行为不变。
- 函数体和静态库编译不证明参数、存档、窗口回调、资源初始化、主循环或退出已经贯通。
- `InitializeWindow` 与 `MainLoop` 新声明显式保留机器返回值，分别为尾部
  `UpdateWindow` 结果与两个正常出口的 0。原源码返回类型未知，原入口仍忽略这两个结果。

## 加载画面淡入与淡出 SPEC

2026-09-27，在原 `ida-17524` 会话只读核完整
`458390–4585ED`、`4585F0–4587C6` 两个半开函数区间。
同时核 `44B610–44B624` 与共享槽引用，不重开或保存数据库。
按用户工程委托采用下述实现，保留初始化父函数的原调用位置。

### 状态与阶段

- `73ECE8` 是两函数共用的 W32 图号，全部九个直接引用都在二者内；
  归现有 `ClientInitialization.cpp` 私有存储，初值继承 PE 零填充，
  不把 IDA 未 loaded 时的 FFFFFFFF 当初值。
- `628FDC` 就是已有 `render::gPaletteFrameVersion`，
  不是新建的帧计数；`58B7E4` 复用 `platform::gFrameCount`。
  `9A7F64/628FEC` 复用既有 palette capability/changing，
  截止、阈值、增量、追赶计数、调色板重载槽也不另建副本。
- 淡入先调用 `45C970` 并发布 capability，再写默认图号 22025、
  局部调色板 0。结果 3/4 改图号 98979、调色板 26；
  结果 1/2 改图号 22211、调色板 29，其他结果保持默认。
  随后独立读取 32 位 tick，零扩展为 double 写共享截止。
  淡出不重新探测或选图，仅单独读取 tick 重置截止。
- 两段都先泵消息；返回 0 时调用一次真实 `ShutdownClient`，
  然后返回 0。外层初始化不重复清理。
- 淡入首帧先 `SelectPalette(selected,30)`，再入队
  `(320,240,255,共享图号,0,nullptr)`；淡出首帧先入队，
  再 `SelectPalette(19,30)`。后续帧先入队，再读 changing，
  恰为零标记结束；**本次帧处理仍须完成**，不能立即返回。

### 公共帧合同

原 `458489–458598` 与 `458695–4587A0` 除指令地址与导入调用形式外，
数据和控制流相同。私有 helper 仅合并该完整公共段，不泛化 MainLoop：

1. SortTextures→UpdatePalette→ClearKeyFlags，随后先计算
   `threshold + deadline`，再取 tick。只有有序严格大于阈值，
   且追赶计数按 S32 小于 20，才跳过本次绘制。
   先计算新截止，再写追赶计数+1，最后发布截止。
   不把 `!(tick>deadline)` 改成 `tick<=deadline`，保留 unordered 分支。
2. 实际绘制前调用 `44B610`；返回零才递增已有调色板版本 W32。
   然后 ClearSurface→DrawAllQueued。重载槽恰为 1 时，
   将当前 256 色交既有 palette binding，忽略返回，再清重载槽。
   随后 Flip，不因绘制/提交失败自行添加退出或重建。
3. Flip 后取 tick，直到有序严格大于共享截止；未满足则 Sleep(1)
   后再取 tick。等待内不重新泵消息、重载调色板或重读结束标志。
   最后先计算下一截止、读取旧帧数，再写追赶计数=1、帧数+1、截止。
4. 跳帧和绘制两路均返回原外层结束判断，不以 helper 的提前返回
   跳过淡入/淡出的完成判断。未额外清图形队列计数、ResetGraphicCache、
   改队列模式或加入普通 MainLoop 的窗口激活/防护门禁。

淡入结束额外执行 DrawGraphic→ClearSurface→DrawAllQueued→Flip，
随后返回 1；这段没有 Sort、调色板更新、按键清理、等待或帧数递增。
淡出结束直接返回 1，没有这次额外提交。即使最后一轮走跳帧，
两者仍按各自尾部执行。

`gRenderer!=nullptr` 或当前请求模式代替。RendererResources 的 owner

## 标准流 CRT 接入

本步仅处理553020/553024的453E00/453E40，沿用户工程委托采用本机标准流，
不模拟旧STL对象布局，不用空构造或固定成功替代。音频553028、网络排除接线、
424620及三项补零待决不在本步授权范围。

### 原端证据

- 453E00先453E10→5482DD，再453E20登记453E30退出；
  453E40先453E50→549397，再453E60登记453E70退出。
  两项分别持有628FE9/628FE8；对象本身只有构造/退出直接引用。
- 592894/5929EC映像初值均-1。首次进入设1并初始化相应流，之后仅递增；
  退出54843C/5494FE先递减，只在到0时同步三个输出缓冲。
  另有553134→5491D6、553138→549200两个运行期控制器，
  分别通过5491E0/54920A使用同一计数器，不把它们当成第二套业务流。
- 窄输入1086430使用stdin，输出10863A0使用stdout，
  错误10864C8与日志1086310使用stderr；宽流分别为1086578、
  1086668、1086500、1086540。数据来源是两构造函数实际缓冲实参，
  不仅依据反编译函数名。
- 窄流54839B/5483ED/548424分别把输入、错误、日志的tie指向输出；
  5483FB给错误流flags并入2。宽流549477/5494AD/5494E7和5494BB对应相同配置。
- 窄退出按10863A0→10864C8→1086310，宽退出按
  1086668→1086500→1086540调用5495EE。
  该叶先检查状态bits6，清位才调用缓冲虚表+2Ch；
  返回-1才向状态并入badbit并交clear处理。没有sentry或tie刷新调用。

### x64 局部方案

本机MSVC 14.50.35717的`iostream.cpp`中ios_base::Init只处理窄流计数，
退出顺序为cerr/clog/cout；`wiostrea.cpp`的_Winit处理宽流，
但公开iostream头仅在_CRTBLD条件下声明_Winit。因此不强行声明私有类、
定义_CRTBLD或用两个ios_base::Init冒充旧窄/宽控制器。

采用两个应用侧静态生命周期对象，位于既有WorldObjects之后、
LegacyUi455490之前，分别对应553020/553024；退出由同一翻译单元反序执行。
构造使用公开std::cin/cout/cerr/clog及宽流，设置三处tie与错误流unitbuf。
本机各流源文件通过`init_seg(compiler)`建立真实流和FILE缓冲；
显式引用这些对象，不仅包含头文件，不额外创建文件或替换rdbuf。
原运行期附加控制器和私有计数器由本机CRT管理，不建立影子计数表。

两析构分别按原三流顺序执行同一类型化同步助手：
fail()/bad状态清时调用rdbuf()->pubsync()，返回-1才setstate(badbit)；
不调用ostream::flush()，不额外刷新tie，不更改异常掩码、locale、
sync_with_stdio或输入流状态，不吞异常或增加空缓冲保护。
缓冲由现有标准库拥有，helper只同步借用，不释放或替换任何流。

原窄/宽初始化在实际缓冲内部的布局、共享缓冲实现、构造失败时刻和
CRT异常/退出机制不据本步判等；正常tie、错误流unitbuf和显式同步顺序
在应用侧保留。未验证完整标准流文件往返或完整进程退出，不降低总验收标准。
本线源码此前未直接引用上述八流，本步不把缺少直接引用当作全局不可达证明，
仍落实实际初始化/退出职责。实现放现有LegacyMouse启动承载，不新增依赖或源目标。

实施结果：两个静态对象及同一同步助手已落位。静态核对六处tie、两处unitbuf、
六次显式同步次序和失败置badbit路径；剔除本段与iostream包含后，
LegacyMouse原源码逐字不变，其他初始化器未重排。
本机八个标准流源文件的compiler初始化段、stdin/stdout/stderr来源，
以及fail()/pubsync()公开边界已核对；未改工具链头文件或运行库。
未编译、测试、执行新增函数、运行客户端或检查产物，
不将应用侧接线计作全部CRT或退出验收完成；不对齐总SPEC、不压缩日志。
