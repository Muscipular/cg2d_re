# 2026-11-05 加壳后loading结束崩溃分析

## 输入与验证边界

- 用户提供转储`cg2d_crash_20261105_120228_933_28552_16608_1.dmp`，以及`build/windows-msvc-x64-release/cg2d_re.exe`与同目录`cg2d_re.map`作为未加壳对照。
- 转储主模块与MAP时间戳同为`6AEBF9C4`，基址同为`0x140000000`；保护后映像大小`0x282A000`，原EXE为`0xDF4000`。原生代码用实际字节及相同地址交叉核对，不将新增保护区地址直接套入原MAP。
- 本轮只读转储、原EXE/MAP及局部源码，使用二进制读取和MSVC dumpbin局部反汇编。未切换或新建IDA数据库，未计算摘要，未编译、测试、运行客户端或重新加壳；保护区调用栈未获得可靠完整展开。

## 已证现场

1. 异常线程`16608`，异常码`0xC0000005`，RIP=`0x14050334A`。该处实际指令为`vmovdqu [rcx+r9-60h],ymm1`，属于MAP中的`memcpy/memmove`实体；不是loading图像提交入口。
2. RCX=`0x0044003200470043`，R9=`0x60`，R8=`0x44`，RDX=`0x108AFF80`。RCX的字节是UTF-16的`CG2D`，不是合法目标指针。虽然异常记录参数0为0，故障指令实际是向该非规范地址写入，不据记录参数将其误写成源图像读取失败。
3. 栈顶返回地址`0x140034AD2`对应`std::wstring::_Assign`的memmove调用后指令；其入口`0x140034A90`从目标对象`+0x18`读取容量，大于7时从`+0x00`取堆指针，并在`+0x10`写入新长度。模板实体在MAP中归属Font.cpp的合并符号，不代表故障来自字体业务。
4. RDI即赋值目标对象地址`0x140E31720`，位于新增保护区域。其前16字节为`CG2D RE`及终止符，`+0x10`为新长度`0x22`，`+0x18`为`0xE900000000000000`；该“容量”使赋值错误地走堆模式，将内联字符当作目标指针。对象末尾的`E9`后还有代码形态字节，不能将该块当成完整的真实std::wstring。
5. 原MAP的`gTitle`为`0x14064C618`；原EXE和转储该原位置均仍保存完整SSO对象：文本`CG2D RE`、长度7、容量7。原`RefreshSessionWindow`在`0x14009A3FE`取得该对象地址，并在`0x14009A405`调用上述`_Assign`。实际赋值目标却不是该合法对象地址。
6. 用户同时报告Themida的`Encrypted Strings Not Removed from Original Location`警告，其中包含`CG2D RE`。当前源码在VM区域内比较、赋值`gTitle`，且该静态对象以同一字面量初始化，编译后的内联字符缓冲区与对象起址相同。

## 判断与修正

- 直接崩溃原因已证为标题缓存赋值目标不具备合法的std::wstring布局；“loading后”是首次刷新标题的时间点，不据此修改渲染器、纹理、AVX或网络/参数交接代码。
- 结合原对象未变、目标改到保护区文本及字符串警告，强证据支持自动字符串处理将静态SSO对象地址当作字符串地址重定向。壳内部具体处理步骤仍属推断，尚未进行字符串保护开关或同版重新加壳对照，不宣称已完成机制及运行验收。
- 将`gTitle`改为空构造，避免在静态映像的对象起址放置`CG2D RE`文本；原VM范围、局部标题生成、比较、赋值和SetWindowText次序不变。首帧会照常发布标题，不改标题内容、Tab或游戏状态。不扩大为批量删除静态字符串、关闭所有保护或调整加壳配置。
- Oreans官方FAQ说明，未移除警告可能因为字符串仍被保护区外代码引用；它本身不等于运行崩溃。`STR_ENCRYPT_FORCE_DESTROY`会强制清除原位置，不作为本轮消警告或修复方案。其他列出的字符串没有本次崩溃证据，不一并改写。
- 源码针对性修正不代替重新编译及按相同配置加壳复验。待验证项为首次标题刷新、后续标题变化、未加壳路径以及其余现有字符串消费者。
