## 浏览区启动与退出构造

### 方案与边界

2026-10-01沿实际CRT槽5530A4确认4CD240入口。此处构造不是4CED60接包行为：
此前“不增加CryptInt构造”只限该步数据布局/回复路径，不表示原启动阶段没有构造。
本轮复用已有gStallBrowseD046D8及其pets，不建立第二套浏览宠物存储。
在WindowRuntime.cpp增加成对ConstructStallBrowsePetValues/DestroyStallBrowsePetValues，
由LegacyMouse.cpp现有中央静态初始化链调用；放于55309C/5530A0选择器之后、
5530C8地图及5530F8鼠标之前，退出顺序相反。其他未落位CRT项仍待。

按用户既有工程委托采用原生C++静态对象表达“构造成功后登记退出析构”，
不复制x86 FS/SEH或CRT栈布局；原入口并不消费内部构造返回的D046D8地址，
新成对接口不伪造地址返回。初始化发生一次且不懒置于回复/查询入口，
不修改4CED60现有整区清零、临时CryptInt复制或宠物数量，也不改主玩家宠物构造。

失败路径沿原证据：成员构造失败先逆序销毁本宠物已完成成员，
再逆序销毁此前完整宠物。新端用完成计数记录同一30成员前缀，
catch时只逆序析构已完成项并重新抛出，不析构失败项、不回退RNG，
不清整个浏览区或吞掉异常。销毁叶只写原vft token，没有可抛调用；
该适配不宣称x86硬件SEH现场等价。

### 原端证据

- CRT5530A4=4CD240，先call4CD250，随后尾跳4CD260登记退出入口4CD270。
  4CD250只取D046D8到ECX并跳4CD2A0；后者以`this+F83C`即D13F14、
  步长5110、数量5交给53C45E，构造/析构回调分别4CD360/4CD2D0。
  原构造完成后返回对象T*，但4CD240未消费该返回。
- 4CD360按+0C/+1C/+2C/+3C/+4C/+5C调用401C70，除此之外不清宠物字段。
  六成员对应现有values0C[0..5]；构造写vft token、取一次NextRandom产生mask、
  清readCount并写零值，不改三个保留字节。
