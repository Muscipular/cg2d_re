## 2. 整表存储与启动绑定

### 2.1 表槽、容量与分配

| 对象 | 已证事实 | 地址证据 |
|---|---|---|
| `0x103CFA4` | 原 W32 堆表指针槽；76 个直接交叉引用中仅 1 写、其余 75 读 | 唯一直接写为 `0x457565: mov [0x103CFA4], eax` |
| 槽中值 | `eax` 来自 `malloc`，不是图号、句柄或内嵌表 | `0x45755A` 分配，`0x457565` 写槽 |
| 初始空值 | 仅继承映像初值证据；不据此声称有运行时清槽路径 | 本交接未给出运行时清槽证据 |
| `0x103CFA0` | 容量唯一直接写为十进制 `2200000` | `0x457528: mov [0x103CFA0], 2200000` |
| DX cache 整表 | 每项 `0x10` 字节，分配 `35200000` 字节 | `0x45754B` 读容量，`0x457556: shl ecx, 4`，`0x457559: push`，`0x45755A: malloc` |
| 相邻 GraphicInfo 表 | 通过 `shl edx, 5` 另行分配，与 DX cache 不是同一张表 | 继承本次交接的分配链结论 |

不能把 `0x103CFA4` 解释为每图 surface，也不能拿 GraphicInfo 表或另造的尺寸表替代它。

### 2.2 成功清零与分配失败

四个相关分配全部非空后，才执行 DX cache 整表清零：

| 顺序 | 指令证据 | 含义 |
|---|---|---|
| 1 | `0x457600: mov ecx, [0x103CFA0]` | 读取项数 |
| 2 | `0x457606: mov edi, [0x103CFA4]` | 读取表基址 |
| 3 | `0x45760C: shl ecx, 4` | 换算表字节数 |
| 4 | `0x457611: xor eax, eax` | 清零填充值 |
| 5 | `0x457613: shr ecx, 2`；`0x457616: rep stosd` | 按双字清零 |
| 6 | `0x45761A: and ecx, 3`；`0x45761D: rep stosb` | 保留原清零尾序列，不另行改写解释 |

分配失败路径在 `0x4575C6` 释放已分配的 DX 表，但不清 `0x103CFA4` 槽。该路径与启动映像初值不同，不能写成“失败后自动恢复空表”。

### 2.3 启动顺序

本交接确认的顺序为：

1. `0x457747` 调用 `BuildSurfaceCache`。
2. `0x457770` 初始化调色板池。
3. `0x457775` 调用 `InitPalette`。
4. `0x457782` 调用 `GraphicAlloc`。
5. `0x4577AA` 重置表引用。
6. `0x4577B9` 调用 `GraphicInit`。

`GraphicAlloc` 仅有上述直接调用；未发现运行期另换整张 DX 表的直接路径。该结论不扩展为对未知间接路径的推断。

## 3. 单项真实生产与条目布局

### 3.1 `0x522570` 的输入与资源来源

- `0x522579/0x52257B` 检查图号非负，`0x52257D/0x522583` 检查小于容量。
- `0x52258C: shl esi, 4` 以同一全局图号定位 DX 条目；条目 `+0x00` 非空时直接返回 `1`。
- 仅空链头才在 `0x5225A9` 调用 `0x45A900`；输入仍为该全局图号，不是资源文件 slot 或 `MapNo`。
- 读取使用四个输出槽 `0x1020EC0/0x1020ED4/0x1020ED0/0x1020ED8`。
- 尺寸来源继承已通过的资源证据：`0x45A900 -> 0x52D5C0` 从资源头 `+0x04/+0x08` 读取 W32 宽高，不是 GraphicInfo 的 `+0x10/+0x12`。
- 资源依据只引用 [图形解码证据](cg2d_graphic_decode.md) 第 44 行起，本任务不重新分析解码流程。

### 3.2 写入顺序与失败保留

| 顺序 | 地址与操作 | 约束 |
|---|---|---|
| 1 | `0x5225E3: mov dx, word [0x1020ED4]` | 取资源宽度低 16 位 |
| 2 | `0x5225EA` 写当前图号 | 位于宽度写入之前 |
| 3 | `0x5225F1: mov [esi+ecx+4], dx` | 写当前条目 `+0x04` |
| 4 | `0x5225F6` 重读表基址 | 保留该读取顺序 |
| 5 | `0x5225FB: mov cx, word [0x1020ED0]` | 取资源高度低 16 位 |
| 6 | `0x522603: mov [esi+eax+6], cx` | 写当前条目 `+0x06` |
| 7 | `0x522608` 调用 `0x5222D0(imageNo, 0)` | 尺寸已写入，随后建立纹理节点链 |

读资源失败时，当前图号置 `-1`，上述四个输出槽清零并返回 `0`；不清旧条目的宽高。不能把失败输出清零扩展成条目尺寸清零。

### 3.3 原端 `0x10` 字节条目

| 偏移 | 原端存储与语义 | 证据与限制 |
|---|---|---|
| `+0x00` | W32 纹理节点链头原生指针 | `0x522451: mov [ebx+eax], ecx`；不是 direct surface |
| `+0x04` | W16 宽度 | `0x5225F1` 写资源宽度低 16 位，消费按 S16 解释 |
| `+0x06` | W16 高度 | `0x522603` 写资源高度低 16 位，消费按 S16 解释 |
| `+0x08` | W32 调色板转换缓存项引用 | `0x520D54: mov [esi+8], eax`；不是每图独占分配 |
| `+0x0C/+0x0D/+0x0F` | 字段与用途未知 | 仅证整表清零；不得命名为 padding |
| `+0x0E` | W8 标志 | `0x520D87/0x520D97` 按当前 palette 长度是否大于 `0` 置 `0/1`；不扩展其业务含义 |

`0x507090/0x507140` 使用同表、同一 `imageNo << 4` 的消费结论直接继承 [既有消费者证据](cg2d_sub_507140.md)。本任务不复查旧算法，也不据此批准 x64 结构。

## 4. 纹理节点池与链生命周期

### 4.1 池范围、块尺寸与对齐

- 节点池为 `[0x1020F08, 0x103CF08)`，原端 stride 为 `0x1C`。
- `0x52325A` 取池起址；`0x5232C5: add esi, 1Ch` 推进；`0x5232C9: cmp esi, 103CF08h` 检查边界；`0x5232D1` 写实际计数。
- 完整成功时有 `4096` 项；实际计数不能无条件替换成固定成功容量。
- `0x44B77C/0x44B788` 将块宽高分别写为 `0x40/0x30`，即 `64/48`。
- `0x5222D0` 先按 signed 除法及余数计算宽度除以 `64`、高度除以 `48` 的块数。
- 随后 `0x52238F..0x522398` 执行 `neg edx; and edx, 3; add eax, edx; mov [0x1020ED4], eax`，对齐当前宽度。
- DX 条目宽高已先在 `0x5225F1/0x522603` 写入；不能以对齐后的当前宽度替代条目宽度。
- `0x5222D0` 唯一直接调用的第二参数 `p=0`；非空 `p` 的类型未知，不声明为已知结构。

### 4.2 旧链解绑与新链串接

| 阶段 | 地址证据 | 已证行为 |
|---|---|---|
| 旧节点解绑 | `0x5223BC/0x522425` | 将 `node+0x04` 图号写为 `-1`，沿 `node+0x10` 继续 |
| 清旧入口 | `0x5223CC/0x52241B` | 清条目链头 |
| 绑定新链头 | `0x522451` | 将新节点指针写入当前条目 `+0x00` |
| 串接节点 | `0x522466: mov [edx+10h], ecx` | 写节点 next 引用 |
| 正常末端 | `0x52251E` | 将末节点 next 写为 `0` |

节点来自共享池，不按每个图号单独分配或释放。图号解绑、条目入口清零和节点 surface 释放是不同操作。

### 4.3 复用资格、消费状态与不足路径

- `0x5223F2: add edi, FFFFFFFEh` 形成当前 state 减 `2` 的比较值。
- `0x5223F8` 比较 `node.state`，`0x5223FE: jnb` 按 U32 排除 `state >= 当前 state - 2` 的节点。
- `0x5224EF/0x5224FB` 使扫描索引按池实际计数回到 `0`，不得删去原有取模式循环行为。
- 消费端 `0x520FE3/0x5211FF/0x521536` 将当前 `0x58B7E4` 写入 `node+0x08`。
- `0x522505` 扫回起点时，经 `0x52254A/0x522557` 日志路径返回，没有经过 `0x52251E` 的末节点 `next=0`。
- 外层 `0x522612: mov eax, 1` 仍报告成功，因此返回成功不等于纹理链完整生成。
- 容量不足与部分建链属于上层缓存生命周期，不能按 DX driver 故障豁免，也不能擅改为事务式全成或全退。

## 5. 调色板转换池与引用失效

### 5.1 动态池和静态共享项

| 对象 | 地址证据 | 已证事实 |
|---|---|---|
| 动态调色板池分配 | `0x44E0C0: push 1A680h`；`0x44E0C5: push 40h`；`0x44E0C7: GlobalAlloc` | 分配原端动态池 |
| 锁定与绑定 | `0x44E0CE: GlobalLock`；`0x44E0D4` 写 `0x62B068` | 记录池引用 |
| 动态池项 | stride `0x410`，共 `104` 项 | 每项首 W32 为图号，初始为 `-1` |
| 静态共享项 | `0x44E290` 也可返回 `0x627368 + index * 0x410` | 共四项，不属于每图独占 heap |

DX 条目 `+0x08` 可以指向上述不同来源；不能对每个图号的该引用分别执行 heap 销毁。

### 5.2 绑定、复用、老化与绘制

1. `0x520CEB` 将旧调色板项图号写为 `-1`，`0x520CF1` 清条目 `+0x08`。
2. `0x520D4C` 取得缓存项，`0x520D54` 将其绑定到当前条目 `+0x08`。
3. `0x520D5E: add eax, 10h` 取得缓存项载荷供上传；引用指向缓存项本体，不是载荷起点。
4. 池复用在 `0x44E1C7/0x44E204` 清旧图条目的 `+0x08`。
5. 老化在 `0x44E24F` 清引用、`0x44E25D` 将池项图号写为 `-1`。
6. 绘制在 `0x5213CD/0x5216DD` 清调色板 `cache+0x0C`，并在 `0x521428` 调用老化。

这里的调色板 `cache+0x0C` 不是 DX 条目 `+0x0C`；后者仍属未知字段，不能据同偏移推定用途。

### 5.3 `44E230` 帧末动态池老化

2026-09-25，当前 IDA `sub_44E230@[44E230,44E286)`
仅由 `DrawAllQueued@521428` 直接调用，无参数、无 callee、
无返回值合同。`44E230–44E283` 从全局
`gGraphicDataCacheList@62B068` 读取动态池指针，
依次遍历 `104` 项、步长 `0x410`、末偏移 `0x1A680`：

1. 每项先读取 `+0` S32 图号；负值直接前进，不读取、
   递增或清该项的 `+0x0C` 脏计数。
2. 图号非负时，按 S32 比较 `+0x0C` 计数与 `1`。
   小于 1 则不清引用；大于等于 1 时先重新读取
   `gGraphicInfoDxCache@103CFA4` 指针，按图号乘
   `16` 清 DX 条目 `+8` 的 W32 调色板引用，
   再重新读取动态池指针，将当前项 `+0` 图号
   写 `-1`。不释放该池项或 DX 整表，不检查图号
   是否在 DX 表容量内。
3. 图号非负的上述两路随后均从当前池项 `+0x0C` 重新读取
   完整 W32、加一并写回；**即使刚把图号设为
   `-1`，本轮仍递增**。每项尾部重新读取动态池
   指针，继续下一槽；负图号分支则沿已有指针
   直接前进，不执行重读。数值 overflow 域按总计划
   不专项处理，不据此增设钳制。

此入口只有局部老化合同；动态 104 项池和 2200000 项
DX 表的新端唯一 owner、x64 指针字段及生命周期仍依
[待批 x64 SPEC](cg2d_graphic_dx_cache_x64_spec.md)。
不能把 `44E230` 实现为删除纹理资源、清整张 DX 表
或只递增未回收项；当前未实施源码与父队列接线。

### 5.4 动态/静态池、退出与帧末老化现行落位

2026-09-27，本线程在当前已打开的 IDA 会话只读核
`44E0C0–44E10F`、`44E110–44E141` 和
`44E230–44E285` 全部指令及各自唯一直接 caller：
`457770`、`457A4A`、`521428`。新端在同一
render owner 保存连续 104 项动态池与独立四项
静态池，项长 `0x410`，首四个 W32 分别承接
图号、活动调色板索引、帧快照和脏计数，
`+0x10` 起保留 `0x400` 个原字节。
动态池零初始化后逐项只把首 W32 写 `-1`；
静态四项逐项只把 `+4` 写 `-1`，其余字节
保留，不能合并两种重置。
`627368/62736C/627F98/6283A7` 位于
IDA `is_loaded=false`、文件映射偏移 `-1`
的虚拟数据区；此处 `get_byte=FF` 是
未装载的工具读值，不是四项的原始 `FF`
初始化，不能据此覆盖零初值。

退出 `44E110` 对动态池释放后清
`gGraphicDataCacheList@62B068`，不清静态池，
也不清 DX 表中尚可能存在的悬空引用；
原 caller 弃 `GlobalFree` 返回，新端采用
`void` 适配。`44E230` 对每项先读有符号
图号，负数不碰计数；非负且有符号脏计数
`>=1` 时先清对应 DX 项调色板引用，再把
当前项图号写 `-1`；无论是否刚回收都重读
并递增计数。DX 项仍复用已落位的 x64 表
owner，不新增第二张表。

原 `GlobalAlloc/GlobalLock` 失败后没有
正常分支，会继续解引用；新端分配异常
也不伪造成功返回。重复初始化时原端的
覆盖/泄漏风险与现代 owner 的自动释放
不计逐次故障等价。`InitializeClient_4576B0`
和 `DrawAllQueued_520DD0` 尚未调用创建与老化
入口；退出调用已接真实释放叶，但完整链接
与实际画面仍受其余依赖阻断。

### 5.5 `44E150` 从动态池领取/复用单项

2026-09-27，本线程只读当前 IDA 的完整
`[44E150,44E22F)`，唯一直接 caller 为
`44E290@44E38B`。入口读动态池指针，
首轮从 0 到 103 按 `0x410` 步长找
首个有符号图号 `<0` 的项；找到后先写
新图号，再重读池指针清 `+0x0C`
脏计数并返回项指针（`44E182–44E1AB`）。

若全满，第二轮只查首个有符号脏计数
`>0` 的项；找到后 `44E1B8–44E1C7`
以旧图号清 DX 条目 `+8` 调色板引用，
`44E1D1–44E1EB` 先将旧图号写 `-1`、
再写新图号、清计数并返回（`44E1F5`）。
若第二轮仍无项，`44E1F9–44E228`
无条件复用第 0 项，按相同清旧引用、
先写 `-1`、再发布新图号和清计数的
顺序返回。正常已发布池域三路均返回
项指针，没有“耗尽返回空”的路径。

新端 `TakeIndexCacheFromPool_44E150`
复用 §5.4 的唯一 104 项池和 DX 表
owner；不额外清 `+4/+8` 或 `+0x10`
载荷，也不增加图号越界或池空门禁。
在 §5.5 完成时，`44E290` 的颜色构建与
模式分流尚未落位；该叶本身不等于图像
上传、完整队列或画面完成。后续状态见
§5.6。

### 5.6 `44E290` 的 32 位调色板缓存项

2026-09-27，当前已打开的 `ida-17524/cg2d.exe`
中只读核 `[44E290,44ED6C)` 的相关分流和
唯一直接 caller `Graphic::LoadTexture@520D4C`。
两个源指针均为空时强制模式 0
（`44E2B1–44E2BF`）；模式 0 按色调中性与否
选静态槽 0/2，并用备份调色板 `629F2C`；
模式 1 选槽 1/3，并用当前调色板 `629B20`
（`44E2DD–44E32D`）。槽 0 的 `+4==0`
即直接返回，其他静态槽需 `+4` 活动索引和
`+8` 帧版本同时匹配才直接返回
（`44E33D–44E381`）。未命中时先发布槽的
索引与版本，再写颜色；动态模式 `>=2`
先经 `44E38B` 领取池项，清 `+4/+8`，
仅启用色调时重写这两槽
（`44E386–44E3C8`）。

32 位静态项依次写头 16 色
（`44E3F6–44E426`）、中间 224 色
（`44E7B9–44E829` 或无色调分支
`44EB19–44EBAB`）及尾 16 色
（`44EC22–44EC78`）；只有中间段按开关
应用红/绿/蓝三张通道映射。动态项若
`palData` 非空，取连续 BGR 三字节源；
否则取第五参指向的 BGRX 四字节源，
两者分别遍历全部 256 色，色调开关
控制是否查通道表（`44E509–44E578`、
`44E66A–44E6D3`、`44E92F–44E983`、
`44EA34–44EA7A`）。非零索引的纯黑
先存 `1`，最终清索引 0 的完整 W32
（`44ED2C–44ED49`）。第五参按字节及
四字节步长读取，不能误声明为

## 6. 重建只使引用失效，不更换整表

### 6.1 重建链与保留内容

`0x466B80` 内部按如下顺序执行：

1. `0x466B8C` 调用 `Destroy`。
2. `0x466B91` 调用 `Init`。
3. `0x466C11` 调用 `BuildSurfaceCache`。

`BuildSurfaceCache` 在 `0x5232D7` 重置 nodes，再于 `0x5232DC` 调用 `0x523350`：

- `edx=0`，以 `0x10` 为 DX 条目 stride。
- `0x523367: mov [eax+esi], edx` 清条目 `+0x00` 纹理节点链头。
- `0x523370: mov [eax+esi+8], edx` 清条目 `+0x08` 调色板缓存引用。
- 仅清这两处引用，保留宽高和其他字节，不重新分配或更换整张表。

整表初次清零、节点池重置和重建时的两引用清零必须分别记录，不能合并为一个全表清空动作。

### 6.2 触发时机边界

- MainLoop 在模式不同的 `0x457067`、lost 路径的 `0x4570A7` 触发重建。
- WndProc 在 `0x4670D2/0x467158/0x467194/0x4673EB` 消费 dirty 后调用重建。
- WndProc 在 `0x46720E` 切换模式后调用重建。
- 本文仅定位生命周期时机，不展开消息或主循环调度，不修改其源码、状态或文档。
- 按 `RPLAN.15`，仅底层 DX7 调用允许作等价 SDL/CPU 适配；该豁免不扩大为一般故障豁免，上层状态、顺序、字段和生命周期仍须对应，包括引用失效、节点复用、部分建链及缓存生命周期。

## 13. G1a 新增关键指令与外流证据

### 13.1 疑似 base 压栈在调用前已变为坐标

- `0x418C9B/0x418CCB/0x419568/0x419595: push ecx` 表面上疑似将 base 外传。
- 对应 `0x418CC7/0x418CEB/0x419591/0x4195B5` 的机器码均为 `D9 1C 24`，即 `fstp dword [esp]`，覆写刚压入的栈槽。
- 到 `0x418CF0/0x4195BA` 调用时，param3/5 已是坐标而非 B；不能只看 `push ecx` 就判定 DX 地址 escape。

### 13.2 head 外流为 node，DX entry 另行局部定位

| 取 head 并判空 | 参数压栈 | 调用 |
|---|---|---|
| `0x520FC4: mov esi, [eax+ecx]`，后接 `test esi, esi` | `0x521030: push esi`；`0x521031: push edi` | `0x521032: call 0x520B10` |
| `0x5211EB: mov esi, [edx+ecx]`，后接 `test esi, esi` | `0x52124C: push esi`；`0x52124D: push edi` | `0x52124E: call 0x520B10` |
| `0x521522: mov esi, [ecx+ebp]`，后接 `test esi, esi` | `0x521571: push esi`；`0x521572: push edi` | `0x521573: call 0x520B10` |

- 三组调用形成 `(graphic, N)`；`0x520B50: mov edi, [esp+18h+texture]` 取得 param2。
- node 消费证据：`0x520B54: mov dx, [edi+14h]`；`0x520C1E: movsx ecx, word [edi+0Ch]`；`0x520C42: movsx ecx, word [edi+0Eh]`；`0x520D7E: mov edx, [edi]` 取 surface。
- DX entry 则由 `0x520B2C: mov edi, gGraphicInfoDxCache`、`0x520B32: shl esi, 4`、`0x520B35: add esi, edi` 独立局部定位，不从 N 的地址反算 DX。

### 13.3 node 后继与 surface 指针继续外流

- `0x5211D7/0x5213B0/0x5216C0: mov esi, [esi+10h]` 跟随 node.next。
- `0x52119F/0x521372/0x521688` 从 `[esi]` 取 surface，分别传给 `0x5211BE -> 0x44DA90` 的 param6、`0x521393 -> 0x44D520` 的 param4、`0x52169F -> 0x44DA90` 的 param6。
- 外传的是 node 中另一个对象的指针，不是 N、E 或 DX 原始整项；本任务不继续扩展这些 renderer 业务。

### 13.4 palette 状态比较与 DX flag 的对象边界

- `0x520CCE: mov eax, [esi+8]` 取 P，`0x520CD1: test eax, eax` 判空。
- `0x520CD9: mov edx, [eax+4]` 与 `0x520CE4: mov ecx, [eax+8]` 读取 palette 状态标量参与比较，不是指针数值排序。
- `0x520B7F: cmp [esi+0Eh], bl` 仅读取 DX flag W8；不能据此推定未知尾字段用途。

### 13.5 palette payload 作为 param7 连续传递

- `0x520D57: mov eax, [esi+8]` 取 P，`0x520D5A: test` 判空；非空走 `0x520D5E: add eax, 10h`，空值走 `0x520D63: xor eax, eax`。
- `0x520D6D: push eax` 后再压入六个参数，`0x520D82: call 0x450400`；param7 是 palette payload 或空值，不是 DX entry。
- `0x450400: mov eax, [esp+arg_18]`、`0x450405: test` 消费该参数；非空时 `0x450415: push eax` 后再压入六参，`0x450428: call 0x450190`，仍是 param7 palette payload。

### 13.6 payload 色项索引不是 DX stride 或未知尾字段

- `0x4502D3: mov bx, [edx+ebx*2]` 为 W16 色项读取。
- `0x45032D: lea ebx, [ebx+ecx*2]`、`0x450330: add ecx, ebx` 得到 `payload + 3 * U8index`；`0x450338: mov bp, [ecx]` 为 W16，`0x450340: mov cl, [ecx+2]` 为 W8。
- `0x4503A2: mov ebx, [edx+ebx*4]` 为 W32 色项读取。
- 前述 `0x10` 是 palette payload 在缓存项内的起始偏移；`2/3/4` 是 color stride，不是 DX entry stride，这些读取不访问 DX unknown tail。

### 13.7 stack RECT 组装与 pixel buffer copy 不是 DX 整项 copy

- `0x52137B/0x521381/0x521388/0x52138B` 的四次 W32 写入取自局部 rect，用于组装 stack RECT，不是跨字段复制 DX 条目。
- `0x450278: rep movsd`、`0x450285: rep movsb` 的源是 pixel buffer，长度来自 tw，并经 `shr ecx, 2`、`and ecx, 3` 处理。
- 这些 copy 不是 B、E 或 P 的整项复制；不能因出现连续写入或 `rep movs` 就归为 DX raw copy。

### 13.8 返回寄存器未保留有效 DX 地址

- `0x517D96/0x517F54: xor eax, eax` 清除 EAX；`0x517BF5/0x518201` 的 object index 计算覆写 EAX。
- `0x520DB8: mov eax, 1`，且 ESI 已恢复。
- 上述返回路径未形成有效 DX 地址返回；该结论只覆盖这里交接的路径。

## 14. 有界结论与待批 32B 候选

### 24.2 入口及循环顺序

1. `0x523350` 以 R32 读取容量槽 `0x103CFA0`；`EDX/ECX` 清 0，入口容量按有符号比较 `<= 0` 时直接跳至 `0x523382`。
2. 正容量路径保存 `ESI`，将 `EAX` 偏移清 0；每轮先在 `0x523360` 重读 base 槽 `0x103CFA4`，再递增 `ECX` 计数。
3. `0x523367` 以 W32 清当前 `entry+0x00` 纹理节点链头；`0x52336A` 独立重读 base，然后 `0x523370` 以 W32 清当前 `entry+0x08` 调色板缓存引用。两次 base 读取不能合并为一次快照。
4. `0x523374` 重读容量，`0x52337A` 将偏移加 `0x10`，再以有符号 `ECX < ESI` 判断是否继续；循环上界不是入口容量的固定快照。
5. 正容量正常结束后恢复 `ESI`。本体保持 `ESI`，两条返回路径均保持栈平衡。

本体没有 base 判空，不读取条目旧值；不改宽高、`flag` 或未知尾字节，不写 capacity/base 槽，不分配或释放。这里只记录指令读写顺序，不新增保护或提前返回。

### 31.1 连续函数范围及返回点

`InitializeClient` 的连续函数区间为 `[0x4576B0, 0x457A3C)`，共 253 条指令；17 条显式跳转均向前，本体没有回边或间接 `jmp`。“连续函数区间”不等于单个基本块，也不能替代被调用函数或回调的重入分析。

本体共 8 个 `ret`：`0x45776F`、`0x4577A9`、`0x45784C`、`0x45791A`、`0x4579C7`、`0x4579E7`、`0x457A1B`、`0x457A3B`。仅 `0x4579C7` 返回完整 `EAX32=1`，其余返回 `EAX32=0`。

### 31.2 分配前的 Renderer 局部重试

1. `0x4576C2` 调用 Renderer 初始化 `0x44B630`；`0x4576CD: movsx eax, al` 后以两次 `dec` 区分首次返回的低字节 1 与 2。
2. 仅首次低字节为 2 时，`0x4576DE: cmp edx, 1`、`0x4576E1: setnz al` 将 `gWindowMode`（`0x9A7F48`）写为“旧值不等于 1”，随后 `0x4576E9` 再次调用 Renderer 初始化。
3. 第二次调用后，`0x4576EE: test al, al` 为零时直接前进至 `0x45773D`；非零时经过 `MessageBox` 及 `0x457737` 的 `PostMessageA(..., 10h, 0, 0)`，随后仍前进至 `0x45773D`。
4. 首次低字节为 1 时走另一条 `MessageBox` 路径，其他首次结果直接前进。

这是 `GraphicAlloc` 之前的 Renderer 局部重试，不是重入 `InitializeClient`，也不导致两次 `GraphicAlloc`。这里保留局部显式路径事实，不据此排除 `MessageBox` 内的消息回调。

### 31.3 GraphicAlloc 前后门禁

以下继承前进门禁，只补充是否返回初始化入口的结论，不重审 G2a/G2b 算法：

- `0x45774C: test eax, eax`、`0x45774E: jnz 0x457770` 要求前置调用返回非零才能继续。
- `0x45777A: test eax, eax`、`0x45777C: jz 0x457A31` 在返回零时转入失败返回尾部。
- `0x457782` 调用 `GraphicAlloc` 后，`0x457787: test eax, eax`、`0x457789: jnz 0x4577AA` 在成功时继续；失败经 `MessageBox` 到 `0x4577A9: ret`，没有显式 retry。

## 38. 三加载链汇合与跳过清理的另一失败

### 38.1 初始化返回尾及 MainLoop 前导出口

三个加载段的上述返回均汇合至以下 `InitializeClient` 尾部：

```asm
457A31 pop edi
457A32 xor eax,eax
457A34 pop esi
457A35 add esp,408h
457A3B ret
```

完整 `EAX32=0` 返回至 `MainLoop` 后，`0x457028: test eax, eax` / `0x45702A: jnz 0x457030` 不跳转，继而执行 `0x45702C: add esp, 30h`、`0x45702F: ret`。这条前导失败出口不再调用 `ShutdownClient`，也不调用 `0x4042B0`，不进入主循环；不能把它与 §37 的主循环消息泵退出尾部合并。

### 38.2 返回 0 不等于已经清理

`InitLoading` 另有 `0x45815E: cmp eax, 1` / `0x458161: jz 0x4582F4`。条件成立时直接进入恢复寄存器的返回尾，跳过 `0x4582EF` 的清理调用，随后仍将 `EAX32` 清 0 并在 `0x4582FD` 返回。

因此“加载函数返回 0”不能替换为“已执行清理”。本项只保存该分支差异，不添加 cleanup、提前 return 或失败回收策略。

## 39. 唯一额外应用层 callee：0x4042B0

四条清理返回链中，只有 `MainLoop` 在 `0x4574CB` 额外调用 `0x4042B0`：

| 地址 | 已交接指令行为 |
|---|---|
| `0x4042B0` | 读取模块槽 `[0x59E55C]` |
| `0x4042B5` / `0x4042B7` | `test` 后，槽值为 0 时转至 `0x4042C0: ret` |

## 40. 两类 MainLoop 出口到 WinMain 与 CRT 入口

主循环消息泵退出与初始化返回 0 的前导出口，均返回同一 `WinMain` 尾部：

```asm

4659E0 pop esi
4659E1 xor eax,eax
4659E3 pop ebx
4659E4 add esp,1444h
4659EA ret 10h
```

`WinMain` 再次将完整 `EAX32` 写为 0，按上述 `pop`、`add esp, 1444h` 和 `ret 10h` 返回。启动层在 `0x53DE83` 保存 EAX，`0x53DE86` 压入退出码 0，`0x53DE87` 调用 IDA 标签 `_exit@0x53C8FA`。

`_exit` 按原记录标签书写，不根据名称推定标准 CRT 语义；具体后继以下列指令为准。应用层返回链无显式回边不等于退出后继中没有循环或 callback。

## 41. CRT 实际 flags、回调表与回边

### 41.1 _exit 到 _doexit 的实参及前置分支

- `0x53C8FA`、`0x53C8FC` 各执行 `push 0`，`0x53C8FE` 压入退出码，`0x53C902` 调用 `_doexit@0x53C91C`；因此本条退出链的退出码为 0，`arg_4=0`、`arg_8=0`。
- `0x53C920` 比较 `[0x1086028] == 1`；成立时先经 `0x53C92C: GetCurrentProcess`、`0x53C933: TerminateProcess`。若该调用返回，仍接续到 `0x53C939`，不把 API 名称当作必不返回的路径证明。

### 41.2 运行期退出回调表

本链 `arg_4=0` 使 `0x53C94F` 不跳过 callback 段。`0x53C951` 读取首指针槽 `[0x1087AF4]`；非 0 时再取尾指针槽 `[0x1087AF0]`，从尾减 4 逆序遍历，遇非 0 条目在 `0x53C96E: call eax` 调用。

该遍历的真实回边为 `0x53C979 -> 0x53C968`。运行时条目目标未闭合，不能宣称本链没有 CRT callback，也不能据此断言 callback 已实际重入清理或消费 DX 表。

### 41.3 两段静态表与 __initterm 间接调用

| 调用指令与 callee | 遍历的半开区间 | 当前 IDB 中的非零项 |
|---|---|---|
| `0x53C986 -> __initterm@0x53C9B5` | `[0x553184, 0x553190)` | `0x553188 -> 0x53EA4A`；`0x55318C -> 0x54B20C` |
| `0x53C997 -> __initterm@0x53C9B5` | `[0x553194, 0x55319C)` | `0x553198 -> 0x545091` |

`__initterm` 在 `0x53C9C6: call eax` 间接调用条目，真实回边为 `0x53C9CB -> 0x53C9BA`。三处已知静态目标的内部未展开，不虚构其业务，不由静态表目标已知推定传递调用已闭合；这些表值仅转录 Zeno 的当前 IDB 记录，不是本次重新查表或运行观测。

### 41.4 本链最终退出分支

本链 `arg_8=0` 使 `0x53C9A1` 不走返回支；随后 `0x53C9A7` 写 `[0x1086028]=1`，`0x53C9AD` 调用 `ExitProcess`。

因此可以保留“四条应用层返回链未见回边”的局部结论，不能改写成“清理后全部代码无回边”或“CRT 没有 callback”。本次不继续展开 CRT、三处静态目标或外部回调。

## 47. 非空 p 的四次直接访问

首次判空位于 `0x5222E8/0x5222F7`，再次判空位于 `0x522363/0x522369`。本体对 `p` 的直接访存仅有以下四次：

| 地址与指令 | 访问 | 已证用途 |
|---|---|---|
| `0x5222F9 mov edi,[ebp+4]` | `p+4`，R32 | 首次宽 `W0`，按 S32 参与横向分块 |
| `0x5222FC mov ebx,[ebp+8]` | `p+8`，R32 | 首次高 `H0`，按 S32 参与纵向分块 |
| `0x52236B mov eax,[ebp+4]` | `p+4`，再次 R32 | 取得宽值 `v`，随后只测试已读值的低 2 bit |
| `0x52237B mov [ebp+4],ecx` | `p+4`，条件 W32 | 低 2 bit 非 0 时原位写回宽值 |

- 四次均为一级解引用；读出数值用于算术，没有再作为指针解引用。`0x52236E test al,3` 测的是寄存器低位，不是额外的 R8 内存读取。
- 本体未访问 `p+0`，未直接写 `p+8`。最小可证访问要求仅为 `[p+4,p+8)`、`[p+8,p+0C)` 可读，触发条件写回时前一窗口可写。
- 以上不证明对象恰好 12 字节，也不证明 `int[3]`、某个 struct、指针数组、像素指针或已知资源类型；基址、完整容量、其他字段及声明对齐未知。不能由访问窗口推定完整类型或 `const` 合同。

## 48. 原尺寸分块、条件改宽与索引重读

### 48.1 W32 高度纠偏与先存块数

| 地址或范围 | 已证操作与顺序 |
|---|---|
| `0x5222FF` | 将首次宽 `W0` 按 W32 保存 |
| `0x52231F/0x522325` | 两个 `H0` 副本均按 W32 保存；相关实际保存、读取、减法均为 W32，不能采用反编译的 `__int16` |
| `0x52231B..0x52233D` | 经 `cdq/and/sar`、余数修正及 `inc`，得到 `S32(W0)/64 + (S32(W0)%64 != 0)` |
| `0x522343..0x52235F` | 经有符号 `imul/sar/idiv/inc`，得到 `S32(H0)/48 + (S32(H0)%48 != 0)` |
| `0x522360/0x522365` | `imul edi,esi` 以 W32 相乘形成块数并保存；此时尚未改写 `p+4` |

上述有符号除法向零截断，不能统称为对所有 signed 输入的向上取整。此处记录原位宽和算术次序，不承诺数值 overflow 域结果。

### 48.2 再读宽值后条件写回

- `0x52236B` 再次从 `p+4` 读取 W32 宽值 `v`，`0x52236E test al,3` 判断低 2 bit；不把这次读取合并为首次保存的 `W0`。
- 低 2 bit 非 0 时，`0x522372..0x52237B` 依次执行 `mov ecx,eax; neg ecx; and ecx,3; add ecx,eax; mov [ebp+4],ecx`，按 W32 操作形成并原位写回 `v+((-v)&3)`。
- 写回后 `0x52237E` 重读 `gDxCacheIndex@0x103CF20`，随后 `0x522384` 跳到 `0x52239D`；不写回时由 `0x522370` 直接汇合，不执行该次重读。
- 首次读取 `gDxCacheIndex` 位于 `0x5222D6`。首次读取与写回后的条件重读不得合并，也不能由未知别名关系承诺两次读值相同。
- 已保存块数取自写回前的 `W0/H0`，不使用新宽重新分块；正常位宽、掩码及取模保留，不据此增加数值 overflow、专项回绕或令牌耗尽处理。

## 57. 重置与三快照的次序和返回边界

### 57.1 完整重置循环的写集

`0x523310` 完整 reset 循环按实际 count 遍历，仅写 `+04/+08/+10`，唯一直接调用者为 `0x5232D7`。`0x523324` 令 `EAX=N+8`，随后通过 `[eax-4]/[eax]/[eax+8]` 分别写图号、state 和 next；不能据此声称整 node 清零，也不证明 `+1A/+1B` 的初值。

### 57.2 快照目标、写序与失败边

- `0x520B19/0x520B1E` 读取 `0x628FD0/0x628FDC` 两个全局；`0x520B3B..0x520B4C` 在绘制模式位4置位时将两个比较目标都改为 0。这里只沿用报告的“模式位4”，不改称“第四位”，也不命名新模式。
- 三快照的写序固定为 `+14 → +16 → +18`，对应 `0x520DA5/0x520DA9/0x520DB1`。前两项写低 16 位，但比较时符号扩展后对照完整 W32 目标；`+18` 另有 W16 相等比较及键内 S16 比较，不能统一为同一种宽度或 signed 规则。
- 三快照匹配时可直接返回；节流路径可保留旧快照后返回，不能把进入函数等同于已更新快照或已上传。
- `0x520C8E` 的 palette 查找为空时仍跳到 `0x520D9B`，随后写入三快照。因此快照更新不能作为 surface 上传成功凭证，本项不补造成功返回或新增保护。
- 报告中的“绘制记录+22”已由 Locke 依据既有上下文明确为 `+0x22`（十进制 34），不是十进制 `+22`；该澄清没有新增 IDA 查询。

## 59. 同为 28 字节的栈键与 surface 数值依赖

### 59.1 栈键复制不是 node rawcopy

- `0x44CD80` 将 surface、imageNo、W16 paletteIndex 与 RECT 重组为栈键；`0x44CDC9/0x44CDBA/0x44CDC0` 各写前三项。
- `0x44CE14..0x44CE25` 以 `ecx=7; rep movsd` 复制 `0x1C`（28）字节，源是新构造的栈 key，不是 `N`。不能仅因复制长度等于原 node stride 就称为 node rawcopy。
- 本项不猜测未交付的键字段偏移或额外字段，栈键构造事实也不裁决 node 的现代布局。

### 59.2 已证 surface 值排序

- key 进入 `0x454420`；`0x44D3F4..0x44D400` 对键首 surface 值执行 `cmp; sbb; neg`，形成 U32 排序，`0x454468/0x45446C` 也执行 `cmp; setb`。
- 这是 surface 值的数值排序，不是 `N/next` 地址排序。即使本覆盖未见 node 强 raw layout 依赖，也不能忽略此处正面证据或声称不存在任何指针数值依赖。
- surface 键的引用保存、排序和生命周期仍须由后项承接；本项不指定替代引用、owner 或 API。

### 59.3 +18 的低 W16 栈传递不覆盖尾字节

- caller 虽执行 `push eax`，node 读取仍仅为 `mov ax,[N+18h]`；不能把四字节栈参数当作从 node 读取四字节的证据。
- 经 `0x44DA02/0x44E023` 转传后，`0x44CDB2/0x44D2B2` 再取低 W16；键比较 `0x44D41A..0x44D42C` 为 W16/`setl`，按 S16 解释。
- 上述传递不证明读取 `N+1A/+1B`，不能据此推定 `+18` 与尾字节重叠或合并字段。

下表的“逻辑实参”按第 1 至第 4 实参排列；“压栈点”仅按指令地址升序列出，**不是逻辑实参顺序**。这些四栈参调用由 caller 清理 `0x10` 字节参数。

| 阶段 | 逻辑实参 | 压栈点（地址升序） | 调用与发布/判空 |
|---|---|---|---|
| AutoMap | `(640, 480, 0, 0x800)` | `0x5231A5`、`0x5231AA`、`0x5231AB`、`0x5231B0` | `0x5231C7 -> 0x44C8B0`；`0x5231CF` 先发布到 `[0x6287B0]`，再由 `0x5231D4/0x5231D6` 判空。 |
| Temp 首次 | `(640, 480, 0, 0x4000)` | `0x5231F6`、`0x5231FB`、`0x5231FD`、`0x523202` | `0x523207 -> 0x44C8B0`；`0x52320F` 发布到 `[0x103CF14]`；零返回才进入回退。 |
| Temp 回退 | `(640, 480, EAX=0, 0x800)` | `0x523218`、`0x52321D`、`0x52321E`、`0x523223` | `0x523228 -> 0x44C6D0`；`0x523230` 再覆盖 `[0x103CF14]`。第三实参来自首次失败后的零 `EAX`。 |

AutoMap 使用 `0x44C8B0`，Temp 首次与回退分别使用 `0x44C8B0/0x44C6D0`，不能合并成同一个已审 factory 合同。零返回同样先写入目标全局；错误提示及失败后的残留见 §67–68。

## 66. 节点创建模式、逐槽发布与完成次序

本体在 `0x523258` 将 `EBP` 置零，在 `0x52325A` 令 `ESI=0x1020F08`。入口清零的 `EBX` 是**创建模式**，不是 node state；本体仅给它赋 `0/1`。

| 阶段 | 直接证据与次序 |
|---|---|
| 首模式取参/调用 | `0x523263` 读取 `W16[0x103CF28]`，`0x52326A` 读取 `W16[0x103CF2C]`；逻辑实参为 `(W低16, H低16, 0, 0x4000)`。压栈点按地址升序为 `0x523270/0x523275/0x523276/0x523277`，`0x523278 -> 0x44C6D0`。caller 高半未清，不能改写为 W32 零扩展实参；callee 的低 S16 消费见 §69。 |
| 首模式发布/成功 | `0x523280 mov [esi],eax` 先发布 surface，`0x523282/0x523284` 再判空。非零时 `0x52328D` 递增首模式统计，`0x523293` 转入推进。 |
| 首模式失败/切换 | 零返回时 `0x523286` 令 `EBX=1`，`0x52328B` 转入同一节点的回退；不推进 `EBP`，也不先换槽。 |
| 模式检查的保留分支 | `0x523295 cmp ebx,1`、`0x523298 jnz 0x5232C5` 保留“其他值跳过创建、直接推进”的机器分支。虽然本体仅赋 `0/1`，也不能据此删去该分支或增补保护。 |
| 回退取参/调用 | `0x52329A/0x5232A1` 重读同两处 W16 尺寸，逻辑实参为 `(W低16, H低16, 0, 0x800)`。压栈点按地址升序为 `0x5232A8/0x5232AD/0x5232AF/0x5232B0`，`0x5232B1 -> 0x44C6D0`。 |
| 回退发布/分流 | `0x5232B9` 先覆盖 surface，`0x5232BB/0x5232BD` 再判空；零返回转 `0x5232EA` 报错，非零在 `0x5232BF` 递增回退统计。`EBX` 不恢复为零，后续节点均使用回退模式。 |
| 推进/终止 | `0x5232C5 add esi,0x1C` -> `0x5232C8 inc ebp` -> `0x5232C9 cmp esi,0x103CF08` -> `0x5232CF jl 0x52325F`。这里是 signed 地址比较，不能只记为抽象的无符号长度判断。 |
| 整轮完成 | `0x5232D1` 发布 count=`4096` -> `0x5232D7` reset -> `0x5232DC` DX 引用失效 -> `0x5232E3` 完整 `EAX=1` -> `0x5232E9 ret`。本体没有把未完成前缀发布为 count 后成功返回的路径。 |

所有 surface 写入均按原顺序先发布再检查。`EBP` 是局部完成推进计数，不应把每次 factory 非零返回直接视为全局 actual count 已更新。

## 67. 三类失败的本体写入与残留

下表仅描述本体显式写序；`k` 表示节点回退失败所在槽，`a/b` 表示此前首模式/回退模式非零返回统计。错误回调可能重入，因此不单凭本体写序断言回调后或返回时全局最终值。

| 失败点 | 返回尾 | 本体已写入及未触碰范围 |
|---|---|---|
| AutoMap 返回零 | `0x5231F2` 置返回值 `0`，`0x5231F5 ret` | 三项计数已在入口清零；AutoMap 已发布零。全节点池与 Temp 未触碰。 |
| Temp 两次返回零 | `0x523254` 置返回值 `0`，`0x523257 ret` | AutoMap 已发布非零；Temp 两次发布后为零。三项计数的本体写值仍为零，全节点池未触碰。 |
| 节点回退返回零 | `0x523304` 置返回值 `0`，`0x523307 ret` | actual count 的本体写值仍为入口的 `0`；两统计保留 `a/b`。`[0,k)` 保留本次创建的非零 surface，槽 `k` 已写零，后缀未被本次覆盖；若在该槽刚从首模式切换失败，则同槽有两次零发布。 |

- 三类失败均不执行成功路径的 reset、DX 引用失效、扫描下标清零或前缀回收；不能把失败前缀解释成全局 count 标识的有效节点数。
- 所有分支在覆盖 surface 前均不读取并释放旧值。本体没有静态表或 DX 表的重分配/释放；这不等于外部永不回收，也不能据此新增自动释放、回滚、幂等或保护路径。
- 后缀“未覆盖”只限定本轮本体写入，不证明其初值、可用性或所有权；节点前缀非零同样不证明其后续生命周期安全。

## 77. `BuildSurfaceCache` 的 CPU 建面替换与发布边界

2026-09-27，在现有 IDA 会话只读核完整
`BuildSurfaceCache@[5231A0,523308)`、
`CreateSurrface@[44C8B0,44C998)` 与
`MakeSurface@[44C6D0,44C8A5)` 的直接调用和
关键指令。前一工厂在非 3D 分支复制 renderer
描述并以传入 caps 创建 offscreen surface；
3D 分支固定 `0x2040` caps。后一工厂从前两
实参的低 S16 取宽高，非 3D 分支以请求尺寸
及传入 caps 创建；3D 分支先各加 2，再按设备
caps 可能扩成 2 的幂或正方形。两者都只在
底层创建非零后设置所传颜色键，未检查
`SetColorKey` 返回，最后返回 surface 引用。
这些 DX 描述与显存 caps 属已批准的底层替换
范围，不能反推上层模式/状态也可省略。

新端 [GraphicDxCache.cpp](../src/render/GraphicDxCache.cpp)
按调用次序先清实际 count 与两项统计，依次
创建并发布 AutoMap、Temp 首模式；Temp 失败
才再试 CPU 回退。然后 4096 个节点先逐槽尝试
首模式；首次失败在同槽切到回退，后续节点
保持回退。每次先写节点 `surface` 再判断，
成功分别累计 `103CF9C/103CF98`；回退失败
直接提示并返回 0，不发布成功前缀为 count，
也不调用 reset/失效叶。完整成功才发布
count=4096，再依序调用已落位的
`523310→523350` 并返回 1。AutoMap、Temp
和节点的三处失败提示复用现有
`ShowLegacyMessage`，传入从当前 IDA 读取
的原 UTF-8 正文/标题与 `0x10` 类型。

[SurfaceState.cpp](../src/render/SurfaceState.cpp)
把 AutoMap、Temp 拆为两次可发布的 CPU
创建，当前槽销毁仍按 Temp→AutoMap；
被下一次创建覆盖的旧面继续由内部 owner
持有至进程退出，不因本体覆盖而提前释放。

闭合。Debug 两静态库编译通过，仅见既有

## 78. `Renderer::Destroy` 节点面释放段

2026-09-27，当前 IDA 只读核完整
`Renderer::Destroy@[44C3C0,44C55C)`。
PALDATA 只在 renderer 与其 `+0xC0` 均非空
时先释放、清槽（`44C3CF–44C402`）。
随后 `44C408` 读取实际节点数，按 S32
`>0` 门禁循环；每轮读取节点 surface，
非空才调用其 `Release` 并写零
（`44C41A–44C426`），再重读实际 count、
推进原 `0x1C` 步长。零 count 时不扫描
失败创建留下的节点前缀；本体不清 count。

节点段之后依次有条件释放并清
Temp `44C436–44C446`、AutoMap
`44C44C–44C45B`；再按设备 `+0xA0`、
3D `+0x9C`、调色板 `+0x90`、clipper
`+0x10`、Back `+0x0C`、front `+0x08`、
DDraw `+0x04` 的顺序释放并清各槽，
最后释放 renderer 本体并清全局指针。
当前 SDL/CPU 替换不保留这些原生 COM
对象，但不能把整个上层销毁序合并成
一次不透明后端析构。

[GraphicDxCache.cpp](../src/render/GraphicDxCache.cpp)
现在由同一个 CPU 纹理 owner 逐个摘除并
释放当前节点面；`ReleaseTextureNodeSurfaces_44C408`
按动态实际 count 遍历，仅非空时清
`node.surface`，不改 count、其他节点字段
或被覆盖的旧面。后者在进程退出时由 owner
回收，不能冒称与原 DX7 分配失败后的资源
压力逐次一致。此叶尚未接到
`RendererDestroy_44C3C0`；PALDATA、
调色板、SDL 呈现器及剩余阶段的现代
owner 未闭合，不计完整退出或重建。

与 Debug `cg2d_re_core/cg2d_re_startup`
静态库编译通过，无新增告警；未运行客户端
