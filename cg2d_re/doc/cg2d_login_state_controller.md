## 编码边界裁决

2026-09-22，文档任务 `RPLAN.16.B`（所属 `RPLAN.16`）同步用户已批准的[文本编码边界 SPEC](cg2d_text_encoding_spec.md)：`cg2d_re` 忠实还原核心按原编码字节处理，保留原字节容量、偏移、终止符和处理顺序；Unicode 仅在确有需求的现代边界集中转换。这是对“内部文本统一 UTF-8”的局部例外，源码与文档文件仍为 UTF-8。

`R6.1.2.8` 已将连接提示源码对齐为原字节；确认文本修复前的 7 字节 UTF-8 表示属于历史状态，`R6.1.2.10` 的当前 5 字节原字节合同见下文。登录进度、登录超时与登录失败三项的 UTF-8 常量及对应复制长度仅为 `R6.1.2.14` 之前的历史状态，当前原字节恢复合同见文末 `R6.1.2.14` 节；本项独立 review 与文件验证另行执行，不预记通过。其他文本链不因此视为已修复，也不推定其使用同一编码。

`R6.1.2.8` 当轮编码沿用分析交接及既有证据，不再查询 IDA；该轮分析交接已核对 `asc_55C7F0@0x55C7F0` 与连接调用者，Font、Queue、Yobi 直接复用既有复核结论，不重复复检。该轮源码仅修改连接提示常量与长度断言，未编译、运行或新增、执行测试；验证结论见[独立进度](../plan/cg2d_full_reconstruction_progress.md)，不据此宣称实际画面或完整连接流程已验收。

## 顺序状态处理

状态检查不是互斥 `switch`，而是顺序执行的四段判断：

1. 状态 0：`0x45E969` 调用 `sub_45EA50`，`0x45E96E` 调用 `sub_532D80`，`0x45E973` 将状态增至 1；同帧继续状态 1。
2. 状态 1：`0x45E985` 调用 `sub_45EA60`。
   - 返回 1：先在 `0x45E98F` 调用 `sub_534290`，再以参数 9 调用 `SetCurrentSceneType@0x51C770`；该函数把子状态清零。之后本函数重新读取子状态，最终返回 0。
   - 返回 -1：写状态 100，复制“處理登入逾時。”。
   - 返回 -2：写状态 100，复制“登入處理失敗，或斷線後，數分鐘內無法登入。”。
   - 其他值：不改变状态。
3. 状态 100：`0x45E9A7` 调用 `sub_45CE00`，`0x45E9AC` 将状态增至 101；错误路径同帧进入该段。
4. 状态 101：将 `0x9A5348` 传给 `sub_45CE10@0x45CE10`。返回 0 时本函数返回 0；任意非零时调用 `SetCurrentSceneType(2)` 并立即返回 2。

其他状态直接返回当前子状态。

## 登录消息重置与更新

`sub_45CE00@[0x45CE00,0x45CE0A)` 共 2 条指令、1 个基本块；它只把 `word_9A6E2C` 以 16 位宽度写为 0 后返回。`sub_45CE10@[0x45CE10,0x45D714)` 共 723 条指令、53 个基本块，原型为接收 `const char*` 并返回 32 位整数；全程序共有 26 个直接调用点、13 个唯一调用者，当前登录控制器中的调用点为 `0x45E9C3`。该函数内部有 46 个直接调用点、10 个唯一直接目标，返回值只有 0 和 1。

两函数在新端由独立消息模块中的唯一公开入口直接替代。16 位状态、32 位结果值、四个 32 位布局值、强类型 `YobiAction*` 和 16 字节图形描述均为模块私有；重置入口不清结果值、布局或对象。仅因 `LoginScene::Process` 也交叉引用原文本区，连续缓冲 `[0x9A620C,0x9A6E0C)` 以唯一公开存储 `char[12][256]` 保留，第 `i` 行对应 `0x9A620C + i * 0x100`，映像初值全为 0。

更新入口沿用原有效输入前提：参数非空、存在 NUL，且正文不超过 255 字节。它先复制包含 NUL 的输入，再只按 LF `0x0A` 原地分行，不处理 CR；连续 LF 产生空行，末尾 LF 产生最后一个空行。每个分行都用 `TextMeasure(..., 0)` 求像素宽度并累计最大值，不能用 UTF-8 字节数代替像素宽度。分行后仍对原输入做区分大小写的 ASCII 精确比较：

| 原地址 | 内容 | 原始字节（含 NUL） |
|---|---|---|
| `0x55C5C4` | `Multiline_New` | `4D 75 6C 74 69 6C 69 6E 65 5F 4E 65 77 00` |
| `0x55C5D4` | IDA 显示“確定” | `BD 54 A9 77 00` |
| `0x55C5DC` | `Multiline` | `4D 75 6C 74 69 6C 69 6E 65 00` |

三个分支的原控制流与布局规则如下；当前源码的文本表示差异另行标注，不能据此认定链级布局已经等价：

1. `Multiline` 首次进入时把状态写为 1、结果值写为 -2；宽度按第 8 行测量结果计算 `((width + 95) / 64) * 64`，高度为 192，X 居中，Y 为 144，并以 `(x, y, width, height, 1, 1)` 创建对象。`sub_45D7A0(&result, 1)` 返回 0 时播放 `(79, 320, 240)`、对象非空时先标记死亡再清指针并返回 1。否则对象就绪后，第 6 至 11 行共用按第 6 行宽度得到的居中 X，分别绘制在 `y + 30..130`，文本样式参数为 0；确认文本“確定”绘制在 `y + 156`，样式参数为 4、交互参数为 2、末参数读取 `0xD69768` 低 8 位，`DrawText` 的 32 位返回值写回结果值。原确认文本共 5 字节且含 NUL；修复前同一测量与绘制入口共用 7 字节含 NUL 的 UTF-8 常量，这是历史方案；本项恢复 5 字节原字节表示，两路完整合同见文末。
2. `Multiline_New` 首次进入时按第 0 行测宽，高度为 336、Y 为 72，其他创建和完成规则相同。第 0 至 5 行绘制在 `y + 30..130`、样式参数为 4；第 6 至 11 行绘制在 `y + 160..260`、样式参数为 0；所有行共用按第 0 行宽度得到的居中 X；确认文本位于 `y + 296`。
3. 通用分支首次进入时高度为 `(lineCount - 1) * (fontHeight + 2) + 96`，宽度按最大行宽取 64 的上述整倍数，X/Y 都相对 `640 * 480` 居中，并以末两参数 `(4, 1)` 创建对象。每次都检测居中 `66 * 17` 区域；只有命中后才读取 `0xD68D9C` 低 8 位的 bit 0，命中点击时按相同顺序播放、清理并返回 1。对象就绪后，各行以共同最大行宽基准居中，Y 为 `y + 30 + i * (fontHeight + 2)`；按钮图像位于 `(x + width / 2, y + (lineCount - 1) * (fontHeight + 2) + 69)`，层为 `0xDF`，命中时图号 243050，否则为 243048。16 字节描述原样为 `00 00 00 00 00 00 00 00 FF FF FF FF 00 04 00 00`。

`sub_45D7A0@[0x45D7A0,0x45D7CF)` 共 19 条指令、7 个基本块且没有直接
callee。它先单次读取 `gMouseClickState@0xD68D9C` 的低字节，bit 0 未置位时
直接返回 -1；随后按有符号 W32 判断 `count <= 0`，成立时同样返回 -1。只有
上述两项都通过后才单次读取 `dword_D68BEC@0xD68BEC`，顺序扫描调用者给出的
W32 数组并返回首个相等元素的零基下标，无匹配返回 -1。新端由文本待提交模块的
`FindClickedTextIndex_45D7A0` 唯一承接，两处消息确认调用直接复用该入口；
`gMessageResult` 继续保存 `DrawText` 返回的文本记录零基索引，不建立副本。

`dword_D68BEC` 的全部直接 xref 只有三处：`0x507264` 写 -1、`0x507341`
写当前命中的文本记录下标，以及本函数 `0x45D7B8` 的唯一读取。该存储无文件
后备、由 PE 零填充，故新端唯一 `gHoveredTextPendingIndex` 初值保持 0，并归属
文本待提交模块。真实生产者仍是尚未实现的 `sub_507140`；当前函数不计算命中、
不修改该值，也不以 -1 预初始化伪造生产者。有效调用要求 bit 0 置位且
`count > 0` 时 `values` 指向至少 `count` 个可读 W32；原函数不检查空指针或
容量，新端不增加相关门禁。

原 `0x9A6E2C` 为 16 位零填充状态；`0x55A04C` 为 32 位文件初值 -2；四个布局值和原 x86 对象指针均为零填充。共享系统值 `0xD69768`、`0xD68D9C` 的底层存储均为 32 位且映像初值为 0，本函数只读低 8 位；`gFontList.doubleHeight@0x558F78` 按 32 位读取，映像初值为 17。对象 readiness 复用唯一强类型适配边界，上层不做原 x86 `action + 0x170` 运算。

## 服务器连接控制器

`sub_45D990@0x45D990` 的证据同样只来自上述 `ida-17524` 权威实例：

- 精确边界为 `[0x45D990,0x45DBEF)`，共 165 条指令、38 个基本块，原型为无参数并返回 32 位整数。
- 唯一调用点是 `LoginScene::Process@0x45FEA0` 的 `0x4601B5`。调用者在 `0x460197` 执行 `sub_45D980` 并把场景子状态增至 3 后，会在同次调用中继续执行本函数。
- 原函数共有 17 个唯一直接目标。新端复用已有 `sub_5044E0`、`Yobi::MarkDeath` 和唯一 readiness 适配边界，直接调用 `sub_508350` 与 `sub_401000` 的唯一实现；无格式参数的 `sprintf` 拷贝在当前源码中改为保留 `sizeof(kServerConnectingText)` 的定长复制，连接提示常量已按下述编码任务恢复原字节；仍在当前范围内且尚未还原的目标只保留真实声明，不提供空实现或固定返回。`sub_50FC30`、`sub_50FE30`、`sub_50FF10`、`sub_50FF70`、`sub_510120` 另按下述用户范围排除处理。

主阶段 `word_9A6E3C` 与次阶段 `word_9A6E3E` 均按 16 位访问：

1. 主阶段 0：`0x45D9AC` 写入提示文本，`0x45D9B7` 测量像素宽度；以有符号向零截断计算 `(width + 111) / 64`，再将列数下限钳为 2。随后写行数 2、Y 基准 192、`((10 - columns) * 64) / 2` 的 X 基准，以 `(x, 192, columns * 64, 96, 4, 1)` 调用 `sub_5044E0@0x5044E0`。`0x45DA28` 把主阶段写为 2，`0x45DA31` 同帧进入主阶段 2。
2. 主阶段 1、次阶段 0：`sub_50FC30@0x50FC30` 返回负值时结果为 -4；否则 `sub_50FE30@0x50FE30` 只有返回 1 才调用 `sub_50FF10@0x50FF10`、把次阶段写为 1 并同帧继续，其他值都令结果为 -3。
3. 主阶段 1、次阶段 1：`sub_50FF70@0x50FF70` 返回 1 时先把次阶段写为 2，再调用一次 `sub_510120@0x510120`、把主阶段写为 2，并同帧进入主阶段 2；返回 -1 时结果为 -3，其他值均继续等待。这里不能因刚写入次阶段 2 而再次调用 `sub_510120`。
4. 进入函数时次阶段已为 2：调用一次 `sub_510120`、把主阶段写为 2，并同帧继续。
5. 主阶段 2：严格依次调用唯一实现 `cg::network::ShutdownNetworkRuntime_5081A0()`、`cg::blacklist::PersistAndReset_401000(gValue55A054)`、`cg::network::InitializeNetworkRuntime_508140()`。三者分别对应原 `sub_5081A0@0x5081A0`、`sub_401000@0x401000`、`sub_508140@0x508140`；前两项返回值保持忽略。最后一项返回 0 时结果为 -1；任意非零时依次写主阶段 3、调用 `sub_508350@0x508350`、写主阶段 4，并同帧轮询。
6. 主阶段 3：调用 `sub_508350`、写主阶段 4，并同帧轮询。
7. 主阶段 4：`sub_508360@0x508360` 返回 1 时结果为 1；任意负值统一映射为 -2；0 或大于 1 的值继续等待。其他主阶段仍可进入绘制尾部并返回 0。

### 网络运行期关闭接线

callsite。当前 11 个对应源码表达式已全部直接调用网络运行时唯一公共入口，其中本

### newest 检查链的用户范围排除

上列主阶段 1 的第 2 至 4 项继续作为原端 IDA 行为的历史证据保留，不改写为原函数不存在。2026-09-21 用户明确登录无需再处理该 `newest` HTTP/raw-socket 请求，当前不再使用；因此 R6.1.3.115–119 对应的 `sub_50FC30`、`sub_50FE30`、`sub_50FF10`、`sub_50FF70`、`sub_510120` 五函数链登记为用户范围排除，不实现，也不计为已实现。

新端的明确旁路差异仅位于 `UpdateServerConnection` 的主阶段 1：写 `gValue9A6E3C = 2`，再令本次调用的局部 `phase = 2`，从而同帧继续执行原主阶段 2。旁路不读写 `gValue9A6E3E`，不调用上述五函数，不执行该链的清理，也不改变主阶段 0、2、3、4 或 `ResetValues_45D980`；次阶段仍只由既有重置入口按原宽度清零。后续连接初始化、轮询、结果清理与绘制尾部保持原接线。

结果非零时，原端在 `0x45DB4D` 读取对象；对象非空则先在 `0x45DB57` 调用 `Yobi::MarkDeath`，再在 `0x45DB5F` 清空指针。无论对象是否为空，之后都在 `0x45DB70` 调用 `sub_401030(gValue55A054)`。结果为 0 时不执行清理。

### 黑名单持久化后重置边界

`sub_401000@[0x401000,0x401029)` 共 41 字节、11 条指令、3 个基本块，原型为
接收 signed W32 并返回 W8。它只有 `sub_4011A0@0x4011A0` 一个 callee，唯一
caller 是本控制器中的 `0x45DAE1`。该函数调用 callee 恰好一次：AL 为 0 时
不写状态并返回 0；AL 任意非零时，先把当前文件 ID `0x5531A0` 以 W32 写为
-1，再把游标 `0x59384C` 以 W32 写为 0，最后返回 1。它不清记录表、不清路径，
也不附加门禁。

四项状态由 `cg::blacklist` 唯一公开：`records[100][17]@0x592FA8` 共
`0x6A4` 字节且 PE 初值全零，`path[512]@0x59364C` 共 `0x200` 字节且 PE
初值全零，signed W32 游标 `0x59384C` 初值 0，signed W32 当前文件 ID
`0x5531A0` 初值 -1。`gValue55A054` 是不同 owner，只作为本调用参数；R110 的
两个状态也不属于这四项。

原 `sub_4011A0` 会格式化 `data\blacklist_%d.txt`，仅在结果与共享路径相等时
以 `w` 模式持久化记录；新端已由 cpp 私有的
`PersistBlacklistFile_4011A0` 实现，并由 `PersistAndReset_401000` 保持原外层
重置语义。原 `sub_401030@[0x401030,0x401167)` 也已由地址中立公开入口
`cg::blacklist::LoadBlacklistFile` 独立实现：先清路径和记录表，以 `rb+` 打开，
再按 `feof`、17 字节 `fgets` 和 signed W32 回绕游标规则加载；所有路径最终写入
当前文件 ID 并返回 W8 的 1。本控制器在结果非零路径保持原顺序调用该入口并
忽略返回值。加载与持久化实现不合并。完整布局与异常域见
[黑名单共享状态证据](cg2d_blacklist_state.md)。

上述黑名单边界的闭合不代表最终链接、服务器连接链或整体客户端已经闭合；本
控制器仍有下文列出的其他真实依赖尚未实现。

对象非空且 readiness 阈值 1 成立时，`0x45DB99` 每帧重新测量提示文本；绘制坐标保持原有两次有符号向零截断计算：

```text
y = baseY + (rowCount * 48 - 16) / 2
x = baseX + (columnCount * 64 - currentTextWidth) / 2
```

`Renderer::DrawText@0x456780` 是返回 32 位整数的 8 参数函数，本调用点忽略返回值；调用参数为 `(int16(x), int16(y), 2, 0, 0, text, 0, 0)`，不能替换为登录进度所用的 6 参数 `DrawText3`。

### 服务器连接共享状态重置

`sub_508350@[0x508350,0x50835D)` 共 13 字节、4 条指令、1 个基本块且没有 callee，原始字节为：

```text
33 C0 A3 50 3B DA 00 A3 C0 3F 59 00 C3
```

### 原端边界与写入

- `sub_532D80` 主块为 `[0x532D80,0x532DEE)`；`0x532DE9` 跳入共享尾块 `[0x4AFF00,0x4AFF25)`。另一路 `sub_50F280` 经 `0x532E63` 进入该尾块，不能把 `sub_50F280` 进入尾块前的调用、写入或副作用归给 `sub_532D80` 本体。唯一直接 caller `0x45E96E` 调用后在 `0x45E973` 将场景状态递增，弃用返回值；[新端对应调用](../src/LoginState.cpp#L422)也不消费结果。
- 主块对三处共享 W32 写入 -1、两处共享 W8 写入 0；按各项原宽度逐项清零 200 个步长 `0x7C` 的记录（每项 W32/W16/W8/W8）、32 个步长 `0x30` 的记录（每项 W32/W8）、3 个步长 `0x29` 的记录（每项 W8）。主块最后将 `0x1051510` 以 W32 写为 0。这些是共享状态写入，不是为本函数创建的私有存储；原路径无分配。
- 尾块读取 `gWindowState[48].window`；指针为空时返回 W32 的 0。非空时只借用已有窗口实例，对该实例的 W32 state 执行 `state |= 0x8000`（按位或并写回完整 W32，保留其他位，而非覆盖赋值），随后调用 `World::PlaySe@0x52C450` 并返回音效调用的 W32 结果，而非窗口指针。原指令可见压入 `0xF0`、`0x140`、`0x39`，但该 callee 只读取前两个参数；第三个压栈值的意义未定，不能将它擅定为音效参数语义。

### 窗口共享生命周期与新端现状

窗口 48 是[既有 71 条 `gWindowState` 记录](cg2d_scene_state.md#L643)的一项，记录窗口指针在原 `+0x0C`；这里借用的是 UI 窗口实例，不是 Win32 `HWND`，也不是本函数分配或持有的私有副本。原 UI `Window::open@0x4714DE` 分配、`0x4718AE` 发布；`UIWindowInstance::free@0x471276–0x47140F` 清引用并释放，`Windows::close@0x472160` 沿该生命周期关闭。窗口 48 另由 `0x4AF161` 使用，故登录重置不能独占或伪造一个空窗口壳；发布、失效须与[共享窗口 owner 待批边界](cg2d_scene_state.md#L667)一致。

新端 [LoginStateDependencies.hpp 第 11–12 行](../src/LoginStateDependencies.hpp#L11) 目前前置声明 `UIWindowInstance`，并将 `Sub_532D80()` 声明为 `UIWindowInstance*` 返回；这与原端“空返回 0、非空返回音效 W32 结果”的证据矛盾。[LoginState.cpp 第 422 行](../src/LoginState.cpp#L422)虽弃用该返回值，也不能据此称旧指针返回声明正确。本项不修改声明或源码；现有 `LegacyUiRecord`、Yobi 对象及 Win32 主窗口均不是上述 71 项共享 UI 窗口 owner。

### 待用户批准的 UI owner 与音效接口 SPEC

1. **返回接口**：决定新端 `Sub_532D80` 返回 W32 以保留原结果，还是因唯一 caller 弃返回而改为 `void`；批准前不改现有指针返回声明，不把结果冒充实例指针。
2. **唯一 UI owner 与 x64 布局**：决定由谁持有 71 个窗口槽及 71 条状态记录、窗口 48 的读取窄接口，以及原 W32 指针字段和实例 state 在 x64 下如何表示；不得直接把原 `+0x0C` 当作原生指针偏移，亦不得在登录模块自建私有表或空壳。
3. **发布与失效**：明确 `open` 分配／发布、`free` 清引用／释放、`close` 及 `0x4AF161` 等使用方在同一 owner 下的借用有效期、状态写入和失效合同；不能因本函数不分配而跳过完整生命周期门禁。
4. **音效窄接口**：明确 `World::PlaySe@0x52C450` 的唯一 owner、可供登录重置调用的最窄入口、前两参数的位宽与结果传递；对第三个压栈值保留未定，不借现有三参数 `PlaySe` 声明猜测其含义，不提供固定返回或假实现。
