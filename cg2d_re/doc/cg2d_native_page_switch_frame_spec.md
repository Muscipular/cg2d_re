# 原生页面切换空帧修复 SPEC（PSF01）

状态：用户回复“go”批准；源码实施及静态核对完成，待运行验收。

## 1. 问题与证据

用户确认个人状态、简介切换时整个面板消失一下、露出游戏画面，并补充宠物页有相同现象。

- `WindowRuntime_Update` 在帧首通过 `MergeWindowOrder` 固定本帧窗口集合。
- 人物状态、明细、称号、简介的切页回调先标记旧窗口关闭，再 `WindowRuntime_Open` 新窗口，最后复制坐标。
- 宠物能力、详细、技能共用 `WindowPetDetail_SwitchPage`，执行相同流程。
- 当前帧绘制跳过已关闭窗口，新窗口又不在帧首集合，形成一帧面板缺失。上述结论来自当前源码与用户症状，未运行采样。
- 两组页面各自同层、同尺寸。宠物技能页使用专属 draw；不能统一替换为默认绘制。
- 宠物页面 `update(-1)` 会提前返回，正常数据刷新发生在后续 update；仅补画创建后的元素会漏掉首帧内容。

## 2. 修复范围

人物页面：状态（7）、明细（8）、称号（9）、简介（58）。

宠物页面：能力（16）、详细（17）、技能（18）。

通过公共的原生切页登记入口处理这两组已经确认的页面替换。宠物列表选择其他宠物、图鉴翻页及其他窗口创建不凭相似名称改变调度；本次证据确认的是上述切页回调。

## 3. 拟采用的时序

1. 保留现有关闭、创建、逐轴复制坐标和音效顺序；切页完成后登记源窗口和目标窗口的 ID、实例代次。
2. 当前窗口的输入回调退出、点击消费完成后，在原本绘制旧页的位置处理该替换记录。保留帧首交互集合，不把新页加入当前鼠标分发。
3. 确认目标仍是同一实例、未关闭且可见，切换当前窗口上下文，执行一次目标页正常原生 update，再调用其原有 draw。宠物数据由此在首帧填充，宠物技能页的专属绘制保留。
4. 本次仅补目标页的原生刷新和绘制，不执行新页拖动、元素鼠标分发或提前派发 Lua 打开事件及生命周期回调。下一帧按正常窗口调度进入完整交互与脚本回调。
5. 补画结束恢复调用前上下文，绘制返回值沿现有 carried 传递；旧窗口继续在原安全点回收。

替换记录仅存在于当前 UI 帧，逐条消费，不递归处理补画期间新建的其他窗口。目标如果已在本帧集合中，不重复刷新和绘制；本次七页正常切换目标均为新建窗口。

## 4. 取舍与边界

- 新页接替旧页的绘制位置，维持其相对其他窗口的入队顺序；不在全帧末尾追加补画，避免同层遮挡关系改变。
- 全局窗口集合、关闭门禁、下一帧回收及扩展窗口的 shared_ptr 保活继续保留。
- 不在 `WindowRuntime_Open` 内立即绘制，因为调用者此时尚未复制切页坐标，宠物页面也尚未完成正常刷新。
- 不将全部窗口改成“先 update 后 draw”，保持现有原生 update/draw 返回值传递合同。
- 此方案是针对当前调度的局部修复设计，不宣称已由原端指令证明同样机制。
- 若目标 update 因宠物失效等业务条件主动关闭窗口，按现有关闭语义停止补画；不恢复已失效页面来掩盖业务关闭。

## 5. 验证与完成条件

实施时静态核对：七页切换接线、正常刷新与专属 draw、上下文恢复、实例代次、目标关闭/隐藏门禁、同帧唯一绘制、原有点击消费和回收时序。

运行验收待明确授权后执行：两组页面往返切换不再露出游戏画面；首帧文案、宠物属性及技能完整；拖动后切页位置不跳变；叠放其他窗口时遮挡稳定；一次点击只切换一次；关闭、重新打开及 Lua 打开通知保持正常。

当前不编译、不运行客户端、不新增或执行测试、不计算摘要。静态检查不能替代画面验收。

## 6. 实施结果（2026-10-22）

- 五个切页回调接入统一登记函数，覆盖人物四页及共用回调的宠物三页；登记放在原坐标复制和音效调用之后。
- 每个窗口调度使用栈上切页记录，作用域结束自动解除借用；仅保存ID和实例代次，无新增窗口字段及堆分配。输入阶段结束即停止登记，补画不会递归扩展本帧集合。
- 旧页关闭后，在其原绘制位置复查源和目标身份，目标不在帧首集合中时执行原生正常update及其自己的draw。update后的关闭、隐藏或实例失效会停止绘制；已有调度项不会重复刷新/绘制。
- 补画使用目标窗口上下文，结束后恢复窗口、状态、窗口ID和元素ID；GBK错误继续由既有invoke处理。绘制返回值沿carried传递，不调用新页的元素鼠标、拖动或脚本绑定回调。
- 静态核对声明/定义、五处接线、七页刷新/绘制入口及关闭消费顺序；Git差异检查通过。未编译、运行或执行测试，画面和交互结果仍须运行验收。
