# 旧 UI 455490 组初始化

## 局部方案

补齐 CRT `55302C..553050` 的十项尾跳包装与十个完整本体，
在已有 `LegacyUiRecord.cpp` 保存唯一初始化状态，经
`LegacyMouse.cpp` 接在已实现对象表之后、场景转换值之前。
不填充其间尚未实现的 CRT，不引入析构、随机消费或推测的交互入口。

四个标量分别承接 `556C28/556C2C/556C30/62B39C`；
十五组只存八个已证 W32 初始化值，分组保持原地址间隙。
目前不公开存储，不据布局相似强转既有按钮类型，不冻结未知消费者
所需的完整结构或 x64 ABI。前六组相同读写序列使用私有助手，
后面单组、三组与五组各保持自身交错写序，不改为逐记录赋值。
本次为局部合同及实现，不触发总 SPEC 对齐或日志压缩。

## 同期双缓存核对

CRT `553018/55301C` 分别对应 `44CC20/44CD30`，通过
`44CC30/44CD40 → 453FB0` 构造两棵缓存树；退出登记
`44CC60/44CD70`，后者尾跳前者公共段。共享
`62B0B0/62B0AC` 是原STL哨兵与引用计数，析构树节点未逐值释放
缓存surface；业务释放仍由 `44D490` 负责。

现有 `GraphicDxCache.cpp` 已以两私有 `std::map` 承接
`629300/62A630` 的构造与析构，见[DX §79](../cg2d_graphic_dx_cache.md#79-64-位类型化地址键与变换双缓存)。
因此不重复创建原树、共享哨兵或CRT包装占位；这是原有标准容器
替代范围的补证，不证明原分配失败时机、跨模块退出次序或整个CRT已等价。

## 验证边界

只静态核本步原指令、源码、声明定义、CRT相对顺序和文件编码。
不执行初始化、绘制、构建、测试、客户端或检查编译产物。
其他CRT、十五组记录的完整消费者及整体客户端验收均未因此完成。

本步已实现并接入上述二十入口，源码解析展开私有助手后，十份
有序读写摘要与原指令一致；十五组120槽的符号表达式/常量、
十项返回、尾跳目标及中央调用序列逐项一致。初值保持64/-1/192/0，
原有源码只新增，未改变已有底部栏、保护对象或其他CRT本体。
