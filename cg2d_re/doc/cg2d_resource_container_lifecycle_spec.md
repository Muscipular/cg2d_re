## 2. 实施决定

1. 四 owner 都使用同文件 alignas/sizeof 的真实被动存储，固定 construct_at / destroy_at；两个模块各一个无析构动作启动适配，保持本模块当前启动位置、按原相邻两槽调用并忽略实际登记结果。
2. 四个具名 S32 入口各先固定构造，再 std::atexit 登记固定无参退出；透传宿主真实结果，不使用旧退出表/跨堆，也不造 once、懒构造、回滚、固定成功、重复调用保证或空保护。取消四个自动对象构析，只有一套活动路径。
3. 各消费者通过纯借用接口取同一已存活对象。mapNo仍S32，GraphicInfo*与解压记录指针仍非拥有；保留清空、去重、排序、首次记录及 DBF 入队/迭代读写和原时点。
4. PaletteDbfState 的 records 成员放在 decodedBlocks 前，构造顺序改为原 map→vector。整体析构按原U32索引逐次重读data/size并释放各解压块，然后 decodedBlocks.clear()、records.clear()；成员逆序先释放空集合容量，再销毁已空树。current/载荷不增加释放或复位，不重写旧数据、申请容量或分配/释放函数；空data判断对应原522704/522706，不新增保护。
5. 原晚段注册/异常展开由真实宿主登记及 C++成员生命周期承接，批准私有节点/树形/allocator/异常差异不称原体等价；正常业务前缀和清理职责必须对应。
6. C02/C04 接全应用原序时，必须同一步移除两个模块适配；当前不能在适配仍活动时再次执行四个公开入口。全 C++90 分类、四 Init/流与所有活动构析、快速退出及资源完整生命周期继续待验，不启用半表、空 callback 或虚构可执行入口。
