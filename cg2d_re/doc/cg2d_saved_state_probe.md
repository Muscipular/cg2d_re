# cg2d 保存位置探测证据

## 函数边界与调用关系

- 原函数：`sub_5333D0@[0x5333D0,0x533461)`，共 145 字节、43 条指令、
  7 个基本块。
- 唯一 caller 是 `sub_533300@0x533305`。
- 共有 5 个 callsite、3 个唯一目标：循环内
  `sprintf@0x5333EC`、`fopen@0x5333FB`，旧位置
  `fopen@0x53341F`、`fclose@0x53342C`，以及当前位置命中后的
  `fclose@0x533442`。
- 源码只在 `LoginSavedState.cpp` 匿名命名空间增加私有
  `[[maybe_unused]] ProbeSavedStateLocation_5333D0()`；本项不接 caller。

## 探测顺序

函数保留未初始化的局部 `char path[0x400]`，并严格执行：

1. 按下标 `0..9` 顺序遍历十项 `gSavedState.paths`。
2. 每轮使用
   `sprintf(path, "%s\\%s", gSavedState.paths[index].text, "save.dat")`
   构造当前槽路径，再以 `rb+` 调用 `fopen`。
3. 首个成功打开的当前槽文件会立即调用 `fclose`，忽略关闭结果并返回 0；后续槽
   不再探测。
4. 十个当前槽全部打开失败后，才以 `rb+` 打开固定路径
   `data\\save.dat`。
5. 固定路径打开成功时立即关闭并返回 1；打开失败时返回 2。

函数不调用记录 loader，不跳过空路径项，也不读取或写入其他全局状态。

## `rb+` 与返回域

两阶段均保留原 `rb+` 模式，而不是改为 `rb`：目标必须已存在，并且 CRT 必须能
以读写方式打开。因权限只能读取但不能写入的文件会落入“打开失败”路径；本函数
探测的是该精确打开条件，不是抽象的文件存在性。

返回值严格只有：

- `0`：十个当前槽中至少一个按顺序成功打开；
- `1`：当前槽全部失败，但 `data\\save.dat` 成功打开；
- `2`：两阶段全部打开失败。

## 路径前提与异常域

正常调用要求每个 `paths[index].text` 都在其 0x100 字节槽内以 NUL 终止，且与
反斜杠和 `save.dat` 拼接后的总长度适合 `path[0x400]`。实现按原函数使用
`sprintf`，不使用 `snprintf`、filesystem 或长度门禁；不满足前提时可能发生读取
越界或栈缓冲区溢出，属于 C++ 未定义行为。空字符串也不会跳过，而是照常形成
以反斜杠开头的路径并调用 `fopen`。

本项不写全局、不实现 loader/reset、不修改公开声明或 CMake。行为证据只取自
当前 `ida-17524 / cg2d.exe`，STONAGE 不参与结论。
