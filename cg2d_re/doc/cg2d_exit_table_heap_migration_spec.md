<a id="exit-table-heap-decision"></a>
## 实施裁决

1. 退出表整块使用私有std::malloc/std::realloc/std::free和UCRT `_msize`；
   这四API属于已有MSVC宿主，无新增/下载依赖。容量取实际宿主块容量，
   返回仍U32，不伪造为32槽、已用元素或申请容量。没有第二张回调表、
   容量影子槽、句柄映射、压缩指针、原block-4或16B双链访问。
2. 只在既有LegacyRuntimeExit.cpp匿名空间新增三个私有提供者，均使用真实
   LegacyRuntimeExitCallback*，只在标准分配边界转型，不用void*擦除接口。
   分配保持原U32上界FFFFFFE0、入口new-mode快照、零请求按宿主1B、
   真实失败时按快照决定原541A28处理器/原请求重试，异常传播。
3. 扩容保持空块先走同域分配、非空且零请求同域free后返空。
   其他请求沿宿主realloc；失败不释放旧块，每轮重新读取原new-mode，
   需要时调用原处理器。分桶、内部对齐、容量及低内存时机按D02宿主承接，
   不复造原mode3块头/复制长度或把宿主块交旧Free/Resize/HeapSize。
4. 原53B3A0/53B3BF两容量查询都切同一 `_msize` 提供者；
   53B3CE扩容和53B41D初分配同时切同域。标准分配器的内部错误机制按D02，
   不另加null/范围保护，RPLAN.24异常不专项模拟或声称安全/故障等价。
5. 初分配仍32个真实函数指针槽，x64每槽只因地址拓宽变8B；
   初始请求U32=32×sizeof(callback)。先发布首，空走原错误24，
   若错误处理返回则重新读共享首；只清首槽，再读共享首并发布末/返回。
6. 登记仍先查询容量再取共享首末；不足再查保存首的实际容量，
   按4个原生槽增加U32请求，扩容参数独立新取共享首。失败返空且保旧块/首末，
   成功后重取共享首末整数地址差，先写首再写末，最后写实际callback、
   递增共享末并返callback。空callback仍入表，包装仍返回-1。
7. 两原函数只换四个实际提供者表达式，余正文保持；53B406包装/53C91C调度、
   C5真实表及其adapter、62原caller和所有业务构析不改、不提前执行或重复登记。
   本组不是把通用RegisterLegacyAtExit改为std::atexit，既有已迁宿主登记组保持。
8. 两变化根登记为具名 `adapted`，不得标原体等价；原分配/扩容/容量元数据
   和其他环境/对象caller继续保留，不能把通用53FA5B/53FCFB整体排除或替换。
   唯一退出表仍持有真实块，所有权、借用、重读和回调顺序按原应用合同保持。

本机Windows SDK 10.0.26100.0的ucrt/malloc.h包含corecrt_malloc.h，
后者实际声明 `size_t __cdecl _msize(void*)`；按已有Windows x64目标调用，
只核文本/声明，不据此声称编译或链接成功。未构建/测试/运行任何分配或故障样例。
