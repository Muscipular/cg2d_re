## 四组跳转表陷阱

四组分发都不能直接按反编译器生成的普通有符号 `switch` 理解。

1. 主状态：`0x461005` 以无符号 `ja` 检查 `state > 21`，
   `0x461013` 经 `jpt_461013@0x461A78` 分发 22 项。负状态按位解释后也走
   默认，不会命中正数状态。状态 3 与范围外值只跳到主分发尾部。
2. 第二分类：`0x4614AF` 先以无符号门槛 20 检查，再以
   `byte_461AD8@0x461AD8` 映射到 `jpt_4614BC@0x461AD0`。状态
   0..9、19、20 走第一条返回路径；10..18 以及无符号范围外值进入两槽
   角色循环。特别是状态 21 并不走早退。
3. 动作：`0x461500` 以无符号门槛 6 检查，
   `jpt_461509@0x461AF0` 的 3/4、5/6 分别共用目标。返回 -1 的位模式大于
   6，必须走默认动作，不能误作数组下标。
4. Puk 版本：`0x461A20` 先把 `0x9A6E1C` 截为 `uint8`，再以无符号门槛
   7 检查 `jpt_461A2A@0x461B0C`。0/2、5/6 各共享发送分支，7 使用独立
   载荷，1/3/4 及范围外值不发送；不论是否发送，只要更新标志非零，尾部
   都把场景状态清为 0。

第二分类形成两条不同返回路径：

- 状态 0..9、19、20 直接返回
  `sub_45F090(0,0,3,245060,0,-1)` 的结果；
- 其余状态完成两槽循环、按钮和背景绘制后，返回更新标志 0、版本发送结果，
  或没有发送分支时的 Puk 数值。尾部背景绘制结果在这条路径上会被覆盖。

## 角色列表读取进度 `sub_45DD50/sub_45DD60`

### 边界、调用与返回域

- 重置函数范围 `[0x45DD50,0x45DD5A)`，共 2 条指令、1 个基本块；更新函数
  范围 `[0x45DD60,0x45DED9)`，共 118 条指令、12 个基本块。
- 更新函数有 6 个真实 `call`，目标为 `sub_5044E0`、`sub_508910`、
  `sub_508950`、`CryptInt::gte`、`Yobi::MarkDeath` 与
  `Renderer::DrawText3`。
- 两个函数的唯一调用者都是 `sub_460FF0`：状态 0 调用重置，状态 1 调用
  更新。重建以
  `ResetCharacterListProgress_45DD50/UpdateCharacterListProgress_45DD60`
  两个公开入口直接替代旧声明，场景控制器不经过包装层。
- 更新函数的已确认返回域为 `{0, 1, -1, -2, -3}`。外层场景控制器仍按
  原函数保留 `-4` 分支；不能因当前依赖返回域使该分支不可达就将其删除。

### 私有状态与阶段时序

`0x9A6E5C` 是映像零值的 `uint16` 阶段；`0x9A6E60` 是映像为空的原生
`YobiAction*`。文本 `char[256]` 以及列、行、X、Y 四个 `int32` 布局值也都
是映像零值。这七项的全部 xref 都局限在本函数对内，因此新端均保持为实现
文件私有状态，不从内部或公开头文件导出。重置函数只以 16 位宽度把阶段写
为 0，不清对象、文本或布局。

更新入口先采样阶段并把结果初始化为 0：

1. 阶段 0 复制 UTF-8“登入成功，開始計費！”到私有缓冲，写阶段 1，计算
   布局并调用 `sub_5044E0(192,192,256,96,4,1)`。返回值即使为空也先写入
   私有对象槽；随后重新读取阶段，因此同次调用继续阶段 1。
2. 阶段 1 调用 `sub_508910`，忽略其 `uint32` tick 返回，再以 16 位阶段
   自增为 2。首帧由这条分支结束阶段分发，不会同帧调用 `sub_508950`；因此
   全局阶段可在同一帧完成 0→1→2，但首帧不轮询。
3. 阶段 2 调用 `sub_508950`。返回 0 时保留对象并进入公共绘制；返回非零时
   重新读取对象，非空才调用 `Yobi::MarkDeath`，随后无条件清空对象槽并
   原样返回，不绘制终态帧。
4. 其他阶段不调用启动或轮询目标，只进入公共绘制并返回 0。

提示框建立失败不阻止同次阶段 1 发起请求；对象为空只会跳过公共绘制。

### 固定旧编码布局与未决依赖

原正文 Big5 字节为 20 字节；源码保存 UTF-8 文本，但布局不得使用 UTF-8
字节数或 `strlen` 重算。固定计算为：列数 `20 / 8 + 2 = 4`，行数 2，
`x=((10-4)*64)/2=192`，`y=192`；公共绘制坐标为
`xText=192+(4*64-20*8)/2=240`、`yText=192+(2*48-16)/2=232`，参数为
`DrawText3(240,232,2,0,text,0)`。对象就绪只通过接收真实
`YobiAction*` 的 `IsYobiActionReady(action,1)` 窄边界判断，不在上层硬编码
原 x86 `+0x170` 偏移。

`sub_508910/sub_508950` 目前仅新增真实声明，不提供空实现、固定成功或包装
实现；`sub_5044E0`、死亡标记、readiness 适配和 `DrawText3` 也仍是既有未决
依赖。本步不扩展实现这些目标。

### 初始化、点击与绘制顺序

每次更新先把返回值初始化为 0、悬停初始化为 false，并使用一份 16 字节图形
描述：坐标和尺寸均为 0，颜色为 -1，裁剪为 0，混合模式为 4，调色板为 0。

1. 阶段为 0 时，先写阶段 1，再依次保存未知值 -2、宽 512、高 144、X 64、
   Y 168，最后调用 `sub_5044E0(64,168,512,144,4,1)` 并原样保存返回指针。
   建立失败后阶段也已是 1，后续帧不会重试。
2. 初始化后无条件先检测按钮。左边界为 `x+((width-66)>>1)`，检测调用严格为
   `sub_5049A0(left,y+115,left+66,y+132,-1)`；矩形的半开边界语义由该依赖
   承接，不在调用层改写。
3. 命中时置悬停，并读取共享 `0xD68D9C` 的低 8 位 bit 0。点击时先把返回值
   写 1，再播放 `(51,320,240)`；私有对象非空则标记死亡并清槽，随后立即
   返回 1。该路径不绘制，且对象为空时仍返回 1。
4. 非点击路径中，对象为空或 `CryptInt::gte(action+0x170,1)` 不成立均返回
   0。就绪时先调用
   `DrawText3(int16(x+140),int16(y+20),2,6,"登入認證失敗。",0)`，再调用
   `DrawGraphic(x+width/2,y+123,uint8(0xDF),hover?243050:243048,0,descriptor)`，
   最后返回 0。

原字符串的 CP950 字节（含首个 NUL）为
`B5 6E A4 4A BB 7B C3 D2 A5 A2 B1 D1 A1 43 00`。源码只保存对应 UTF-8
文本，固定坐标和尺寸不通过 UTF-8 字节数重算。

### x64 边界与未决依赖

对象槽使用原生 `YobiAction*`；对象就绪继续通过接收真实指针的
`IsYobiActionReady(action,1)` 窄边界判断，不在上层硬编码 x86
`action+0x170`，也不把指针截入 32 位整数。图形描述复用既有定宽
`GraphicDescriptor16`，鼠标只读取共享 W32 的低 8 位。

`sub_5044E0`、按钮检测、声音、死亡标记、readiness、文字与图形绘制均复用
既有真实声明，实际实现与 `YobiAction` 的 x64 布局仍未决；本模块不提供空体
或固定返回桩，也不复用 `LoginMessage` 的阶段、对象或布局状态。

### 私有初值与阶段推进

阶段 `0x9A6E54` 是映像初值为 0 的 `uint16`；对象槽 `0x9A6E58` 的映像初值
为空。X、Y、列数、行数四个 signed32 槽
`0x9A4EA4/0x9A5FDC/0x9A50DC/0x9A5950` 的映像初值均为 0。这六项 xref
封闭在两个函数内，全部由模块私有状态承接。重置入口只把阶段写 0，不清对象
或布局。

更新入口每次先把结果初始化为 0：

1. 阶段 0 先写阶段 1，再依次写行数 2、列数 3、Y 192、X 224，最后调用
   `sub_5044E0(224,192,192,96,4,1)` 并保存返回值，包括空指针。随后重新
   读取阶段，因此同次调用继续阶段 1。
2. 阶段 1 调用无参 `sub_508F70()`，忽略其返回值，再以 W16 将阶段增加到

3. 阶段 2 调用无参 `sub_508FC0()`。返回 0 时进入公共绘制并返回 0；返回
   非零时，对象非空才标记死亡，随后清空对象槽并立即原样返回，包括
   1、-1、-2，不绘制终态帧。
4. 其他阶段不调用启动或轮询目标，直接进入公共绘制并返回 0。

公共绘制仅在对象非空且 `IsYobiActionReady(action,1)` 成立时调用
`DrawText3(280,232,2,0,"角色刪除中",0)`；否则不绘制。

### 固定旧编码布局、x64 边界与未决依赖

`0x55ABE8` 的原 CP950 字节（含首个 NUL）为
`A8 A4 A6 E2 A7 52 B0 A3 A4 A4 00`，正文长度严格为 10 字节。列数保持原
公式 `((9*10)>>6)+2=3`，行数为 2，进而得到 X 224、Y 192；绘制坐标固定为
280、232。源码只保存 UTF-8 文本，不通过 UTF-8 字节数或 `strlen` 重算布局。

对象槽使用原生 `YobiAction*`，就绪判断继续通过强类型窄边界
`IsYobiActionReady(action,1)`，不硬编码原 x86 `action+0x170`，也不截断
x64 指针。IDA 已确认 `sub_508F70` 与 `sub_508FC0` 均无参数；前者按实际
`DWORD` 返回声明为 `std::uint32_t`，后者按 signed32 结果声明为
`std::int32_t`。两者本步只保留真实声明，不展开协议逻辑；对象创建、死亡标记、
readiness、文字绘制及 `YobiAction` 的 x64 实际布局同样保持未决，不提供空体
或固定返回桩。

## 两槽角色记录与动作

角色记录复用 `login::gCharacterRecords` 的 `2 * 0x94` 原始字节，并复用
`login::gSelectedCharacterIndex` 的 `int16`。循环从原 `0xFF03F8` 开始、每次
推进 `0x94`，以 `0xFF0520` 为末端，严格执行两次。

| 记录偏移 | 访问与证据 |
|---:|---|
| `+0x00` | 名字。原函数用 20 字节栈缓冲和 `strcpy`；重建保留“输入已在临时区内 NUL 终止”的原有效输入前提。 |
| `+0x18` | signed32 图号；`0x4615EA` 读取，动作 3/4 在 `0x461702..0x4618C2` 读写。 |
| `+0x20` | signed32 删除条件；`0x461664` 判零。 |
| `+0x24` | signed32 图号分类；原 `v9[3]`。 |
| `+0x50` | signed32 预览切换值；原 `v9[14]`。 |

四个定宽字段全部通过 `memcpy` 读写，不把原始记录强转为结构指针，也不做
x86 绝对地址指针算术。

动作映射如下：

- 0：写选择索引，依次调用五个准备目标，切场景 4，播放 `(53,320,240)`，

## 角色预览构造 `sub_460D00`

### 边界、调用与返回类型

- 函数范围 `[0x460D00,0x460FD8)`，大小 `0x2D8`，共 187 条指令、47 个
  基本块、6 个真实 `call`。六个目标分别是 `Yobi::MarkDeath@0x404D00`、
  `sub_51B110@0x51B110`、`sub_51BB80@0x51BB80`、
  `sub_51BFF0@0x51BFF0`、`YobiAction::new@0x404AE0` 与
  `sub_517880@0x517880`。
- 唯一调用者为 `sub_460FF0`，共有三处调用：状态 10 依次处理槽 0、1，
  动作 5/6 的共用分支处理当前槽。三个调用点都忽略返回值。
- 当前唯一公开入口为
  `cg::character_select::ProcessCharacterPreview_460D00(std::uint32_t)`；
  `slot` 的有效调用域为 0、1，保持原函数不检查范围的前置条件。
- IDA 将原返回类型标成 `YobiAction*`，但函数的普通尾部直接返回
  `sub_517880` 的 signed32 结果，两个失败分支返回 0。重建因此统一公开为
  `std::int32_t`。原 `0x460D42` 确实会把第二次读到的 x86 指针位模式留在
  EAX；该分支通过独立的 32 位兼容适配声明承接，不能在 x64 上把真实指针
  强转或截断成 `int32`。

入口先独立读取 `gPreviewActions[slot]`。非空时调用 `Yobi::MarkDeath`，调用
返回后再清槽。随后调用 `sub_51B110(slot)`；返回 0 时立即返回 0。返回非零
时必须重新读取共享槽，不能复用入口快照；第二次结果非空时走上述
`0x460D42` 兼容返回分支，不继续建立对象。

### 记录规范化与状态快照

角色记录继续复用 `login::gCharacterRecords`，`+0x18` 与 `+0x50` 都通过
`memcpy` 按 signed32 读写，不把原始记录转换成结构指针。

1. `+0x18 < 30000` 时先写为 33100。
2. 重新读取 `+0x18`，依次调用
   `sub_51BB80`、`sub_51BFF0`，后者结果记为 `converted`。
3. 读取 `+0x50` 的旧值。旧值为负时，`converted` 位于
   `[240000,241400)` 写 1，否则写 2。旧值非负时先独立检查
   `converted >= 241400` 并写 2，再独立检查闭区间
   `[205000,205600]` 或 `[270000,270200]`，命中时写 3；第二项能够覆盖
   第一项。
4. 状态更新结束后重新读取 `+0x50` 作为表选择快照，不能复用旧值。

四个 14 项私有表严格为：

```text
state 0: 100002 100027 100052 100077 100102 100127 100152
         100252 100277 100302 100327 100352 100377 100402
state 1: 105002 105027 105052 105077 105102 105127 105152
         105252 105277 105302 105327 105352 105377 105402
state 2: 106002 106027 106052 106077 106102 106127 106152
         106252 106277 106302 106327 106352 106377 106402
state 3: 105502 105527 104402 104432 104462 104492 120102
         100900 100900 100900 120126 100900 100900 100900
```

快照 0、1、2、3 分别选择同号表，其他 signed32 值也选择 state 2 表。

### 对象建立、下标与字段顺序

对象通过强类型边界调用 `YobiAction::new(2,0)`：第一参数 `priority` 是 W8
unsigned，第二参数 `yobiSize` 是 W32 unsigned。IDA 在 `0x404B85` 以
`mov dl, byte ptr [arg_0]` 读取 `priority`，并在 `0x404C1A..0x404C1D` 以
W8 `cmp` 后接无符号 `ja` 比较；在 `0x404B2F` 以 W32 读取 `yobiSize`，
`0x404B33..0x404B35` 与 0 比较后接无符号 `jbe`。调用处据此显式传入
`std::uint8_t{2}` 与 `std::uint32_t{0}`。返回指针必须先写入
`gPreviewActions[slot]`，再判空；分配失败返回 0。`converted` 到表下标的
分支和顺序如下，不增加范围保护：

| 条件 | 下标 |
|---|---|
| `converted` 在闭区间 `[270000,270200]` | `q=(converted-270000)/100`；`q==0` 取 6，`q==1` 取 10，其他取 `q` |
| 否则在闭区间 `[205000,205600]` | `(converted-205000)/100` |
| 否则 `converted >= 241400` | `(converted-241400)/100` |
| 其他 | `(converted-240000)/100` |

建立成功后重新读取规范化的记录 `+0x18`。值为 33100、33101 时分别只对
对象 `+0x2A8` 写一次 100900、100901。普通路径先把所选表项写到
`+0x2A8`，再经窄 getter 重新读取该字段，计算
`field + 6 * ((converted % 100) / 25)` 并二次写回。其后严格按下列顺序写入：

| 顺序 | 原字段 | 宽度 | 值 |
|---:|---:|---:|---:|
| 1 | `+0x2B0` | W32 | 0 |
| 2 | `+0x15` | W8 | 10 |
| 3 | `+0x30` | W32 | `315 * slot + 163` |
| 4 | `+0x34` | W32 | 292 |
| 5 | `+0x2B8` | W32 | 5 |

所有字段访问都通过接收真实 `YobiAction*` 的窄 getter/setter 声明；新端不
建立原 x86 `0x330` 字节布局，也不在调用层做偏移运算。原单角色槽函数的
`+0x2B0=1` 写入同步复用同一个通用 setter。最后再次从共享槽读取指针，
调用 `sub_517880(pointer,100,0,0)` 并原样返回 signed32 结果。

`YobiAction::new`、`Yobi::MarkDeath`、旧指针 EAX 位模式、各字段
getter/setter、`sub_51B110`、`sub_51BB80`、`sub_51BFF0` 与
`sub_517880` 目前都只保留真实声明，没有空实现或固定返回桩；实际 x64
`YobiAction` 布局和这些窄适配实现仍待后续目标提供。
