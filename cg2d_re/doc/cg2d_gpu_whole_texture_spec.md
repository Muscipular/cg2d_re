# 整图 GPU 渲染（GRT01）

2026-10-17：用户根据当前 CPU 火焰图，要求整块纹理交给 GPU 缩放，取消普通贴图的小块切割与 CPU 采样路径，并要求改完再提交。本项覆盖既有 CPU 合成整屏及固定 64×48 节点的实现约定。

## 实施范围

1. 使用已有 SDL3 renderer 建立持久 Back 渲染目标；精灵、字形、PNG、纯色矩形及三角形按原队列顺序提交 GPU。最终呈现直接使用 GPU Back，不再每帧上传旧 CPU Back。
2. 普通 graphic 每图一份实际尺寸的缓存表面和 GPU 纹理；取消固定小块分配及拼图。保留图号、源裁剪、翻转、缩放、独立调色板与调色板版本失效。只在内容改变时重新上传，不每帧重建未变纹理。
3. 普通矩形以源矩形／目标矩形绘制，采用 nearest。取消 CPU `SampleWrappedCoordinate`、逐像素 UV 除法与逐行 blit；旧块边缘 padding／WRAP 不再作为整图矩形的采样方式。图内裁剪、透明／加色及覆盖顺序继续保留。
4. GPU 资源归 render 后端持有，renderer 销毁前统一释放；CPU 表面和字体缓存仍可按既有生命周期保留并在设备重建后重新上传。
5. Back／Temp 复制与少量既有 CPU 像素消费者显式同步：读取前取得最新 GPU 内容，写入后标记 CPU 内容变化，在下一次 GPU 绘制前上传。常规精灵、字体、矩形绘制不得触发整屏回读。后续可继续迁移特殊 CPU 效果，本项不删除其业务。
6. 采用原节点池容量对应的像素预算管理整图缓存，按最近使用帧回收；不按资源总数预建整图纹理。超出后端能力或资源失败沿实际失败结果处理，不引入外部依赖或无声降画质。

## 验证与边界

核对纹理所有权、脏标记、调色板更新、源矩形／翻转、绘制顺序、Back／Temp 同步和设备重建。遵守当前构建／运行权限；静态核对不等同编译或画面验收。之后在同场景、同分辨率采样并比较 CPU／帧率／内存，覆盖场景与战斗切换、文字阴影、特效和截图。性能收益须以修改后采样为准。

## 复测与持续更新纹理（GRT02）

2026-10-17 按用户“再pref一下”“完成后提交代码”继续本项。对用户已启动的新版 Release 取相同 60 秒窗口，客户端 MAP 与运行进程、ETL 时间戳一致，SDL 使用本地匹配 PDB；采样周期 1 毫秒，无丢事件／缓冲区。运行样本由此前 61,307 降至 16,029，减少 73.85%；20 秒帧计数为 59.27 FPS，其中前台有效区间约 60.14 FPS。场景并非严格控制的 A/B，Windows 短窗口进程时间读数与 ETW 估计不一致，因此只报告同采样口径的变化，不把瞬时读数作为持续 CPU 占用结论。

旧逐像素采样热点已消失，剩余 AutoMap 路径占 4,117 样本（25.68%），其中创建纹理占 3,976 样本；最终呈现占 4,879 样本（30.44%）。已确认小地图逐帧修改表面后，`GetTextureGpuTexture` 每次调用 `SDL_CreateTextureFromSurface`，反复分配、转换颜色键并复制整张表面。

本次调整只针对持续更新：首次使用／设备重建创建 ARGB8888 GPU 纹理，后续通过 `SDL_UpdateTexture` 复用；多处 CPU 写入合并脏矩形，首次上传覆盖整图，AutoMap 和新增字形只上传实际写入范围，调色板更新继续全图上传。更新失败保留脏状态。

原 AutoMap 的零色色键在写像素时编码成零 Alpha，绘制显式启用 Alpha 混合；非零颜色维持不透明。此转换保留已有 GPU 上传时按 RGB 比较颜色键的行为，依据 [SDL 3.4.8 的颜色键转换实现](https://github.com/libsdl-org/SDL/blob/release-3.4.8/src/video/SDL_surface.c#L654)，避免再次扫描／复制整个表面。其他表面的生产者已直接生成 ARGB8888，GPU 所有权、设备重建与绘制顺序保持 GRT01。

上述复测数据属于 GRT01 版本；GRT02 的运行降幅须在用户换用新进程后另测，不能混用为本次小地图修复的验收结果。
