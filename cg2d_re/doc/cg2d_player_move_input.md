# 玩家移动输入父链 SPEC

完整只读核469C90@[469C90,469FB6)、51B3E0@[51B3E0,51B530)及
510B80@[510B80,510CD4)。沿既有[移动调度](cg2d_ui_window_runtime.md)、
[World对象表](cg2d_world_objects.md)、[网络运行期](cg2d_network_runtime.md)
接线，不以固定命中、私有坐标或发包替身补依赖。

## 同源状态裁决

- SceneState增加C8A7A0/C8A7A8两个W32事件槽，均由尚未实现的
  RendererCursorGrid生产，不能等同鼠标held/edge状态或默认启用。
- FF0D38独立U32时间初值零；55DDAC的已映射原字节为`FF FF FF FF`，
  初值必须为0xFFFFFFFF。250/500ms运算和比较保持U32，不换成64位计时器。
- D67BE0是UI多处读写的独立W8，归现有UI运行期唯一持有；
  world只通过窄读接口获取，不复制到SceneState，不假设恒零。
  当前仅有门禁消费，UI真实写入链仍缺。
- 469CC0原opcode `F6 05 8E A8 FD 00 80` 只TEST FDA88E W8的bit7，
  对应既有玩家flags18C的bit23，不是完整S32<0或FDA88C低字节。
- 469DBD读取D68D9C低W8的bit0，即既有LegacyMouseState.edgeButtons；
  不另建click状态。所有共享目标仍为C8A784/C8A788 S32。

## fIM 请求510B80

原58B21C命令字节为`fIM`，大小写不可改。复用同一58B5F0输出缓冲：
BuildProtocolCommand后按X/Y/方向三个S32分别采容量、格式化，再重读
缓冲追加；无新失败返回或容量保护，既有失败残留仍参与后续处理。

三项完成后捕获输出指针，逐字节数空格，达到第三个即停止第一轮；
未达三项时每轮重算同一指针的strlen。选中序号初值1。
至少有一个空格才调用原time@53BA26(nullptr)，按返回低W32重新SeedRandom，
再从同一共享RNG取一次值，对实际空格数作S32余数；余数零改1。
time失败的-1仍照原作为种子，不新增拒绝。重设后重新捕获输出指针。
不能将此改为固定序号、私有random引擎或std::rand，否则改变CryptInt后续RNG。

第二轮以从0开始的空格序号逐项扫描；遇选中空格写原字节0x17，
随后重读共享输出指针并退出扫描。未找到则保留原捕获指针。
每轮仍重算strlen；最后向517480发送并透传S32返回。
该替换属于原请求本体，不恢复用户已排除的403C50/403E50加密链。

## 邻格请求51B3E0

接口用U32承接EAX位型：既可为S32数值返回，也可为完整GetTickCount。
先读581800，非-1直接返回。否则X轴先Subtract(playerX,目标X)判断符号，
再重新采目标X、重新Subtract，按第一次符号选择是否取负；
S32结果>1直接返回。Y轴同样两次读取且只在X通过后执行。
不可用一次读取的abs替代；不为INT_MIN专项增加保护或回绕模拟。

按目标Y→X采样调用4450D0(...,7)，失败返回0；成功后重新采目标X求
IntMinusCrypt差，先采目标Y，再落X为F32，求Y差并落F32，调用46CDF0。
此后才第一次取tick，再读取FF0D38，旧时间加500严格小于tick才发送。
未过时间门禁返回第一次tick，仍已消费上述坐标/RNG/方向计算。

发送时读取当前玩家Y→X，再读取socket，调用真实510B80(socket,x,y,方向)。
网络返回不作门禁，第二次取tick写FF0D38并返回；不额外发布玩家朝向。

## 完整469C90

1. 入口先Equal(C821D8,0)，仅该结果真且9A86D8/9FB92E都为零才清C82220。
   然后查玩家bit23；置位直接返回入口Equal的AL，不调下游。
2. C8A7A8非零且UI门禁W8为零时，目标Y→X采样，445030(...,8,0x1000)。
   返回S32>=0才4CD3E0→4CD400→512190(socket,编号)；
   无论命中与否，都继续46B370→51B3E0，再重新采目标Y→X，
   调445160(...,8)。这次仅返回值等于-1才跳过511760(socket,3,编号)，
   不能把两个判断都写成>=0，也不新增网络成功门禁。
3. gate非零且玩家flags18A bit8为0时跳过输入处理；
   其余路径再依次查62B5AA/C82220/UI门禁，任一非零也跳过输入。
   都不因此跳过末尾顺序表重建和普通/跟随分流。
4. C8A778按U32>=500时先写C8A79C W16=1；否则只在该W16已为1时
   进入持续路径。持续路径检测鼠标edge低W8 bit0，置位则清C8A79C并
   跳过本次坐标提交及光标方向提示。

### 持续路径

先取tick，再查55DDAC+250<=tick，**相等也通过**。
通过时第二次取tick，先采目标X，再发布55DDAC，再构造X临时CryptInt，
按mask→encoded→count写9A7F88并析构；随后采目标Y、构造，
按encoded→mask→count写9A7F98并析构，最后写C821FC=1。
未通过时间门禁不构造，但仍执行后面的光标方向判断。

先IntMinusCrypt(目标X,玩家X)，只有零时才对Y同样查询。
任一非零则重新读取Y差，采目标X，Y差落F32后再读取X差并落F32，
调用46CDF0，取低S32加3给既有RequestCursorState_506DE0(...,0)。
不缓存之前的差值、不把Y→X反过来，不强制覆盖既有非零光标请求。

### 单次路径与公共尾

未进入持续路径时，仅C8A7A0非零才查250ms；通过后第二次取tick并
**先发布55DDAC再采目标X**。X按encoded→mask→count写回，
Y按count→encoded→mask写回，每轴独立构造/析构，最后C821FC=1。
此路不执行光标方向判断，不能与持续路径合并成忽略写序的坐标辅助函数。

公共尾无条件46A990，再重读gate与玩家标志：
gate非零且bit8为0调46A190，否则469FC0，返回其低U8。
完整普通场景51D25A是已证唯一caller，其父函数仍未实现；
对象记录/目标格/UI门禁生产、角色回调和完整画面仍待后续。
本步不构建、测试、运行或实际发包，只做必要静态核对。
