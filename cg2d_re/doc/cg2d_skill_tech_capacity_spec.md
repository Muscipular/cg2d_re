# SKILL／TECH 固定30栏 SPEC

## 最终决议

2026-10-18，用户最终选择std::array加30栏限制，覆盖此前vector动态容量及超过32槽战斗的方向。角色技能槽和每项技能的技术槽均支持索引0—29，以kSkillSlotCount和kTechniqueSlotCount统一定义。用户先前确认的正常槽位语义继续适用：技能搜索只遍历实际槽位；战斗索引-1表示未选中。

## 数据与读写

- 扩展技能记录、技术数组、排序索引、战斗筛选行号、遗忘技能映射及技能经验结算数组。
- 保持SkillRuntimeRecord平凡可复制及连续数组存储；整块清零和原memcpy继续有效。后续成员偏移及整体大小按容量公式断言，原出处地址和旧偏移作为注释保留。
- SKILL回复仍按每项11字段解析，负索引保持原终止语义，索引≥30的条目不写入数组并继续下一项，末尾排序覆盖30槽。
- TECH回复先验证所属技能索引0—29，按原6字段格式最多写30项；原技术表先清零，短回复不会残留上次后续数据。超过30条的尾部不再写入。原空名称不推进分词的异常行为本次不另改。
- 制造配方回复的技能索引也限定0—29，配方数量保持56。
- 技能结算数组扩为30，原末尾顺序字段解析沿用；短回复继续按原缺失字段解析／负值归零分支处理。结算窗口原可见行数不扩展。

## 消费端

普通技能／技术与战斗技能／技术列表保持每页10行，计数、查找、滚动上限覆盖30槽。遗忘技能映射、制造技能搜索、投掷物技能／技术查找、Lua列表及自动战斗边界同步更新。输入栏技能占用统计覆盖30槽，总栏位额度读取既有服务端玩家字段，不将存储容量30当作玩家必定拥有的额度。

技能和技术索引最大29，现有S8／U8／S16索引承载足够，宠物共用的SkillPairRecord布局保持。

## 战斗协议

P消息技能可用状态仍为uint32_t，bit 0—29对应30槽，静态断言技能容量不超过32。Rg的S|技能索引|TECH索引|目标仍以原十六进制编码发送。无需提供超过32槽的扩展协议，也不新增协议或修改既有位序。

- Sub_504F10只搜索30条真实技能，移除原额外读取相邻pairs[6]的行为。
