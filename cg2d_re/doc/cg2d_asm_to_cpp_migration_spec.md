# ASM 数学源迁移 CPP 合同（ACP01）

<a id="asm-cpp-decision"></a>
## 1. 已确认范围与数值取舍

用户2026-10-09要求将现有ASM处理为CPP，并明确选择“允许 double／标准数学差异，并明确更新 SPEC”，随后确认“可以使用std::math做近似替换”。标准C++数学接口实际位于`<cmath>`，使用`std::pow/log/sqrt/sin/cos`等。

| 原源文件 | PUBLIC / PROC | 迁移职责 |
|---|---:|---|
| `src/platform/LegacyAudioMath.asm` | 6 / 6 | 128项声像/音量表、空间距离、坐标与发布 |
| `src/platform/MapEffectMath.asm` | 13 / 13 | 地图效果、运动/方向、轨迹与双向投影 |
| `src/platform/LegacyFloatEnvironment.asm` | 92 / 97 | CRT浮点环境、分类/幂/异常及私有数学链、实际整数读取叶 |

三文件共111个PUBLIC、116个PROC。这是源清点数，不是原函数/功能完成数。迁移必须为实际CPP算法及宿主接口；不嵌机器码、不改后缀冒充CPP、不生成/加载替代ASM、不增加外部依赖。

原输入、输出及共享字段的F32/F64/S16/S32/I64宽度保留。F32字段仍用`float`；数学中间计算及转整数之前用`double`。不统一降为`float`：乘65536后的整数偏移、距离取整、幂/对数与阈值判断可能受额外舍入影响。允许`double`和标准库与x87中间值、PC53、T80、超越指令、特殊值载荷及浮点状态的数值差异，不要求位级或指令级精度等价。

本许可具名覆盖三文件及其对应调用桥的旧x87/PC53/私有ST0数值要求；与场景、音频、投影、幂应用及CRT各数学子SPEC冲突时，以本合同为最新数值实现边界。其它模块的未授权业务、字段、容量、协议、读取/发布序、owner及生命周期要求保持。不扩大为完整功能验收或数学异常故障等价通过。

<a id="asm-cpp-preserved-contract"></a>
## 2. 必须保留的接口与业务合同

- 既有CPP调用入口的参数、返回、指针借用及结果结构布局保持；含`X87`的旧符号可暂保留以减少接线变化，名称不再承诺x87实现。
- 正常整数计算域与原W32整数段、向零截断及只消费低W32的边界保持。无效F64到I64采用现有MSVC/SSE2向零转换接口，避免C++对NaN/无穷直接强转整数；不新增钳制、拒绝、补值或故障模拟。
- 音频表保留奇数写点、正向/反向覆盖、端点覆盖、音效音量0槽复制1槽、固定音乐含0槽及原上限判断。只迁实际WAV客户端数值，不恢复MIDI/DLS工具开发或重生成WAV。
- 空间扫描先做原W32平方和，再转浮点；直接距离先转浮点再平方。空间源先Y后X；空间记录按原条件决定发布，未发布返回索引，发布返回截断Y，保留X/Y重读及字段写序。
- 地图效果保留原常量位样本、F32落存位置、借用输入的重读及逐轴发布。效果除数以`std::pow(1.25, exponent)`取代私有CI幂，继续在幂返回后读取借用幅值。
- 双向投影保留参考位槽的volatile读取：世界到屏幕先采两轴参考再写结果；屏幕到世界写X后再取Y参考。
- CRT环境迁移只在已有宿主边界承接标准数学/浮点环境；原业务错误记录、errno、回调门控、异常记录及实际调用不得改成空体或固定成功。无CPP调用的私有ST0链须逐项登记由真实宿主数学承接，不能留下伪造ST0的CPP函数。
- 整数读取叶不在数学近似许可中：实际BYTE/W32宽度、重读与顺序保持；P07未生产第二命令仍未解决，不为其猜值或补默认值。

<a id="asm-cpp-history"></a>
## 3. 历史证据与实施步骤

原三ASM及其旧静态验收固定于迁移前Git命名快照`cg2d-re-asm-history-20261009`，按上述原路径读取。旧证据仅证明该历史实现，不证明新CPP已编译、链接或运行。旧附件文字、结果与实现快照保持；静态汇总器仅对这三个已删除原路径核固定Git历史对象存在，不读取/执行原源，不扩大任意缺失路径豁免。

按音频、地图、CRT环境分别推进并精确提交。现提供者路径与语义登记同步到真实CPP；历史原指令/取证文件不改写成CPP验收。最后移除三ASM与`ASM_MASM`配置及专用对象名规则，仅保留仍需使用的RC语言。

<a id="asm-cpp-acceptance"></a>
## 4. CRT环境阶段的具体承接决议

<a id="asm-cpp-crt-decision"></a>
按最新数学许可和既有工程委托，旧92个PUBLIC中的22个CPP值接口/读取叶继续由真实CPP提供；其余70个私有ST0接口以及5个非PUBLIC内核不再暴露机器栈ABI。静态全源调用检索确认：这些私有接口只在待删除ASM内部互调，地图唯一外部ASM CI消费已经在ACP01-M改为std::pow；CPP中原分派描述符只有类型/布局声明与static_assert，没有目标表生产或调用。这是当前接线事实，不是原端未知间接入向已闭合。

私有幂/指数/对数、除法、余数和三角数值由CPP的类型明确的单参/双参数学入口及std::pow/exp/expm1/log/log10/fmod/remainder/atan2/tan与原生除法承接；旧寄存器、T80暂存、P5缺陷修正、64项机器栈变形和FLAGS分派不再模拟。现普通pow仍保留错误门控，实际错误进入原40B错误记录/88B异常记录、errno与RaiseException路径。旧私有错误/状态帮助体的数值条件允许随标准数学变化，不将原完整原体标成等价或完整验收。

控制与状态接口直接读写宿主环境，无私有影子控制字/状态：MSVC `_control87`仅处理宿主支持的异常掩码和舍入，读取按现有位映射表示为旧W16形式；`double`按53位有效精度表示，PC/IC请求不传给x64不支持的接口。`_statusfp/_clearfp`及标准fenv承接异常标志读取、清除与生产；不承诺x87 TOP/C0–C3/等待时序/硬件异常触发完全相同。只在本三源的数值状态范围覆盖旧“不改MXCSR”要求，业务状态字段/错误记录生产与回调后读取仍保持。

原未生产记录的W32更新前读取与Shop命令读取采用已有MSVC `__movsd`明确复制一个DWORD，Count/成功NLS两BYTE采用`__movsb`逐BYTE读取，不在CPP对未生产S32/char直接求值；不猜读到的值、不补默认值，不声称未初始化生产问题或P07已修复。Nullsub仅保原RET空体；指数读取叶保高W32特殊分支重读。

宿主边界依据：[MSVC浮点控制接口](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/control87-controlfp-control87-2?view=msvc-170)、[DWORD复制intrinsic](https://learn.microsoft.com/en-us/cpp/intrinsics/movsd?view=msvc-170)。只用于确认现宿主能力，不作为原程序证据或新增依赖。

<a id="asm-cpp-final-acceptance"></a>
## 5. 本次静态验收与剩余门禁

核各入口/调用方、类型/布局、常量、计算与读取/写入顺序、条件/返回、CMake源项、提供者及历史引用；同步唯一进度、关联收尾任务与验收登记，再运行静态台账汇总器。只登记具名局部源码证据，不关闭完整B/I/W/S/R门禁或完整成员库存。

最新限制仍为单线程，不编译、测试、执行客户端/算法样例、检查编译产物或计算摘要。实际编译/链接、数值结果、声音/坐标/轨迹、状态与异常以及完整应用寿命待授权验收；整体SPEC未完成。

<a id="asm-cpp-source-state"></a>
## 6. 当前实施状态

数值取舍已按用户授权确定。音频源6入口已迁移为`LegacyAudioMath.cpp`，CMake改接CPP并删除音频ASM；音频记录定义从既有CPP移至私有头，布局与原调用保持。`log/sqrt`与中间`double`承接，I64向零转换用宿主SSE2接口，F32字段与表格/投影顺序保持。

地图源13入口已迁移为`MapEffectMath.cpp`并删除地图ASM，CMake改接CPP。CRT环境已由`LegacyFloatMath.cpp`与既有CPP值桥承接，删除第三ASM及MASM/专用对象名配置，仅启用RC。三份源迁移已完成，当前CPP未编译/链接/运行。

<a id="asm-cpp-audio-source-state"></a>
音频阶段ACP01-A对应6入口、5条现有原函数语义登记与V05。旧x87证据仍只绑定原命名快照；当前CPP仅登记接口/源码顺序的限定I/S静态证据，完整声音、状态、错误/设备与生命周期验收保持开放。

<a id="asm-cpp-map-source-state"></a>
地图阶段ACP01-M对应13入口、8条现有语义登记及U11/G04。原常量位样本、F32落存/后续消费、零/无序分支、I64截断、逐轴输入重读与发布、投影volatile参考时点和返回保持；CI幂依赖改为std::pow后再读取幅值。旧ST0/PC53保证被许可覆盖，其余原业务门槛、RNG调用与owner不改。只登记限定I/S，不代替轨迹/坐标/画面或ABI与生命周期运行验收。

<a id="asm-cpp-crt-source-state"></a>
CRT阶段ACP01-C已提供原22个CPP值/读取叶、类型明确的单参/双参宿主数学及F64分解/指数设置；70个私有ST0接口及5个非PUBLIC内核按本合同取消机器ABI，不用空函数冒充提供者。保留22接口的参数/返回与低宽读取；其它现提供者标记宿主承接/原私有接口退役，历史符号及逐指令证据保持固定快照。地图11个原临时027F效果叶由局部RAII保存/设置宿主全部异常掩码与最近舍入，在结果发布后恢复原宿主控制，保原数值作用域；两双向投影仍沿调用者当前控制，不追加局部控制。

普通pow仍消费真实错误门控，错误走40B数学记录、类型/掩码优先级、88B异常字段、回调门控/errno及系统RaiseException后重读/回写；对标准pow已落F64的次正规结果，在既有下溢错误入口前放大600h，再由掩码处理缩回，避免重复缩小最终值。原系统回调后PC字段实际使用的RC清位掩码也按旧指令保持，不按名称猜改旧算法。W32未生产字段/命令和两BYTE读取使用宿主复制intrinsic，P07仍未解决。原记录未生产载荷/高位不补零，正常别名/读取与字段发布顺序保留。

三ASM在现源码/CMake中均已移除；原111 PUBLIC中的41个值/读取入口由CPP提供，70个仅机器栈私有接口已取消，5个非PUBLIC算法按类型明确的宿主计算承接。此计数不是111个原函数等价实现或全功能验收。当前只核静态源码/接口/路径/登记，错误数值条件与硬件状态允许具名近似；原未知间接入向、完整CRT/原成员/机器与生命周期及总SPEC门禁继续开放。
