## 原端证据与当前承载

[机器归档](cg2d_workspace_byte_pointer_evidence.json)保原DA3F98的90个直接引用：
512E40的85个文本工作区基址读取、516B60的3个表生产引用、
5081A0（含516BF0尾块）的2个退出读取，无其他直接父或无函数数据引用。
原18槽由malloc分配表和各字节区，同编号槽接517690字节复制，退出由free释放。
NDR01已有全部85字段的源/工作区槽号与原两类读序证据，继续有效。
直接引用不证明未知间接别名或所有权/重进已闭合。

源码唯一workspaceSlots当前为void**，局部工作区快照也为void**，
表及元素分配/复制目的转换仍靠类型擦除。已证生产/消费均为字节缓冲，
本轮按原生已知T*规则收敛为std::uint8_t**，不新增结构或状态。

另归档四完整解码/格式入口196条/518B及244直接call：
517190为8/19、157调用；5171B0为16/50、85调用；
5176B0为49/113、1调用；517730为123/336、1调用。
前两均为512E40直接调用，后两分别经517190和517670消费。
原58B644字母表实63B含NUL，不将局部第64字节补零。
四入口当前正常流程已对应，本轮不改算法或正文，只补全语义与R1分类基线。

<a id="workspace-byte-decision"></a>
## 开发裁决

1. 一个CPP五个限定块：workspaceSlots成员/局部快照改std::uint8_t**，
   目的槽直接取std::uint8_t*；表malloc以18*sizeof(std::uint8_t*)承载，
   元素malloc结果转std::uint8_t*。仅已证地址槽原生拓宽，长度/数量不扩宽。
   std::fill_n的18个nullptr初值及每次malloc返回后重新取表发布保持。
2. 表和18元素继续同一SDK malloc/free域；没有新RAII清理、析构登记或新allocator。
   失败仍仅free当前首项、返-1，不清槽或补回滚；启动弃分配返回、
   退出18项每轮重读表/最后free外表、不清指针及原泄漏/悬空行为保持。
3. NDR01的38工作区基址先读/47容量先读、槽后读与逐字段完成规则保持，
   原账号引用、108命令/类型/回调/返回、实际明文帧及其他源码保持。
   std::uint8_t*只表达字节缓冲，原char*视图仍由既有复制返回边界提供；
   不引入UTF-8转换、严格文本门槛或新协议字段。
4. 四解码/格式入口本体不改：517190空指针返回0，非空交真实5176B0；
   5171B0非空交反转义，空指针先容量/缓冲/593850复制，再读当前缓冲返回。
   5176B0保仅首负号、原0-9/a-z/A-Z、无效字符0、W32基数62累积与S32返回；
   无效高位字节原S8比较与现有U8区间均拒绝，不改变接受字节集合。
5. 517730保63B原表/单字符不读容量/原负号与首字符写序；
   多字符余数按S32存储，先写前缀，再按capacity-2检查，失败不补NUL，
   正常末尾NUL/目的指针或NULL返回保持。数学溢出/非法地址等异常沿RPLAN.24，
   不新加拒绝、保护、钳制、回绕模拟或故障等价声明。
6. 只新增四既有入口的adapted分类。分配/退出与分派父只补当前类型合同，
   NDR01完整父未验状态不提升；实际SDK ABI/链接、所有owner/alias及运行继续待验。
   原格式明文、两算法叶排除、音频暂停及单线程保持。
