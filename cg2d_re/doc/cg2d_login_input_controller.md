# 登录输入控制器证据

## 范围与调用

本文只记录当前 `ida-17524/D:\SOFTSTAR\cg2d.exe` 的
`sub_45CA20@[0x45CA20,0x45CDF6)`：大小 `0x3D6`、287 条指令，原型为
`int32(mode)`，可观察返回值为 `-1、0、1、2`。唯一公开承接入口为
`login::ProcessLoginInput_45CA20`，由外层登录状态机调用。

函数的 22 个直接调用点对应 10 个唯一目标，均复用既有入口：一次能力探测、
两次 `QueryLoginControlState_5036F0`、四次 `IsRejectedInputText_404060`、两次
`DrawInputText_4568A0`、三次 `ReadKeyPressFlag_4597B0`、四次公共命中、两次
`SetContext_44B330`、两次 `DrawLoginControl_503780`，以及各一次图形和文字绘制。
没有为这些函数建立重复实现。

## 控件、探测与鼠标提交

低能力控件严格为：

```text
{338,390,288,364,100,52,0,22003}
{506,390,456,364,100,52,0,22004}
```

探测结果大于等于 1 时改用：

```text
{320,240,71,376,90,50,0,22238}
{320,240,195,376,90,50,0,22239}
```

入口初始化与探测位于 `0x45CA20–0x45CAE3`：`0x45CAC9` 先以原返回值比较是否
大于等于 1，`0x45CACC` 随后才写唯一 `render::gPaletteCapability`。鼠标路径位于
`0x45CAF7–0x45CB92`；第一个控件始终先查询，只有命中且
`mode==0` 时进入校验并跳过第二个控件，否则才查询第二个控件。因此非零 mode
仍会查询两项，但不会产生鼠标提交结果。

第一个控件的校验短路顺序严格为：第一文本 `strlen`、第二文本 `strlen`、拒绝
第二文本、拒绝第一文本。任一步失败把结果写为 -1；全部通过时依次读取两个
`totalByteLength@+0x12C`，写结果 1，再按第一、第二上下文顺序在该长度处补 NUL。
第二个控件命中且 `mode==0` 时写结果 2。

## 文本、按键与焦点

文本与按键段为 `0x45CB92–0x45CC5A`。`mode<2` 时固定依次把
`gInputContext9A5960`、`gInputContext9A5678` 传给
`DrawInputText_4568A0`。随后候选焦点从 -1 开始：先读取键 9，只有未置位才读取
键 13。触发后实时读取本控制器私有焦点状态：

- 焦点 1：候选改为 0；
- 焦点 0：再次独立读取键 13，不能复用前一次结果；未置位时候选为 1；置位
  时依次检查第一、第二文本非空，再拒绝第一、拒绝第二。失败时候选为 1；成功
  时与鼠标提交相同，读取两个总长度、写结果 1、依次补 NUL；
- 其他值：候选保持 -1。

矩形段 `0x45CC5A–0x45CD38` 在 `mode==0` 时按当时
`gPaletteCapability>=1` 选择两个焦点命中矩形。高能力右、下
边界分别为 `X+222/Y+21`，低能力为 `X+268/Y+25`；左、上均为 `X-5/Y-5`，
layer 为 206。第一项按 X 后 Y 读取，第二项按 Y 后 X 读取；两项独立测试，第二
项命中可把候选覆盖为 1。

焦点切换段为 `0x45CD38–0x45CD8B`。私有焦点 `0x55A048` 初值为 1，私有挂起
状态 `0x9A6E28` 初值为 0；它们不与
`gValue9A6E20` 合并。`mode>0` 先 `SetContext(nullptr)` 再把挂起状态写 1。
`mode<=0` 时，挂起非零会重读私有原始焦点并忽略本帧候选；否则只有候选 0/1
触发切换。仅在实际访问三项焦点表前，将 0..2 以外索引归一为 0；随后严格依次
`SetContext(table[safeIndex])`、清挂起、把私有焦点写回归一前的原始索引。

## 公共绘制尾部与安全差异

公共尾部 `0x45CD8B–0x45CDF6` 始终依次绘制两个控件，参数均为
`(layer=4,state=0,overlay=0)`，最后参数
严格为 `mode!=0` 的 0/1。背景表为 `{22002,22212,22311,22311}`；尾部实时读取
原 `gPaletteCapability`，仅在实际访问四项表前把 0..3 以外值归一为 0，不写回
全局，也不影响此前能力分支。随后严格依次：

```text
DrawGraphic(320,240,3,background,0,null)
DrawText3(540,424,0,0,"7.1.00",0)
return accumulatedResult
```

焦点表和背景表的两处归一是唯一有意安全差异，且都不写回原始焦点或能力状态；
新端不复现原 x86 越界栈别名，也不构造 `image338`。两个 `totalByteLength`
延续现有输入上下文有效域前提，不增加新的业务门禁。

## 尚未闭合的直接目标

本控制器 10 个唯一直接目标中，`Renderer::DrawText3@0x456560` 在当前源码仍只
有真实窄声明；其余目标均复用既有实现。这里没有为该目标补空体或固定返回，
因此完整最终链接仍取决于后续对该文字绘制入口的还原。
