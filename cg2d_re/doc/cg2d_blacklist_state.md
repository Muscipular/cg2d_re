# cg2d 黑名单共享状态与加载、插入、持久化证据

## 权威范围

本文的行为、地址和指令结论只依据当前只读 IDA 实例 `ida-17524` 中的
`D:\SOFTSTAR\cg2d.exe`；IDB 记录的原始输入 SHA-256 为
`dad3f292c6df28e9b7208ad1d339f56ab68c1e728f6595e849e37296551c0f08`。
当前同名磁盘副本的 SHA-256 为
`e7c2790f479862635932e043b2d7e93b9e791a1edc276a960af05f1454c54010`，
与 IDB 原始输入不同，不覆盖 IDA 基线，也不参与本项验收。STONAGE 不参与本项
行为、地址、语义或验收结论。

本项还原 `sub_401030` 的加载语义、`sub_401000` 的外层语义、其持久化 callee
`sub_4011A0`、`sub_401270` 的插入语义和四项共享状态 owner。

## `sub_401000` 边界与行为

- 精确范围：`sub_401000@[0x401000,0x401029)`，共 41 字节、11 条指令、
  3 个基本块。
- 原型：`char __cdecl(int32_t fileId)`；新端以
  `std::int8_t PersistAndReset_401000(std::int32_t fileId)` 保持 W8 返回值和
  signed W32 参数。
- 唯一 callee：`sub_4011A0@0x4011A0`。
- 唯一 caller：`sub_45D990` 中的 `call` 指令 `0x45DAE1`；调用者传入
  `gValue55A054`，并忽略返回值。

控制流严格为：

1. 以原参数调用一次 `sub_4011A0`。
2. 返回 AL 为 0 时立即返回 0，不写任何共享状态。
3. 返回 AL 为任意非零值时，先把 `0x5531A0` 以 W32 写为 -1，再把
   `0x59384C` 以 W32 写为 0，最后返回 AL=1。

该函数不清空记录表或路径，不附加文件 ID、路径、游标或空指针门禁。登录连接
控制器保持 `sub_5081A0`、本入口、`sub_508140` 的原调用顺序。

## `sub_4011A0` 边界与行为

- 精确范围：`sub_4011A0@[0x4011A0,0x401269)`，共 201 字节、72 条指令、
  13 个基本块。
- 原型：`char __cdecl(int32_t fileId)`；新端以 cpp 私有的
  `std::int8_t PersistBlacklistFile_4011A0(std::int32_t fileId)` 保持 signed W32
  参数，且 AL 只返回 0 或 1。
- 原二进制的 4 处直接调用指令位于 `0x401005`、`0x4012DB`、`0x4013BE`、
  `0x4014A1`；其中 `0x4012DB` 属于本项新增的 `sub_401270`。新端源码现有
  `PersistAndReset_401000` 和 `AddBlacklistRecord_401270` 两处调用，尚未接线其他调用方。
- 直接库调用依次覆盖 `sprintf`、`fopen`、循环内的 `fputs` 两次和 `fclose`。

控制流严格为：

1. 建立全零的 512 字节局部路径缓冲区，以 `sprintf` 和原 signed W32 参数格式化
   `data\blacklist_%d.txt`，忽略返回值。
2. 将局部路径与共享路径作内联、区分大小写、逐字节至 NUL 的比较；新端用
   `strcmp` 只判断相等或不等，不依赖其返回值符号。不等时立即返回 0，不打开
   文件，也不写四项共享状态 owner。
3. 相等时严格以共享路径作为 `fopen` 参数，并以 `w` 模式打开；不改用局部路径，
   也不检查返回的 `FILE*`。
4. 按共享记录表的固定顺序最多遍历 100 条、每条 17 字节。每轮只先检查首字节；
   首字节为零就立即结束。否则将记录首地址作为 C 字符串调用一次 `fputs`，再以
   `"\n"` 调用一次 `fputs`，两次返回值均忽略。源代码提交 LF；Windows CRT 的
   文本 `w` 模式在磁盘上写为 CRLF。
5. 循环结束后无条件调用 `fclose` 并忽略结果，返回 AL=1。

该函数不读取 `gCursor`，不按长度写入，不补 NUL，不做编码转换，也不检查
`fileId`、目录、打开、写入或关闭结果；它本身不写 `gRecords`、`gPath`、
`gCursor` 或 `gCurrentFileId` 中任何一项。`fopen` 返回 NULL 时，原控制流仍会把
该值传给后续 `fputs` 或 `fclose`；17 字节记录若首字节非零但没有 NUL，`fputs`
也会继续越过该记录寻找终止符。这些异常域按原函数保留，不新增恢复、重试或
失败返回门禁。

## `sub_401030` 加载边界与行为

- 精确范围：`sub_401030@[0x401030,0x401167)`。
- 原型：`char __cdecl(int32_t fileId)`；新端以地址中立公开入口
  `std::int8_t LoadBlacklistFile(std::int32_t fileId)` 保持 signed W32 参数和
  公开 W8 返回值。完整 EAX 高位不属于新端 API 契约。
- 唯一 caller 是 `sub_45D990`；调用者传入 `gValue55A054` 并忽略返回值。
- 直接库调用只覆盖 `sprintf`、`fopen`、`rewind`、`fgets` 和 `fclose`；加载逻辑
  不调用或复用 `sub_4011A0`。

入口先依次清零共享路径的全部 512 字节和记录表的全部 `100 * 17` 字节，不清
游标或当前文件 ID；随后用 `sprintf` 格式化 `data\blacklist_%d.txt` 并以
`rb+` 打开。打开失败时不调用 `rewind`、`fgets` 或 `fclose`，也不改变游标；
所有路径最终都把当前文件 ID 写为参数并返回 1。

文件打开成功后先 `rewind`，再检查 `feof`；只有未处于 EOF 才进入由 `feof`
驱动的循环，不能改写成以 `fgets` 返回值为条件的循环。每轮先按当前 signed W32
游标定位 17 字节槽，以长度 17 调用一次 `fgets` 并忽略返回值，再重新采样游标
和对应槽：

1. 槽首字节为 NUL 或 LF，或槽首两个字节为 CRLF 时，先对本轮采样游标作 W32
   位模式回绕减一并写回，再将刚读取的原槽恰好 17 字节清零，然后检查 `feof`。
2. 其他记录（包括首字节为孤立 CR 的记录）进入索引 0 至 16 扫描：NUL 结束扫描；
   CR 后紧跟 LF 时将两个字节清零并结束；LF 只清当前字节并继续；孤立 CR 保留。
   索引 16 的 CR 后继读取不新增边界保护，以保留原函数的非可移植异常域。
3. 接受记录后，对本轮采样游标作 W32 位模式回绕加一并写回；仅新值恰好等于
   100 时退出，否则再按 `feof` 决定是否继续。

非空 `FILE*` 的所有路径恰好调用一次 `fclose` 并忽略结果。W32 增减通过
`std::bit_cast` 保持位模式回绕；实现不增加文件 ID、游标、容量、读取错误、目录
或权限门禁。无效游标和越界访问仍属于原函数的非可移植异常域，仅保持无门禁，
不宣称具体破坏落点等价。该加载入口与两个持久化入口各自保持独立实现。

## `sub_401270` 插入边界与行为

- 精确范围：`sub_401270@[0x401270,0x4012E6)`，共 118 字节、45 条指令、
  10 个基本块。
- 原型：`char __cdecl(const char* name)`；新端以公开入口
  `std::int8_t AddBlacklistRecord_401270(const char* name)` 保持 W8 返回值（AL=0/1）。
- 唯一 callee 为 `sub_4011A0@0x4011A0`；原二进制 3 处调用指令分别位于
  `0x4018A7`、`0x44AD33`、`0x507891`，均测试 AL。新端本步不接线 caller。

入口仅在 `gCursor == 100` 时立即返回 0；此路径不读 `name`、不扫描或写入记录、
不读当前文件 ID，也不持久化。其余路径从 `gRecords[0]` 开始，逐条以 17 字节
步长检查首字节，直至首个空槽或恰好扫完 100 槽。找到空槽后，先完整计数
`name` 含终止 NUL 的字节数（原 `repne scasb`），再按低地址到高地址将这些
字节逐一前向复制到该槽（原 `rep movsd/movsb`）；空字符串也复制 NUL。复制后
重新读取 `gCursor`，按 W32 位模式回绕加一并写回，不使用入口比较时的缓存值。

扫完 100 槽且所有首字节均非零时，即使入口游标不等于 100，也不复制或增加
游标，仍执行后续路径并最终返回 1。所有非早退路径均在扫描及可选复制之后
读取 `gCurrentFileId`：非负时以该值调用一次现有私有持久化函数并忽略其 AL，
负值则跳过；两者最终都返回 AL=1，文件持久化失败也不改变本入口返回值。

本体对四项原状态的直接访问为：读取 `gRecords` 槽首字节、仅在找到空槽时
写入该槽；原函数仅使用 `gPath` 起始地址作记录表尾界，不直接读取路径内容，
新端以固定 100 槽判尾；入口读取 `gCursor` 作等于 100 的比较，复制后再读取
并写回；非早退路径读取 `gCurrentFileId`，本函数不写它。持久化 callee 对路径
和记录的间接读取见上节。正常有效输入域要求 `name` 可读且以 NUL 终止、
与目标不重叠、文本长度不超过 16 字节（含 NUL 最多复制 17 字节）；不增加
长度、去重、空指针或截断门禁。超长、重叠、无 NUL、空指针及无效游标仍为
原函数的非可移植异常域，不宣称具体越界破坏
落点等价。

加载、插入与持久化边界已经按当前证据实现；这不代表最终链接、服务器连接链
或整体客户端已经闭合。

## R6.1.3.158：`sub_4013D0` 查询证据与未决门禁

本节仅记录 Carson 交接事实，文档任务为 `R6.1.3.158.D`；主状态仍为
`NEEDS_CLARIFICATION`，未编码。源码状态固定为基线 `7653aa4` 的快照，
后续落实以[唯一执行进度](../plan/cg2d_full_reconstruction_progress.md)为准，
不把本节视为实现许可或已获批 SPEC。

### ABI 与返回值

- 精确范围：`sub_4013D0@[0x4013D0,0x401463)`，147 字节、69 条指令、
  20 个基本块、单 chunk，无 callee。
- `0x4013D2` 读取入口栈指针 `S+4` 处的一个 W32 指针；cdecl，只读字串输入，
  无 this，各 caller 均清栈 4 字节。这里只确认本入口 ABI，不代表 caller ABI 已审。
- 返回合同仅为 AL 的 W8 0/1：`0x40145F: mov al, 1` 表示命中，
  `0x401458: xor al, al` 表示未命中。完整 EAX 不保证为 0/1；
  末次比较结果为 -1 且最终未命中时，EAX 可为 `0xFFFFFF00`。
- 本体无状态或文本写入、I/O、分配、持久化。

### 固定遍历与字节读取合同

外循环在 `0x4013D8` 从 `0x592FA8` 开始，`0x40144A` 每次步进 17 字节，
`0x40144D` 比较 `0x59364C`，`0x401453` 以 signed `jl` 决定继续；
覆盖固定 100 槽、合计 `0x6A4` 字节，末槽起址 `0x59363B`。
不读 `gCursor`，不用 72 门槛、不计非空槽，也不遇空槽早退。

每轮先在 `0x4013DD` 取右侧共享串地址 `0x593850`，在 `0x4013E2` 取左侧输入；
第一段 `0x4013E4..0x401411` 内联比较二者。相等时经 `0x401413` 转入槽推进，
完全不读本槽记录；仅不等时才执行 `0x401415..0x401446`，以记录为左、输入为右
作第二段比较。第二段相等时由 `0x401448` 转入命中返回。

两段均按每对字节执行以下读取顺序，不能直接以 `strcmp` 替代已核合同：

1. 先读左侧第一字节，再读右侧第一字节；不等时按 unsigned 比较，经 SBB
   归一为 -1/+1。相等且左字节为零即结束；仅相等且非零才读取第二字节。
2. 第二字节同样先左后右，不等时作相同归一；相等后两指针各加 2，再依据
   第二字节是否为零结束或继续循环，不提前读取下一对字节。

| 比较段 | 两次不等分支 | 两次零判断 | 结果处理位置 |
|---|---|---|---|
| 输入 / `0x593850` | `0x4013EC`、`0x4013FC` | `0x4013F0`、`0x401406` | `0x401408`、`0x40140C`、`0x40140E` |
| 记录 / 输入 | `0x401421`、`0x401431` | `0x401425`、`0x40143B` | `0x40143D`、`0x401441`、`0x401443` |

空记录遇非空输入继续遍历；空输入在共享串非空时可命中空记录。只有共享串
确为空串时，空输入才会在 100 轮中均跳过记录比较，最终返回 AL=0。
本体无空指针保护、不先读长度、不设 17 字节限长；缺 NUL 且字节持续匹配时，
记录读取可跨槽延伸到路径区域。`0x59364C` 只是循环尾界，不是直接读取路径的
指令，但它不阻止上述越槽读取。
