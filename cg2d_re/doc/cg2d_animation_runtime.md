## 2. 三个查询叶

`45B420@[45B420,45B439)` 是 qsort 比较器。
`45B428/42A/42C` 先取两记录首 W32，按无符号
比较返回 `-1/0/1`；相等返回零，左小于右返回
-1，左大于右返回 1。新端不以有符号减法
冒充该比较，保留相等元素的比较值。

`Animate::BinarySearch@[45B390,45B3F7)` 的入参
依次为无符号 W32 图号和有符号 S32 `min/max`。
起始 `min>max` 返回 -1；`max-min>=10` 时取
`min+(max-min)/2` 的整数中点，按原表步长
`0x24` 读取首 W32，与图号作无符号比较；
相等立即返回中点，大于图号将 `max=mid-1`，
小于图号将 `min=mid+1`，交错后返回 -1。
跨度小于 10 时从 `min` 到 `max` **包含上界**
逐项顺扫；首个相等即返回下标，否则 -1。
新端不重新排序、去重或改成半开区间。

`Animate::getIndex@[45B400,45B41D)` 只读取
`gAnimateCount`，传 `(图号,0,count)` 给上叶，
负结果转成 -1，其余原样返回。直接 caller
包括 `Yobi::FrameMove@517974`、
`Yobi::PlayFrame@517F7E` 与
`CoordLoad@45BFE8`；三个调用链均未因
本叶静态落位而闭合。

## 3. 满容量一过尾

原 `AnimeInit` 只排序前 `count` 项，
而 `getIndex` 将 **count** 当包含上界：
`count<20500` 时，`GraphicAlloc` 清零过的
尾项仍位于已分配区间，不能静默改作
`count-1`；`count==20500` 时，原指令可能
读出所分配的 `20500×0x24` 之外一项，
其原 x86 内容没有确定的业务值。

新端的 x64 backing 在 `GraphicAlloc`
实现中为索引 20500 额外预留一项零哨兵，
而对真实 `count` 项的清零、填充及 qsort
范围保持原样。这是消除宿主越界的确定性
兼容裁决，不声称原端满容量一过尾值为零；
只有受该未定义值影响的满容量分支不纳入
逐次等价。分配生产者尚未接启动链，
不得在分配前调用查询或把静态库编译当作
`FrameMove`、SDL 画面、完整链接/运行验收。

### 7.1 未定义域和资源证据

门禁；不在此域的记录会越过 20500 项栈表。

## 8. `AnimeLoadAction` action 与帧生产

2026-09-27，现有 `ida-17524` 只读核 `[45B760,45BB1F)` 全部指令、
反编译及直接 caller `FrameMove@517990/PlayFrame@517F9A`。
新端完整本体复用 `AnimationRuntime.cpp`、既有主表/槽链/清理函数，
下游 `CoordInit_45C150` 同步实现，见 §9。不引入独立资源副本。

### 8.1 布局与原宽度

既有私有 `ActionEntry` 的 32B x64 大小、frames 在 +18 的原生指针
位置不变，只把已证 24B 前缀细化；原无指针帧和坐标不扩宽。

| 原 action 偏移 | 新端字段与写入 |
|---|---|
| +00/+02 | direction/action 低 W16 |
| +04 | U32 duration，先低 W16、再合高 W16；帧数非零时执行无符号 `duration/(16*frameCount)`，结果为零再写 1 |
| +08 | 磁盘 duration **低 W16 的零扩展值**，不是未经折算的完整 duration |
| +0C | U32 frameCount，同样先写低 W16 再合高 W16 |
| +10/+12 | 扩展头 paletteIndex/revert 的 W16；短头各写零 |
| +14 | 扩展头 W32 的两半，短头写 FFFFFFFF |
| +18 | 原 W32 frames 指针扩为现有原生指针，其他字段不移动 |

运行时 `FrameEntry` 为 12B：+0 U32 图号、+4/+6 坐标 W16、+8 flag W16，
末两字节不由装载写入。磁盘帧为 10B，每帧依次写图号低 W16、
合高 W16、加 `GraphicInit` 的来源槽基址，再写 x/y/flag；
不把末两字节补成零或把十字节磁盘记录直接作为运行时步长。
静态断言表达要求，本轮未构建，不声称新断言已由编译器验证。

### 8.2 控制流与失败边

- `45B77E–45B79C`：先取文件槽低 U16；actionList 非空则调用既有
  `45B5B0` 移到链左端、返回 1，不再读文件或坐标。
- `45B7A8–45B80C`：领取 `45B530`，空返回 0；非空先 seek，再读
  `gGraphicStartIndices[fileIndex]`，最后才检查 count。count=0 返回 0，
  不把取出的槽归还、不新增清理。
- `45B80D–45B89F`：按 x64 action 大小分配并发布，成功后先写
  槽 index、主记录 listNode，调用 `45B590` 链接，再写槽的旧字节计数
  `28*count`，最后按新步长清子表。旧计数是原运行状态，不改成 `32*count`。
- `45B8AC–45B9C5`：主表 count 的 U16 大于 10000 才拒绝；
  action 的 U32 frameCount 大于等于 10000 则拒绝。后者门禁在
  duration 的原除法之后，不提前移动。flag 的 U16>=1 读 20B，
  否则读 12B；不把 cg3a 的 `flag==1` 判断搬入这里。
- `45B9D2–45BA83`：包括帧数零在内都调用 `malloc(12*frameCount)`；
  返回非空后先加槽字节计数，再以一次 `fread(10*frameCount,1)` 读帧。
  不把零帧特殊处理为失败/成功，也不依据 fread 返回新增分支。
- action 分配、两个计数门禁、帧分配或 CoordInit 失败均走
  `45BAC6→45B440(&slot.index)` 再返回 0；仍按已落位的清理函数释放
  帧、子表、坐标并置槽 index=-1，不额外摘链、归还或恢复业务状态。
- `45BADC–45BB0C`：坐标成功后按原坐标 count 加 `8*count`，
  先增活动项数，再累加槽字节计数。无坐标文件的原跳过返回 1
  不改变这项累计规则。

原 `sub esp,7E4` 加四个寄存器保存后，从 `[esp+24]` 开始的共享
读取区到局部区末端是 **2000B**；Hex-Rays 显示 `Buffer[20]` 仅覆盖头部，
不能据此只分配 20B。新端同一 `uint16_t[1000]` 用于头和帧，
不预清零、不扩为 10000 帧、不增加新的帧数拒绝。原帧数门禁不能
保证该栈区不越界；越界、数学溢出等按 RPLAN.24 不专项处理，
短读未写字节不猜值，不宣称原故障现场等价。

可信 `AnimationLoader.cpp` 的 12/20B action 和 10B 帧格式用于对照，

## 10. `FrameMove/PlayFrame` 真实播放状态推进

2026-09-27，本线程只读核 `517880@[517880,517D9D)`、
`517DA0@[517DA0,5182A1)` 全部指令与反编译，完整接入既有动画查询、
action 装载、Graphic 查询/加载和现有音效入口。实现留在唯一
`YobiRuntime.cpp`，没有重建另一套动画状态或私有资源快照。

### 10.1 同源状态与入口差异

新增已证标量仍属于现有私有 `YobiAction`，不搬出 opaque 对象：
原 +2AC/+2B4/+2BC 为上次图号/动作/方向，+2C0 是帧下标 W32，
+2C4 为剩余计数，+2C8/+2CC 为绘制偏移，+2D0 为帧事件，
+2D4 为隐藏值，+2DC 为结束/循环计数，+2E0 保存完整停播参数，
+2F0/+2F4 为帧与坐标文件叠加后的偏移。
既有 `calloc(sizeof(YobiAction))` 负责这些字段首轮清零，
不新增特例构造或对用户对象附加旁表；原 x86 偏移仅作来源证据。

| 合同 | FrameMove `517880` | PlayFrame `517DA0` |
|---|---|---|
| 空指针、隐藏 | 均在对象为空或 +2D4 严格为 1 时返回 0；不把任意非零当隐藏 | 同左 |
| 图号 <=999 | 只清 graphicIndex，返回 0 | 同左 |
| 静态图分支 | `[1000,100000)` 及 `>=200000` | 仅 `[1000,100000)`；不照搬前者的 200000 分流 |
| 静图方向翻转 | 仅第四参数低 W8 非零时按方向 2..4 设横翻 | 始终按方向 2..4 设横翻 |
| 动画速率 | 第二参数的 W32 位型 | 选中 action 后才读取对象 +2A4，不提前捕获 |
| 末帧停播 | 停播参数**严格等于 1**时写 remain=255、循环槽=1、返回 1 | 同样严格等于 1，不是反编译 `BOOL` 表达的任意非零 |

`517A57/518063` 都将参数与 EAX=1 比较；本轮曾在阅读反编译时
误判第二入口为任意非零，已在编码前按指令纠正，不将该误判写入源码。

两入口都先读取当前动作、写 playRevert，再比较上次动作/方向/图号；
任一改变时依次写上次动作、图号、方向并清 remain、帧下标和循环槽。
remain 非零先递减即返回 0，负值亦不另加恢复。
静图分支保持各自字段写序，设置 remain=7FFFFFFF、独立调色板索引零、
混合模式及颜色 FFFFFFFF，最后清 frameX/frameY。

### 10.2 动画查找、帧与副作用

1. 动画图号有符号 `>gMaxAnimateCount+100000` 返回 1；否则减去
   100000 交已有 `GetIndex_45B400`，负结果返回 1，真实
   `AnimeLoadAction_45B760` 返回零则返回 -1。不把这些返回合成 bool。
2. actionCount 取低 U16；零或找不到动作返回 1。查找顺序不变，
   direction/action 的记录 W16 **零扩展**后与对象 S32 相等比较；
   不因为结构中用 int16_t 存位型就改成符号扩展比较。
3. 对选中 action 的 duration 作 W32 乘积，再无符号除以 100，
   发布 remain，结果小于 1 才写 1；保留之前捕获的 frames 引用。
   帧下标以 U32 与 frameCount 比较；非停播回绕时先清帧下标再递增循环槽。
   不增加空 frames/零 frameCount 的新门禁。
4. flag W16 非零且 >=10000 时写原 +2D0；1..9999 在场景不是 9，
   或对象 flags 与 80200 无交集时调用现有 `PlaySe_52C450(flag,x)`。
   原额外 y 压栈未被该已证音效入口读取；本步不改音频实现。
   flag=0 不清旧事件，也不产生新音效。
5. 先清 drawMode 混合低两位，再发布当前帧 graphicIndex，调用既有
   `GetGraphicXY`，叠加帧 x/y 生成绘制偏移；随后写独立调色板 W16、
   revert 低 W8、value14 W32。只改 descriptor 的 +0E/+0D/+08，
   不扩写邻字段。
6. 翻转位非零才调用真实 `LoadGraphic_522570`；返回非零后，按需要
   分别读取同一 DX 表的宽/高低 S16，再作 `-(offset+dimension)`。
   新增 `ReadGraphicDxWidth/Height` 仅为渲染边界的窄读取，
   不加载、不判图号、不预取另一维，也不暴露 DX 条目或底层 surface。
7. 按当前 graphicIndex 在该动画坐标表顺序查找首个匹配项；先写帧
   x/y，再按当前坐标 count 门禁叠加坐标偏移，然后分别按混合低两位
   取负。最后先写帧下标+1，再写 remain-1，返回 0。

两个入口只共享上述已核对相同的帧应用和尺寸翻转阶段；前缀门禁、
静图写序和速率来源独立实现，未用额外策略表改变行为。
可信 `src/world/AnimationState.cpp` 提供帧偏移合成等参考，但其
deltaMs、多帧追赶、取模采样及空帧回退不是本端上述状态推进，
未拿它替换原每次调用的计数与事件消费。
