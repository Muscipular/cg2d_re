## 四组跳转表陷阱

四组分发都不能直接按反编译器生成的普通有符号 `switch` 理解。

1. 主状态：`0x461005` 以无符号 `ja` 检查 `state > 21`，
   `0x461013` 经 `jpt_461013@0x461A78` 分发 22 项。负状态按位解释后也走
   默认，不会命中正数状态。状态 3 与范围外值只跳到主分发尾部。
2. 第二分类：`0x4614AF` 先以无符号门槛 20 检查，再以
   `byte_461AD8@0x461AD8` 映射到 `jpt_4614BC@0x461AD0`。状态
   0..9、19、20 走第一条返回路径；10..18 以及无符号范围外值进入两槽
   角色循环。特别是状态 21 并不走早退。
3. 动作：`0x461500` 以无符号门槛 6 检查，
   `jpt_461509@0x461AF0` 的 3/4、5/6 分别共用目标。返回 -1 的位模式大于
   6，必须走默认动作，不能误作数组下标。
4. Puk 版本：`0x461A20` 先把 `0x9A6E1C` 截为 `uint8`，再以无符号门槛
   7 检查 `jpt_461A2A@0x461B0C`。0/2、5/6 各共享发送分支，7 使用独立
   载荷，1/3/4 及范围外值不发送；不论是否发送，只要更新标志非零，尾部
   都把场景状态清为 0。

第二分类形成两条不同返回路径：

- 状态 0..9、19、20 直接返回
  `sub_45F090(0,0,3,245060,0,-1)` 的结果；
- 其余状态完成两槽循环、按钮和背景绘制后，返回更新标志 0、版本发送结果，
  或没有发送分支时的 Puk 数值。尾部背景绘制结果在这条路径上会被覆盖。

## 角色列表读取进度 `sub_45DD50/sub_45DD60`

### 边界、调用与返回域

- 重置函数范围 `[0x45DD50,0x45DD5A)`，共 2 条指令、1 个基本块；更新函数
  范围 `[0x45DD60,0x45DED9)`，共 118 条指令、12 个基本块。
- 更新函数有 6 个真实 `call`，目标为 `sub_5044E0`、`sub_508910`、
  `sub_508950`、`CryptInt::gte`、`Yobi::MarkDeath` 与
  `Renderer::DrawText3`。
- 两个函数的唯一调用者都是 `sub_460FF0`：状态 0 调用重置，状态 1 调用
  更新。重建以
  `ResetCharacterListProgress_45DD50/UpdateCharacterListProgress_45DD60`
  两个公开入口直接替代旧声明，场景控制器不经过包装层。
- 更新函数的已确认返回域为 `{0, 1, -1, -2, -3}`。外层场景控制器仍按
  原函数保留 `-4` 分支；不能因当前依赖返回域使该分支不可达就将其删除。

### 私有状态与阶段时序

`0x9A6E5C` 是映像零值的 `uint16` 阶段；`0x9A6E60` 是映像为空的原生
`YobiAction*`。`0x9A5554` 的文本 `char[256]` 以及列、行、X、Y 四个
`int32` 布局值也都是映像零值。这七项的全部 xref 都局限在本函数对内，因此
新端均在实现文件的匿名 namespace 中静态持有，不从内部或公开头文件导出。
重置函数只以 16 位宽度把阶段写为 0，不清对象、文本或布局。公共文本绘制
只读取该私有文本缓冲；本次文本恢复不新增分配、释放或所有权转移。

更新入口先采样阶段并把结果初始化为 0：

1. 阶段 0 将“登入成功，開始計費！”的原字节常量连同 NUL 共 21 字节复制
   到私有缓冲，写阶段 1，计算布局并调用 `sub_5044E0(192,192,256,96,4,1)`。
   返回值即使为空也先写入私有对象槽；随后重新读取阶段，因此同次调用继续
   阶段 1。
2. 阶段 1 调用 `sub_508910`，忽略其 `uint32` tick 返回，再以 16 位阶段
   自增为 2。首帧由这条分支结束阶段分发，不会同帧调用 `sub_508950`；因此
   全局阶段可在同一帧完成 0→1→2，但首帧不轮询。
3. 阶段 2 调用 `sub_508950`。返回 0 时保留对象并进入公共绘制；返回非零时
   重新读取对象，非空才调用 `Yobi::MarkDeath`，随后无条件清空对象槽并
   原样返回，不绘制终态帧。
4. 其他阶段不调用启动或轮询目标，只进入公共绘制并返回 0。

提示框建立失败不阻止同次阶段 1 发起请求；对象为空只会跳过公共绘制。

### 原字节、NUL 与复制尾部

`kCharacterListProgressText` 对应原址 `0x55C864`，原 Big5/CP950 字节
（含首个 NUL）为：

```text
B5 6E A4 4A A6 A8 A5 5C A1 41 B6 7D A9 6C AD 70 B6 4F A1 49 00
```

正文严格为 20 字节，范围 `[0x55C864,0x55C878)`；首个 NUL 位于
`0x55C878`，含 NUL 长度为 21。原机器执行顺序为：

- `0x45DD73` 的 `mov edi,offset 0x55C864` 取常量首址；
  `0x45DD78..0x45DD82` 置 `ECX=-1`、`AL=0` 并执行 `repne scasb`，
  随后的 `not ecx` 得到含 NUL 的 21，`sub edi,ecx` 回到首址。
- `0x45DD86..0x45DD91` 以 EAX 保存 21、ESI 指向常量、EDI 指向私有缓冲
  `0x9A5554`，ECX 右移 2 得到 5；`0x45DD94` 的 `F3 A5`
  （`rep movsd`）依次向 `0x9A5554/0x9A5558/0x9A555C/0x9A5560/0x9A5564`
  写入 5 个 DWORD，覆盖正文 20 字节。
- `0x45DD96..0x45DD9A` 恢复 21 并取 `21 & 3 = 1`；
  `0x45DD9F` 的 `F3 A4`（`rep movsb`）把 `0x55C878` 的 NUL 写到
  `0x9A5568`。总写入区间为 `[0x9A5554,0x9A5569)`，共 21 字节；
  沿用的 256 字节容量中，尾部 `[0x9A5569,0x9A5654)` 的 235 字节不写。
- `0x45DDA1..0x45DDAD` 在复制完成后重新扫描，得到正文长度 20；
  到 `0x45DDBC` 才以 W16 写阶段 1。片段内的 `push` 写入栈，不是文本
  缓冲写入。

此前 UTF-8 常量的 `sizeof` 为 31；本项沿 RPLAN16 恢复上述原字节后，
`sizeof(kCharacterListProgressText)` 为 21。源码恢复合同仅调整常量、
注释及含 NUL 的 21 字节断言，其他语句不变。
阶段 0 既有 `std::memcpy(..., sizeof(kCharacterListProgressText))`
自然改为覆盖缓冲偏移 `[0,21)`，NUL 在偏移 20，余下 235 字节保留，
不补清零。上述地址序列是原机器证据；保留 `std::memcpy` 不保证新产物
生成相同指令序列。

### 固定旧编码布局与未决依赖

正文长度常数仍为 20；恢复原字节不改变固定公式，也不改取动态文本宽度，
不得通过 UTF-8 字节数或 `strlen` 重算。列数 `20 / 8 + 2 = 4`，行数 2，
`x=((10-4)*64)/2=192`，`y=192`；公共绘制坐标为
`xText=192+(4*64-20*8)/2=240`、`yText=192+(2*48-16)/2=232`，参数为
`DrawText3(240,232,2,0,text,0)`，返回值忽略；框为 `(192,192,256,96)`。
对象就绪只通过接收真实
`YobiAction*` 的 `IsYobiActionReady(action,1)` 窄边界判断，不在上层硬编码
原 x86 `+0x170` 偏移。

`sub_5044E0`、死亡标记和 readiness 适配已接入统一 Yobi runtime；
`sub_508910/sub_508950` 仍只保留真实声明，不提供空实现或固定成功桩；
`DrawText3` 已通过登录侧薄适配接入唯一文本提交实现。

### 实际桥接、队列副本与呈现边界

实际桥接为 `CharacterSelectSceneDependencies.hpp` →
`LoginMessageDependencies.hpp` → `LoginStateDependencies.hpp:41`；
`login::detail::DrawText3` 直接转发到 `render::DrawText3_456560`。
桥接的 X/Y 为 S16，mode、color、value7 为 S8，text 为 `const char*`；
桥内无转码，也无另一个文本缓冲。这里不是普通 `DrawText` 的 mode U8、
marker 0 路径。

队列合同继承 R6.1.2.16：`DrawText3` 向 `DrawText2_456670` 传
marker `0xF9`、font 0。队列有 4096 个独立记录，每条大小 `0x110`；
X/Y 存储为 S16，color、font、renderMode、value7、marker 存储为 U8，
`text[255]` 位于 `+0x09`，`field108` 为 S32，`nextToken` 为 U32。
从列表私有缓冲同步复制含 NUL 共 21 字节到记录文本区 `[0,21)`，
记录文本区尾部 234 字节不清；它与静态源缓冲中未写的 235 字节尾部不同。
token 是一基记录索引，记录不保留源文本指针；队列副本有效至记录覆写，
该文本提交不新增分配、释放或所有权转移。

既有提交顺序是先检查计数、模式、指针与长度，再写字段和文本，之后才检查
尾 token；不能把所有失败返回概括为无写入。font 0 的初始双字宽为 17，
不用于改写上述固定布局。此处仅闭合原字节、复制及提交边界；字形解码、
真实呈现与画面一致性仍未闭合，不据此宣称已通过呈现验证。

### 初始化、点击与绘制顺序

每次更新先把返回值初始化为 0、悬停初始化为 false，并使用一份 16 字节图形
描述：坐标和尺寸均为 0，颜色为 -1，裁剪为 0，混合模式为 4，调色板为 0。

1. 阶段为 0 时，先写阶段 1，再依次保存未知值 -2、宽 512、高 144、X 64、
   Y 168，最后调用 `sub_5044E0(64,168,512,144,4,1)` 并原样保存返回指针。
   建立失败后阶段也已是 1，后续帧不会重试。
2. 初始化后无条件先检测按钮。左边界为 `x+((width-66)>>1)`，检测调用严格为
   `sub_5049A0(left,y+115,left+66,y+132,-1)`；矩形的半开边界语义由该依赖
   承接，不在调用层改写。
3. 命中时置悬停，并读取共享 `0xD68D9C` 的低 8 位 bit 0。点击时先把返回值
   写 1，再播放 `(51,320,240)`；私有对象非空则标记死亡并清槽，随后立即
   返回 1。该路径不绘制，且对象为空时仍返回 1。
4. 非点击路径中，对象为空或 `CryptInt::gte(action+0x170,1)` 不成立均返回
   0。就绪时先调用
   `DrawText3(int16(x+140),int16(y+20),2,6,kAuthenticationFailedText,0)`，再调用
   `DrawGraphic(x+width/2,y+123,uint8(0xDF),hover?243050:243048,0,descriptor)`，
   最后返回 0。

原字符串的 CP950 字节（含首个 NUL）为
`B5 6E A4 4A BB 7B C3 D2 A5 A2 B1 D1 A1 43 00`。原字节来源绑定
`UpdateAuthenticationFailure_45D7E0`，不另猜字符串的独立 RVA。
“源码只保存对应 UTF-8 文本”仅描述历史阶段；源码文件仍为 UTF-8，本次 C
限定恢复 `CharacterAuthenticationFailure.cpp` 的 `kAuthenticationFailedText`

font 0 初始双字宽 17 不改变上述固定布局；字形解码、真实呈现与画面一致性

### 对象建立、下标与字段顺序

对象通过强类型边界调用 `YobiAction::new(2,0)`：第一参数 `priority` 是 W8
unsigned，第二参数 `yobiSize` 是 W32 unsigned。IDA 在 `0x404B85` 以
`mov dl, byte ptr [arg_0]` 读取 `priority`，并在 `0x404C1A..0x404C1D` 以
W8 `cmp` 后接无符号 `ja` 比较；在 `0x404B2F` 以 W32 读取 `yobiSize`，
`0x404B33..0x404B35` 与 0 比较后接无符号 `jbe`。调用处据此显式传入
`std::uint8_t{2}` 与 `std::uint32_t{0}`。返回指针必须先写入
`gPreviewActions[slot]`，再判空；分配失败返回 0。`converted` 到表下标的
分支和顺序如下，不增加范围保护：

| 条件 | 下标 |
|---|---|
| `converted` 在闭区间 `[270000,270200]` | `q=(converted-270000)/100`；`q==0` 取 6，`q==1` 取 10，其他取 `q` |
| 否则在闭区间 `[205000,205600]` | `(converted-205000)/100` |
| 否则 `converted >= 241400` | `(converted-241400)/100` |
| 其他 | `(converted-240000)/100` |

建立成功后重新读取规范化的记录 `+0x18`。值为 33100、33101 时分别只对
对象 `+0x2A8` 写一次 100900、100901。普通路径先把所选表项写到
`+0x2A8`，再经窄 getter 重新读取该字段，计算
`field + 6 * ((converted % 100) / 25)` 并二次写回。其后严格按下列顺序写入：

| 顺序 | 原字段 | 宽度 | 值 |
|---:|---:|---:|---:|
| 1 | `+0x2B0` | W32 | 0 |
| 2 | `+0x15` | W8 | 10 |
| 3 | `+0x30` | W32 | `315 * slot + 163` |
| 4 | `+0x34` | W32 | 292 |
| 5 | `+0x2B8` | W32 | 5 |

所有字段访问都通过接收真实 `YobiAction*` 的窄 getter/setter 实现；新端不
建立原 x86 `0x330` 字节布局，也不在调用层做偏移运算。原单角色槽函数的
`+0x2B0=1` 写入同步复用同一个通用 setter。最后再次从共享槽读取指针，
调用 `sub_517880(pointer,100,0,0)` 并忽略结果；公开入口为 `void`。

`sub_51BFF0` 与 `sub_517880` 仍只保留真实声明，没有空实现或固定返回桩。

### 鼠标半开矩形命中辅助

`sub_5049A0@[0x5049A0,0x504A25)` 共 55 条指令、8 个基本块，返回域严格为
0/1。它按顺序短路执行四次有符号比较：第一次读取 `mouseX@0xD68CF8`
判断 `mouseX < right`，第二次独立读取同一坐标判断 `left <= mouseX`，然后
以同样方式两次独立读取 `mouseY@0xD68D08`，依次判断 `mouseY < bottom`
与 `top <= mouseY`。所以命中区域为 `[left,right) × [top,bottom)`；任一比较
失败立即返回 0，后续坐标不再读取。

四个读取不能缓存：`CryptInt::lt@0x401DB0` 与
`CrypyInt::lte@0x401FC0` 最终都会进入 `sub_401EC0`，该函数在
`0x401EE3..0x401EED` 更新对象读取计数，并可能在计数超过 20 时重随机化存储。
x64 不重建原 16 字节 `CryptInt`，而由 `ReadLegacyMouseX/ReadLegacyMouseY`
分别表达一次真实读取，保留原短路次序与副作用次数。

命中后，`layer < 0` 直接返回 1；`layer >= 0` 则在 `0x504A0C` 调用
`Renderer::DrawGraphic_Hover@0x522180`，传入四个坐标低 16 位、层低 8 位、
`gHoverImageSeq@0xD69768` 的完整 32 位与固定 step 0，忽略绘图结果后返回 1。
当前登录相关六个源码调用都传 `layer=-1`，但实现仍保留了非负层的原绘图路径。

### 悬停图形编码辅助 `Renderer::DrawGraphic_Hover`

`Renderer::DrawGraphic_Hover@[0x522180,0x52220B)` 共 41 条指令、8 个基本块，
原函数是 `void` 契约。四个 W16 坐标分别打包为
`packedX=(uint32(left)<<16)|right` 和
`packedY=(uint32(top)<<16)|bottom`；层只转交低 8 位，图号保留完整 32 位。
step 0/1/2 分别把 `0xA0000000/0x90000000/0xC0000000` 以按位或写入图号，
其他 step 不改图号。三个 W32 位模式均以 `bit_cast<int32_t>` 转交
`DrawGraphic(packedXBits,packedYBits,layer,encodedImageBits,0,nullptr)`，
不把高位或负数位模式改作数值转换。

`DrawGraphic` 返回的 signed32 legacy 索引随后无条件把对应记录的
`batchType` 写为 2。原目标即使返回 -2，旧函数仍会写到原队列基址之前的
`0xFF4E8C`；新端禁止用负数组下标表达这项行为，也不吞掉 -2，而是无条件调用
`SetPendingGraphicBatchTypeAtLegacyIndex(index,2)`。待提交队列与这个 x64 窄适配
现已按下述固定布局承载，不伪造返回值或失败过滤。

待提交存储唯一覆盖原 `[0xFF4E30,0x1020EB8)`：前缀
`[0xFF4E30,0xFF4EB8)` 为 `0x88` 字节；其后是 4096 项、步长 `0x28` 的
`GraphicCacheItem32`，再后是从 `0x101CEB8` 起 4096 项、步长 4 的
`GraphicCache3`。`GraphicCacheItem32` 的 `batchType` 位于项内 `+0x24`；
`GraphicCache3` 只确认 `+0` 的 S16 cacheIndex 与 `+2` 的 U8 layer。
原 `0x1020EB8` 的 W16 计数继续复用 `platform::gPendingGraphicCount`，不并入或复制
这份存储；`platform::gTextFF4E30` 同址绑定前缀的完整 `0x88` 字节。

适配入口只承诺原调用前提：索引是 `-2` 或 `[0,4095]`。`-2` 显式写
`prefix[0x5C]`，即原 `0xFF4E8C`；有效非负索引只写对应记录的 `batchType`，
不清理 `+0x25..+0x27` 尾字节。其他损坏索引在 x64 新端安全拒绝，不通过负指针
或越界访问复现旧端内存破坏。

### 底层图形提交 `Renderer::DrawGraphic`

`Renderer::DrawGraphic@[0x521B10,0x521C72)` 共 113 条指令、19 个基本块。
入口把 `pendingGraphicCount@0x1020EB8` 的 W16 按 S16 解释；合法的
`0..4095` 才能继续，`4096` 及以上返回 -2。原 x86 对损坏的负计数会形成队列前
地址；x64 还原明确返回 -2，不用负下标复现越界写入。

原图号位于 `[-1,999]` 时返回 -2；小于 -1 时保留原图号并使用零偏移；大于
999 时依次调用 `GetGraphicMapNoIndex(original,&mapped)` 与
`GetGraphicXY(uint32_bits(mapped),&offsetX,&offsetY)`，两个返回值均不参与分支。
初始队列索引先写 `GraphicCache3.layer` 的低 8 位，再把此时重新读取的 W16 计数
写入 `cacheIndex`。主记录严格按原顺序写入 `x+S16(offsetX)`、
`y+S16(offsetY)`、最终图号、第五参数与零 `dataBits`；坐标加法按 W32 回绕，
不依赖 C++ 有符号溢出。

描述符非空时精确复制 16 字节。空描述符将项内 `+0x14..+0x1B` 清零，
`+0x1C` 写 `0xFFFFFFFF`，`+0x20/+0x21/+0x22` 分别写零字节、零字节、
零 W16。随后先写 `batchType=0`，仅描述符第 12 字节恰等于 1 时改为 1；
不写记录 `+0x25..+0x27` 或 `GraphicCache3+3`。

最终图号在 `[0xC18,0xC21]`，或原图号在 `[0x1DF0,0x1DFF]` 时，只把原
`0x1020EDC` 对应的唯一 `gSpecialGraphicPending` 置 1，普通路径不清零。
末尾再次读取 W16 计数，以 S16 符号扩展作为返回值，再将 W16 加一写回；因此
合法索引 4095 成功后计数为 4096。排序见下节；实际批次消费与该特殊标志的清理方仍未决。

### 待提交索引排序 `Renderer::SortTextures`

`Renderer::SortTextures@[0x520790,0x5208E8)` 大小 `0x158`，共 84 条指令、
7 个基本块。入口只读取一次 `gSpecialGraphicPending@0x1020EDC`，依其是否非零
预留 4 或 3 个槽。`0x5207A9 mov ax,[count]` 读取 W16 计数，
`0x5207AF movsx esi,ax` 符号扩展至 32 位，`0x5207B2 add esi,ecx` 是 32 位加法，
`0x5207B4 cmp esi,1000h` 与 `0x5207BA jl 0x5207C9` 作有符号比较；
`count+reserve >= 4096` 时把 W16 计数裁为 `4096-reserve`。因此正高值不会先按
W16 加法回绕而跳过裁剪。

裁剪后依次追加可选的 `(layer=2,batchType=8)`，再追加必选的 `(5,6)`、`(6,7)`、
`(20,9)`。`0x5207A9` 保留裁剪前的 `AX`：第一条的记录和并行索引
仍写在旧计数槽，但 `GraphicCache3.cacheIndex` 读取裁剪后的当前计数。
随后 `0x520801/520848` 才从共享计数重载 `AX`，后续槽以当时计数
索引。无特殊图形且旧计数为 4094 时，先裁为 4093，第一条写
槽 4094/索引值 4093，下一条又写槽 4094；特殊图形且旧计数为
4093 时也先裁为 4092，可选条目写槽 4093/索引值 4092，
下一条覆盖槽 4093。不能把第一条的槽索引也提前改成裁剪值。
每个槽写对应 `layer`；
主记录只写 `imageNo=-1`、`dataBits=0`、`value4=0` 和所列 `batchType`，
其余字段保持原值，随后递增 W16 计数。末尾 `qsort` 以最终计数排序 4 字节的
`GraphicCache3` 项，不重排 `GraphicCacheItem32`。比较器 `0x5222A0` 按 U8 `layer`
升序、同层按 S16 `cacheIndex` 降序。

原函数不拒绝 S16 负计数位型，会以越界索引写队列；新端排序入口显式拒绝该位型，
不把安全保护归于原版。非负但已超 4095 的旧计数仍沿用新端已有的裁剪槽
处理，不宣称原端越界写入等价。此步只还原索引排序；`DrawAllQueued_520DD0` 目前仅有声明与
调用、尚无实现，实际批次消费及特殊标志清理均不能由排序入口推定。
