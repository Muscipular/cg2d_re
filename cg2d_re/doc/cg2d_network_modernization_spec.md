# 网络传输现代化 SPEC（NTM01）

日期：2026-10-20。状态：已实施并完成Debug编译/链接验证；运行验收待完成。

2026-10-20修订：用户明确要求支持IPv6，随后要求实施SPEC并执行build.bat验证；本轮按下述双栈候选与Windows 8及以上可取消DNS方案实施，覆盖初稿的IPv4限制和IPv6排除项。

目标：将当前主循环轮询式网络传输改为独立 I/O 线程和事件驱动，支持IPv4与IPv6，明确连接、缓冲与退出的所有权；保留现有服务器协议及主线程业务处理。首版仅服务当前单个游戏连接，不新增依赖。

## 2. 技术选择

推荐使用现有Windows SDK：Winsock2、`WSAEventSelect`/`WSAEnumNetworkEvents`、可唤醒的等待事件，以及C++20线程与RAII。当前客户端为单游戏连接，采用一个I/O线程即可；不引入IOCP线程池、Asio、无锁队列或协程框架。

I/O线程等待网络事件、控制事件、DNS完成事件和停止信号；空闲时阻塞等待，不用Sleep轮询。主线程只持有短时间队列锁，不等待网络连接、DNS或服务端回复。关闭阶段允许等待线程退出。

WSAEventSelect将Socket设为非阻塞；收到可读/可写通知后仍须处理WSAEWOULDBLOCK。新发送入队也必须唤醒线程，不能只等待FD_WRITE：该通知主要出现在连接建立和先前写入阻塞后的恢复时。[Microsoft事件接口说明](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-wsaeventselect)

实施新增一个运行时I/O线程，无新增第三方代码。开发过程仍由本线程独立完成，不使用subAgent。

## 3. 所有权与线程边界

| 对象或动作 | 唯一职责方 |
|---|---|
| Socket创建、连接、send/recv、关闭及网络事件 | 平台后端的I/O线程 |
| DNS请求、取消句柄、OVERLAPPED和结果释放 | 平台后端，资源保留至异步操作真正完成 |
| 有界发送/接收字节队列 | 平台后端拥有，主线程与I/O线程通过短锁访问 |
| 登录步骤、请求状态、场景断线状态 | 主线程 |
| LF分包、压缩解码、字典、参数工作区、命令分发 | 主线程 |
| Lua收发回调、自动战斗记录、原生Hook、UI及世界状态 | 主线程 |
| 错误与连接状态通知 | 后端发布值类型，主线程解释并写入业务状态/日志 |

调用关系为：

```text
主线程：协议组包 → 原发送回调 → 有界发送队列
                                      ↓ 唤醒
I/O线程：事件等待 → 非阻塞send/recv → 有界接收队列
                                      ↓ 原主循环位置
主线程：取字节 → 原拆帧/解压/取行 → 原接收回调与业务派发
```

跨线程只传拥有式数据或在锁内消费的字节视图；不得保存Lua字符串、共享组包区、拆包参数数组的借用地址。I/O线程不得调用Lua、读写登录/场景全局、执行协议回调或访问已经关闭的窗口。

同一会话的接收字节严格FIFO。控制通知采用有限状态记录，连接结果及终止结果不得因字节队列满而丢失，也不能建立无上限事件列表。

## 4. 会话与连接

### 4.1 身份和状态

每次连接使用新的64位`ConnectionId`；0表示无会话，身份单调递增且不复用。所有请求、连接结果、数据和终止记录携带该身份。主线程只接受当前身份，旧连接的迟到DNS结果和断线通知不能污染新连接。

状态为`Idle → Resolving → Connecting → Connected → Closing → Closed`；错误转`Failed`并携带失败阶段、系统错误码及会话身份。数字IPv4/IPv6不需要域名查询，但不能跳过既有地址策略。取消、关闭和重复停止幂等，每个会话最多发布一次终止结果。

新的业务接口不暴露SOCKET/HANDLE。旧`gConnectionSocket`及`uintptr_t socket`形参必须逐项清点：仅转发身份的调用可经适配保留签名；实际使用原生Socket的调用必须迁入平台后端。不得未经清点就把ConnectionId塞进仍被当成SOCKET的参数，或同时保留两个可关闭同一连接的owner。

### 4.2 DNS和connect

1. 同时接受数字IPv4和IPv6。保留旧IPv4缩写数值地址兼容路径；IPv6使用系统数值地址解析并保留scope ID，不使用仅支持IPv4的inet_addr解析IPv6，也不将地址截成32位。
2. 域名采用`GetAddrInfoExW`异步解析，设置`AF_UNSPEC/SOCK_STREAM/IPPROTO_TCP`，保留返回的AF_INET和AF_INET6候选及系统顺序。每个候选按其地址族创建Socket，使用实际地址长度；平台内部使用sockaddr_storage或等价拥有式存储，保留IPv6的scope ID，不固定使用sockaddr_in和16字节长度。[系统双栈解析说明](https://learn.microsoft.com/en-us/windows/win32/api/ws2tcpip/nf-ws2tcpip-getaddrinfoexw)
3. 宽字符DNS接口与旧GBK窄字符查询可能在非ASCII域名及结果顺序上有差异，列为本次需要确认和验收的变化；不修改协议正文编码。
4. DNS支持取消；取消发出后仍等待完成通知，才释放请求上下文及结果，不能仅丢弃旧代次而泄漏资源。[异步解析](https://learn.microsoft.com/en-us/windows/win32/api/ws2tcpip/nf-ws2tcpip-getaddrinfoexw)、[取消接口](https://learn.microsoft.com/en-us/windows/win32/api/ws2tcpip/nf-ws2tcpip-getaddrinfoexcancel)
5. 上述可取消DNS路径以Windows 8及以上API为前提，实施前确认目标系统范围；若仍要求Windows 7，先修订DNS方案，不静默提升最低系统版本或加入阻塞回退。
6. connect立即成功和FD_CONNECT异步完成均支持，按实际返回值/事件错误码确认成功；不能仅因Socket可写就判定已连接。同一域名候选的尝试顺序和失败处理见第4.4节。
7. TCP_NODELAY仍由现有`gNoDelay`控制，不新增其他Socket调优参数。初始化或设置失败清理已创建的资源并报告原阶段错误，不返回伪成功。

登录主线程消费Connected后才推进至既有71阶段并打开请求轮询门禁，保留账号请求、登录前导和后续71～99业务流程。现有600000ms整体超时不改为新的短超时；超时由主线程发出取消，再走现有提示和状态出口。

### 4.3 地址输入与既有策略

服务器记录已使用`std::wstring address`和独立`portText`，无需改成IPv4/IPv6两套配置。原命令行解析有127个地址字符和63个端口字符的限制，首版保持该容量；IPv6括号仅是输入语法，不存入内部host，不作为协议数据发送。

| 输入 | 处理 |
|---|---|
| `IP:2:127.0.0.1:9030` | 旧IPv4写法保持 |
| `IP:2:game.example.com:9030` | 域名可解析出A、AAAA或两者 |
| `IP:2:[2001:db8::1234]:9030` | 新增IPv6写法，提取完整host和独立端口；此为文档地址示例 |
| `IP:2:[::1]:9030` | IPv6本机回环 |
| `IP:2:[fe80::1234%12]:9030` | 支持数字scope ID；12为客户端本机接口索引示例，不能硬编码为实际接口 |

命令行中IPv6必须带方括号；缺失右括号、右括号后没有端口分隔符、或未加括号而存在多个地址冒号，返回明确配置错误，不猜测最后一个冒号为端口，也不发布截断记录。其他旧IPv4/域名语法不借本次机会批量收紧。

`BeginConnect(host, port, options)`的host和port本来就分开传递，内部host接受无括号IPv6文本。需要scope的链路本地地址必须明确提供可用scope；不静默选择接口。首版承诺数字scope ID，不新增接口名称别名解析。显示或记录带端口的IPv6端点时统一使用`[地址%scope]:端口`，避免歧义。

`ApplyServerAddressPolicy`另有TAOMOLI地址映射及“地址、端口拼接为策略查询名”的DNS校验。该查询与游戏服务器的A/AAAA解析不是一回事：保留映射、查询名构造、策略查询的IPv4结果选择、空结果分支和非空结果校验/退出语义，不把策略查询一并改为AF_UNSPEC，不为IPv6跳过策略或自行设计新的DNS编码规则。

当前策略查询本身也会同步等待。实施时把其DNS等待接入平台异步请求，主线程消费策略结果后再开始连接候选解析；保留现有策略先后关系和结果处理。IPv6字面地址、带scope地址经现有策略名构造后的实际结果须单列验收；如果策略服务需要新增IPv6名称约定，先另行确认，不能擅自修改远端规则。

### 4.4 双栈连接候选

以下为建议的首版策略，覆盖初稿“只使用首个IPv4结果”：

1. 按系统返回顺序串行尝试同一host/port的IPv4及IPv6候选；不强制IPv6优先或IPv4优先，不额外创建多服务器连接。
2. 单个候选遇连接拒绝、无路由或系统连接超时后，关闭该Socket并尝试下一个。候选列表只遍历一轮；全部失败后报告终止结果，记录最后失败的地址族/端点/错误码。
3. 该过程属于一次连接建立，使用同一个ConnectionId；内部增加尝试序号区分候选Socket，前一候选的迟到事件不能影响后一候选。
4. 任一时刻最多一个候选Socket处于连接/已连接状态。成功后仅发布一次Connected，废弃其余候选，随后才由主线程发送登录前导和账号请求。
5. 600000ms整体请求期限覆盖地址策略、DNS和全部候选，不因换候选重新计时。取消或整体超时立即停止剩余尝试。
6. 首版不增加Happy Eyeballs并行竞速或自定单候选短超时。因此IPv6链路黑洞时可能等待系统连接超时后才尝试IPv4；这不是快速回退方案。若要求快速双栈连接，另确认竞速延迟和并发上限后扩展本节。
7. 建连后认证失败、协议错误或断线不自动切换到其他候选，不自动重发账号请求。已有服务器选择、重连触发和协议保持原职责。

IPv6互通验收需要实际支持IPv6监听、路由和防火墙放行的服务器端点；本任务仅改客户端，不把客户端支持当作现有服务端已支持。

## 5. 队列、背压与回调重入

### 5.1 发送

- 唯一待发字节队列保留`0x4000`上限；包括尚未被send接受的部分，不在另一层私藏一份不计容量的待发队列。
- 主线程先按当前顺序执行轮询门禁、包快照、自动战斗记录、Lua发送回调和首个匹配的原生发送Hook，再尝试入队；原观察者、LF添加和成功入队日志的相对顺序保持。
- 回调执行时不持队列锁。回调可能重入发送或关闭会话；回调返回后重新核对原ConnectionId和门禁，再基于当时队列状态提交。若会话已变化，外层发送失败，不把旧消息发送给新会话。
- 普通消息全量追加或全量失败；门禁失败继续映射`-100`，容量不足继续映射`-1`，成功入队映射`0`。新增后端错误在适配层明确映射，不向旧调用者直接暴露枚举数值。
- 首个发送Hook仍先于容量判断，因此入队失败不撤销已经执行的回调副作用；不把Hook观察到消息解释为成功发送。
- send成功仅消费其实际返回的字节数；WSAEWOULDBLOCK保留剩余字节等待可写，其他错误终止当前会话。非空请求send返回0按无进展失败处理，禁止忙循环，单列为具名差异。
- 后台读取队列头、一次非阻塞send及提交已发送数量，与主线程入队/替换受同一锁序列化；锁内不等待事件、不解析协议、不记录正文日志、不执行用户回调。

### 5.2 JFVf登录前导

保留现有N03：匹配`JFVf`前缀的请求通过容量检查后，用六字节`XCNY \n`加完整登录行替换所有尚未发送的队列字节；检查失败保留旧队列。前导不再次触发发送Hook。

替换与send在同一队列锁下确定先后：send先完成的字节属于已交给系统的前缀，不能撤回；替换先完成则后台只能发送新队列。不得先把旧队列整段移到后台私有缓冲，再声称JFVf清除了全部待发字节。

### 5.3 接收

- 新增后台到主线程的`0x4000`有界字节缓冲；原主线程`0x4000`接收区、压缩帧和明文累积区的容量与格式保持。新增缓冲会增加最多16KiB在途原始数据，不宣称总缓存完全不变。
- recv长度不超过后台缓冲剩余空间，缓冲满时暂停读取，让TCP接收窗口形成背压；不丢字节、不覆盖旧数据、不自动扩容。
- 主线程释放空间后唤醒I/O线程，线程主动尝试继续recv，不能依赖一次新的FD_READ通知；满区状态下消费已记录事件后不得反复空转。
- 主线程只向旧接收区搬运其可用容量内的数据，并交原解析器消费；合法压缩帧继续分段承接，不要求整帧塞入16KiB队列。
- 旧原始队列、压缩输出上限、明文累积不足及失败分支保持原合同。本稿的“背压不丢字节”仅描述新增传输缓冲，不把旧解析器的具名异常处置改写成无损保证。
- FD_CLOSE/recv=0先处理已经接收的有效数据，再发布流结束；终止记录必须排在该会话最后一批接收字节之后。若缓冲满，记住关闭状态，待腾出空间继续排空残余；终止后不把半行伪造成完整消息。

## 6. 主循环、协议与计时

`NetworkLoop_507DF0`保持在MainLoop中“消息泵、保活及时间更新之后，world::Update和Lua场景更新之前”的位置，改为主线程Pump入口。取消它对实际收发和业务派发的8次调用节流，每轮处理当前可消费的网络数据。

一次Pump先确定该轮后台已接收字节的快照上限，再分批搬运和消费；不追逐本轮中新到达的无限字节流。原解析器中已存在的完整行照序处理。首版不增加任意每帧消息条数/毫秒预算；大量业务回调仍可能占用主线程，不承诺所有网络相关卡顿都被消除。

每条业务回调结束后重新核对会话身份和停止状态；回调引起关闭或重连时，停止派发旧会话剩余消息。正常远端关闭时，已入队完整消息先完成派发，随后至多一次切入现有断线场景。主动取消/退出可以明确丢弃旧会话队列，不与正常EOF排空混同。

`gRequestPollingEnabled`仍是业务门禁。后端不跨线程读取它，由主线程发布可收发状态；关闭门禁暂停尚未开始的I/O并保留本会话待处理数据，恢复时唤醒。已经完成的系统调用不能撤回；新会话不继承旧缓冲。连接完成通知不受此门禁阻塞，否则无法进入登录71阶段。

保留以下协议合同：

- 原命令、字段顺序、Base62、转义、GBK及LF；不新增包头、协商或加解密。
- 0xEF压缩帧、24位帧长、16位块长、现有LZ4容量检查、半帧/半行和当前TAOMOLI字典分支；不回退到历史空字典描述。
- 当前接收Hook、Lua回调及原业务分发顺序，注册表重连保留，借用参数只在当前同步回调有效。
- 不更改已经实现的业务字段解析，不批量改写NetworkRuntime中的所有协议函数。

协议基线见[当前明文合同](cg2d_network_compatibility_spec.md#local-server-plaintext-contract)、[N01–N03及后续字典修订](cg2d_network_hook_business_migration_spec.md)；以当前源码和这些文档的最新修订为准，不恢复旧W16或已撤回的字典方案。

30000ms探测和60000ms保活仍由主线程构造原命令，发送成功时点由后端发布实际send成功的单调时钟值；入队不能冒充实际发送。保留两个调度器原有采样/重复入队节奏，不能因Pump改为每轮执行就变成每帧追加探测。必要时将原探测采样相位独立保留，仅解除业务I/O节流。

## 7. 停止、重连与退出

1. 主线程关闭入队入口并使当前会话代次失效，唤醒后端；后端取消DNS或连接，关闭Socket，回收网络事件并结束本会话。
2. Socket只由I/O线程关闭。不得让登录代码与后台线程同时closesocket，或让旧Socket数值复用后被迟到操作关闭。
3. 主动重连仍由现有业务发起，没有自动重连、自动补发或切换配置中的其他服务器。同一host首次建连的候选遍历按第4.4节执行，不属于断线重连。新会话开始前清原始接收、压缩帧、半行、待发送数据和旧完成记录；保留注册表。
4. 客户端退出分两阶段：在ShutdownLua之前停止并join I/O线程；随后沿现有顺序释放Lua/UI等对象；原网络关闭位置释放主线程协议工作区。两阶段都允许重复调用或初始化中途失败。
5. Winsock引用由平台后端RAII配对，异步请求全部结束后才WSACleanup。其他模块独立申请的Winsock引用保持各自配对，不统一释放别人的引用。
6. DNS取消不等于完成；取消上下文及缓冲须存活到完成通知。退出不强杀线程、不detach带旧指针的任务，也不承诺未经实测的固定退出时限。

## 8. 建议接口与文件落点

接口名称为实施建议，最终适配保持旧上层返回合同；新类型不包含原生Socket或HANDLE。

| 接口 | 语义 |
|---|---|
| `BeginConnect(host, port, options)` | 开始一个会话，返回ConnectionId或准备错误；不代表连接成功 |
| `TryQueueSend(id, bytes, mode)` | 原子追加或替换待发内容，返回Accepted/QueueFull/NotConnected/StaleSession/Stopping；仅Accepted映射旧入队成功 |
| `DrainReceived(id, destination)` | 复制当前可消费字节，保留顺序，不在锁外借用队列内存 |
| `PollConnection(id)` | 提供值类型连接进展、终止原因及发送时点；不执行业务回调 |
| `SetIoEnabled(id, enabled)` | 发布当前业务收发门禁并唤醒线程 |
| `CloseConnection(id)` | 取消指定会话，旧身份不得关闭新连接 |
| `StopNetworkIo()` | 停止工作线程并等待原生资源回收，用于最终退出 |

## 9. 具名行为变化与非目标

以下是方案建议，确认本稿才授权相应差异，不把它们描述成与旧轮询逐时点等价：

| 差异 | 用户可见影响或风险 |
|---|---|
| 收发不再等每8次主循环调用 | 数据更早入队/发出，消息可能在更早一轮业务更新前生效 |
| 新增后台收发与最多16KiB接收桥接缓冲 | 主线程繁忙时仍可先接收有限数据；完整业务处理仍等待主线程 |
| 传输缓冲满时暂停读取 | 慢消费者时采用TCP背压，不沿旧recv后追加失败的方式处理新缓冲 |
| 可取消宽字符DNS | 主界面不再同步等待DNS；域名解析行为及系统版本条件需验收 |
| IPv4/IPv6输入与双栈候选 | 新增方括号IPv6参数和scope；同一域名按系统顺序尝试两种地址族，失败可进入下一候选，整体期限不重置 |
| 重入发送后检查会话身份 | 不把回调前属于旧会话的包意外交给新连接 |
| EOF排空与一次终止通知 | 关闭前完整消息先处理，旧连接迟到事件被丢弃 |
| 统一资源owner和两阶段退出 | 关闭流程改变，须验收取消、重连、异常初始化和退出 |

不包含：修改服务器或协议、TLS、WebSocket、UDP、发送压缩、自动重连、业务请求重试、额外心跳、连接池、多服务器并发、Happy Eyeballs竞速、Lua新网络API、业务handler并行化或批量重构。IPv6属于本轮必需范围。

## 10. 实施步骤

1. **边界清点**：列出所有Socket/会话标识使用者、门禁写入、关闭入口、错误返回和计时生产消费；将真实映射补入本稿。此阶段不引入行为变化。
2. **平台后端**：实现事件等待、可取消DNS、连接状态、单owner及有界队列，完成资源失败路径；新旧后端不同时拥有同一连接。
3. **连接迁移**：接入IPv6参数、独立地址策略、双栈候选和登录开始/结果/取消，移除上层直接Socket关闭；保留登录请求内容和步骤合同。
4. **收发迁移**：串行接通发送回调、JFVf原子替换、接收桥接与主线程Pump，维持协议解析和字典；改为每轮派发并接好计时。
5. **关闭与验证**：两阶段退出、迟到事件和重入路径核对，移除已无消费者的旧select/recv/send接线；保留仍有消费者的适配入口。

各步同步唯一进度并精确提交；不能用尚未接入的后端类或仅编译成功宣布迁移完成。
