# cg2d 基础场景状态与 World::Update

日期：2026-09-20。任务：R6.1.1a、R6.1.1b。证据源仅为当前 `ida-32980` 的 `cg2d.exe` IDB 与当前实现源码。

## 1. 函数边界

`World::Update@0x51C430` 的范围为 `[0x51C430,0x51C726)`，共 188 条指令、36 个基本块、74 个 `call` 指令和 49 个唯一直接目标。当前 IDA 原型为 `void()`；唯一代码调用点是 `MainLoop@0x457117`，调用者不消费返回值。

入口严格按以下顺序执行：

1. 单次读取 `gPendingSceneType@0xFF0D6C`，按有符号值判断是否 `>=0`。
2. 成立时依次写当前类型、读取待提交状态、把待提交类型写成 `-1`、写当前状态。
3. 无条件将 `W8[0xC82204]` 清零。
4. 单次读取当前类型，进入主分发。

## 5. 类型 11 内嵌状态链

函数单次读取当前状态：

- 状态 0：`519D50→446470→404D30→503E80→43F220`；写 `W32[58B6D0]=1`；调用 `51D750`；写 `gValue73ECC0=2`；调用 `52B990`；读取 32 位 tick，把其无符号数值转换为 `double` 后写 `gLastRenderDt`；最后递增当前状态。
- 状态 1：调用 `51FDE0(2,0,0x3F19999A)`；只有返回值严格等于 1 时才清 `gValue73ECC0` 并递增当前状态。第三参数在新端保持 `uint32_t` 位载荷，不使用截断十进制浮点字面量。
- 其他状态：不执行上述两段。

所有路径随后恰调用一次 `sub_455C90@0x455C90`。返回 0 时进入类型 6 的 `0x404C50→0x521F20` 公共尾部；返回非零时执行 `520160→519D50→446470→5081A0`，调用 `resource::ProbePaletteCapability_45C970`，先按 `0x51C6EA` 比较返回值是否为 3，再由 caller 在 `0x51C6ED` 对应位置把返回值写入 `gPaletteCapability`，调用 `SelectPalette(capability==3 ? 27 : 0, 0)`，切到类型 2，调用 `404D30` 并清 `W8[D9F2CA]`。

### 38.1 九参数、区间与路径合同

`Sub_468C40@[0x468C40,0x468F25)` 的九个参数依次为 `mapId/floor/x/y/x2/y2/tile/obj/hit`。目标矩形严格采用半开区间 `[x,x2) * [y,y2)`；`tile/obj/hit` 均指向 `MapBuffer = WORD[2601]`，单缓冲恰为 5202 bytes。

路径由 `Sub_468520` helper 生成：`mapId == 0` 时为 `map\\0\\{floor}.dat`；否则为 `map\\{mapId}\\{W32[9E0434]}\\{floor}.dat`。`9E0434` 只按原槽值参与路径，不赋予业务名称。helper 使用的原前缀、格式串与打开模式为：

| 用途 | 原字符串 / 字节 |
| --- | --- |
| 路径前缀 | `map\0` / `6D 61 70 00` |
| `mapId == 0` 格式 | `%s\\%d\\%d.dat\0` / `25 73 5C 25 64 5C 25 64 2E 64 61 74 00` |
| `mapId != 0` 格式 | `%s\\%d\\%d\\%d.dat\0` / `25 73 5C 25 64 5C 25 64 5C 25 64 2E 64 61 74 00` |
| `fopen` 模式 | `rb\0` / `72 62 00` |

`fopen` 失败时调用 `PostQuitMessage(0)` 并返回 `-1`，且 `tile/obj/hit` 三个缓冲均不清零。打开成功后按 `tile -> obj -> hit` 顺序各精确清零 2601 个 WORD；最终执行 `fclose` 后返回 `0`。本函数忽略相关 I/O 调用的返回值。

### 38.2 20 字节头与裁剪公式

文件开头共消耗 20 bytes，布局如下：

| 偏移 | 大小 | 含义 |
| ---: | ---: | --- |
| `+0x00` | 4 | 四次 `fgetc` 丢弃 |
| `+0x04` | 4 | 读取 DWORD，后续不使用 |
| `+0x08` | 4 | 读取 DWORD，后续不使用 |
| `+0x0C` | 4 | `fileW` |
| `+0x10` | 4 | `fileH` |

原端按文件范围 `[0,fileW) * [0,fileH)` 裁剪请求矩形，公式为：

```text
dstW  = x2 - x
srcX  = max(x, 0)
dstX  = max(-x, 0)
srcY  = max(y, 0)
dstY  = max(-y, 0)
copyW = min(x2, fileW) - max(x, 0)
copyH = min(y2, fileH) - max(y, 0)
dst0  = dstX + dstW * dstY
```

### 38.3 tile、obj、hit 三平面装载

三个平面在文件中按 `tile -> obj -> hit` 连续排列。令 `plane = 0/1/2` 分别对应三平面，`row` 取 `[0,copyH)`，则每行文件偏移和目标地址为：

```text
planeBytes = 2 * fileW * fileH
fileRow    = 20 + plane * planeBytes
           + 2 * ((srcY + row) * fileW + srcX)
dstRow     = buffer + 2 * (dst0 + row * dstW)
```

每行定位到 `fileRow` 后，严格执行 `fread(dstRow, 2*copyW, 1, file)`。三平面装载整体只以 `copyH > 0` 为门禁，不另加 `copyW` 门禁；短读不作失败分支，已读前缀覆盖目标行，未覆盖后缀保持成功打开后预清零所得的零值。本项不对异常越界或整数溢出作专项处理。

### 38.4 调用关系与共享 owner 门禁

全局装载路径的第九参数 `hit` 为 `MapBuffer@9ED44C`；`Sub_469030` 与 `Sub_46CF60` 传入同一组三个全局缓冲，`Sub_469290` 使用一组三个局部缓冲。`Sub_468C40` 本体不直接读取 `S16[9A86E0]` 或 `S16[9ED43C]`，但全局调用所传边界满足 `dstW` 与行数分别对应这两个跨度。
