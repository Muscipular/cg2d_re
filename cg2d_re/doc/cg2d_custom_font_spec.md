## 配置合同

启动字体初始化时读取当前工作目录的 UTF-8 `font.yml`，与现有 `cgmsv.yml`、`effectHook.yml` 的定位方式一致。字体文件相对路径以该配置所在目录为基准，也支持绝对路径。

```yaml
fonts:
  - id: 0
    file: "fonts/custom.ttf"
    family: "自定义字体"
    width: 9
    height: 17
    style: normal
    weight: 400

  - id: 14
    family: "宋体"
    width: 8
    height: 16
    style: italic
    weight: 700
```

- `fonts` 为列表；`id` 为 0～32 的整数，可不连续，不可重复。
- `file` 可省略；指定时只从该文件的私有字体集合解析 `family`，省略时查系统字体。文件路径和字体族名按 UTF-8 转 UTF-16，不经过 GBK。
- 其余字段必填。`family` 必须非空且能解析到实际字体族；不接受系统悄悄替换成另一字体。
- `width` 为半角格宽，全角为两倍；`height` 为字格高度，均为整数像素。范围均为 1～255：高度受既有 fontHeight 字节字段限制，宽度受 512 像素图集及两像素间隔限制。
- `style` 为 `normal` 或 `italic`。`weight` 为 `400` 或 `700`；当前 GDI+ 字体风格只有常规与粗体，本轮不将任意数值近似成这两种风格。字体族不支持所选风格时视为加载失败。
- 配置字号按字格高度及字体行距换算为 GDI+ em 大小；水平排版仍按指定格宽。过窄的字格可能裁切字体轮廓，不自动扩大布局。
- 不存在配置文件或配置为空列表时，使用内置字体；解析失败、根结构错误、非法或重复 ID 时整份配置不应用并记录原因。已定位到合法唯一 ID 后，其余字段、文件或字体创建失败只影响该 ID。
- 未配置的原有字体保留原设置；新增 ID 仅成功加载后注册。已配置但加载失败的非 0 号不保留旧字体，使用时回退 0 号；0 号配置失败保留内置宋体。

## 映射与一致性

- 私有 `std::map<std::int32_t, ...>` 统一拥有度量和字体资源；不向业务模块暴露可变 map 或平台资源。
- `GetFontMetrics(id)` 和 `ResolveFontId(id)` 采用同一查找规则，查询不得用 `operator[]` 隐式插入记录。
- 查不到、未成功加载或越界的 ID 统一使用 0 号。队列存储字体序号前归一化，保持 0～32 在原字节字段内可表示。
- 0 号内置宋体在初始化时首先创建；若系统字体/GDI+ 基础资源本身无法创建，则沿现有异常路径报告初始化失败，不能伪称有可用字体。
- 原表 6 号没有创建字体句柄；本次将其按“未加载字体”回退 0 号，允许通过配置显式注册 6 号。这是本次用户要求的回退行为对原实现的具名调整。
- 自定义条目同步设置 sWidth、sHeight、doubleWidth、doubleHeight、fontHeight；其他字段继续保留结构承载，不作为新配置项。
- 聊天记录原有 14 项上限改为统一字体查询，保留记录序号与行距的对应关系，支持 14～32。

## 资源生命周期

- GDI+ 会话由字体系统持有；私有字体使用 `Gdiplus::PrivateFontCollection::AddFontFile`，字体对象从该集合中的实际 FontFamily 创建。
- 不采用仅 GDI 注册后期待 GDI+ 自动识别的方式。依据：[微软私有字体集合文档](https://learn.microsoft.com/en-us/windows/win32/gdiplus/-gdiplus-creating-a-private-font-collection-use)、[AddFontFile](https://learn.microsoft.com/en-us/windows/win32/api/gdiplusheaders/nf-gdiplusheaders-privatefontcollection-addfontfile)。
- 原有内置字体保留原 CreateFontW 参数及度量，通过 GDI+ 字体对象绘制；配置条目使用私有/系统 FontFamily。
- 重建与退出按“字形图集 → 字体对象/旧 GDI 句柄 → 私有集合 → GDI+ 会话”顺序释放；重复释放安全。
- 渲染器重建仅清理字形图集，不卸载字体；配置在字体系统初始化时读取，修改后重启生效。
