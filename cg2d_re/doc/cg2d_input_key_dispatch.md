# cg2d 输入按键分派节点

## 函数边界

- 原函数为 `sub_4596D0`，公开契约为 `void()`，全部调用者均忽略机器
  `EAX` 残值。
- 主块为 `[0x4596D0,0x45975F)`，大小 `0x8F`，37 条指令；分离尾块为
  `[0x401920,0x401953)`，大小 `0x33`，17 条指令。逻辑函数合计
  `0xC2` 字节、54 条指令、24 个基本块。IDA 普通函数大小只显示主块，不能
  漏掉尾块。
- 当前实现为 `cg::input::ProcessKeyInput_4596D0`，无参数、无返回值。

## 控制流与读取顺序

函数本体只逐项读取唯一 `platform::gKeyStates[256]`，不直接写全局或结构字段。
所有条件均保持独立，不能改成互斥分支，也不能预先复制整张键表：

1. `0x4596D0/0x4596DF` 依次检查索引 17、16 的 `0x02` 位；任一非零便只跳过
   四个方向动作。
2. `0x4596E7/0x4596F4/0x459701/0x45970E` 依次检查索引
   38、40、37、39 的 `0x10` 位，并调用 `sub_44A5D0`、`sub_44A7D0`、
   `sub_44A540`、`sub_44A580`。
3. `0x45971B/0x459728/0x459735/0x459742` 依次检查索引 8、46、9、13 的
   `0x10` 位，并调用 `sub_44A990`、`sub_44AA90`、`nullsub_1@0x509080`、
   `sub_44AB60`。
4. `0x459750` 检查索引 35 的 `0x04` 位；未置位从 `0x45975E` 返回，置位则
   由 `0x459759` 跳入分离尾块。
5. `0x401920` 调用 `sub_5043D0(2)`。返回非零时依次调用
   `sub_5042D0(100)` 与 `World::PlaySe(57, 320, 240)`；返回零时调用
   `sub_504180(99)`。`PlaySe` 的三个 W32 实参由原调用点压栈和
   `add esp, 0x10` 共同确认，不能按 IDA 当前不完整的二参数自动原型降参。

## 当前源码映射与边界

- `platform::gKeyStates` 继续唯一承接原 `gKeyState.states@0x73EFF8`，本项不建立
  第二份键状态。
- `World::Update` 场景 1、4、13 的三个原调用点已直接改接唯一公开入口；未来
  正常和战斗场景实现可复用同一入口。
- `World::PlaySe` 复用既有 `login::detail::PlaySe` 三参数声明；不新增音频状态或
  第二个适配器。
- `sub_44AB60`、`sub_5043D0`、`sub_5042D0` 与 `sub_504180`
  当前仍只有真实窄声明，不提供空体或
  固定返回。`sub_44A540/44A580`、`sub_44A990/44AA90`、
  `sub_44A5D0/44A7D0` 已按下文落位。
  `nullsub_1` 已按其唯一 `retn` 直接改接 `cg::NullSub_509080()`；这不扩展输入
  语义，也不代表输入编辑、提交或音频行为闭合。
- `sub_45CA20` 不在本函数的调用图内；两者仅可能通过当前输入上下文和键状态形成
  跨帧状态关系。本函数所有键索引均是落在 256 字节表内的固定常量，不继承
  `sub_45CA20` 的异常索引争议。

行为、地址与通过结论只取自当前 `ida-17524/cg2d.exe`、当前二进制及实现源码；
本项未使用 `D:\Source\STONAGE` 作为证据。

## 左右光标叶 `44A540/44A580`

- `sub_44A540@[0x44A540,0x44A580)`：`0x44A540/545` 先取当前输入上下文，空指针立即返回零；`0x44A549/551` 在 IME 组合文本首字节非零时返回该上下文指针。光标偏移 `+0x128` 不大于零也原样返回。其余路径将 `text` 与当前光标偏移传给既有 `44B1D0` 边界分类（`0x44A55E..566`），`0x44A572` 从光标减去完整返回值，`0x44A574` 将输入相位写 20；本路径返回分类结果，不读取或改写总长度。
- `sub_44A580@[0x44A580,0x44A5C8)`：相同的上下文空指针和 IME 首字节门禁；`0x44A593..5A1` 只有光标偏移严格小于总字节长度 `+0x12C` 才继续。`0x44A5AA/5AE` 读取 `text[caret]` 并以原 `44B250` 规则按 bit7 返回 1 或 2；`0x44A5BA` 将该值加到光标，`0x44A5BC` 写输入相位 20。本路径返回字节宽度，未移动时返回当前上下文指针。
- 原 `EAX` 因分支而承载指针或整数；新端私有接口以 `uintptr_t` 原样承载本机指针或小整数，不缩窄指针。唯一调用者 `459709/459716` 均弃返回。`gCurrentInputData`、IME 组合首字节及相位分别复用既有唯一 owner；不缓存上下文、不提前消费键位、不为有效输入增加长度或容量门禁。
- 此步只接通左右两个叶；退格、删除与上下移动另见后节。提交和尾部分支仍有真实未实现依赖；`ProcessKeyInput_4596D0`、输入整链、客户端链接与运行不因两个叶完成而验收。

## 退格与删除叶 `44A990/44AA90`

- `sub_44A990@[0x44A990,0x44AA8D)` 为 void。`0x44A990..9AC` 仅在当前上下文非空、光标 `+0x128` 大于零时继续；没有 IME 首字节门禁。`0x44A9B8` 用当前 `text` 与光标调用 `44B1D0`，`0x44A9BD/CA` 重读上下文及光标；将光标位置起的含 NUL 尾段复制到本地 `0x120` 字节缓冲（`0x44A9F1/FA`），`0x44AA09` 在 `caret-width` 写零，`0x44AA22/29` 从缓冲拼回尾段。随后分别在 `0x44AA3A/4E` 从总长度 `+0x12C`、光标 `+0x128` 减去原分类结果；光标负值在 `0x44AA64/66` 钳为零，文本首字节为零时在 `0x44AA71/76` 清总长度，最后 `0x44AA7C` 写相位 20。
- `sub_44AA90@[0x44AA90,0x44AB59)` 先取上下文；空指针或光标不小于总长度则返回当前指针。`0x44AAB7/ABF` 从 `text[caret]` 取低 W8 调 `44B250`，依 bit7 得 1/2；`0x44AAC6/D2` 重读上下文及光标，把 `text[caret+width]` 起的含 NUL 尾段通过本地 `0x120` 字节缓冲复制回 `text[caret]`（`0x44AAF2/AFB`、`0x44AB13/1A`）。`0x44AB2A` 只从总长度减宽度，不改光标；新文本首字节为零时再次清总长度，`0x44AB48` 写相位 20，返回重读的上下文指针。没有 IME 门禁或额外删除标志。
- 两者只沿原门禁触发，不用字符串内容重新计算 `totalByteLength`，也不把删除尾段改为提前清整个输入上下文。现有 `Input.cpp` 复用同一上下文、分类与相位 owner；`459723/459730` 两个分派调用均弃返回。其余分派目标仍未完成，不计输入整链、客户端链接或运行。

## 下移光标叶 `44A7D0`

- 原 `sub_44A7D0@[0x44A7D0,0x44A989)` 为无参 void，唯一直接 caller `4596FC` 弃返回。`44A7D6..802` 读取当前上下文并检查 IME 首字节；两者通过后先在 `44A808` 写相位 20，随后仅 `maxLine@+0x144 > 1` 时继续。原局部行长栈区为 `0x480` 字节，即 288 个 W32。
- 每轮自当前偏移扫描：遇 CR 则连同该字节计入当前行长（`44A835..868`）；否则扫描至 NUL 或 `maxCharPerLine@+0x148`，再由 `strlen` 与最大宽度作无符号比较（`44A86E..882`）。剩余长度不少于最大宽度时调用既有 `44B1D0`，其结果严格等于 3 才将推进量减 1；记录行长后重读当前上下文与光标。仅当当前光标严格小于已推进偏移且先前未定位时，保存当前行号及相对列（`44A8C9..F8`），扫描仍继续至最后一行。
- 末行保存 `strlen(text+offset)+1`（`44A91B..92E`）；当前行号不小于已记录行数则不移动。否则 `44A934..954` 用当前行长推进，下一行不够长时改为 `当前行长-相对列+下一行长-1`。写回光标后，`44A95A..979` 重读当前上下文，对全文新光标再次调用 `44B1D0`，仅分类 3 时将光标减 1；不写总长度和文本。
- 新端复用 `Input.cpp` 的唯一上下文、IME 首字节、分类函数与相位槽，未将 CR 规则改作视觉行布局或 UTF-8 字符计数。上移另见下节；回车提交和按键尾部分支仍未闭合，不计输入整链、客户端链接或运行。

## 上移光标叶 `44A5D0`

- 原 `sub_44A5D0@[0x44A5D0,0x44A7CD)` 为无参 void，唯一直接 caller `4596EF` 弃返回。`44A5D6..602` 的当前上下文/IME 首字节门禁后，`44A608` 先写相位 20，只有 `maxLine@+0x144 > 1` 才继续。局部行长区为 `0x480` 字节、288 个 W32；扫描 CR、最大宽度、`44B1D0` 返回 3 时的少推进一字节，以及首个光标所属行的记录，分别在 `44A62A..6F8`，与下移叶各自独立执行。
- `44A6FD..74D`：若光标未落在已记录行内，先取行数与末行相对列；当 `maxLine <= 已记录行数`，还在 `44A71D` 先减光标一字节、`44A723` 重读上下文后重新计算相对列。目标行号不大于零即返回，这一步可能只保留先前的相位写入；不补额外归零。
- 目标行号大于零时，`44A74F` 取上一行长度。若其严格大于相对列，`44A78F..79D` 从当前光标减去整段行长并重读上下文；否则 `44A757..78B` 在最大宽度为正时逐次减光标，每步重读上下文及当前字节，遇 CR 或达到当轮重新读取的最大宽度就停止。最后 `44A7A3..7BD` 对当前文本和光标调用 `44B1D0`，仅返回 3 时再减一字节；不写总长度和文本。
- 新端保留与下移各自的完整函数入口及读写次序，复用唯一上下文、IME 首字节和相位 owner；不把上移简化为常量行宽回退或 UTF-8 字符移动。回车提交及按键尾部分支未完成，不计输入整链、客户端链接或运行。

## 回车链的历史记录写入叶 `449FA0`

- 原 `sub_449FA0@[0x449FA0,0x44A084)` 为单个 W32 索引参数的 cdecl 函数，唯一直接 caller `44AB60@44AC26` 弃返回。虽然 IDA 自动原型为 `FILE*`，反汇编返回路径只有完整 `EAX32=0/1`，新端私有签名为 `std::int32_t`。
- `449FA6..9CF` 在本地 128 字节路径缓冲中用原 `"%s\\%s"`、可写 `gDataPath` 与 `"chathis.dat"` 拼接后，以 `"r+b"` 打开；失败直接返回零，不创建文件或修改历史表。成功后 `449FE0..A01A` 先以 `index*0x121` 为绝对偏移 `fseek`，再从唯一历史文件块的第 `index` 项写 `fwrite(record,0x121,1)`；定位结果不参与门禁，写入项数小于 1 则关闭并返回零。
- 首次写入成功后 `44A035..54` 再定位到 `0x4840`，从本函数**参数槽**写出同一索引的四字节值 `fwrite(&index,4,1)`；第二次定位结果也不参与门禁。关闭文件后按第二次写入项数返回完整整数 0/1，忽略关闭结果。不另写内存 `tail626838` 或独立游标 `62683C`；它们由原调用者或文件加载链分别负责。
- 新端复用 [既有 `0x4844` 字节历史文件块](cg2d_scene_state.md)、路径 owner 和文件名格式，在同一 `Input.cpp` 落位完整叶。不把本体成功写入等同回车提交完成：`44AB60` 的其他上下文、黑名单与消息下游仍未闭合，客户端链接及运行未验收。

## 聊天文本转义 `52D1B0/52D2D0`

- `sub_52D1B0@[0x52D1B0,0x52D2C6)` 以 `strlen(source)` 取不含 NUL 的长度，目标指针 `EAX` 始终原样返回；无论输入长度或容量如何，最终在当前输出偏移写 NUL（`52D2BA..C5`）。原表 `58E944..58E94B` 的八字节为 `0A 6E 2C 63 7C 7A 5C 79`，每对是输入/转义字母：LF→`\n`、逗号→`\c`、竖线→`\z`、反斜杠→`\y`；`52D211..255` 按四项顺序查找。与网络全局缓冲的 `5171F0` 不同，不合并两入口。
- 输出计数从 1、下一字节门槛从 2 起。每轮先在 `52D1EF..1F5` 比较当前输出计数与容量；不匹配的低位字节无第二道容量检查，写一字节；命中四项时仅在下一门槛小于容量时写反斜杠和对应字母，并把调整后的源长度加 1（`52D253..280`）。高位字节在 `52D286..2A5` 同时要求下一门槛小于容量、输出计数小于调整后的源长度，再原样复制当前与后一字节；随后源游标额外前进一字节。所有分支最终都写 NUL，不另补编码转换、替代字符或容量回退。
- `sub_52D2D0@[0x52D2D0,0x52D2F0)` 先在 `52D2D5/2D6` 将上下文指针传给不读参数的 `nullsub_1`，再按 `context->text`、目标缓冲、容量调用 `52D1B0`（`52D2DB..2E6`），完整透传目标指针。新端复用 `cg::NullSub_509080()` 和同一 `InputContext` 布局；`50C940@50CA3B` 是一处直接调用，但后续 `511900`、玩家/禁言状态与消息下游仍未闭合，不计聊天发送或输入整链完成。

## 历史光标的旧字节边界叶 `44B440`

- 原 `sub_44B440@[0x44B440,0x44B49D)` 为两个栈参数；`44B440` 将第二参数**低 S16** 符号扩展为 S32 偏移，非完整 W32。`44B445..476` 从零游标扫描至不小于该偏移：每轮读一个 W8，仅 `0x81..0x9F` 或 `0xE0..0xFC` 时推进 2，否则推进 1；比较为有符号。零或负偏移不进入扫描。
- 扫描后游标不等于偏移时 `44B478..47D` 返回 `AL=2`；恰好相等时才读 `text[cursor]`，仍按两段相同区间返回 `AL=1` 或 0（`44B47E..49C`）。没有 NUL 扫描、文本长度或容量参数，不把两区间扩为所有 bit7 字节，也不与 `44B1D0` 的截断分类合并。
- 新端 `cg::input::ClassifyLegacyBoundary_44B440(const char*,int16_t)` 返回定宽 W8，复用既有输入模块而不新增状态。原 `44A1B0@44A2D2/44A3E5` 两次调用仅比较 AL 是否为 2；该父函数还依赖 `4A80E0` 读取的跨窗口 `C9A930` 布局槽，当前 owner 未获确认，不能凭本叶完成声称历史翻页或完整输入链已接通。
