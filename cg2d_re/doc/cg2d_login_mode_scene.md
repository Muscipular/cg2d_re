# 能力 0/1 登录场景状态机证据

## 范围与调用

本文只使用当前 `ida-17524` 中 `D:\SOFTSTAR\cg2d.exe` 的证据。

- `sub_45C5A0` 精确范围为 `[0x45C5A0,0x45C7C0)`，大小 `0x220`，共
  161 条指令、40 个基本块；线性比较状态，没有跳转表。
- 唯一调用者是 `World::Update@0x51C430`，调用点 `0x51C493` 对应场景类型 1、
  调色板能力 0/1。`0x51C498` 直接跳向公共尾部，不读取返回寄存器，因此新端
  唯一公开入口 `login::ProcessModeScene_45C5A0` 使用 `void`。
- 原状态是 `gWorld::SceneState@0xFF0D64`，映像初值为零；新端复用唯一
  `world::gCurrentSceneState`，没有建立第二份场景状态。

`World::Update` 已在原分支改接公开入口，并移除旧
`world::detail::Sub_45C5A0` 占位声明。

## 状态流与同帧贯穿

入口先令 `sub_45CA20` 的 mode 默认为 2，再按入口时读取的状态线性处理 0..5；
所有状态及默认路径最终都恰调用一次控制器，只有入口状态 2 把 mode 改为 0。

| 入口状态 | 地址与严格顺序 |
|---:|---|
| 0 | `0x45C5AF–0x45C619`：先写状态 1；调用 `sub_45C970` 并把原返回值写 `0x9A7F64`；调用 `sub_45C7C0`，其内部再次探测并写能力；随后读取最终能力，等于 3 选择 `(29,30)`，等于 2 或 1 选择 `(32,30)`，其余选择 `(24,30)`。本帧继续以 mode 2 调控制器。 |
| 1 | `0x45C623–0x45C636`：调色板变化标志为零时写状态 2；本帧仍使用 mode 2。 |
| 2 | `0x45C638–0x45C63F`：只把本帧 mode 改为 0。 |
| 3 | `0x45C641–0x45C675`：变化标志为零时，能力严格等于 0 选择 `(18,30)`，否则选择 `(19,60)`；调用后重新读取状态并加一。 |
| 4 | `0x45C677–0x45C687`：变化标志为零时选择 `(19,30)`；调用后重新读取状态并加一。 |
| 5 | `0x45C689–0x45C69E`：变化标志为零时调用 `SetCurrentSceneType(2)`；本帧仍继续以 mode 2 调控制器。 |

状态 0、1、3、4、5 的写入都不重新进入前段分派；“同帧贯穿”只指继续进入
`sub_45CA20` 及其返回处理。状态 3/4 的加一保留 `0x45C667`、`0x45C670` 的
调用后重读顺序。

## 控制器返回处理

`sub_45CA20(mode)@0x45C6A2` 返回后严格按以下顺序处理：

1. 返回 1：`nullsub_1@0x509080`；把 `gInputContext9A5960.text` 写入
   `sub_5203B0` 对应槽；把 `gInputContext9A5678.text` 写入 `sub_520410`
   对应槽；`sub_520200`；`PlaySe(53,320,240)`；实时读取能力，值大于等于 1
   时选择 `(19,30)`；写状态 3并立即返回。
2. 返回 2：`PlaySe(54,320,240)`，再以实时窗口句柄调用
   `PostMessageA(window,0x10,0,0)`；`0x45C733` 继续检查消息状态，不能提前
   返回。
3. 返回负数：写状态 100，把固定提示复制到私有消息缓冲；同帧直接进入状态
   100 的消息处理。
4. 其他返回值不增加副作用，但仍按当前状态检查 100/101。

状态 100 严格依次调用 `sub_45CE00`、`PlaySe(56,320,240)`，再重读状态并加一；
同帧随后继续检查状态 101。状态 101 调用 `sub_45CE10(buffer)`，任意非零返回把
状态写回 1。返回 2 的路径同样保留这两次状态检查。

## 提示串与存储适配

- 原私有缓冲位于 `0x9A5FE0`，容量 256 字节、映像初值为零，只有本函数在
  `0x45C769/0x45C7A9` 引用。新端以同容量私有 UTF-8 缓冲承接，不复制状态。
- 原提示串位于 `0x55C59C`，IDA 解码为“`請輸入ＩＤ和ＰＡＳＳＷＯＲＤ`”。
  含末尾 NUL 的原 CP950 字节为：
  `BD D0 BF E9 A4 4A A2 D7 A2 D2 A9 4D A2 DE A2 CF A2 E1 A2 E1 A2 E5 A2 DD A2 E0 A2 D2 00`。
- 新端遵循内部 UTF-8 边界，源文件固定文本按 UTF-8 编译，并连同 NUL 复制到
  256 字节缓冲；不把原 CP950 字节直接送入 UTF-8 消息接口。

## 复用与未决依赖

能力探测、输入初始化与控制器、调色板、两个持久槽、场景切换、登录消息及原生
窗口存储均复用现有唯一实现。`nullsub_1@0x509080` 已直接改接唯一
`cg::NullSub_509080()` 空操作实现。`PostMessageA@0x54D2F0` 已由地址中性的
`PostLegacyWindowMessage(...)` 原生边界承接。目标函数的直接依赖中，以下仍
只有真实窄声明：

- `Sub_520200()` / `sub_520200@0x520200`；
- `PlaySe(...)` / `World::PlaySe@0x52C450`。

此外，已实现的 `ProcessLoginInput_45CA20` 对
`Renderer::DrawText3@0x456560` 的传递依赖已接入唯一文本提交实现。本项仍不为
音频或登录请求补占位实现。
