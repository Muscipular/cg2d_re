# Graphic::readGraphicData 核心还原证据

## 1. 基线与范围

- 取证日期：2026-09-14。

- 原端：x86、小端；新实现：原生 x64 指针，32 位数值字段。
- `ida_nalt.retrieve_input_file_sha256()` 返回
  `dad3f292c6df28e9b7208ad1d339f56ab68c1e728f6595e849e37296551c0f08`，
  原始输入大小为 `1670816` 字节。
- `survey_binary` 返回的 `e7c2790f479862635932e043b2d7e93b9e791a1edc276a960af05f1454c54010`
  对应当前同名磁盘 EXE，不替代 IDB 原始输入；差异见 `cg2d_reconstruction_baseline.md`。
- 函数范围 `[0x52D5C0, 0x52D78D)`，461 字节，完整反汇编共 182 条指令。
  函数内没有 `call`；反编译中的 `memset32`、`memset` 对应 `rep stosd`、`rep stosb`，

实现位于 `include/cg/GraphicDecode.hpp`、`src/GraphicDecode.cpp`。

不据 IDA 名称推断原类布局，整个 RLE 分支仍在该核心函数内，不复用旧 switch 解码器。

## 2. 六参数与返回

下表偏移以函数入口 ESP 为基准，不把 IDA 自动结构类型当作完整布局证据。

| 参数 | 原栈偏移 | 新端表达 | 证据 |
|---|---|---|---|
| source | `+0x04` | `const uint8_t*` | `0x52D5D9` 取源指针，随后逐字节检查签名 |
| destination | `+0x08` | `uint8_t* const*` | `0x52D5C3` 取第二参数，`0x52D5CA` 仅读取其偏移 0 的目标地址 |
| widthOut | `+0x0C` | `uint32_t*` | `0x52D650`、`0x52D773` 写入宽度 |
| heightOut | `+0x10` | `uint32_t*` | `0x52D656`、`0x52D779` 写入高度 |
| lengthOut | `+0x14` | `uint32_t*` | `0x52D646`、`0x52D76C` 写入长度 |
| paletteLengthOut | `+0x18` | `uint32_t*` | `0x52D615/0x52D629`、`0x52D67F/0x52D687` 写入调色板长度 |

原函数不读取第二参数指向对象的其他字段，也不改写该目标地址槽。
新端只接收存活且正确对齐的原生指针槽，不将原 x86 的 4 字节指针槽直接强转为 x64。

`0x52D5CD..0x52D5EA` 依次检查目标地址非零、首字节 `0x52`、次字节 `0x44`；
没有检查源指针、参数槽或输出参数是否为空。目标地址为空时尚未读取源。
检查失败跳至 `0x52D783`，`0x52D786` 清零 EAX 后返回，不写任何输出。
成功时 `0x52D658` 或 `0x52D77B` 返回最初的目标地址，不返回写入末尾。

## 3. 头部与写入顺序

| 源偏移 | 内容 | 证据 |
|---|---|---|
| `+0x00/+0x01` | `RD` | `0x52D5DD/0x52D5E6` |
| `+0x02` | flags：bit 0 压缩，bit 1 扩展头；其他位不参与分支 | `0x52D5F0/0x52D5FD/0x52D608/0x52D66A` |
| `+0x03` | 不读取 | 完整反汇编 |
| `+0x04` | 小端宽度，保留 32 位位模式 | `0x52D5F3` |
| `+0x08` | 小端高度，保留 32 位位模式 | `0x52D5F6` |
| `+0x0C` | 小端压缩命令边界偏移，包含头部；无压缩路径不读取 | `0x52D660/0x52D665` |
| `+0x10` | 扩展头存在时为小端调色板长度，否则为载荷起点 | `0x52D605..0x52D615`、`0x52D667..0x52D67F` |
| `+0x14` | 扩展头存在时的载荷起点 | `0x52D612/0x52D67C` |

无压缩路径在 `0x52D615` 写扩展调色板长度，再执行乘法并读取 `paletteLengthOut` 中的长度相加；
无扩展时在 `0x52D626` 执行乘法，在 `0x52D629` 将调色板长度写零。
`0x52D635..0x52D63E` 按乘加的低 32 位结果正向逐字节复制，不检查头部长度。
随后严格依次写 `lengthOut`、`widthOut`、`heightOut`，最后返回目标基址。
`lengthOut` 等于实际循环复制次数，即 `(width * height + paletteLength) mod 2^32`。

压缩路径先在 `0x52D660..0x52D665` 计算 `source + header.length`，
再读取可选扩展头并写调色板长度；无扩展则写零。
初次比较位于 `0x52D68D/0x52D68F`，每条命令后比较位于 `0x52D756/0x52D758`，
只要源游标小于该边界就继续，不比较目标写入量。
若载荷起点已经达到或超过边界，仍成功写出宽高及其乘积，不执行命令。

压缩成功后 `0x52D769` 计算宽高乘积低 32 位，
依次在 `0x52D76C/0x52D773/0x52D779` 写长度、宽、高。
长度不包含调色板，也不是实际解压字节数。

## 4. RLE 控制字

令 `n = command & 0x0F`，`b1`、`b2` 按源顺序读取；所有长度均不加一。

| 类型 | 条件 | 长度与载荷顺序 | 指令证据 |
|---|---|---|---|
| literal | bit 7 为零，bit 4 为零 | 长度 `n`，随后复制该数量字节；bit 5、bit 6 忽略 | `0x52D728..0x52D73B`、`0x52D749..0x52D750` |
| literal 扩展 | bit 7 为零，bit 4 为一 | 先读 `b1`，长度 `(n << 8) \| b1`，再复制；bit 5、bit 6 忽略 | `0x52D72C..0x52D738` |
| repeat | bit 7 为一 | bit 6 为一则填零且不消费 value，否则先消费一个 value；之后才解析长度 | `0x52D6A0..0x52D6AE` |
| repeat 长长度 | bit 5 为一 | 读取 `b1`、`b2`，长度 `(n << 16) \| (b1 << 8) \| b2`；bit 4 被忽略 | `0x52D6B2..0x52D6CE` |
| repeat 扩展长度 | bit 5 为零、bit 4 为一 | 读取 `b1`，长度 `(n << 8) \| b1` | `0x52D6D1..0x52D6E2` |
| repeat 短长度 | bit 5、bit 4 均为零 | 长度 `n` | `0x52D6E6..0x52D6E9` |

repeat 原填充为 `0x52D707` 的 `count >> 2` 次双字写入，
再执行 `0x52D712` 的 `count & 3` 次字节写入。
新端用同一函数内的字节循环产生相同结果；不承诺机器写入宽度、原子性或故障时部分写入相同。
零长度命令仍消费控制字及其要求的 value/长度字节，但不写目标数据。

literal 在 `0x52D73E/0x52D743` 保留 `count >= 0xFFFFF` 的失败判断。
其真实解析结果最大为 `0xFFF`，因此在上述可定义条件下不可达；
不能将此比较解释为 repeat 或输出容量检查。
该失败路径不会回滚先前目标写入及调色板长度，亦不会写长度、宽、高。
新实现仍保留此判断，没有新增非法控制字拒绝逻辑。

## 5. 可定义边界与未覆盖项

- 调用者保证原生目标指针槽和四个数值输出对象有效；不额外要求所有对象两两不重叠。
  实际读取、写入和数组内/末尾指针运算合法，类型化输出对象存活且正确对齐，不存在并发修改。
- 压缩命令内部不检查 `header.length`，一条命令可读过逻辑结束位置。
  调用者必须提供实际需要的可访问字节，不能仅凭声明长度判断源内存充足。
- 目标容量按实际命令输出负责，而非仅按宽高乘积负责。
  不补做尺寸、调色板、声明长度、解压长度匹配等检查，也不补齐或截断输出。
- 小端字段逐字节读取，复制与填充逐字节写入；不将源头强转为结构体或未对齐 `uint32_t*`。
  宽高乘法及无压缩调色板长度加法保留原 W32 数值宽度，地址采用已证原生指针。
- 原源/目标越界、失效指针、原 x86 32 位地址回绕及依赖这些行为的输入不在还原保证内；
  本次未解决其安全问题，也不提供原 x86 ABI、完整目标描述符或故障现场的兼容。
- 仅完成该函数源码与证据，不接入 CMake，不实现调用方、资源加载、调色板颜色转换或客户端启动。
  未新增测试用例，未编译、调试或运行客户端；独立验证由主线程另派。
