# Yobi 角色动画编号命名（YCA01）

日期：2026-10-25。用户要求分析characterAction动画编号，定义枚举并替换引用；未证实的业务名称按动画号和已证行为命名。

## 范围与命名裁决

在既有公开YobiRuntime.hpp的cg::yobi中定义CharacterAnimationId，以std::int32_t为底层类型，列出0～19。字段、参数、局部变量和表元素仍保留原整数类型；不增加合法值门禁，不改变负值、未知资源编号或Lua输入的承接。

0～11结合服务端编号、客户端播放与实际生产路径命名；12～19使用Animation12等编号名，并说明已证播放／透传行为。服务端高编号的HAND、PLEASURE、ANGRY、SAD、NOD、GUU、CHOKI、PAA及IDA同名类型只作来源线索，不据此推定每个角色资源的具体手势。11按Sit命名，骑乘是它的一个使用场景，不统一叫Mounted。

替换范围为Yobi源码、其公开枚举及相关声明说明，包含赋值／比较、骑乘及附件映射case、构造调用中的动画实参、预览表第一列、战斗动画序列的有效项和Lua默认动画。其他模块的协议命令及调用保持。17已由51A840的动作命令分支透传至51A060／43EFC0，本轮Yobi内部没有独立的17字面量生产，不为制造引用新增分支。

## 原端与参考证据

- 原0x517DC6读取对象+2B0，0x517DD2读取+2B4；517DA0按动作／方向／图号变化重置播放，随后将+2B0与资源动作表的U16 action匹配。517880采用同一动作匹配合同；编号不是角色phase或播放次数。
- 原0x406697在死亡位分支向+2B0写10；待机路径写0。0x406E31先写7探测攻击帧事件，失败在0x406E47改写5。原4065E0只探测当前动画，0x406614将+2B4写-1以失效播放缓存，不把-1定义为动画。
- 原0x40C1A8／40C1E8／40C225／40C248／40C288／40C2B8分别写13／14／15／15／12／18；当前对应动作分别保留终帧推进、清帧或仅赋值的区别，不把该消费过程当作资源动画的独占业务名。
- 原43EFC0按坐骑动画映射角色：2／3／4映射3，5／6映射5，8／10映射8，9映射9，其他按原资源族选择11或0。421FB0也有独立骑手映射；不改映射规则、restart及缓存失效顺序。
- 当前IDA的CHAR_ACTION已有类型与服务端include/char_base.h:276起枚举在0～19一致。IDA类型来源未证，仅作为声明资料；服务端0～11命名同时由当前角色移动、近战、施法、受击、死亡及坐姿使用支撑。51A840明确将0～19分别传入动画设置，而30／31转换为1／0，40以上另行处理；这些协议命令不混进动画枚举。
- 实际读取原0x5538F4的200个S8，与当前战斗序列表完全一致；读取0x55B2C0的16行三列S32，与当前预览表一致。预览第一列才是动画编号，后两列为持续次数及图号偏移；战斗序列的-1为终止符，终止后的显式0及后八行隐式0保持原填充。

## 独立域与实施边界

- environment.cpp把characterAction借作场景运动阶段，含1→2自增和阶段3离场，整个文件保持原值及自增，不套用角色动画编号。
- map_observation的characterAction形参81／82是观察场景命令，保持；其counter1DC只有已证向子对象动画透传的0／3替换，其他计数及-1哨兵保持。
- lastCharacterAction的-1仅用于缓存失效；phase、direction、frameIndex、frameRemain、frameEvent、stopAtEnd、restart、RNG及所有资源号保持。比较动画后产生的0／1播放标志也不替换为动画枚举。
- Lua的charAction默认值0可以具名，最小值0、最大值和验证逻辑保持；字符串键、动态输入及原字段宽度保持。
- 不把资源动作表U16改为枚举，不假设每个资源都包含0～19全部动画，不把20视为上界或新增回退。原无匹配返回、装载失败及帧事件探测顺序保持。
