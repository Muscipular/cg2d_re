## 2. 整表存储与启动绑定

### 2.1 表槽、容量与分配

| 对象 | 已证事实 | 地址证据 |
|---|---|---|
| `0x103CFA4` | 原 W32 堆表指针槽；76 个直接交叉引用中仅 1 写、其余 75 读 | 唯一直接写为 `0x457565: mov [0x103CFA4], eax` |
| 槽中值 | `eax` 来自 `malloc`，不是图号、句柄或内嵌表 | `0x45755A` 分配，`0x457565` 写槽 |
| 初始空值 | 仅继承映像初值证据；不据此声称有运行时清槽路径 | 本交接未给出运行时清槽证据 |
| `0x103CFA0` | 容量唯一直接写为十进制 `2200000` | `0x457528: mov [0x103CFA0], 2200000` |
| DX cache 整表 | 每项 `0x10` 字节，分配 `35200000` 字节 | `0x45754B` 读容量，`0x457556: shl ecx, 4`，`0x457559: push`，`0x45755A: malloc` |
| 相邻 GraphicInfo 表 | 通过 `shl edx, 5` 另行分配，与 DX cache 不是同一张表 | 继承本次交接的分配链结论 |

不能把 `0x103CFA4` 解释为每图 surface，也不能拿 GraphicInfo 表或另造的尺寸表替代它。

### 2.2 成功清零与分配失败

四个相关分配全部非空后，才执行 DX cache 整表清零：

| 顺序 | 指令证据 | 含义 |
|---|---|---|
| 1 | `0x457600: mov ecx, [0x103CFA0]` | 读取项数 |
| 2 | `0x457606: mov edi, [0x103CFA4]` | 读取表基址 |
| 3 | `0x45760C: shl ecx, 4` | 换算表字节数 |
| 4 | `0x457611: xor eax, eax` | 清零填充值 |
| 5 | `0x457613: shr ecx, 2`；`0x457616: rep stosd` | 按双字清零 |
| 6 | `0x45761A: and ecx, 3`；`0x45761D: rep stosb` | 保留原清零尾序列，不另行改写解释 |

分配失败路径在 `0x4575C6` 释放已分配的 DX 表，但不清 `0x103CFA4` 槽。该路径与启动映像初值不同，不能写成“失败后自动恢复空表”。

### 2.3 启动顺序

本交接确认的顺序为：

1. `0x457747` 调用 `BuildSurfaceCache`。
2. `0x457770` 初始化调色板池。
3. `0x457775` 调用 `InitPalette`。
4. `0x457782` 调用 `GraphicAlloc`。
5. `0x4577AA` 重置表引用。
6. `0x4577B9` 调用 `GraphicInit`。

`GraphicAlloc` 仅有上述直接调用；未发现运行期另换整张 DX 表的直接路径。该结论不扩展为对未知间接路径的推断。

## 3. 单项真实生产与条目布局

### 3.1 `0x522570` 的输入与资源来源

- `0x522579/0x52257B` 检查图号非负，`0x52257D/0x522583` 检查小于容量。
- `0x52258C: shl esi, 4` 以同一全局图号定位 DX 条目；条目 `+0x00` 非空时直接返回 `1`。
- 仅空链头才在 `0x5225A9` 调用 `0x45A900`；输入仍为该全局图号，不是资源文件 slot 或 `MapNo`。
- 读取使用四个输出槽 `0x1020EC0/0x1020ED4/0x1020ED0/0x1020ED8`。
- 尺寸来源继承已通过的资源证据：`0x45A900 -> 0x52D5C0` 从资源头 `+0x04/+0x08` 读取 W32 宽高，不是 GraphicInfo 的 `+0x10/+0x12`。
- 资源依据只引用 [图形解码证据](cg2d_graphic_decode.md) 第 44 行起，本任务不重新分析解码流程。

### 3.2 写入顺序与失败保留

| 顺序 | 地址与操作 | 约束 |
|---|---|---|
| 1 | `0x5225E3: mov dx, word [0x1020ED4]` | 取资源宽度低 16 位 |
| 2 | `0x5225EA` 写当前图号 | 位于宽度写入之前 |
| 3 | `0x5225F1: mov [esi+ecx+4], dx` | 写当前条目 `+0x04` |
| 4 | `0x5225F6` 重读表基址 | 保留该读取顺序 |
| 5 | `0x5225FB: mov cx, word [0x1020ED0]` | 取资源高度低 16 位 |
| 6 | `0x522603: mov [esi+eax+6], cx` | 写当前条目 `+0x06` |
| 7 | `0x522608` 调用 `0x5222D0(imageNo, 0)` | 尺寸已写入，随后建立纹理节点链 |

读资源失败时，当前图号置 `-1`，上述四个输出槽清零并返回 `0`；不清旧条目的宽高。不能把失败输出清零扩展成条目尺寸清零。

### 3.3 原端 `0x10` 字节条目

| 偏移 | 原端存储与语义 | 证据与限制 |
|---|---|---|
| `+0x00` | W32 纹理节点链头原生指针 | `0x522451: mov [ebx+eax], ecx`；不是 direct surface |
| `+0x04` | W16 宽度 | `0x5225F1` 写资源宽度低 16 位，消费按 S16 解释 |
| `+0x06` | W16 高度 | `0x522603` 写资源高度低 16 位，消费按 S16 解释 |
| `+0x08` | W32 调色板转换缓存项引用 | `0x520D54: mov [esi+8], eax`；不是每图独占分配 |
| `+0x0C/+0x0D/+0x0F` | 字段与用途未知 | 仅证整表清零；不得命名为 padding |
| `+0x0E` | W8 标志 | `0x520D87/0x520D97` 按当前 palette 长度是否大于 `0` 置 `0/1`；不扩展其业务含义 |

`0x507090/0x507140` 使用同表、同一 `imageNo << 4` 的消费结论直接继承 [既有消费者证据](cg2d_sub_507140.md)。本任务不复查旧算法，也不据此批准 x64 结构。

## 4. 纹理节点池与链生命周期

### 4.1 池范围、块尺寸与对齐

- 节点池为 `[0x1020F08, 0x103CF08)`，原端 stride 为 `0x1C`。
- `0x52325A` 取池起址；`0x5232C5: add esi, 1Ch` 推进；`0x5232C9: cmp esi, 103CF08h` 检查边界；`0x5232D1` 写实际计数。
- 完整成功时有 `4096` 项；实际计数不能无条件替换成固定成功容量。
- `0x44B77C/0x44B788` 将块宽高分别写为 `0x40/0x30`，即 `64/48`。
- `0x5222D0` 先按 signed 除法及余数计算宽度除以 `64`、高度除以 `48` 的块数。
- 随后 `0x52238F..0x522398` 执行 `neg edx; and edx, 3; add eax, edx; mov [0x1020ED4], eax`，对齐当前宽度。
- DX 条目宽高已先在 `0x5225F1/0x522603` 写入；不能以对齐后的当前宽度替代条目宽度。
- `0x5222D0` 唯一直接调用的第二参数 `p=0`；非空 `p` 的类型未知，不声明为已知结构。

### 4.2 旧链解绑与新链串接

| 阶段 | 地址证据 | 已证行为 |
|---|---|---|
| 旧节点解绑 | `0x5223BC/0x522425` | 将 `node+0x04` 图号写为 `-1`，沿 `node+0x10` 继续 |
| 清旧入口 | `0x5223CC/0x52241B` | 清条目链头 |
| 绑定新链头 | `0x522451` | 将新节点指针写入当前条目 `+0x00` |
| 串接节点 | `0x522466: mov [edx+10h], ecx` | 写节点 next 引用 |
| 正常末端 | `0x52251E` | 将末节点 next 写为 `0` |

节点来自共享池，不按每个图号单独分配或释放。图号解绑、条目入口清零和节点 surface 释放是不同操作。

### 4.3 复用资格、消费状态与不足路径

- `0x5223F2: add edi, FFFFFFFEh` 形成当前 state 减 `2` 的比较值。
- `0x5223F8` 比较 `node.state`，`0x5223FE: jnb` 按 U32 排除 `state >= 当前 state - 2` 的节点。
- `0x5224EF/0x5224FB` 使扫描索引按池实际计数回到 `0`，不得删去原有取模式循环行为。
- 消费端 `0x520FE3/0x5211FF/0x521536` 将当前 `0x58B7E4` 写入 `node+0x08`。
- `0x522505` 扫回起点时，经 `0x52254A/0x522557` 日志路径返回，没有经过 `0x52251E` 的末节点 `next=0`。
- 外层 `0x522612: mov eax, 1` 仍报告成功，因此返回成功不等于纹理链完整生成。
- 容量不足与部分建链属于上层缓存生命周期，不能按 DX driver 故障豁免，也不能擅改为事务式全成或全退。

## 5. 调色板转换池与引用失效

### 5.1 动态池和静态共享项

| 对象 | 地址证据 | 已证事实 |
|---|---|---|
| 动态调色板池分配 | `0x44E0C0: push 1A680h`；`0x44E0C5: push 40h`；`0x44E0C7: GlobalAlloc` | 分配原端动态池 |
| 锁定与绑定 | `0x44E0CE: GlobalLock`；`0x44E0D4` 写 `0x62B068` | 记录池引用 |
| 动态池项 | stride `0x410`，共 `104` 项 | 每项首 W32 为图号，初始为 `-1` |
| 静态共享项 | `0x44E290` 也可返回 `0x627368 + index * 0x410` | 共四项，不属于每图独占 heap |

DX 条目 `+0x08` 可以指向上述不同来源；不能对每个图号的该引用分别执行 heap 销毁。

### 5.2 绑定、复用、老化与绘制

1. `0x520CEB` 将旧调色板项图号写为 `-1`，`0x520CF1` 清条目 `+0x08`。
2. `0x520D4C` 取得缓存项，`0x520D54` 将其绑定到当前条目 `+0x08`。
3. `0x520D5E: add eax, 10h` 取得缓存项载荷供上传；引用指向缓存项本体，不是载荷起点。
4. 池复用在 `0x44E1C7/0x44E204` 清旧图条目的 `+0x08`。
5. 老化在 `0x44E24F` 清引用、`0x44E25D` 将池项图号写为 `-1`。
6. 绘制在 `0x5213CD/0x5216DD` 清调色板 `cache+0x0C`，并在 `0x521428` 调用老化。

这里的调色板 `cache+0x0C` 不是 DX 条目 `+0x0C`；后者仍属未知字段，不能据同偏移推定用途。

## 6. 重建只使引用失效，不更换整表

### 6.1 重建链与保留内容

`0x466B80` 内部按如下顺序执行：

1. `0x466B8C` 调用 `Destroy`。
2. `0x466B91` 调用 `Init`。
3. `0x466C11` 调用 `BuildSurfaceCache`。

`BuildSurfaceCache` 在 `0x5232D7` 重置 nodes，再于 `0x5232DC` 调用 `0x523350`：

- `edx=0`，以 `0x10` 为 DX 条目 stride。
- `0x523367: mov [eax+esi], edx` 清条目 `+0x00` 纹理节点链头。
- `0x523370: mov [eax+esi+8], edx` 清条目 `+0x08` 调色板缓存引用。
- 仅清这两处引用，保留宽高和其他字节，不重新分配或更换整张表。

整表初次清零、节点池重置和重建时的两引用清零必须分别记录，不能合并为一个全表清空动作。

### 6.2 触发时机边界

- MainLoop 在模式不同的 `0x457067`、lost 路径的 `0x4570A7` 触发重建。
- WndProc 在 `0x4670D2/0x467158/0x467194/0x4673EB` 消费 dirty 后调用重建。
- WndProc 在 `0x46720E` 切换模式后调用重建。
- 本文仅定位生命周期时机，不展开消息或主循环调度，不修改其源码、状态或文档。
- 按 `RPLAN.15`，仅底层 DX7 调用允许作等价 SDL/CPU 适配；该豁免不扩大为一般故障豁免，上层状态、顺序、字段和生命周期仍须对应，包括引用失效、节点复用、部分建链及缓存生命周期。

## 7. 退出与未闭合前提

以下为交接中与 DX cache 相关的退出先后，不补写中间无关调用：

| 顺序 | 调用与地址 | 行为 |
|---|---|---|
| 1 | `0x457A4A -> 0x44E110` | 释放动态调色板池；`0x44E130: GlobalFree` 后，`0x44E136` 清池槽 |
| 2 | `0x457A4F -> 0x44C3C0` | `0x44C423: call [ecx+8]` 释放 `node.surface`，`0x44C426` 清 surface |
| 3 | `0x457A6D` | 关闭资源文件 |
| 4 | `0x457A72 -> 0x457670` | `0x457682` 读取 `0x103CFA4` 并经 test/push，`0x45768C: free` 释放整表 |

最后一步不清 `0x103CFA4`、不重置 `0x103CFA0`。分配失败路径同样可能留下悬空表槽，不能把释放等同于恢复初始状态。

重复初始化、重复清理以及清理后消费的合法前提尚未闭合。本文不擅自补成幂等清理、自动清槽、容量清零或新的合法调用约束。

## 9. 待批候选与未决项

### 9.1 仅有的候选边界

- 候选归属仅到 `cg::render`；具体文件、owner 类型、函数接口尚未批准。
- 复用既有资源 capacity、文件/共享 buffer/读入口及队列 owner，不新增同义全局状态或平行副本。
- 原生指针需要按 x64 适配；现代布局、引用表达与访问形式均待批准，原端 W32 指针不能直接照搬为现代指针大小。
- 后续设计必须区分整表分配、单项生成、纹理链引用失效、调色板引用失效、重建和退出。
- 不把共享纹理节点、动态调色板池及四个静态共享项改成每图独占清理，不用替代尺寸表绕过真实生产绑定。
- 本次不形成详细新 SPEC，更不编码；后续实现仍须先完成 owner 和适配边界审批。

### 9.2 必须保留的未知与风险

| 项目 | 当前边界 |
|---|---|
| DX 条目 `+0x0C/+0x0D/+0x0F` | 仅证整表清零，字段及用途未知，不称 padding |
| `0x5222D0` 非空 `p` | 唯一直接调用为 `0`，非空类型未知 |
| 重建 | 只清两个引用，不能误清尺寸和其他字节 |
| 容量不足 | 可部分建链、未走末 next 清零而外层仍返成功；不能隐藏或转为驱动故障豁免 |
| 释放后状态 | 整表槽与 capacity 未清，重复调用及后续消费合法前提未闭合 |

## 13. G1a 新增关键指令与外流证据

### 13.1 疑似 base 压栈在调用前已变为坐标

- `0x418C9B/0x418CCB/0x419568/0x419595: push ecx` 表面上疑似将 base 外传。
- 对应 `0x418CC7/0x418CEB/0x419591/0x4195B5` 的机器码均为 `D9 1C 24`，即 `fstp dword [esp]`，覆写刚压入的栈槽。
- 到 `0x418CF0/0x4195BA` 调用时，param3/5 已是坐标而非 B；不能只看 `push ecx` 就判定 DX 地址 escape。

### 13.2 head 外流为 node，DX entry 另行局部定位

| 取 head 并判空 | 参数压栈 | 调用 |
|---|---|---|
| `0x520FC4: mov esi, [eax+ecx]`，后接 `test esi, esi` | `0x521030: push esi`；`0x521031: push edi` | `0x521032: call 0x520B10` |
| `0x5211EB: mov esi, [edx+ecx]`，后接 `test esi, esi` | `0x52124C: push esi`；`0x52124D: push edi` | `0x52124E: call 0x520B10` |
| `0x521522: mov esi, [ecx+ebp]`，后接 `test esi, esi` | `0x521571: push esi`；`0x521572: push edi` | `0x521573: call 0x520B10` |

- 三组调用形成 `(graphic, N)`；`0x520B50: mov edi, [esp+18h+texture]` 取得 param2。
- node 消费证据：`0x520B54: mov dx, [edi+14h]`；`0x520C1E: movsx ecx, word [edi+0Ch]`；`0x520C42: movsx ecx, word [edi+0Eh]`；`0x520D7E: mov edx, [edi]` 取 surface。
- DX entry 则由 `0x520B2C: mov edi, gGraphicInfoDxCache`、`0x520B32: shl esi, 4`、`0x520B35: add esi, edi` 独立局部定位，不从 N 的地址反算 DX。

### 13.3 node 后继与 surface 指针继续外流

- `0x5211D7/0x5213B0/0x5216C0: mov esi, [esi+10h]` 跟随 node.next。
- `0x52119F/0x521372/0x521688` 从 `[esi]` 取 surface，分别传给 `0x5211BE -> 0x44DA90` 的 param6、`0x521393 -> 0x44D520` 的 param4、`0x52169F -> 0x44DA90` 的 param6。
- 外传的是 node 中另一个对象的指针，不是 N、E 或 DX 原始整项；本任务不继续扩展这些 renderer 业务。

### 13.4 palette 状态比较与 DX flag 的对象边界

- `0x520CCE: mov eax, [esi+8]` 取 P，`0x520CD1: test eax, eax` 判空。
- `0x520CD9: mov edx, [eax+4]` 与 `0x520CE4: mov ecx, [eax+8]` 读取 palette 状态标量参与比较，不是指针数值排序。
- `0x520B7F: cmp [esi+0Eh], bl` 仅读取 DX flag W8；不能据此推定未知尾字段用途。

### 13.5 palette payload 作为 param7 连续传递

- `0x520D57: mov eax, [esi+8]` 取 P，`0x520D5A: test` 判空；非空走 `0x520D5E: add eax, 10h`，空值走 `0x520D63: xor eax, eax`。
- `0x520D6D: push eax` 后再压入六个参数，`0x520D82: call 0x450400`；param7 是 palette payload 或空值，不是 DX entry。
- `0x450400: mov eax, [esp+arg_18]`、`0x450405: test` 消费该参数；非空时 `0x450415: push eax` 后再压入六参，`0x450428: call 0x450190`，仍是 param7 palette payload。

### 13.6 payload 色项索引不是 DX stride 或未知尾字段

- `0x4502D3: mov bx, [edx+ebx*2]` 为 W16 色项读取。
- `0x45032D: lea ebx, [ebx+ecx*2]`、`0x450330: add ecx, ebx` 得到 `payload + 3 * U8index`；`0x450338: mov bp, [ecx]` 为 W16，`0x450340: mov cl, [ecx+2]` 为 W8。
- `0x4503A2: mov ebx, [edx+ebx*4]` 为 W32 色项读取。
- 前述 `0x10` 是 palette payload 在缓存项内的起始偏移；`2/3/4` 是 color stride，不是 DX entry stride，这些读取不访问 DX unknown tail。

### 13.7 stack RECT 组装与 pixel buffer copy 不是 DX 整项 copy

- `0x52137B/0x521381/0x521388/0x52138B` 的四次 W32 写入取自局部 rect，用于组装 stack RECT，不是跨字段复制 DX 条目。
- `0x450278: rep movsd`、`0x450285: rep movsb` 的源是 pixel buffer，长度来自 tw，并经 `shr ecx, 2`、`and ecx, 3` 处理。
- 这些 copy 不是 B、E 或 P 的整项复制；不能因出现连续写入或 `rep movs` 就归为 DX raw copy。

### 13.8 返回寄存器未保留有效 DX 地址

- `0x517D96/0x517F54: xor eax, eax` 清除 EAX；`0x517BF5/0x518201` 的 object index 计算覆写 EAX。
- `0x520DB8: mov eax, 1`，且 ESI 已恢复。
- 上述返回路径未形成有效 DX 地址返回；该结论只覆盖这里交接的路径。

### 24.2 入口及循环顺序

1. `0x523350` 以 R32 读取容量槽 `0x103CFA0`；`EDX/ECX` 清 0，入口容量按有符号比较 `<= 0` 时直接跳至 `0x523382`。
2. 正容量路径保存 `ESI`，将 `EAX` 偏移清 0；每轮先在 `0x523360` 重读 base 槽 `0x103CFA4`，再递增 `ECX` 计数。
3. `0x523367` 以 W32 清当前 `entry+0x00` 纹理节点链头；`0x52336A` 独立重读 base，然后 `0x523370` 以 W32 清当前 `entry+0x08` 调色板缓存引用。两次 base 读取不能合并为一次快照。
4. `0x523374` 重读容量，`0x52337A` 将偏移加 `0x10`，再以有符号 `ECX < ESI` 判断是否继续；循环上界不是入口容量的固定快照。
5. 正容量正常结束后恢复 `ESI`。本体保持 `ESI`，两条返回路径均保持栈平衡。

本体没有 base 判空，不读取条目旧值；不改宽高、`flag` 或未知尾字节，不写 capacity/base 槽，不分配或释放。这里只记录指令读写顺序，不新增保护或提前返回。

### 24.3 实际 EAX32 与零次循环

| 路径 | 完整 EAX32 实际结果 | 其他可见行为 |
|---|---|---|
| 入口容量有符号 `<= 0`，循环 0 次 | 保留入口容量的原 W32 位模式；容量为 0 时结果为 0 | `ECX/EDX=0`；不读 `0x103CFA4`，无全局或表写入 |
| 正容量正常结束 | 每轮累计 `0x10` 后的偏移，即 `16 × 实际轮数` | 按上述顺序清两引用，容量与 base 逐次重读 |

## 31. InitializeClient 的前进控制流与局部重试

### 31.1 连续函数范围及返回点

`InitializeClient` 的连续函数区间为 `[0x4576B0, 0x457A3C)`，共 253 条指令；17 条显式跳转均向前，本体没有回边或间接 `jmp`。“连续函数区间”不等于单个基本块，也不能替代被调用函数或回调的重入分析。

本体共 8 个 `ret`：`0x45776F`、`0x4577A9`、`0x45784C`、`0x45791A`、`0x4579C7`、`0x4579E7`、`0x457A1B`、`0x457A3B`。仅 `0x4579C7` 返回完整 `EAX32=1`，其余返回 `EAX32=0`。

### 31.2 分配前的 Renderer 局部重试

1. `0x4576C2` 调用 Renderer 初始化 `0x44B630`；`0x4576CD: movsx eax, al` 后以两次 `dec` 区分首次返回的低字节 1 与 2。
2. 仅首次低字节为 2 时，`0x4576DE: cmp edx, 1`、`0x4576E1: setnz al` 将 `gWindowMode`（`0x9A7F48`）写为“旧值不等于 1”，随后 `0x4576E9` 再次调用 Renderer 初始化。
3. 第二次调用后，`0x4576EE: test al, al` 为零时直接前进至 `0x45773D`；非零时经过 `MessageBox` 及 `0x457737` 的 `PostMessageA(..., 10h, 0, 0)`，随后仍前进至 `0x45773D`。
4. 首次低字节为 1 时走另一条 `MessageBox` 路径，其他首次结果直接前进。

这是 `GraphicAlloc` 之前的 Renderer 局部重试，不是重入 `InitializeClient`，也不导致两次 `GraphicAlloc`。这里保留局部显式路径事实，不据此排除 `MessageBox` 内的消息回调。

### 31.3 GraphicAlloc 前后门禁

以下继承前进门禁，只补充是否返回初始化入口的结论，不重审 G2a/G2b 算法：

- `0x45774C: test eax, eax`、`0x45774E: jnz 0x457770` 要求前置调用返回非零才能继续。
- `0x45777A: test eax, eax`、`0x45777C: jz 0x457A31` 在返回零时转入失败返回尾部。
- `0x457782` 调用 `GraphicAlloc` 后，`0x457787: test eax, eax`、`0x457789: jnz 0x4577AA` 在成功时继续；失败经 `MessageBox` 到 `0x4577A9: ret`，没有显式 retry。
