## 原滚动载荷与标志

从当前窗口第 index 元素取得一次载荷字节地址并一直保留。先按低 BYTE bit1 判定，未置则发布整个 W32 零；state bit3 非零时发布整个 W32 3，结果置 S32 1。随后重新取低 BYTE bit1，置位才以当前窗口 y 调用 401E60 计算 mouseY 差，再读取先前元素的 height、算术右移一位，写先前元素 y。

载荷 +0 在 type4 为 flags，在既有 type1 为 imageNo；+8 分别为 deltaY 和 offsetY。沿现有 std::byte/固定 W32 memcpy 访问和两个 offsetof 关系，不强转异型结构，不另造布局或 owner。原数据访问和借用地址不变，三个真实结构保持。

## 三个边界取样阶段

1. 下界阶段：从现场元素数组先读前项 y，再读当前项 y，比较命中时用同一当前项 y 写前项；当前正文分支内会再读当前项 y，改为原保存值。
2. 上界阶段：重新取得现场数组，按当前项 height → 当前项 y → 前项 height → 前项 y 读取；前两项相加为底边，后两项相加比较，超过时用保存的底边减保存的前项 height。当前正文的加法读取顺序未明确，改为四个原样本的显式读取。
3. 差值阶段：再次取得现场数组，先读当前项 y，再读前项 y，差值仍为前项减当前项，写入最初载荷地址 +8。当前正文减法两侧顺序未明确，改为两个显式样本。

三个原取样阶段对应三段源码；阶段之间的现场全局窗口和数组读取保留，不把它们合并成早期数组。首次载荷地址和第一次 mouseY 更新所用元素地址继续保留；函数末仍以原 state bit3 是否为零决定重读初始载荷 W32、只清 bit1、写回。结果只由原 state bit3 决定，透传 S32 0/1。

上下界调整、清零和标志清位都是原业务行为；不补新的 index>0、null、尺寸或容量门槛，不扩大清零，不增加保护、默认值、钳制、回滚、异常或溢出模型。原有边界调整必须保留。只修改现有滚动根三段和两定义/两真实声明四条关联注释，零回调 body 保持；不新增函数、API、字段、类型、owner 或资源分配释放。
