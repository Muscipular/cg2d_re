## 范围与边界

整理 `src/ui` 的窗口专属函数、通用窗口运行期函数及其声明和调用引用。窗口归属以当前原型表、元素回调绑定、源码正文及 `doc/ui_windows` 的已证合同为依据；现代窗口编号与旧选择编号保持独立。其他模块只同步这些符号的调用或声明，不修改业务逻辑，不拆文件、不新增依赖。

只修改命名、枚举常量与必要说明，保留函数签名、调用顺序、分支、返回、字段宽度、原数值、原型顺序、共享对象和生命周期。保留所有已有原函数／全局／字段地址注释；从名称中移除地址时，在对应声明和定义上方补齐原地址注释。

## 命名

- 窗口专属函数使用 `Window<业务类型>_<职责>`，例如 `WindowBank_Update`、`WindowBank_TabDeposit`。
- 主回调统一为 `Update`、`Draw`、`Release`；刷新正文使用 `Refresh`，按钮使用 `Button<作用>`，输入、滚动、拖动和回复分别明确职责。
- 同一函数供多个窗口共用时，按已证共享职责命名；不复制函数或强行归到其中一个窗口。
- 通用机制使用 `WindowRuntime_`、`WindowElement_`、`WindowDrag_`、`WindowInput_`、`WindowNumber_` 等职责前缀。协议回复按所属窗口及回复内容命名，保留原协议与参数。
- 旧选择面板内部函数不在本次目录范围；其调用上述 UI 函数的引用同步。已经明确表达职责的辅助函数只在确有窗口归属时统一命名，不为了命名增加包装。
- 使用独立对应表记录旧符号、新符号、原地址和依据。不能从相邻地址或标题关键词推断窗口归属。

## 枚举

1. 在既有公开 `WindowRuntime.hpp` 定义 `WindowId : std::int32_t`，成员使用 `WindowId_` 前缀并显式赋原值；整数接口与实例字段保持，避免扩大接口改造。现代编号 0～70 的含义按已证文档定义，不用于旧选择编号、协议类型或原型记录下标。
2. 在既有内部 `WindowRuntimeState.hpp` 定义 `WindowElementType : std::int32_t`，显式保留 0～7：事件区域、图片、动画、文本、鼠标区域、输入、输入光标、数字图片文本。控件实例与原型的 type 字段使用此枚举，创建／绘制／释放／输入分发和原型初始化同步常量。
3. 明确的窗口 ID 参数、实例／状态表下标与 id 比较使用枚举；动态 ID、数量、位置、元素编号、协议编号及原型记录下标保持原值。原型数组 36／37 同源和 38 以后记录下标偏移保持。
4. 不增加转换工具、接口重载或重复编号表；枚举底层宽度静态断言。
