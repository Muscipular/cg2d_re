## 1. 原端消费基线

只读当前 cg2d.exe 会话。四地址各只有两个直接引用，共八处：

| 原对象 | 构造入口 / 唯一消费 | 退出入口 |
|---|---|---|
| 628FE9，早段窄 Init | 453E10：固定 ECX，尾入 5482DD | 453E30：固定 ECX，尾入同一窄计数/刷新体 |
| 628FE8，早段宽 Init | 453E50：固定 ECX，尾入 549397 | 453E70：固定 ECX，尾入同一宽计数/刷新体 |
| 1086539，晚段窄 Init | 5491E0：固定 ECX，尾入 5482DD | 5491F6：固定 ECX，尾入共享窄退出体 |
| 1086538，晚段宽 Init | 54920A：固定 ECX，尾入 549397 | 549220：固定 ECX，尾入共享宽退出体 |

四构造前缀各两条，共八条；两控制器全部 156/155 条含后置 EH chunks，合计 311 条，只在入口把 Init this 存到 var_10，返回时读取该槽传出。var_10 不作为内存解引用、偏移基址、复制/编码或其他对象字段的来源；七阶段构造与清理中的 var_14 是实际标准流/缓冲对象，与 Init this 不同。54843B 只有 RET，不读取参数。

两控制器原直接入向各只有上述两个固定构造前缀；各前缀返回的地址由已存在的 CRT 登记父弃用，随后登记实际计数/刷新退出。四退出前缀设置 Init ECX 后，共享体只处理独立计数和固定输出/错误/日志流，不读取 Init 字节。四个全局地址仍应独立，不能合并成一个对象或整数令牌。

本组可证明的是这些原直接路径的地址身份合同，不能声称全程序没有尚未分类的计算地址/间接读取，也不能证明原完整对象容量。原14流、两独立 S32 计数、文件/缓冲生产与实际退出本体已提交，保持唯一原生 owner。

<a id="standard-init-identity-decision"></a>
## 2. SI01：定义四个独立的原生对象

原完整私有 Init 布局不影响上述已证路径。按 D02 的 C++私有表示承接，采用无业务字段、平凡默认构造/析构的 LegacyStandardStreamInitializer 完整类型；定义四个独立非 const 实例，地址供现有 LegacyStandardStreamInitializer*控制器实际保存/返回。这是本线明确的表示选择，不声明原 sizeof 为1或复制未知对象字节。

- 对象不携带计数、FILE、locale 或标准流；这些原状态由既有真实存储与显式本体持有。
- 不使用 std::ios_base::Init 宿主对象强转、伪原SDK布局、整数地址、统一影子槽或动态句柄表。
- 不增加自动初始化/退出登记、构造副作用、once、懒调用、预清/补值、回滚或固定成功。
- 既有四构造/退出/登记、两控制器/计数、14标准流、绑定与失败路径保持源码原文；只补被引用对象的实际定义和类型。
- 新类型 sizeof 属本线原生表示，不能用作原容量/相邻字节或原SDK对象布局的证据。任何后续证据涉及 Init 字节、偏移、序列化或其他原布局消费，必须重新落实该契约，不能以本组迁移豁免。
- 全 C++90 启用、Legacy 与宿主标准流活动构析归属、原登记数组/退出表、codecvt与SDK/运行仍待；本步不启用原私有CRT启动或调用初始化方法。

该裁决覆盖早期局部合同“类型仍不完整/先不造1B替身”的实施保留，保留原尺寸未知这一事实；实际数据不是零字节模拟业务，而是有独立存活期、可返回真实地址的四个对象。只在本组无字段消费的路径成立，不外推其他 opaque 对象。
