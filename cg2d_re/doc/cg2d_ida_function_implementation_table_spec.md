整体目标仍为完成整体 SPEC。本阶段不降低[总计划 §10](../plan/cg2d_full_reconstruction_plan.md#10-完成门禁)的适用条件；原事实不足先跳过，不猜容量、值、布局或路由，不以准备表格、增加注释或源码存在宣布功能验收完成。

## 2. 全量表的身份与权威

1. 分母来自当前已打开的 cg2d.exe IDA 会话。已按索引分页只读取得 3680 个唯一函数入口和当前名称，与冻结原库存的地址集合一致；不是从旧日志推导的数量。
2. 每个原入口一行，地址升序，保留当前 IDA 名称；共享实现、内联、宿主承接、排除和元数据均保留原行，不从表中删除或合并原入口。新增或变化入口须先核当前 IDA，再更新表及受影响行。
3. 本表是后续判断函数实现状态和选择补码入口的唯一依据。旧日志、语义表、处置记录、追踪快照和差集队列仅作历史或定位线索，不复制其状态作为本表结论，也不反向覆盖本表。
4. 判断依据为当前 CPP/HPP 实际定义、明确的内联或容器操作、实际宿主/平台提供者及对应原入口事实。仅有声明、符号名称、文件存在、文档关联、函数计数或库类别不证明已有实现。
5. 全量表至少记录：序号、IDA 地址、IDA 函数名、是否有实现、当前提供者、接线或缺项。提供者写当前路径、符号或操作、必要行号；无法证实对应关系时明确待确认。

## 3. 状态口径

| 表内状态 | 必要依据与含义 |
|---|---|
| 有正文 | 已找到对应入口的当前非占位 CPP/HPP 定义；只证明正文存在，不等于整根逻辑、完整接线或运行通过 |
| 有承接 | 已证实当前共享、内联、容器、MSVC 或 SDL 提供者；注明实际承接点与获批边界，不要求补无消费者的旧包装 |
| 部分实现 | 已确认实际代码只覆盖部分原业务，逐项写出尚缺正文、分支、数据生产或接线；不能把待验直接当缺代码 |
| 未实现 | 已确认应实现的原入口缺当前正文或真实提供者，或只有占位；注明确认范围，不凭命名筛选直接定性 |
| 待确认 | 现有证据不足以确定实现关系或承接范围；既不标已实现，也不猜成未实现 |
| 已排除 | 用户已明确排除的具体原入口；历史正文仍在时注明，不计已实现或已验收 |
| 不适用 | 已证只是元数据或填充而非业务正文；记录原入口与事实，不扩大排除 |

接线与数据缺项独立填写：正文已有但未接线、缺运行期数据生产也纳入开发候选。未发现源码调用或绑定只作为限定定位事实，不证明原不可达；地址编号表项不冒充可调用函数指针。静态引用不能提升完整 W 门禁。

## 4. 函数地址注释

1. 对本线有明确原入口对应的函数定义及接口声明，在函数名上方标注原 IDA 地址。示例：`// 原函数：0x00401000。` 地址指原 x86 基线，不是新端装载地址。
2. 现有相邻函数注释已包含该入口地址时保留，不重复加一条。保留名称、签名、正文、调用、字段、业务文字和文件编码风格；本步骤只修改关联注释。
3. 重命名函数仍按已证对应入口注释；多个原入口共用实现时明确“关联原入口”及共享关系，不能伪称新函数有一个唯一旧入口。
4. 只有调用关联、候选关系或宿主内部替代时，不给本线辅助函数猜原地址；不修改外部 MSVC/SDL 代码，不给调用点、数据表或新辅助函数冒加函数入口。
5. 注释依据来自全量表中已核实的映射及当前源码。声明和定义关联一致；地址未知的函数明确保持未知，不为覆盖率补值。

## 5. 分工与 IDA 串行

用户本轮许可仅覆盖全量函数表核对，可以交给一个独立会话或子 Agent 持续处理。优先使用子 Agent 承接核表，本线程负责 SPEC、地址注释、实际补码、必要验证和精确提交；不据此自动扩大到其他独立复核或多 Agent 开发。

同一个 IDA 数据库必须串行：任何时刻仅一个线程查询当前 cg2d.exe 会话；交接前结束自己的请求并明确查询归属。本线程在子 Agent 持有 IDA 查询期间只处理源码或文档，不并发查同一数据库；不重开、重载或修改数据库，不另起 IDALib。文件写入也按归属交接，核表期间本线程不覆盖全量表，子 Agent 不改业务源码或提交。

本项具名许可覆盖子项目规则第 11 条对本次核表委派的禁止约定，其他范围的单线程约定保持。目标工具中既有整体目标的文本保持历史描述；当前阶段和这项并行例外以用户最新要求及本 SPEC 为准，不擅自把未完成整体目标标为完成以替换文本。
