# 原多字节分类与目录驱动器转换

## 本轮实施 SPEC（2026-10-02）

接续目录创建修复，53DD2F切目录先SetCurrentDirectoryA、再GetCurrentDirectoryA，
仅非两个相同斜杠的路径才调用543D37，将首字节大写后建立“=X:”环境项。
53DD75传参前movzx，故唯一直接调用543D37的值域是0..255。
本步先实现其真实共享存储、U8读取以及初始化所需的确定性基础函数，
不把宿主_mbctoupper或ASCII转换当原表替代，也不提前接线未完成的初始化。

## 原共享存储

当前原.data的[1086764,1086988)为无文件后备区域，沿已批准映像虚拟零合同初始化。
新LegacyMultibyteStorage逐字段保持原数值/字节偏移，不含指针：

| 相对偏移 | 原地址 | 类型与职责 |
|---|---|---|
| 00 | 1086764 | U32多字节代码页 |
| 04 | 1086768..108676F | 8B暂不解释，保持原共享窗口 |
| 0C | 1086770/74/78 | 三个U32代码页表参数 |
| 18 | 108677C | S32多字节标记 |
| 1C | 1086780 | 256B大小写映射 |
| 11C | 1086880 | 257B分类表；1086881[value]为字符槽，首项单独保留 |
| 21D | 1086981..83 | 三字节间隔 |
| 220 | 1086984 | U32多字节locale，不能误放到108676C |

该存储与LegacyStringCompare的C语言分类表、1086160 locale分开；
它们是原端不同地址和生产链，不因都称locale就合并。
它也不是第二份模拟表：后续5468EA/546B29必须直接写这一对象。
未来跨区间原字节别名必须映射到同一owner，不因已有独立对象忽略别名。
初始零仅是映像装载状态，不代表初始化已完成或可用空目录数据。

## 已实现的三个基础入口

- 546ACD..546B00共19条：932→1041、936→2052、949→1042、950→1028，
  其他代码页返回0，包括原表同时支持但本映射未列的1361。
- 546B00..546B29共17条：先清257字节分类表，再清代码页、多字节标记、
  多字节locale，最后清三个U32参数；不清大小写映射或暂未解释间隔。
- 543D37..543DB2共43条：仅以U8接口承接唯一直接caller的值域。
  读取classification[value+1]的20h位，命中返回caseMap[value]，否则返回原值，
  返回仍U32。不映射为宿主字符转换，也不实现不可由该caller传入的>255 NLS分支。

平台私有LegacyMultibyte.hpp/cpp承担存储与基础函数，加入现有startup静态库源清单。
不向应用层暴露Win32类型，不改已有比较器、C语言分类或目录调用。
待初始化生产和调用次序落实后，再将53DD2F与两处存档调用实际接入。

  经542F44返回-1，不回滚已发生的目录改变。未加长度保护或猜测失败默认值。
