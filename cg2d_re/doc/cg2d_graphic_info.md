# 图形元信息结构与查询函数

日期：2026-09-14；2026-09-20 补充 R6.1.3.31。状态：实现完成；R3.2.2 曾独立静态复核及 x64 Debug/Release 编译通过，本次补充仅作静态检查。

原阶段范围为 `include/cg/GraphicInfo.hpp`、`src/GraphicInfo.cpp` 中的两种布局、三个全局状态、七个查询函数及一个调色板能力探测入口，命名空间为 `cg::resource`。2026-09-27 后续增加真实 `GraphicInit_459960`，见文末；后续仅静态核对，未沿用早期编译结论。
布局依据主线程已逐指令核对的 `GraphicInit@0x459960` 证据；七个查询函数曾在 `ida-30904`（`cg2d.exe`）只读复查，本次探测入口在 `ida-17524`（`D:\SOFTSTAR\cg2d.exe`）只读复查，均未改动 IDA。

## 运行时布局

`GraphicInfo` 步长为 `0x20`，不含指针，迁移到 x64 后不扩大记录。头文件对尺寸、全部字段偏移、标准布局及可平凡复制属性设置 `static_assert`。
`seqNo/length` 使用无符号 32 位类型承载原位模式；运行时 `offset` 按主线程 `GraphicRead` 的调用约定使用 `int32_t`，不据此扩展加载时的算术或业务规则。

| 偏移 | 字段 | 存储 | GraphicInit 写入指令 VA |
|---|---|---|---|
| `0x00` | `seqNo` | `uint32_t` | `0x459D05` |
| `0x04` | `offset` | `int32_t` | `0x459D12` |
| `0x08` | `length` | `uint32_t` | `0x459D20` |
| `0x0C` | `x` | `int16_t` | `0x459D2F` |
| `0x0E` | `y` | `int16_t` | `0x459D3F` |
| `0x10` | `w` | `int16_t` | `0x459D4F` |
| `0x12` | `h` | `int16_t` | `0x459D5F` |
| `0x14` | `fileIndex` | `int16_t` | `0x459DA4` |
| `0x16` | `reserved` | 两字节 | 用途未明，保持保留区 |
| `0x18` | `sx` | `uint8_t` | `0x459D6E` |
| `0x19` | `sy` | `uint8_t` | `0x459D7C` |
| `0x1A` | `flag` | `uint16_t` | `0x459D8B` |
| `0x1C` | `mapNo` | `int32_t` | `0x459D9A` |

`fileIndex` 的有符号性另由 `0x45A935` 的 `movsx` 确认。`mapNo` 使用 `int32_t`，查询直接返回字段，不通过数值转换改变原 32 位位模式。

## 磁盘布局

`GraphicInfoRecord` 单独命名，尺寸为 `0x28`（40 字节），同样对尺寸与全部字段偏移设置 `static_assert`。

| 偏移 | 字段 | 存储 |
|---|---|---|
| `0x00/0x04/0x08` | `seqNo/offset/length` | 各 `uint32_t` |
| `0x0C/0x10/0x14/0x18` | `x/y/w/h` | 各 `int32_t` |
| `0x1C/0x1D` | `sx/sy` | 各 `uint8_t` |
| `0x1E` | `flag` | `uint16_t` |
| `0x20` | `reserved` | 四字节 |
| `0x24` | `mapNo` | `int32_t` |

磁盘布局不等于运行时布局：坐标与宽高字段宽度不同，磁盘没有运行时的 `fileIndex`，两个保留区不能等同。原查询阶段未实现文件读取或转换；2026-09-27 后续 `GraphicInit` 已按本表逐字段写入，不覆盖运行时保留区。

## 全局状态

| 原 VA | 实现 | 未初始化值 |
|---|---|---|
| `0x103CFA0` | `int32_t gMaxGraphicCount` | `0` |
| `0x9A2970` | `GraphicInfo* gGraphicInfo` | `nullptr` |
| `0x9A2974` | `int32_t* gGraphicMapNoIndex` | `nullptr` |

原查询阶段不分配、不加载、不绑定伪造的数据。后续 `GraphicInit` 在本模块分配 mapNo 索引，主表仍由既有 `GraphicAlloc` 分配；全局指针采用 x64 原生宽度，指向的图形记录及索引元素仍分别为 32 字节、4 字节，不据此声明客户端初始化已经成功。

## 原函数映射

| 实现 | 原指令范围（右端不含） | 对应行为 |
|---|---|---|
| `GetGraphicXY` | `[0x45A710, 0x45A760)` | 无符号索引比较；依次输出 `int16_t x/y` |
| `GetGraphicWH` | `[0x45A760, 0x45A7B0)` | 无符号索引比较；依次输出 `int16_t w/h` |
| `GetGraphicSxSy` | `[0x45A7B0, 0x45A802)` | 无符号索引比较；将 `sx/sy` 零扩展为 `uint16_t` 后依次输出 |
| `GetGraphicFlag1` | `[0x45A810, 0x45A851)` | 无符号索引比较；零扩展 `flag` 后 `% 100`，输出 `uint16_t` |
| `GetGraphicFlag2` | `[0x45A860, 0x45A8A8)` | 无符号索引比较；零扩展 `flag` 后 `/ 100`，输出 `uint16_t` |
| `GetGraphicMapNoIndex` | `[0x45A8B0, 0x45A8C9)` | 不检查索引，直接写 `gGraphicMapNoIndex[index]`，返回 `1` |
| `ProbePaletteCapability_45C970` | `[0x45C970, 0x45CA1B)` | 按 `99657,245151,22311,22212,22002` 两阶段探测，返回 `-1` 或 `4-index` |
| `GetGraphicMapNo` | `[0x45A8D0, 0x45A8F2)` | 有符号负索引或不小于有符号上界时返回 `-1`，否则返回 `mapNo` |

前五个函数使用 `index < static_cast<uint32_t>(gMaxGraphicCount)`，成功返回 `1`；失败按参数顺序写零并返回 `0`，不把负计数修复为零。
双输出函数不预取两个字段或缓存整条记录，先完成首个输出写入，再从全局表表达式读取第二字段，对应 `0x45A733/0x45A783/0x45A7D4`。
`sx/sy` 的零扩展对应 `0x45A7C7/0x45A7DE`。Flag1 的 `xor ecx, ecx`、`mov cx` 与 `idiv 100` 对应 `0x45A824/0x45A829/0x45A836`；Flag2 对应 `0x45A874/0x45A879` 的零扩展及 `0x45A87E` 起的乘常数除以 100。

`ProbePaletteCapability_45C970` 首轮从索引 0 查找首个非零映射；全零返回 `-1`。命中后第二轮从同一索引重新调用 `GetGraphicMapNoIndex`，稳定表下首项因此读取两次；若第二轮结果动态变零则继续后移，首个非零返回 `4-index`。`0x45C9B7/0x45C9EA` 的 `test` 后接 `ja` 等价于按任意非零判断，负非零同样命中。函数不写 `gPaletteCapability`；本次接入的两个 caller 各自保存返回值，其余原调用者留待所在函数还原。

## 调用前提与未覆盖项

- 输出指针必须非空且可写；实际读取表项前，相应全局状态必须已经绑定有效存储。
- `GetGraphicMapNoIndex` 由调用者保证所给索引可访问，不借用图形计数增加边界检查。
- 不新增原函数没有的空指针检查、容量检查或其他修复逻辑。
- 非法地址、实际存储越界，以及原 32 位索引乘步长和地址加法的回绕行为仍未覆盖，不声称这些情形与 x64 指针运算等价。
- 独立代理核对两种布局和七个函数；首次复核发现文档中五个写入地址错配，主线程按原指令修正后再次复核通过，源码无需修改。
- 主线程独立 x64 Debug/Release 编译通过，布局断言已通过编译；未新增或执行测试用例，未启动客户端，不据此宣称完整加载流程已验证。

## `GraphicInit_459960` 完整资源生产入口

2026-09-27，现有 `ida-17524` 会话只读核 `[459960,45A12C)` 全部指令、
反编译及相关容器辅助，不打开、保存或修改数据库文件。初始化本体现落在
既有 `GraphicInfo.cpp`，数据文件使用 `GraphicRead` 的唯一九槽，主表、
mapNo 索引沿用既有资源状态；路径生产仍由 `ResourcePaths` 负责。

### 文件阶段与失败残留

| 指令段 | 实现合同 |
|---|---|
| `45996A–459A31` | 入口先清九数据文件槽，不关闭其旧值。按槽复制输入数据路径到独立的 `9*255` 缓存，再打开并发布文件。0/3/6/7/8 为必需槽；任一必需槽失败先关闭/清全部非空数据槽，再分别返回 1/2/7。 |
| `459A37–459B06` | 按相同步长缓存 Info 路径，逐个打开、seek 到尾、将完整 W32 ftell 结果累加，随后关闭但不清共享 Info 句柄槽。必需 Info 缺失直接返回 1/2/7，不关闭已开数据文件。optional 缺失继续。 |
| `459B0C–459BED` | 发布 `totalInfoBytes/40+10` 到 `833C9C`，再以 S32 比较最大容量。达到容量时按原 `%d` 显示消息，然后关闭数据文件。此时槽计数为 9，原 `sbb/and al,FC/add 7` 的实际返回为 3，不改为 1/2/7。 |
| `459BEE–459C20` | 按 `4*gMaxGraphicCount+0x28` 分配并立即发布 mapNo 索引；空返回 -1，保留文件和既有其他状态。成功只清前 `4*count` 字节，不初始化额外 40 字节，也不先释放旧索引。 |
| `459C22–459C68` | 清去重 vector 的有效长度并清首见记录树；保留 vector 容量。这些阶段只在索引分配成功后执行。 |
| `459C72–459CCE` | 每个 Info 槽先发布当前基址到 `73F100[slot]`，再重开已缓存路径。必需槽这次失败仍直接返回，保留已经写入的前缀；optional 失败跳过且不更新累计基址。 |

容量提示标题保留 `5598B0` 的原字节：
`73 70 72 6D 67 72 3A 20 4D 41 58 5F 47 52 41 50 48 49 43 53 20 A4 A3 B0 F7 A1 43 00`；
通过既有 `ShowLegacyMessage` 传递，不把标题猜测转码为源文件中文。

### 记录、索引与排序

- `459CCE/459F1D` 在 fread **之前**检查 EOF；`459CE2` 读取 40B 后
  不检查返回、不再次检查 EOF，先递增累计处理次数，再消费同一栈记录。
  因此通常完整非空文件在探测 EOF 的最后一次读取中仍重写末条记录，
  下一文件的基址来自累计处理次数，不是最大 seqNo+1 或文件记录数之和。
- 40B 局部槽不预清零，跨读取/文件沿用；短读的未覆盖部分保留，
  首次未写字节不猜值。不增加空文件、非整记录、ferror 或越界拒绝，
  不采用地图短头补零方案；这些未定义域不宣称逐次等价。
- `459CFD–459DA4` 用 `record.seqNo+base` 定位主表，依次写 seqNo、
  offset、length、x/y/w/h 低 W16、sx/sy、flag、mapNo，最后写文件槽低 W16。
  每字段取同一资源主表；不写 `reserved[2]`，不整项清零。
- `459DA9–459DC6`：mapNo 为零时只清直接索引第 0 项；非零且其 U32
  小于最大容量的 U32 才覆盖直接索引。重复 mapNo 在此以最后写入为准，
  但不因此更新下面的首见记录引用。
- `459DD4–459F18`：先线性查找进程期去重 vector；只有首次出现的
  非零 mapNo 才追加值并插入 `mapNo -> GraphicInfo*`，指针借用主表，
  不是记录副本。越过直接索引上界的非零 mapNo 仍可进入该 vector/树。
- 树查找/唯一插入比较 `459E3D setl`、`459ED6 jge` 按 S32；
  `45A9FA` 构造时清重复键标志，`45AA80` 是清整树，`45AF60` 为节点插入。
  当前以 `std::map<int32_t, GraphicInfo*>` 承接同一键语义和首见引用。
- `459F27–45A0FB` 每个成功打开的 Info 结束后，都对累计 vector 按
  S32 排序，再关闭 Info、以累计处理次数更新基址。对应源码使用
  `std::sort`；不按 unsigned 排序、不改成每文件独立集合。

私有缓存路径、Info 句柄、预扫需求计数、vector 和首见树不向业务层暴露。
原九槽基址 `73F100` 的直接消费者为 `AnimeLoadAction@45B7E8`、
`CoordInit@45C200`，公开为同一 `gGraphicStartIndices[9]`；两消费者
后续已在 [动画 §8–9](cg2d_animation_runtime.md) 接入该唯一状态，
不能另建第二份基址。vector/树采用有据等价容器，不声称旧
STL 节点布局、树形、比较次数或分配失败时机一致；首见树析构不释放主表。

可信 cg3a `ResourceManager::LoadGraphicIndex` 提供了 40B 格式、
全局 seqNo 和来源槽的参考，但其整文件读取、拒绝非整记录、最大 seqNo+1
推进及后加载 mapNo 覆盖不能代替本入口以上已证差异，未复制那些控制流。
