继承已过的 [DX 缓存证据](cg2d_graphic_dx_cache.md) 第 16–194 行的生产与生命周期合同，以及 [sub_507140 证据](cg2d_sub_507140.md)；本项不复查旧证据，不复制 IDA 大段内容或引用矩阵。

现有源码定位与所有权边界按交接继承：

- `resource::gMaxGraphicCount` 是唯一容量；`GraphicRead.hpp:18` 是真实资源入口，`GraphicPendingQueue.hpp:52` 是唯一队列。
- `GraphicCacheState` 仅承接 6 个尾槽；`SurfaceState` 仅承接 `BackTemp`；`SdlPresenter` 是最终帧边界，均不是 DX 的所有者。

Raman `160.2.1` 的 G1a 已覆盖 `103CFA4` 的实际直接引用与实际流程，覆盖内没有未解决的 DX 地址逃逸；没有跨字段别名、整项原始字节复制/比较、持久化传输或指针数值编码。外传内容为尺寸标量、节点、表面、调色板载荷；`520DD0` 只向队列复制两个 W16。

原 `+0C/+0D/+0F` 仍是仅知初始化为 0 的未知字节，不是填充字节。上述结论不是全程序所有计算地址均无别名的证明；不再以理论坏指针可能性设无界门禁，也不重复 G1a 扫描。

G1a 增量证据另见 DX 证据文档；其独立审查与文件验证结论不由本 SPEC 代替。本 SPEC 不修改该文档，不要求重抄矩阵。

## 2. 首选 A：原生非拥有指针

建议由私有 `DxGraphicEntry` 承载：仅将两个原生非拥有指针拓宽，采用 8 B 自然对齐，不使用 `pack`、不重排，拟定 `sizeof` 为 `0x20`。

| 原字段与偏移 | x64 拟定偏移 | 拟定承载与语义 |
| --- | --- | --- |
| `head` `+00` | `+00` | `TextureNode*`，非拥有 |
| `width` `+04` | `+08` | `std::uint16_t`，保留 W16 位模式 |
| `height` `+06` | `+0A` | `std::uint16_t`，保留 W16 位模式 |
| `palette` `+08` | `+10` | `PaletteCacheItem*`，非拥有 |
| 未知字节 `+0C` | `+18` | 1 B，`uint8` |
| 未知字节 `+0D` | `+19` | 1 B，`uint8` |
| `flag` `+0E` | `+1A` | 1 B，`uint8` |
| 未知字节 `+0F` | `+1B` | 1 B，`uint8` |

新布局的对齐空隙不等于原未知字段。尺寸由消费者按原阶段作 S16 解释或 W16 原位复制，不统一解释为正数；索引步长使用新的 `sizeof`，不改变分阶段读取/写入。

`2,200,000` 项拟占 `70,400,000 B`，即十进制 `70.4 MB`；原表占 `35,200,000 B`，增量为 `35,200,000 B`。该预算不含两池及后端资源。

上述类型、布局与大小均为待批提案，不是已编译验证的大小，也不冻结尚未取证的池成员类型。

### 备选 B：16 B 与 U32 池编码

B 仅作备选：原 16 B 表项加 U32 池编码可节省空间，但需另行闭合来源覆盖、解析、复用及旧引用失效合同；16 B 不代表与原指针字节语义等价。

G1a 尚未闭合 B 的全池域。选 A 不要求继续补 B 的证明；本推荐不新增令牌、代际或注册机制。

## 3. 候选文件与所有权

以下均为 `cg2d_re/` 下的未来候选路径，仅列代码文本，不视为现存文件或本项授权修改范围：

- `src/render/GraphicDxCache.cpp`：由 `cg::render` 私有实现分别唯一持有 DX 堆表、4096 槽纹理节点存储、104 项动态调色板存储及 4 项静态共享存储。
- `include/cg/render/GraphicDxCache.hpp`：只公开必要的加载、消费视图与分阶段生命周期责任，不公开完整条目/池布局或 SDL 指针。

四类存储不合并生命周期，保留纹理节点的实际成功创建数。DX 表只拥有条目；纹理池负责节点/表面；动态调色板负责其分配；4 项静态共享项不逐图释放。条目引用与 `node.next` 均非拥有。

两池尚未证实的具体成员不得猜类型，也不得将原步长直接当作无指针数据块。

容量复用 `resource::gMaxGraphicCount`，由原分配阶段写入 `2200000`。四输出槽、当前图号、工作状态在新模块中按原身份唯一承接；当前工作宽度与条目宽度本来就是不同状态，不新增影子尺寸表。容量、资源所有者及队列均复用既有实现；资源读取沿用 `GraphicRead` 的共享缓冲区。

既有 `GraphicCacheState`、`BackTemp`、`Palette` 颜色及队列不改变所有权归属。用户脏改、CMake 与唯一进度文件不在方案授权修改范围；未来接线的具体路径由主线程另行锁定。

## 4. API 责任边界

- 候选 `LoadGraphicDx_522570(S32)` 负责真实资源读取与建链，保留原检查、返回值与副作用；成功不等于链完整。
- 基址捕获只采当前表槽，不解引用；非拥有视图按原消费者阶段分别读取 `h/w` 的 W16 位模式，由消费者作 S16 解释或字段复制。
- 不作整项快照、提前加载或缺失回退，不新增索引保护。
- 生命周期分离为分配结果发布、成功后初始化、两个引用失效及最终释放；不自动清槽或整体重置，不虚构未知原入口签名。
- `520B10` 的节点参数与调色板载荷留在渲染模块内部，SDL 创建/释放封装于实现；不引入新依赖或 RTTI。

本节只约定已交接的职责，不补造其他 API、类型或异常策略。

## 5. 六阶段合同

### 5.1 初始化

顺序保留为 `BuildSurfaceCache` → 调色板池初始化 → `InitPalette` → `GraphicAlloc` → 引用重置 → `GraphicInit`。

在原时点发布分配结果；四个分配全部成功后才清表。不得提前清零，也不得用事务式发布抹去失败残留。

### 5.2 单图尺寸生产

顺序保留为：原门禁 → 资源 → 取宽低 W16 → 写当前图号 → 写入 `w` → 重读表基址 → 取高低 W16 → 写入 `h` → 建链。

读取失败时清工作输出，不清旧条目尺寸；工作宽度的对齐结果不回写以替代条目宽度。

### 5.3 纹理引用

旧 `image` 解绑、条目 `head` 清除、新 `head` 发布、`next` 链接与 `state` 写入均保留原时点。

扫描使用实际节点数，保留正常位宽、U32 比较、有符号除余与对齐行为。部分链节点不足时不补末节点 `next = 0`，不回滚，不改变外层成功返回。

### 5.4 调色板引用

顺序保留为：旧缓存项的 `image` 失效 → 清条目引用 → 取得缓存项并发布 → 上传载荷 → 复用/老化。

P 状态与 DX 尾字段分开；共享项不逐图释放。绘制时仅清调色板缓存项的 `+0x0C` 状态，不清 DX 条目的未知字节。

### 5.5 重建

顺序保留为 `Destroy` → `Init` → `BuildSurfaceCache` → 节点重置 → 两个引用置 0。

整表不替换、不重新分配，不清 `w/h`、`flag` 或未知字节，不提前使引用失效。

### 5.6 退出

顺序保留为：动态调色板释放且清其池槽 → `node.surface` 释放且清 `surface` → 关闭资源 → 释放 DX 表。

DX 槽与容量不清；失败回收不自动清除。不清槽的残值合同不代表使用悬空引用的问题已解决。

- 本项不处理数值溢出、专项回绕或令牌耗尽，也不为其新增门槛；保留正常位宽、掩码与取模。
- 当前不编译/测试/运行，不冻结池未知类型；本 SPEC 及另项 G1a 的独立审查与文件验证结论均不能由本次转录自查替代。
