# cg2d_re 文本编码与跨函数契约 SPEC

- 日期：2026-09-22；文档任务：`RPLAN.16`。
- 状态：编码原则已获用户批准；实现授权留待后续，不表示代码已实现或问题已修复。

## 1. 批准范围与非目标

1. `cg2d_re` 还原核心中承接原端行为的兼容数据，以原始字节为权威表示；Unicode 转换集中在实际适配边界。
2. 此兼容域是父级“内部文本统一 UTF-8”的已批准子项目例外；不推广到旧工程或其他模块。源码、文档仍使用 UTF-8，本文件为无 BOM、LF。
3. 既有证据文档中的“新端内部 UTF-8”描述保留为当前源码或历史实现事实，不再作为兼容数据必须转码的依据；相关记录须区分现状、待修复差异与新契约，不因方案批准而改写为源码已对齐。
4. 不预建通用编码框架，不引入外部依赖，不跨写旧 `src/text`，不全局批量替换，不将本规格视为迁移原 API 的授权。
5. 本轮仅更新 SPEC、相关规则、规划和记录文件，不修改生产代码、构建或测试，不编译、新增或执行测试、运行客户端、查询 IDA 或使用图谱；后续实现须另行推进，不能以文档更新代替功能验收。

## 2. 核心与显示契约

| 范围 | 必须保持的契约 |
|---|---|
| 静态文本 | 按 IDA 已取证的原始字节定义，记录原地址并保留字节内容、长度和 NUL；可用明确字节常量并附中文注释，不由源码编码重新生成旧字节，也不要求新端使用原固定地址 |
| Input、协议、存档 | 保留原字节表示、缓冲容量、字段偏移、索引单位、NUL 及读写顺序，不因 Unicode 字符数不同重排数据 |
| 测宽、换行、截断、文字排队 | 沿用原字节算法及处理顺序，保持字节预算、边界推进、队列内容与布局状态；不整体改写 `TextMeasure`，不在调用点反复转码 |
| 现代显示端 | 仅在真实文本消费者需要 Unicode 时派生显示副本；不得反写原缓冲、重算或覆盖原布局、光标及协议或存档数据 |
| 最终呈现 | `SdlPresenter` 仅接收最终像素帧，不是文本转换点；见 [SdlPresenter.hpp](../include/cg/render/SdlPresenter.hpp) |

每条链须区分字节索引、字符索引和像素单位；Unicode 索引须明确是码元、码点或其他单位，不用“长度”混称。
记录权威缓冲与显示副本的所有者、容量是否含 NUL、借用或复制关系、有效期、释放责任及转换位置；不得用临时副本替代共享状态。
来源编码分别取证，包括常量、输入、协议、存档和资源；不能从一个繁体提示推定全工程为 Big5/CP950，也不能使用未取证的默认代码页。
编码名称未知时可以保留已知原字节；依赖该编码的 Unicode 转换不得靠猜测推进。

## 3. 输入侧与未决行为

1. 输入边界必须覆盖适用的键盘文本、IME 组合串与提交串、光标、选区、属性偏移及剪贴板；记录 Unicode 表示到原字节表示的转换和双向索引对应。
2. 原 Input 的字节光标、长度、容量和处理顺序继续有效；不得直接把 Unicode 索引写入字节字段，见 [Input.hpp](../include/cg/Input.hpp)。
3. 是否更换原输入 API、在哪里接入现代输入及如何保持 IME 时序，须后续逐项取证与授权；本规格不授权 API 迁移。
4. 旧算法原本处理的非法编码字节，不得因新增“必须严格解码成功”门槛而被拒绝；显示转换失败也不得擅自改变原数据或原算法路径。
5. 上述要求不扩张原有效内存域，也不宣称原越界行为可移植。转换失败、不可表示字符、超长输入的处置及字体替换允许的显示差异，须逐项取证或用户裁决。
6. 不擅自替换为 `?`、丢字或新增截断；原端已证实的截断等行为仍按原契约保留。未决项明确阻断对应适配，不自动列为获准差异。

## 4. 首个待实施任务 R6.1.2.8

范围：服务器连接提示常量 → 缓冲复制 → `TextMeasure` → 窗口布局 → 文字入队。
原端事实来自既有 [登录状态控制器证据](cg2d_login_state_controller.md) 与 [字体字节度量证据](cg2d_font_measure.md)，本轮未重新查询 IDA。
前者记录的 IDB 原始输入 SHA-256 为 `dad3f292c6df28e9b7208ad1d339f56ab68c1e728f6595e849e37296551c0f08`；后续实施须核对其与当时权威基线的适用关系。

原 `asc_55C7F0@0x55C7F0` 的 13 字节如下，IDA 显示为“伺服器連接中”：

```text
A6 F8 AA 41 BE B9 B3 73 B1 B5 A4 A4 00
```

当前生产者与布局见 [LoginState.cpp](../src/LoginState.cpp)，消费者见 [Font.cpp](../src/render/Font.cpp)。
按 `font0.doubleWidth = 17` 初值、旧双字节推进及现有布局公式静态推导：

| 项目 | 原字节契约：待实施验收值 | 当前 UTF-8 表示：差异记录 |
|---|---:|---:|
| 正文字节 / 含 NUL 字节 | 12 / 13 | 18 / 19 |
| 双字节累计次数 | 6 | 9 |
| 测宽（像素） | 102 | 153 |
| 列数 `max(2, (width + 111) / 64)` | 3 | 4 |
| 窗口 X `((10 - columns) * 64) / 2` | 224 | 192 |
| 窗口宽度 `columns * 64`（像素） | 192 | 256 |

实施验收还须核对：
1. 常量与复制内容逐字节对应，复制包含 NUL 共 13 字节；保留 256 字节缓冲容量，只覆盖文本和结尾，不清空余部。
2. 首次布局及绘制前再次测宽均消费同一原字节缓冲；保留原整数运算、状态写入和调用顺序，不硬编码结果绕过测宽。
3. 沿真实 `DrawText` 调用核对文字入队的字节、长度单位、复制或借用方式及生命周期，不在入队前悄然换成 UTF-8。
4. 本节是后续静态验收标准，不是新增测试用例或通过结论；任务尚待实施和独立复核，不代表连接、渲染或客户端整链完成。

## 5. 跨函数复核模板

每条链按下列顺序记录，可链接既有证据，禁止只汇总单函数 PASS：

`基线/原地址 → 生产者表示与单位 → 转换 → 消费者约定/状态 → 预期布局/输出 → 批准差异 → 源码提交或指纹/复核范围`

| 字段 | 必填内容 |
|---|---|
| 基线 / 原地址 | 基线标识、相关数据指纹或证据引用、原函数和数据地址 |
| 生产者表示与单位 | 来源编码或未知状态、原字节、容量、NUL、索引单位、所有者与有效期 |
| 转换 | 无转换或明确位置、方向、输入输出表示、失败策略状态、副本生命周期及索引映射 |
| 消费者约定 / 状态 | 实际调用者与消费者、字节或字符预算、像素度量、共享状态与读写顺序 |
| 预期布局 / 输出 | 同输入与初值下的原新数值、入队字节及其他可核对输出 |
| 批准差异 | 用户裁决、日期及适用范围；未决项单列，不以历史限制说明代替批准 |
| 版本 / 复核范围 | 源码提交号或工作区文件指纹、证据版本、实际复核范围与结论；不沿用到未经核对的新版本 |

未来每步仍须真实原端证据与独立复核；单函数静态对应不等于跨函数契约、运行或视觉验收通过。
