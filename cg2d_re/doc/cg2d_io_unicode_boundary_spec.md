# NIO01：网络／文件文字在解析边界迁为UTF-16

用户已确认：原始网络包／文件记录保留字节格式，解析后文本字段存为std::wstring，发送／保存时再编码为GBK。此项覆盖先前在UI消费处重复FromGbk的过渡做法；不依赖CP_ACP，不改变协议、文件字段容量或数值类型。

## 合同

1. 先完成原分隔、长度、转义及二进制字段解析，再按来源确定的GBK码页解码文本；不得对整个二进制包做文本转换。业务对象拥有宽字符串，绘制／测宽借wstring_view。
2. 字节数门禁在原GBK输入或最终编码字节上计算，宽正文长度只用于Unicode处理。原合法数据、字段索引、页数、空行、回调及CryptInt取样顺序保持。
3. 字符串对象必须由构造／赋值／析构管理，退休相关memset／memcpy／memmove；原布局断言只约束仍实际读写的字节存储，历史地址／偏移仍保留注释。
4. 写回原GBK字段时在边界编码并检查既有容量；拒绝语义沿UTL02，不静默截字、猜编码或吞解码异常。尚未迁移的旧记录适配单独明确，不伪称整个项目完成。
5. 仅执行必要静态检查和追踪台账汇总；本次未恢复编译、测试、客户端运行或部署授权。

## 第一模块：玩家／宠物装备及摆摊物品

入口为50BFD0／50C260、510150、4CED60；运行时共用PlayerItemRecord。name／memo／32行description改为宽字符串，解析成功后直接保存。5196B0／519770／4CF8A0先按原GBK列与分页规则提取，再解码各行；不把原96B行步长映射到wstring内存。
玩家／宠物父对象的清理避开非平凡成员，两个物品交换和摆摊删除迁为原生对象赋值。UI名称／备注／描述直接消费宽字段。交易／存放等尚在使用的固定原字节记录，在与本模块交接处明确编码，后续逐组迁移，不能保留隐式char指针混用。
当前检索未见PlayerItemRecord本体直接落盘；不为没有消费者的物品文件格式新增读写器。文件迁移须分别沿现有存档、邮件、日志等真实读写入口处理。

## 后续模块与验收

后续按真实依赖处理交易／存放／商店／晶石物品，再处理宠物／技能／角色名称及邮件／聊天／登录存档。各模块检查完整生产、修改、复制、排序、清理、绘制及写回链；原记录布局、实际字节容量和完整运行门禁分别记录。完成一模块不代表全工程迁移结束。

第一模块旁读核查：4BAA50／4BC660的映射20原读D052FC，即摆摊首物品description[30][72]。该表零初值／浏览重置清零，4CF8A0调用503AB0的width=32，最多写前32B及NUL，原72号尾字节无其它写入者；物品移位只复制同域记录。因此两处明确读取零，保原可用性结果，不对动态wstring使用固定字节下标，也不新增影子文本或假生产者。

## 第一模块当前实现与静态核对

- PlayerItemRecord的name、memo和32行description已持有std::wstring；50BFD0／50C260共用字段生产、510150宠物装备、4CED60摆摊生产均在原GBK解转义及字节长度检查后写宽字段。
- 5196B0／519770／4CF8A0保原width=32及分页回扫，用原分行结果生成宽行；48B1A0和4CDB10直接借宽行指针。共享绘制体保清队列、标题、逐行、页脚和背景顺序；尚未迁移的GBK记录使用单独重载，逐行即时解码。
- 两个物品交换改原生深复制；玩家、宠物、摆摊父对象清理避开宽字符串，摆摊删除按顺序赋值；CryptInt不额外构造，不增加RNG读取。宠物已有默认copy使其现存std::move调用继续按对象复制。
- 加工CC40D8与制作CF46D4结果名称一并持宽；背包、赠物、装备、交易选物及制作提示不再把本模块宽字段送FromGbk／strlen／sprintf。旧背包特殊备注仍用原58A38C书名括号格式，原地址保留。
- 本模块与交易／存放旧字节记录的两处交接使用显式StoreGbk，原名称29B、备注17B、描述96B边界保持。未新增没有实际消费者的物品文件读写器。
- 两处旧description[30][72]旁读按上文静态零值不变量处理；退休已不适用的物品及嵌入后缀尺寸断言，仍使用的字节区与数值字段断言保持。退休9条无剩余消费者的UTF-8常量视图。

本模块6个源码／头的接口、源字段、对象复制、原地址、词法及UTF-8/JSON差异集中核对；未编译、测试或运行。交易／存放／商店／晶石和其它文字模型仍待后续模块，全部网络／文件边界迁移及运行验收保持未完成。
