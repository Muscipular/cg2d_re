# cg2d 输入文本绘制还原

## 函数边界与证据

- `Renderer::DrawInputText@[0x4568A0,0x456D27)`，大小 `0x487`，IDA 统计
  332 条指令、52 个基本块，原型为 `void __cdecl(InputContext*)`；栈局部区
  `0x11C`，其中 `Destination[256]` 位于 `ebp-0x100`。
- IDA 对目标函数给出 32 个代码调用点、25 个调用函数。登录路径
  `sub_45CA20` 在 `0x45CB92` 先比较 `esi < 2`，随后于 `0x45CB97..0x45CBA6`
  固定依次传入 `stru_9A5960`、`stru_9A5678`。本项只提供公共绘制入口，不接入
  登录控制器。
- 入口 `0x4568A7..0x4568CF` 把原 `peddingGraphicCount2@0x73ECB8`
  按 signed32 与 4096 比较；满队列直接到函数尾。多行路径位于
  `0x4568EA..0x456A88`，单行直接记录路径位于 `0x456A8D..0x456C4C`，当前输入
  锚点更新位于 `0x456C52..0x456D17`。
- 单行路径的 `0x456BED`、`0x456C0B`、`0x456C2F` 均从 `field138@0x138`
  读取完整 W32 作为六槽索引；多行路径在 `0x456A00` 只取模式低 8 位传给
  `DrawText2`。记录中的模式、字体、颜色也只写低 8 位。实现以 `memcpy` 读取完整
  模式，避免不兼容指针别名。

## 多行路径

当 `maxLine >= 2` 时，只先确认固定 `text[288]` 内存在 NUL，再从字节 0 开始反复
扫描；该分支不要求完整模式、字体、`field158`、总长或光标落在通常输入域：

- 回车 `0x0D` 前的字节复制到 `Destination` 并补 NUL，回车自身只推进、不绘制；
  LF 没有特殊处理。
- 达到 `maxCharPerLine` 后仍按原 `strlen(剩余串) < unsigned(maxCharPerLine)` 的 W32
  无符号比较区分尾串。负值或大于 255 的值若先遇到短 NUL 尾串，仍直接走尾串
  绘制；只有实际遇到 CR 或进入定长复制时才检查 `Destination[256]` 写界限。
  CR 前最多复制 255 字节并在索引 255 补 NUL；定长段也只在实际长度不超过 255
  时复制。若 `ClassifyLastAnsiUnit_44B190` 返回 3，则删去段尾孤立高位字节并少推进
  一字节；实际推进量不大于 0 时返回，避免原端零推进死循环。
- 每个完整段都调用 `DrawText2_456670`，坐标取 W32 加法后的低 16 位，模式、字体、
  颜色取低 8 位，`value7=0`；返回值按原函数忽略。剩余尾串再调用一次同一入口。
- `maxLine` 不限制实际绘制段数，只决定光标恰落在分段边界时使用 `<` 还是 `<=`
  判定所属行。Y 偏移每个完整段按 W32 加 `field14C`。

## 单行路径

单行不调用 `DrawText2`，而是直接写当前 `TextPendingRecord` 的坐标、模式、颜色、
字体和 `value7=0`。它不写 `marker@+8`、`field108@+0x108`，也不清理文本 NUL
后的旧字节。

- 该分支才要求完整 W32 模式落在 `0..5`，并在实际解引用尾令牌前检查其范围。
  字体不作入口门禁，记录中仍只保存低 8 位。
- `encrypt >= 1` 时以 W32 `totalByteLength-field158` 的 signed 结果为长度，每个源
  字节对应一个 `'*'`；差值不大于 0 时只写 NUL，正数只接受至 254。该构造本身
  不读取原文本，也不要求 `field158` 或总长各自落在固定数组域。非加密路径实际
  使用 `text+field158`，因此只在该路径要求起点为 `0..287` 且后缀存在 NUL，并
  最多复制 254 字节。
- `field154 != 0` 且输出非空时，以完整 `field13C` 反复调用
  `Font::measure(entry.text,fontType,n)`。超宽先减一；每轮都对未截断的原始后缀
  调用 `ClassifyLastAnsiUnit_44B190`，结果 3 时再减一。若减到不大于 0，不补写
  新终止符，保留已经写入的完整输出并继续排队；因此保留“一个字符都放不下反而
  不截断”以及正常 DBCS 仍可能被逐字节切断的旧行为。只有测宽结果实际超宽、即将
  调用分类器时，才要求原后缀起点有效且在固定数组内存在 NUL；所以加密且宽度为 0
  且非当前上下文的路径完全不读取 `context->text`。
- 初始记录仍使用入口计数。宽度循环在超宽轮的 `0x456BB5` 以及可容纳分支的
  `0x456BC1` 重读 `peddingGraphicCount2`，随后 `next/entry` 使用该阶段最新计数；
  非空尾先连接旧尾，再于 `0x456C2A` 再次重读计数更新尾槽。所有实际记录索引前
  都按 signed W32 检查 `0..4095`。`0x456C4C` 最后对内存中的当前计数直接做 W32
  加一，而不是写“入口计数加一”。空尾仍先更新尾槽，再调用 `QueueText_521A30`
  并忽略返回；图形队列已满时文本计数仍按原路径递增。

## 当前输入锚点

只有绘制或排队完成且 `input::gCurrentInputData == context` 后才执行锚点局部门禁并
更新 `x/y`；本函数不绘制光标或 IME：

- `maxCharPerLine > 0 && maxLine >= 2`：从记录的光标所属行首测量到
  `caretByteOffset`；字节预算按 W32 减法取得，不提前限制光标。X 为
  `field130+宽度`，Y 为 `field134+该行偏移`，均保留 W32 环绕语义。
- 其余路径：按 W32 计算 `caretByteOffset-field158` 并复现 `jns`。负结果先把
  `field158` 写成光标，再按 0 字节预算的零宽语义处理；非负结果仍以原
  `field158` 为源。只有正预算且完整字体有效、确实调用测宽时，才要求源起点落在
  固定数组内，并按 `Font::measure` 的单/双字节步进确认实际读取不会越界；零预算
  或非法完整字体不检查源地址，首字节 NUL 也不会因后续内容被拒绝。Y 直接写
  `field134`。

## 新端安全边界

以下门禁按实际分支和首次危险操作局部放置，只拒绝会越过已知固定存储、形成无限
循环或索引记录池的损坏状态；正常域的星号按字节、CR 分行及不限制实际行数保持
不变：

1. 文本计数先按 signed32 检查；至少 4096 时立即返回且不更新锚点，负数也在任何
   数组索引前返回。随后才检查空上下文。
2. 多行仅要求 `text[288]` 内有 NUL。CR/定长复制各自在真正写
   `Destination[256]` 前限制为最多 255 字节；定长分割实际推进量不大于 0 才返回。
   不统一限制 `maxCharPerLine`、完整模式、完整字体、`field158`、总长或光标。
3. 多行每段仍调用既有 `DrawText2_456670`。该入口自行拒绝超过文本记录容量、非法
   低 8 位模式或损坏尾令牌；本函数按原控制流忽略返回值。
4. 单行完整模式只接受 `0..5`，尾令牌只接受 `0..4096`。明文后缀和加密正长度各自
   最多 254 字节；加密非正差值只写 NUL，且在无需分类或锚点测宽时不探测原文本。
5. 完整 `fontType` 不作入口门禁；`Font::measure` 对非法 W32 字体和非正预算已有安全
   返回。单行锚点仅在正预算且字体有效、确实测宽时检查源起点和实际读取边界；零预算
   或非法字体不检查源地址。其余原后缀 NUL 与字段门禁也只在实际读取对应文本时局部
   检查。
6. 单行所有阶段重读出的文本计数只在用作记录索引时验证；最终递增使用内存当前 W32
   值，保留原单线程指令顺序。

输入光标闪烁与排队已由 [sub_44A410](cg2d_input_caret.md) 独立实现。本项不实现
`World::RenderInput`、`sub_45CA20` 或最终图形消费器。
